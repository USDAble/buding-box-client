## 1. 目标与非目标

**目标**：把「双击 → 出窗口」这条路径上的所有异常分支变成用户看得懂的界面，并把三种「离开」的语义分清。

**非目标**

- 不做拦截页本身（P4），本 PR 只保证「未登录时窗口起得来、关得掉」。
- 不做代码签名、不做安装器（需求 §7）。
- 不改端口号，不做与本机 Octo 双开（需求 §10 T13）。

## 3. 设计

### 3.1 启动阶段状态机

把 `main()` 前段重构成一条**显式的、可失败的**引导链。每个阶段失败都有对应的用户可见形态，不允许任何一步 panic 到黑屏。

```
  ┌──────────────┐
  │ 0 早期环境   │ TMPDIR 修正（上游已有）
  └──────┬───────┘
  ┌──────▼───────┐  失败 → FatalDialog(reason=webview2)  含下载页按钮
  │ 1 WebView2   │
  └──────┬───────┘
  ┌──────▼───────┐  失败 → FatalDialog(reason=dataroot)  含路径与原因
  │ 2 数据根就绪 │  datapath.Root() + datapath.Writable()
  └──────┬───────┘
  ┌──────▼───────┐  已在运行 → 激活旧窗 + Toast，本进程退出
  │ 3 单实例     │  且当 exe 路径不同 → 提示「请先退出再打开另一份」
  └──────┬───────┘
  ┌──────▼───────┐  失败 → FatalDialog(reason=port)   文案含「Octo 或其它程序」
  │ 4 端口 8088  │
  └──────┬───────┘
  ┌──────▼───────┐
  │ 5 正常启动   │ → 托盘 + 窗口 + 看门狗
  └──────────────┘
```

**FatalDialog** 是本 PR 的新组件：一个不依赖 webview 的原生对话框（Wails 的 `application.ErrorDialog`，WebView2 缺失时 webview 用不了，所以不能用 HTML 页）。文案走 `internal/brand` + `cmd/octo-desktop/lang.go` 的现有多语言表，按系统 UI 语言（简中 → 中文，其余 → 英文，含繁中，需求 §5.3.1 / §10 T10）。按钮只有一个「退出」，点击结束进程 —— 需求 §5.1.2-4 明确要求不是「退出登录」、不挂托盘。

### 3.2 单实例：区分同一份 / 另一份

上游 `OnSecondInstanceLaunch` 只给了 `SecondInstanceData`，需要知道第二个进程是不是同一份目录。做法：

- 第一个实例启动后把自己的 exe 绝对路径写进 `data/serve.pid` 旁的 `data/instance.json`（`{"exe": "...", "pid": 1234, "startedAt": "..."}`）。
- 第二个实例在数据根就绪之后、单实例检查之前，读**自己的** `data/instance.json`：
  - 文件存在且 pid 存活 → 说明点的是同一份目录 → 走 Wails 单实例激活，仅 `showWindow()`，不提示。
  - 文件不存在或 pid 不是自己 → 说明另一份目录已占住互斥量 → 激活已有窗口**并**推一条持久提示：「布丁盒子已在运行，请先退出再打开另一份。」

Wails 的 `SecondInstanceData` 携带 argv，第一个实例据此可拿到第二个的 exe 路径，用于把提示做得更具体（显示对方目录）。若拿不到就用通用文案。

### 3.3 端口探测

在 Wails 起来之前，先自己 `net.Listen("tcp", "127.0.0.1:8088")` 探一次：

- 成功 → 立刻 `Close()`，交给正常启动流程重新监听。存在极小的 TOCTOU 窗口，可接受：真撞上时正常监听也会失败，落回同一个 FatalDialog。
- 失败 → 读 `data/serve.pid`（P1 之后在数据根）。pid 存活且是本产品 → 这条路径已被 3.2 拦掉，正常不会到这里；否则一律按「被其它程序占用」处理。

文案严格按需求 §5.1.2-6：「端口 8088 已被占用。若本机正在运行 Octo 或其它程序，请先退出后再打开布丁盒子。」产品名走 `{brand}` 插值，"Octo" 是外部程序名保持字面量。

> 注意：需求 §8 验收「提示含『Octo 或其它程序』」——这句里的 Octo 指的是**上游那个产品**，不是本产品品牌，不能被 `brand-guard` 当成漏改的品牌字面量。在文案表该行加 `// upstream product name, not our brand` 注记。

### 3.4 拔盘 / 目录消失冻结

新增 `cmd/octo-desktop/watchdog.go`：

- 每 2 秒 `os.Stat(datapath.Root())`。用轻量 stat 而不是文件系统事件通知 —— U 盘拔出时 Windows 的 `ReadDirectoryChangesW` 句柄本身就失效，收不到事件。
- 连续 2 次失败（避免瞬时抖动误报）→ 进入冻结：
  1. 广播 `app.Event.Emit("datastore:lost")`，前端切到全屏冻结遮罩，禁用所有输入。
  2. 后端置一个进程级 `frozen` 门（落在 `internal/datapath`：`Freeze()` / `Thaw()` / `Frozen()`），**所有写路径**在写之前检查它——`datapath.Root()` / `Sub()` 在冻结时返回 `ErrFrozen`，拒绝创建目录，而不是尝试写。这是「禁止改写主机」的实际保证点。门放 `datapath` 而非 watchdog 实例字段，是因为写路径都在 `internal/` 包、只能依赖收口层的进程级标志；`Join()`（只读）不检查，目录没真消失时仍可读。
  3. 继续每 2 秒探测。
- 恢复条件（需求 §5.1.2-10）：**同一路径**再次可用，且 `data/instance.json` 里记录的 pid 仍是自己 → 解冻，`Emit("datastore:restored")`。路径变了（换盘符）→ 不自动续跑，冻结遮罩上给「退出」按钮。

冻结判定只认路径字符串相等，不认卷序列号——需求写的是「同一路径（含同一盘符）」，按字面实现，也避免引入读硬件标识（需求 §7 明确不做）。

### 3.5 关闭自启动与自动更新

`octo-desktop` 这个二进制**就是**便携产品——数据根统一为 `data/` 之后（P1 已删掉 `~/.octo` 与运行期模式判定），不存在「非便携的桌面形态」。所以这两项在桌面端一律关闭，不需要开关：

- `cmd/octo-desktop/settings.go` 的自启动：`AutostartAvailable()` 恒返回 false，桥接层不暴露该字段，前端据此不渲染（需求 §5.1.2-9「完整设置里若仍有该项，便携包也不渲染」）。
- `update.go`：`canInplaceUpdate()` 恒 false，托盘不挂「检查更新」项，不起后台检查 goroutine。个人中心的「检查更新」是纯前端待接入（P5）。

**不删上游代码**，只是让它恒为 false（上游合并策略 §4.4）。这两个函数体里各留一行 `// OCTO-FORK:` 注记说明原因。

### 3.6 三种离开

| 动作 | 实现 |
|---|---|
| 点窗口关闭 | 上游 `ShouldQuit` 已正确（`main.go:236`）。本 PR 只补：拦截页在前台时同样进托盘（不额外分支，天然满足；补一条回归测试） |
| 托盘「退出」 | `bridge.allowQuit.Store(true)` 前先执行 `flushAll()`：会话 `Save()`、`product-state.json` 落盘、`instance.json` 删除、`serve.pid` 释放（`serveproc.ReleaseOwned`）。**落盘完成再** quit |
| 个人中心「退出登录」 | 不经过本 PR，见 P3。本 PR 保证 `flushAll` 与之互不干扰 |

托盘菜单与退出确认里补「退出后再拔出 U 盘」，文案键 `tray.quit_hint` / `tray.unplug_hint`，中英双份。

## 4. 接口与数据结构

```go
// cmd/octo-desktop/bootstrap.go
type BootFailure struct {
    Reason  string // "webview2" | "dataroot" | "port" | "instance"
    Detail  string // 路径、占用进程名等，可为空
}

// 每步返回 nil 或 *BootFailure；main() 拿到非 nil 即弹 FatalDialog 后 os.Exit(1)。
func checkWebView2() *BootFailure
func checkDataRoot() *BootFailure
func checkSingleInstance() (activateExisting bool, f *BootFailure)
func checkPort(addr string) *BootFailure

// cmd/octo-desktop/watchdog.go
type Watchdog struct{ /* ... */ }
func StartWatchdog(root string, onLost, onRestored func()) *Watchdog
func (w *Watchdog) Frozen() bool // = datapath.Frozen()，进程级门

// internal/datapath/datapath.go（冻结门本身）
func Freeze()          // 看门狗 onLost 时调用
func Thaw()            // onRestored 时调用
func Frozen() bool
var ErrFrozen error    // Root()/Sub() 冻结时返回
```

`data/instance.json`：

```json
{ "exe": "D:\\PuddingBox\\PuddingBox.exe", "pid": 12345, "startedAt": "2026-09-07T10:00:00+08:00" }
```

前端事件：`datastore:lost` / `datastore:restored`，由 `web/src/lib/stores.ts` 新增 `frozen` store 承接。

## 6. 测试

**单测**

- `checkPort` 对已占端口返回 `Reason: "port"`。
- `checkSingleInstance`：同目录 / 异目录两种 `instance.json` 分支。
- `Watchdog`：目录被 rename 走 → `onLost` 触发；rename 回原路径 → `onRestored`；rename 到**新**路径 → 不触发 restored。
- `AutostartAvailable()` / `canInplaceUpdate()` 恒 false。

**手工验收**（Windows）

1. 先起一个 `octo serve` 占住 8088，再双击 → 出现含「Octo 或其它程序」的提示，点退出进程结束。
2. 在无 WebView2 的干净 Win10 虚机双击 → 出现说明而非闪退。
3. 把 `data/` 设为只读 → 出现原因说明，不进业务，`%USERPROFILE%` 无新增。
4. 双击第二份目录的 exe → 激活第一份的窗口并提示。
5. 运行中拔 U 盘 → 界面冻结；插回**同一盘符** → 可继续；插回**别的盘符** → 只能退出。
6. 托盘菜单与退出确认里能看到「先退出再拔出 U 盘」。
7. 设置里看不到开机自启动；托盘里没有检查更新。

## 7. 上游合并影响

**等级：中。** 改动集中在 `cmd/octo-desktop/`，上游对这几个文件的更新频率中等。

- `main.go` 的 `main()` 前段被整体重构，**与上游的冲突几乎必然发生**。缓解：把新逻辑全部放进 `bootstrap.go`，`main()` 里只留一串 `if f := checkX(); f != nil { fatal(f) }`，冲突面从「一大段逻辑」缩到「几行调用」。
- `update.go` 与 `settings.go` 只把两个判定函数改成恒 false，用 `// OCTO-FORK:` 注记标出，方便合并时识别。
- 不删上游任何函数（自启动、更新代码全部保留，只是不触发），这样上游对它们的修改能干净合进来。需求 §7 也只要求「隐藏 / 关闭」，不要求删除。

## 9. 风险与决策

| 项 | 处理 |
|---|---|
| WebView2 检测误判（用户装了但注册表键位置特殊） | 检测失败时**不直接退出**，先尝试起窗口，起不来再弹对话框。宁可多试一次也不要把能用的机器挡在外面 |
| 看门狗 2 秒轮询在 U 盘上的 IO 开销 | stat 单个目录开销可忽略；若实测有唤醒功耗问题，退化为 5 秒 |
| 冻结期间已在飞行中的写操作 | `frozen` 标志只能拦住尚未开始的写；已进入 `os.WriteFile` 的调用会自然失败。接受，需求只要求「禁止改写主机」，而不是保证 U 盘上的写原子完成 |
| macOS / Linux 回归 | 单实例、托盘、看门狗全部在非 Windows 上也会跑。所有新分支都要有 `runtime.GOOS` 覆盖测试，避免为 Windows 验收引入 mac 回归（开发计划 §5 已列此风险） |
