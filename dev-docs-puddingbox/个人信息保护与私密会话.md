# 个人信息保护与私密会话

写作参照：`dev-docs/permission-remember-design.md`

> 个人信息保护负责在落库前不可逆脱敏，私密会话负责限制模型处理边界。两者可以组合，但不是同一个等级开关；内容安全防护继续独立处理违规或不适宜内容。

## 范围

本文记录已经确认的隐私产品边界、目标数据流、私密模型要求和首批规则选择方式。它是待实现设计，不表示当前代码已经完成个人信息脱敏或私密模型自动切换；当前实现差距在文末单列。

## 非目标

第一阶段只处理用户提交的普通文本，不覆盖：

- 附件正文、上传文件和 OCR 结果；
- 工具参数、工具调用 JSON 和工具返回值的深层结构；
- thinking block 或签名推理块；
- 依靠关键词自动判断商业秘密、合同秘密或内部经营信息。
- 约束 Web 搜索、MCP、终端、脚本或其他工具的数据去向。私密会话只保证模型路由到私密模型，工具继续遵循现有权限与数据规则。
- IM 渠道、定时任务和系统生成消息的个人信息保护状态。首版只覆盖手工 Web 聊天；其他入口在具备状态选择和用户提示后再单独设计。

现有输出链路已经会遮盖可见的工具结果文本；这里的“不覆盖”表示个人信息保护暂不向工具协议内部扩展，不要求撤掉已有内容安全防护。

## 三项能力各自回答一个问题

| 能力 | 回答的问题 | 主要机制 |
| --- | --- | --- |
| 内容安全防护 | 内容是否允许输入、展示和持久化 | 敏感词检查、拒绝或打码 |
| 个人信息保护 | 文本里是否留有可识别个人的信息 | 落库前不可逆脱敏 |
| 私密会话 | 整段内容允许交给哪类模型处理 | 模型可信标签、路由限制和禁止公共回退 |

三者不得共用一个总开关。界面可以把它们放进同一个“安全与隐私”面板以减少输入区噪音，但每一行保留独立状态、说明和失败结果。

## 个人信息在落库前不可逆脱敏

目标路径只有一份持久化消息：

```text
用户输入 → 本地识别 → 不可逆脱敏 → 保存脱敏文本 → 发送同一份脱敏文本
```

数据库、聊天历史、重新发送、导出和模型上下文都读取脱敏后的文本，不保存原始值，也不保存可恢复映射。这样不需要维护“本地原文”和“模型副本”两套历史，也不会在后续回合重新把历史原文带给模型。

首版使用类型占位符，例如 `<姓名>`、`<手机号>`、`<邮箱>`。不使用 `138****8000` 一类半脱敏结果，也不承诺把跨消息出现的同一个人稳定编号；前者仍泄露部分真实值，后者需要保存额外映射并重新引入敏感数据管理。

个人信息保护是会话级选择，新会话默认开启，并且必须在首条消息前确定。首条消息后不能关闭或开启：已经以原文保存、发送的历史不能靠后来打开开关变成受保护内容，而中途关闭又会让同一会话出现两种持久化语义。已有普通历史的会话需要新建受保护会话。

## 处理顺序与事实所有者

普通文本的权威服务端路径固定为：

```text
原始输入（仅短暂存在于本机进程内存）
  → slash command 分类
  → 内容安全输入门：拒绝则结束
  → 个人信息引擎：保护开启时生成脱敏文本
  → 取得会话绑定与回合锁
  → 广播脱敏文本
  → 持久化脱敏文本
  → 组装模型上下文并发送同一份脱敏文本
```

不能先广播或排队再脱敏。正在运行回合中的 steer、独立 queue 和空闲回合必须共用同一个预处理函数；否则普通发送安全、排队发送泄漏。附件路径注释属于现有附件链路，第一阶段不送入个人信息引擎，但私密会话的模型资格仍覆盖带附件的整个回合。

命令需要按是否携带用户正文分类：`/clear`、`/compact`、`/reload` 等纯控制命令不进入个人信息引擎；`/goal <text>` 等会持久化或进入后续模型上下文的参数先经过内容安全和个人信息保护，再交给命令处理器。不能因为语法以 `/` 开头就让正文绕过保护。

新建 `internal/pii` 作为个人信息规则、校验与替换的唯一所有者，不复用 `internal/sensitive` 的词库语义。建议最小接口为：

```go
type MatchSummary struct {
    Category string
    Count    int
}

type Result struct {
    Masked  string
    Matches []MatchSummary
}

type Engine interface {
    Transform(text string) (Result, error)
}
```

引擎输出只含脱敏文本、类别和数量，不返回原始命中片段或可恢复映射。相同输入、规则版本和配置必须得到相同输出，使前端 transform 与发送入口的权威处理一致；规则版本可记录到诊断事件，但不得连同原文写日志。

服务端注入 `PersonalInfoTransform` 到所有受保护的 Web 用户文本入口，位置与现有 `SensitiveInputGate` 相邻但职责分开。首版明确覆盖普通发送、steer、queue 和编辑后重新运行；重试读取已脱敏历史，不再次接触原文。普通上游 `octo serve` 未组装产品能力时可以没有该依赖；只要会话声明 `personal_info_protection=true` 而引擎缺失或失败，就必须拒绝本次发送，不能把缺失解释为“无需处理”。

## 输入区只提供一个“安全与隐私”入口

聊天输入区的元信息行增加带盾牌的“安全与隐私”控件，打开后分成三个明确条目，而不是三个模式：

```text
[附件] [🛡 安全与隐私] [🤖 厂商 / 模型] [推理]

安全与隐私
  内容安全防护      [开关]  输入检查；输出和昵称始终开启
  个人信息保护      [开关]  落库前不可逆脱敏
  私密会话          [开关]  仅使用私密模型
```

- 内容安全防护：输入检查开关可以随时调整；关闭时二次确认。模型输出防护和昵称校验显示为“始终开启”，不提供关闭开关。
- 个人信息保护：新会话默认开启；首条消息前可以关闭，首条消息后显示“已锁定”。
- 私密会话：新会话默认关闭；首条消息前可以开启，首条消息后显示当前锁定状态。

个人信息保护和私密会话都不放在个人中心的三组默认模式中。私密会话开启后，输入区上方持续显示“私密会话 · 仅使用私密模型”；普通会话不占用额外提示条。模型选择器继续独立存在并展示当前模型的私密属性。

个人信息保护开启且存在附件时，附件区显示“附件内容暂不自动脱敏”。提示不阻止发送，也不能隐藏到详情页；它只说明本阶段的真实能力边界。私密会话仍约束该回合使用的模型，但不改变附件内容和工具读取附件后的数据规则。

## 命中个人信息时自动脱敏并提示

发送按钮先调用本机脱敏接口。未命中时直接进入正常发送；命中时不要求用户再次确认，也不提供“返回修改”，而是立即使用脱敏文本继续发送：

- 聊天气泡从一开始就显示脱敏文本，不能先渲染原文 ghost 再替换；
- 输入框上方或气泡附近短暂提示“已自动脱敏 3 项：姓名、手机号、邮箱”；
- 提示可以展开查看本次使用的脱敏文本和类别，但不展示原值、不提供恢复原文或编辑原文的入口；
- 原始输入在取得脱敏结果后立即从前端草稿状态清除，只允许短暂存在于 WebView 与本地服务的请求内存中；
- 用户后续如需修改，编辑的是已经脱敏并持久化的文本，不恢复原始个人信息。

服务端发送入口仍要执行同一套不可逆脱敏，不能把“来自新版前端”当作可信条件。新版前端提交的是已经脱敏的文本，因此引擎必须把标准占位符视为受保护片段并保持幂等；旧客户端或绕过 transform 的请求提交原文时，服务端完成权威脱敏并发出不含原值的 `privacy_applied` 事件。日志只能记录规则类别、数量和版本。任何失败都不能回退保存原文。内容安全输入检查先判定是否拒绝，只有允许发送的文本再进入个人信息脱敏；被内容安全规则拒绝的文本不需要产生脱敏历史。

脱敏接口只在本机服务中处理请求，不调用中台：

```text
POST /api/product/privacy/transform
{"text":"张三的电话是……"}

200
{
  "hit": true,
  "masked": "<姓名>的电话是<手机号>",
  "matches": [
    {"category":"name","count":1},
    {"category":"phone","count":1}
  ],
  "ruleVersion": "builtin-1"
}
```

请求体和响应均使用 `Cache-Control: no-store`；访问日志不得记录 body。前端不持久化 transform 响应，取得结果后立即用 `masked` 替换待发送文本、清除原始草稿并提交脱敏文本。服务端发送入口再次执行同一引擎：标准占位符保持不变，仍存在的其他命中继续被脱敏，最终只广播和持久化服务端结果。

前端收到 `hit=true` 后直接发送 `masked`，并用 `matches` 生成本地提示。若服务端复核又发现其他命中，只广播和持久化补充脱敏后的文本，并通过 `privacy_applied` 通知“已补充脱敏”；事件不携带前端已经丢弃的原文。

如果用户绕过本机 transform 接口、使用旧客户端或另一个窗口直接发送原文，服务端仍自动使用脱敏结果继续回合。前端接口负责及时反馈和防止原文 ghost，服务端发送入口才是安全边界。

## 会话状态与原子性

会话字段、锁定规则和兼容处理统一由 [模型选择与私密会话](模型选择与私密会话.md) 定义。个人信息侧遵守以下额外约束：

- 新会话默认 `personal_info_protection=true`，不提供个人中心全局默认开关。
- 首个被接受的用户回合才锁定。内容安全拒绝、脱敏失败和模型资格失败都不锁定。
- 首条消息的状态必须在创建会话时持久化，不能只放在浏览器 pending store；刷新或另一个窗口看到同一个空会话时必须得到相同值。
- 多窗口同时修改保护状态和发送首条消息时，由服务端会话锁串行化；先成功持久化首个回合的一方确定最终状态，另一方得到 `session_policy_locked` 并刷新状态。
- 已有含历史消息但缺少新字段的会话按未保护且已锁定处理。旧历史不批量脱敏、不重写、不冒充已经安全。

会话返回对象应直接包含版本化保护策略；`locked` 是持久化事实而不是根据消息数组长度临时推断。服务端才知道清空、回滚、排队消息、其他窗口和持久化的真实状态。生命周期规则见 [模型选择与私密会话](模型选择与私密会话.md)。

## 私密会话限制模型处理边界

个人信息规则无法识别“尚未发布的价格”“收购计划”或内部源代码等机密内容。私密会话因此不依赖关键词判断，而是限制整段对话只能发送到可信的私有模型：

- 产品 Profile 只接受可信目录明确声明的私密资格，不能根据名称、地址字符串或 UI 分组自行猜测；
- 私密模型不可用时停止开始新回合，不能自动回退到公共模型；
- 开启私密会话时，如果当前模型不符合要求，自动切换到目录指定的首选私密模型，并明确提示用户；
- 模型选择器和当前模型标签都要显示可辨认的“私密”标识，不能只靠排序表达安全属性；
- 开发 Profile 允许在本地模型管理中手工标记“可用于私密会话”，用于测试排序、自动切换和禁止回退；该测试标记在产品 Profile 中不可见且不采信。
- 私密会话不改变工具权限，也不承诺工具参数或返回值处于私密模型边界内；工具继续按现有权限、确认和网络行为运行。

私密模型的展示和自动切换复用统一模型列表，具体模型来源、排序和当前实现差距见 [模型选择与私密会话](模型选择与私密会话.md)。

## 失败与提示

- 脱敏处理自身失败时，不得保存原文后继续发送；本次发送失败并提示用户重试。
- 私密会话找不到合格模型时，不得退出私密状态后继续发送；提示用户当前没有可用私密模型。
- 自动切换模型时提示“已切换到私密模型：<模型名>”，同时说明不会自动改用公共模型。
- 私密会话发送首条消息后，普通模型不可选择；需要普通模型时新建普通会话。
- 已有普通历史的会话不能原地升级为私密会话；入口改为“新建私密会话”。

## 日志、指标与故障边界

- 日志只允许记录 session ID 的短哈希、规则版本、命中类别/数量、结果长度和错误码；禁止记录输入、脱敏结果、替换前后片段或映射。
- 指标可统计规则类别命中次数、自动脱敏提示次数、引擎失败次数和私密模型资格拒绝次数；不得以手机号、邮箱、姓名等原值作 label。
- 崩溃恢复、重放和导出只读取持久化后的脱敏文本。内存中的原始输入不进入恢复文件、队列快照或诊断 dump。
- 个人信息引擎失败使用 `privacy_transform_failed`；会话锁冲突使用 `session_policy_locked`；私密模型不合格和不可用分别使用 `confidential_model_required`、`confidential_model_unavailable`。前端只按码取本地化文案。
- 产品 Profile 的私密会话只接受当前验签成功且尚未过期的目录资格。目录过期、缺失或不可验证时立即停止新回合，不能沿用过期资格，也不能回退普通模型；开发 Profile 的本地私密测试模型不依赖中台目录。

## 首版规则验收口径

首版不以“50 类全部覆盖”为完成标准。上表每条规则必须有：正例、相似但不应命中的反例、边界字符、连续多次命中、混合类别、Unicode/全角输入和性能样例。结构化号码使用校验位或前缀/长度组合；访问凭据按登记格式和上下文识别，不能用“长字符串”作为泛化规则。

占位符使用固定中文类型名并保留尖括号，例如 `<手机号>`。同一段连续文本的同类相邻命中不合并成一个不可解释的大块；重复值不编号、不建立跨消息关联。规则重叠时按“凭据与证件 > 金融账号 > 联系方式 > 泛化文本”的优先级选择最长有效命中，避免先把身份证的一部分识别成手机号后破坏校验。

国际手机号、护照、通行证、车牌、助记词、姓名、详细地址、医疗语义等规则继续留在候选池，不进入首版安全承诺。CI 测试校验本文九个规则 ID 与代码注册表完全一致，防止文档和规则集漂移。

## 实施拆分与验证

本主题必须交付四个闭环：`internal/pii` 规则引擎及表驱动测试；版本化会话保护策略和原子更新；普通文本、steer、queue、编辑等入口的服务端权威处理；“安全与隐私”面板、自动脱敏提示和 `privacy_applied` 事件。跨目录、会话、服务端和 UI 的实际先后、门禁及回滚统一由 [安全与隐私实施设计](安全与隐私实施设计.md) 管理，本文不维护第二套总计划。

关键验收场景：

- 保护开启且命中：磁盘、WebSocket history 事件和 fake provider 只出现占位符，仓库测试输出也不打印原值。
- 保护关闭：普通文本沿现有路径发送，但内容安全输入门、输出打码和昵称校验不受影响。
- 内容安全与个人信息同时命中：内容安全先拒绝，不产生脱敏提示或历史。
- steer/queue 命中：行为与空闲发送一致，不存在旁路。
- 引擎报错：回合未开始、历史未增加、模型未调用。
- 两窗口竞态：首个落库回合锁定状态，另一个窗口收到明确冲突并刷新。

## 当前实现差距

当前代码只有隐私标识、提示文案和 `chat_mode` 会话字段，没有在落库前执行上述个人信息不可逆脱敏。“安全与隐私”面板、自动脱敏提示和会话锁定均尚未实现；现有三组模式目录也仍未退出。

实现应先补测试证明“原始个人信息不落库、不广播、不进入模型请求”，再改变界面承诺；私密会话则需要同时验证目录标签、自动选模、模型不可用和禁止公共回退四条路径。
