# 模型选择与私密会话

写作参照：`dev-docs/endpoint-pr5-impl.md`

> 聊天框只保留一套上游模型选择器，继续使用“厂商 → 模型 ID”的两级结构。私密是模型属性和会话约束，不再是模型分组；`privacy`、`smart`、`default` 三组模式及其设置全部退出目标设计。

## 范围

本文件定义模型来源、统一列表、开发/产品 Profile 差异、私密模型标记、排序以及私密会话的选择和锁定行为。中台目录签名由 [中台接口契约](中台接口契约.md) 定义，个人信息脱敏由 [个人信息保护与私密会话](个人信息保护与私密会话.md) 定义。

本文描述模型选择与私密会话的当前产品和技术事实；尚需人工联调的项目在验证章节明确列出，不把未验证行为写成已验收能力。

## 非目标

- 不改变上游“厂商父级、模型 ID 子级”的基本结构和选择交互。
- 不把中台模型写进用户的 `config.yml`，也不允许生产设置页编辑中台托管模型。
- 不按模型名称、厂商名称或地址字符串猜测私密资格。
- 不在私密模型不可用时自动回退到普通模型。
- 不保留“智能模式”“普通模式”“隐私模式”作为兼容分组。
- 私密会话只约束模型路由，不改变工具权限、工具参数、工具返回值或外部工具的数据边界；工具仍按现有权限与确认机制运行。

## 只有一套模型选择器

模型列表按上游方式展示：厂商名称是父级，模型 ID 是子级。会话仍保存能唯一确定路由的复合身份；展示层可以隐藏 endpoint 细节，但同一厂商下出现重复模型 ID 时必须用 endpoint 标签消歧，不能因展示相同而绑定到错误地址。

列表有两个来源，但进入同一个只读投影：

- 中台目录模型：登录后取得、验签并缓存；展示和路由资格以可信目录为准。
- 本地配置模型：开发 Profile 中由上游 endpoint 管理产生；事实源仍是 `config.yml`。

选择器只消费归一化后的模型行，不拥有第二份目录状态。设置页继续管理本地 endpoint；中台模型不出现在可编辑配置中。

## 目标数据模型

选择器的数据适配层把中台目录和本地 endpoint 投影成同一个只读类型。组件只依赖下列字段，不读取签名目录、`config.yml` 或旧模式对象：

```ts
type SelectableModel = {
  id: string                 // 可持久化、可路由的复合身份
  vendorId: string           // 稳定厂商 ID，用于分组而非展示
  vendorName: string         // 已本地化的厂商名称
  modelId: string            // 模型 ID
  displayName: string        // 可空；为空时展示 modelId
  source: 'catalog' | 'local'
  confidential: boolean      // 能否用于私密会话
  confidentialPriority?: number
  trust: 'signed-catalog' | 'developer-local'
  sourceOrder: number        // 保持非私密模型稳定排序
}
```

字段语义如下：

- `id` 是会话绑定和网关路由使用的身份，不能由展示名称反推；同名模型必须保持不同 `id`。
- `vendorId` 是目录长期稳定字段。本地模型使用 endpoint ID 作为分组身份，endpoint `name` 作为 `vendorName`；没有名称时回退 provider，再回退 endpoint ID。
- `confidential` 只表达资格，不表达会话已经受到私密约束。
- `trust` 必须随投影保留。产品 Profile 只允许 `signed-catalog` 成为私密资格，开发 Profile 才允许 `developer-local`。
- `confidentialPriority` 仅在私密候选之间比较；相同或缺失时按 `sourceOrder` 稳定排序。

本地配置的 `EndpointModel` 包含 `confidential: bool`，只在开发 Profile 的编辑界面暴露。首版不增加本地优先级输入框：多个本地私密模型先按当前默认模型、再按 endpoint/model 原顺序选择，避免为了联调引入另一套产品排序配置。

## 目标读取链路

保留 `/api/config/endpoints` 作为上游本地配置接口，不把中台托管模型伪装成可编辑 endpoint。旧 `/api/product/chat-modes` 由新的只读目录投影替代：

```text
GET /api/product/catalog         → 缺失或过期时按需刷新目录状态
GET /api/product/models          → 已验签目录的厂商/模型行
GET /api/config/endpoints        → 本地 endpoint/model 行
GET /api/product/control-plane   → 增加 allowEnvironmentModelSource
                  ↓
        web/lib/selectableModels.ts
        合并、校验、稳定排序、生成 SelectableModel[]
                  ↓
          上游 Composer 模型选择器
```

`GET /api/product/models` 只读最后一次已接受的目录缓存，不因自身调用发起网络请求；没有可信目录时返回明确的 `state` 和空 `vendors`，不能回退到内置中台模型。Composer 在首次挂载和每次**打开**选择器时，必须先调用 `GET /api/product/catalog`，再读取 `/models`：前者仅在缓存缺失或过期时按目录生命周期向中台发起一次刷新；`ready` 缓存不产生中台请求，`unverifiable` 也不能通过反复打开选择器重试。目标响应为：

```json
{
  "state": "ready",
  "catalogVersion": "2026-09-18",
  "vendors": [
    {
      "id": "vendor-a",
      "displayName": "厂商 A",
      "models": [
        {
          "id": "model-a",
          "displayName": "模型 A",
          "compositeId": "gateway::model-a",
          "confidential": true,
          "confidentialPriority": 100
        }
      ]
    }
  ]
}
```

开发 Profile 在目录不可用时仍可使用本地模型；产品 Profile 因不允许环境模型来源而显示目录错误并禁止开始新回合。`allowEnvironmentModelSource` 必须从同一个编译期 Profile 投影，前端据此同时决定三件事：是否合并本地模型、是否显示“管理模型”、是否允许本地私密测试标记。不能再增加三个容易漂移的布尔开关。

`web/lib/selectableModels.ts` 是前端唯一合并与排序所有者。Composer、空白会话默认模型和后续可能使用模型列表的页面都调用该适配层，组件内部不得各自拼接两类来源。

## 开发与产品 Profile 的模型来源不同

| 行为 | 开发 Profile | 产品 Profile |
| --- | --- | --- |
| 中台目录模型 | 展示 | 展示 |
| 本地配置模型 | 展示并可选择 | 不进入可选列表 |
| 本地模型管理入口 | 可见 | 不可见 |
| 本地私密标记 | 可编辑，仅用于开发测试 | 不可见且不采信 |
| 私密资格来源 | 可信目录或本地测试标记 | 仅可信目录 |

隐藏产品 Profile 的本地模型管理入口不删除上游 endpoint 页面、代码和本地 API，便于开发 Profile 继续复用；但产品运行时不把磁盘中预置或历史遗留的 endpoint 加载为模型来源，不将其加入选择器，也不为其构建回合 sender。产品模式只允许已验签目录中的中台 gateway 模型；旧会话绑定本地复合 ID 时必须在 provider 调用前明确拒绝，不能自动改用 gateway。

Profile 身份必须由本地服务明确投影给前端；前端不能通过 host、是否有本地模型或 URL 形状猜测当前构建。该投影与 `allowEnvironmentModelSource` 使用同一个事实源。

## 本地模型必须能真实聊天并支持私密标记

开发 Profile 保留现有 endpoint 管理的完整能力：创建 endpoint、填写提供方、地址、协议和密钥，再添加一个或多个模型。创建 endpoint 时附带的模型、后续新增模型和已有模型编辑都提供“可用于私密会话”开关；该标记属于具体模型而非整个厂商，因为同一 endpoint 下可能同时存在普通模型和私密模型。

`EndpointModel.confidential` 随 `config.yml` 保存，`GET /api/config/endpoints`、创建 endpoint 的嵌套 model、`POST /api/config/endpoints/{id}/models` 及响应都必须读写它。旧配置缺失时为 `false`。保存成功后统一模型选择器立即刷新，不要求重启桌面或手改文件。

本地模型不是只供排序和界面演示的目录行。它的 `SelectableModel.id` 必须保留现有 `<endpoint>::<model>` 复合身份；用户选择后继续走现有会话模型绑定、`senderForEntry` 和对应 provider 适配器，使用该 endpoint 的地址、协议、headers 与密钥产生真实流式回合。统一列表只增加展示和私密属性，不得把本地模型错误改道到中台 gateway，也不得出现“能选择但发送仍使用默认模型”的假成功。

私密标记进入统一模型行的资格属性，用于反复验证私密模型排序、自动切换、会话锁定和禁止普通模型回退。标记或取消标记不能改变 endpoint 的普通聊天能力；未标记模型仍可用于普通会话，标记模型也可在普通会话中使用。界面需要说明标记表达的是该部署模型可用于私密会话，不等于当前会话已经开启私密约束。

中台模型的私密资格只能来自签名目录。两种来源归一化后使用同一个布尔资格和一个可选优先级，但信任来源仍保留在模型行中，便于日志和测试断言。

## 私密模型在厂商结构内优先

排序不打破厂商父子结构：

1. 含私密模型的厂商排在不含私密模型的厂商之前；
2. 同一厂商内，私密模型排在普通模型之前；
3. 多个私密模型按明确优先级排序；
4. 其余厂商和模型保持来源顺序，避免刷新后无理由跳动。

排序不能代替标识。私密模型子项在模型 ID 前显示盾牌和“私密”标签；当前模型 chip 同样显示标识。厂商标题本身不获得私密标签，因为资格属于模型，不属于厂商。

## 私密会话在首条消息前选择

私密会话入口位于聊天输入区的“安全与隐私”控件内，而不在个人中心或完整设置中提供三组默认模式。空白新会话可以开启或关闭；开启时：

1. 当前模型已具备私密资格则保持不变；
2. 否则自动选择排序最高的私密模型；
3. 输入区显示“私密会话 · 仅使用私密模型”，并提示实际切换到的模型；
4. 没有可用私密模型时保持未开启并说明原因，不能只亮盾牌后继续使用普通模型。

首条消息发送后，私密属性锁定：

- 已有普通会话不能原地改成私密会话，只能新建私密会话；此前内容可能已经发送给普通模型，事后切换无法撤回。
- 已有私密会话不能选择普通模型；普通模型仍可在列表中看见，但不可点击，并解释“请新建普通会话后使用”。
- 私密模型被下架或不可用时停止新回合，不修改会话属性，也不自动选择普通模型。

选择私密模型本身不等于私密会话。只有会话约束能保证后续回合不切到普通模型；界面必须分别展示“当前模型是私密模型”和“当前会话已锁定为私密会话”。

普通会话手工选择私密模型后仍是普通会话，绝不静默升级安全边界。空白普通会话选择私密模型时显示一次非阻塞提示“已选择私密模型，是否同时开启私密会话？”；用户可以开启，也可以保持普通会话。已经锁定的普通会话只更新模型并说明“当前仍是普通会话”，不再提供原地升级按钮。

## 会话状态与写接口

新会话使用一个版本化的保护策略替换 `chat_mode`：

```json
{
  "protection_policy": {
    "version": 1,
    "personal_info_protection": true,
    "confidential_session": false,
    "locked": false
  }
}
```

`personal_info_protection` 由个人信息保护链路消费，`confidential_session` 由模型选择和回合路由消费；两者不能互相推导。`locked` 是服务端维护的单调状态：首个用户回合被接受并持久化时从 `false` 变为 `true`，此后永不恢复为 `false`。被内容安全拒绝、自动脱敏失败或发送前失败的输入都不锁定。

锁定状态必须持久化，不能从当前消息条数推导。`/clear`、历史编辑、重试、压缩和回合回滚都可能改变消息数量，但不能撤销该会话曾经使用过的模型和保护边界。`version` 用于区分真正的新策略与缺少字段的旧会话，避免把“字段不存在”和布尔值 `false` 混为同一个状态。

创建会话时，`POST /api/sessions` 必须原子接收模型绑定和两个用户可选字段；`version` 与 `locked` 由服务端写入，客户端不能指定。首条消息前允许：

```text
PATCH /api/sessions/{id}/protection
{
  "personal_info_protection": true,
  "confidential_session": true,
  "model_id": "gateway::private-model"
}
```

`model_id` 可选；当开启私密会话且当前模型不合格时，服务端按目录优先级与源顺序自动选择合格私密模型；客户端也可提交明确选择。服务端在同一个会话锁中校验模型资格、写模型绑定和写保护策略，并返回完整有效状态。任一步失败都不修改任何字段。首个用户回合已持久化后返回 `409 session_policy_locked`。不能只靠前端禁用开关，因为另一个窗口或旧客户端仍可直接调用接口。

更新会话模型时，服务端执行下列约束：

- 普通会话可选择普通或私密模型；选择私密模型不会把此前普通历史升级成私密会话。
- 私密会话只能绑定当前可信模型投影中 `confidential=true` 的模型；不合格返回 `409 confidential_model_required`。
- 开始每个新回合前再次校验模型资格。目录刷新后模型被撤销时返回 `confidential_model_unavailable`，不向 provider 发请求。
- 产品 Profile 对本地模型始终判定为不具备私密资格；开发 Profile 才读取 `EndpointModel.confidential`。

独立的模型切换接口也必须读取会话保护策略：私密会话不能通过旧接口或另一个窗口切换到普通模型。开始每个回合前再做一次权威校验，防止目录资格在会话保存后发生变化。

私密会话的承诺仅为“所有模型回合都路由到具有私密资格的模型”。它不自动禁用 Web 搜索、MCP、脚本、终端或其他工具，也不宣称工具参数和工具结果已经脱敏。面板短说明使用“仅使用私密模型”，详情页明确“工具继续遵循现有权限和数据规则”，避免把模型边界误解为整机或整条工具链隔离。

## 会话生命周期

- `/clear`：清空消息和上下文用量，但保留保护策略、`locked=true` 和当前模型约束；需要改变边界时新建会话。
- 编辑消息：新内容重新经过内容安全和个人信息保护，再在原有会话边界内运行；不能因截断历史解除锁定。
- 重试：只使用已经持久化的脱敏文本；私密会话在重试前重新验证模型资格。
- 分支：复制源会话在分支点之前的历史，同时继承完整保护策略、锁定状态和模型绑定。即使分支前缀为空，只要源会话已经锁定，分支仍保持锁定。
- 压缩、回滚和崩溃恢复：可以改变历史形状，不能改变保护策略；恢复后的首个新回合仍执行个人信息和模型资格校验。
- 删除会话：随会话文件删除保护策略，不另存可恢复的个人信息映射。

## UI 状态与交互

入口固定在 Composer 元信息行，位于附件入口之后、模型选择器之前，名称为“安全与隐私”。这样它与当前会话和下一次发送保持空间关联，又不会被误解成模型选择器里的一个厂商或个人中心的全局偏好。

面板只展示状态和短说明，详细规则通过“了解详情”进入帮助页：

- 空白会话：个人信息保护和私密会话是开关；内容安全输入检查可随时调整。
- 已开始普通会话：个人信息保护和私密会话显示锁定值；私密行的主操作变为“新建私密会话”。
- 已开始私密会话：私密状态只读，输入区上方持续显示私密横幅；模型菜单中的普通模型可见但禁用。
- 窄屏使用同一内容的底部抽屉，宽屏使用锚定弹层，不另造一套移动端设置页。
- 盾牌入口本身显示摘要：默认状态为“个人信息已保护”；私密会话开启后优先显示“私密会话”。不把三个状态压缩成一个总开关或单一绿点。

个人信息自动脱敏提示属于发送结果，显示在输入框上方或已发送气泡附近，不进入“安全与隐私”弹层。提示只说明类别、数量和已经使用的脱敏文本，不复制原值，也不要求用户再次确认。

## 三组模式完整退出

目标设计不再包含 `privacy`、`smart`、`default`：

- 删除个人中心的三组选项和 `defaultChatMode` 偏好；
- 删除两级 `ModeMenu` 和模式名称文案；
- 删除 `/api/product/chat-modes` 的模式分组投影；
- 删除会话 `chat_mode` 的新写入、更新接口和前端状态；
- 删除 `internal/chatmode` 固定集合；
- 中台目录不再用 `modeIds` 表达私密资格。

旧 `chat_mode=privacy` 不能自动迁移成私密会话：旧实现没有真正的个人信息脱敏和私密模型保证，自动升级会制造虚假的安全承诺。已有历史的会话按普通会话处理；旧字段停止写入并在完成迁移后删除。

## 兼容与迁移

- 已有且含用户消息的会话：缺少 `protection_policy` 时按 `personal_info_protection=false`、`confidential_session=false`、`locked=true` 解析；不重写旧历史，也不暗示旧原文已受保护。
- 已有但为空的会话：只有在同时没有已组合系统提示、内容更新时间、历史上下文用量等任何运行痕迹时，才按新会话默认值 `true/false` 创建版本 1 策略；存在任一运行痕迹说明它可能在升级前被 `/clear` 清空，必须按旧历史会话处理为 `false/false/locked=true`。
- 新版本停止写 `chat_mode` 和 `defaultChatMode`；解析器可以忽略旧字段，但新 UI 不再展示旧模式或隐私标识。完成迁移 PR 后直接删除旧字段、路由、store 和测试，不保留一个继续展示旧语义的兼容版本。
- 旧 `/api/product/chat-modes` 与新 `/api/product/models` 不长期并存。迁移 PR 必须一次替换真实消费方、stub、夹具和契约测试，然后删除旧路由。
- 本地 `EndpointModel.confidential` 是向后兼容的可选 YAML 字段，旧文件缺失时为 `false`；生产 Profile 即便读到 `true` 也忽略。

以上迁移不扫描或重写旧历史。旧 `chat_mode=privacy` 也不改变结论，因为旧实现没有足以证明个人信息保护或私密模型路由的安全事实。

## 实施拆分

本主题必须交付五个闭环：新目录 wire 契约及签名夹具；模型目录与 Profile 的只读投影；会话策略、原子模型绑定和私密资格复核；统一选择器与私密标识；旧三组模式的完整退出。跨中台、会话、服务端和 UI 的实际先后、门禁及回滚统一由 [安全与隐私实施设计](安全与隐私实施设计.md) 管理，本文不维护第二套总计划。

每一步修改上游文件都按仓库规范标记 `OCTO-FORK` 原因；产品专属合并和投影逻辑放在 fork 自有模块，不把目录语义塞进上游 endpoint 配置层。

## 当前实现状态

聊天框保留上游选择器的组件结构、厂商/模型层级和复合 ID 路由，并通过唯一适配层合并 `/api/product/models` 与开发 Profile 的 `/api/config/endpoints`。中台目录、语义校验、私密资格复核、自动选择和 Composer 内“安全与隐私”面板已经接入真实服务端路径。

旧三组模式已经完整退出运行时：不再有 `chat_mode` 写入或更新接口、账户默认模式、旧分组投影、前端 store/helper、`ModeMenu`、`PrivacyBar` 或 `PrivacyMark`。历史 JSONL 中出现旧字段时，解析器忽略它并按兼容规则生成保守的 `protection_policy`，不重写历史，也不把旧 `privacy` 提升为新的私密承诺。

## 验证

- 模型列表始终是“厂商 → 模型 ID”，不存在第二套模式选择器。
- 开发 Profile 同时展示中台和本地模型，产品 Profile 只展示中台模型且没有本地管理入口。
- 开发 Profile 能从界面创建 endpoint 和模型、设置或修改模型级私密标记；保存后无需重启就在统一选择器出现，重启后配置仍在。
- 选择新建的本地模型后，真实请求到达该 endpoint 并返回流式聊天结果；会话持久化的复合身份与实际 sender 一致，不能回退默认模型或改道中台 gateway。
- 本地私密标记能驱动排序、自动切换和禁止回退；未标记模型仍能完成普通聊天。
- 开启私密会话会选择合格模型并显示明确状态；首条消息后不能改变会话边界。
- 三组模式、默认模式设置及旧分组接口退出后，不影响普通模型选择、同名模型消歧和会话路由。
- 并发窗口无法在私密会话开启后把模型切回普通模型；目录撤销资格时在 provider 调用前 fail closed。
- 已有历史会话不会因字段缺失被误标为已保护或私密；空旧会话按新默认安全创建。
