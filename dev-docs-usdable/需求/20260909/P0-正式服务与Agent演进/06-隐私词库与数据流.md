# P0-06：隐私发送副本、词库同步与正式数据流

| 项 | 内容 |
| --- | --- |
| 当前仓库主责 | 客户端安全组 |
| 外部协作 | 中台词库组提供版本/摘要 contract sample 与 sandbox；产品/法务确认数据保留规则，并交付已批准的协议/隐私文案与版本规则；本仓库不实现词库服务 |
| 可并行 | 与 P0-02/03/04/07 并行 |
| 依赖 | P0-02 的 token/数据分类，P0-04 的 dictionary version |
| 需求基线 | [P0 正式上线需求基线](../P0-正式上线需求基线.md) R2、R7、R8、R11；本期自动 PII 识别仅限手机号 |

## 目标

把“手机号脱敏”和“敏感词过滤”从当前本地 developer 行为提升为可解释的数据流，并将正式协议/隐私告知从未批准页变为可追溯交付：本期只自动识别手机号；原始会话本地保存，云端模型请求使用符合当前模式的发送副本；本地内置词、用户词和从外部控制面下载的服务器词在离线时仍闭合。

## 实施步骤

1. 写数据流清单：登录字段、会话原文、模型请求副本、附件、日志、诊断包、账本/审计的收集目的、保存位置、保留期、接收方与删除路径；供隐私协议和 L2 评审使用。
2. 在进入 gateway sender 前生成发送副本。隐私模式下手机号脱敏；原文不写进普通网关日志。身份证、银行卡不纳入本期自动正则，但协议/界面不承诺“所有敏感信息均被识别”。
3. 实现服务器词库 `version + ETag + signature/keyId + checksum + TTL` 缓存：先以内置受信任公钥验证签名，再校验版本连续性、大小上限和摘要，然后临时写入并原子替换；签名缺失/未知 `keyId`/验签失败/`baseVersion` 不匹配/摘要错误中的任意一项都丢弃本次更新，继续使用内置词 + 用户词 + 最近有效缓存。
4. 服务器词库为只读层；用户不能删除，用户自定义词仍本地可管理。词库刷新不能改变昵称失败关语义。
5. 诊断包与导出按字段白名单生成，排除 token、API key、自定义认证头和原始敏感内容。
6. 将 `web/src/lib/brand.config.json` 等正式产品页面的协议/隐私未批准内容替换为经批准的文案和版本。若产品/法务要求显式同意，按中台合同展示当前版本和同意状态，并提交 `documentType + version`；客户端不得在本地文件自行标记“已同意”。未要求显式同意时，仍展示版本/生效时间与可访问的正式文案。

## 验收

- 抓取 gateway 请求：隐私模式手机号为脱敏副本，磁盘会话仍保留原文；非隐私模式遵从明确产品规则。
- 词库完整、增量、304、摘要错误、base version 不匹配、签名缺失/未知 `keyId`/验签失败、断网、缓存损坏均有测试。
- 诊断包、日志、导出包审查无法找到 token/key/完整手机号；数据流文档与实际字段一致。
- 正式包不含开发未批准协议；每份展示文档可追溯到批准版本。要求显式同意的环境中，拒绝/过期/已接受三种状态均按合同处理并有测试。

## 并行与交接

中台先提供词库 mock、版本/摘要 contract sample 与 sandbox；客户端可独立实现缓存与发送副本。词库下载服务、存储、发布与审计由中台在其仓库交付；产品/法务交付文案与批准版本。若需要记录用户确认，中台按合同提供当前版本/状态与确认记录接口；法务文案、词库和模型网关可以并行推进。
