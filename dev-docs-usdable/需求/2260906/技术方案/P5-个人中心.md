## 1. 目标与非目标

**目标**：左下角从「设置 + 版本号」变为登录态入口；点击弹出一个**与 Sidebar 同宽、覆盖在 Sidebar 之上**的浮层，本质是一个二级导航 + 信息预览。

**非目标**

- 不做真实支付、不做头像上传（需求 §7）。
- 不做入口隐藏与积分扣减逻辑（P6）。
- 不做未登录形态 —— 未登录时主界面完全不渲染，见 §2.2。

---

## 2. 形态调整（相对需求 §5.4.2）

### 2.1 从「右侧滑出三分之一」改为「左侧同宽浮层」

**需求 §5.4.2 与 §8 已按下述结论改写（2026-09-07）。本节留档解释理由，需求正文与本方案一致。**

原需求写的是：「从**右侧滑出**，左侧为导航，右侧为内容……宽度约覆盖主区**右侧三分之一**」。

现结论：点击左下角 → 一个**宽度等于 Sidebar、覆盖在 Sidebar 之上**的浮层从底部升起，本质是一个导航列表 + 少量信息预览。「账号信息」不单独成页，收进「设置」里。

```
点击前                          点击后
┌──────────┬─────────────┐     ┌──────────┬─────────────┐
│ 会话列表  │             │     │▛▀▀▀▀▀▀▀▀▜│             │
│  · 会话1  │             │     │▌▢ 用户3271│             │
│  · 会话2  │   聊天区    │     │▌  积分 1279│   聊天区    │
│  · 会话3  │             │     │▌─────────│             │
│           │             │     │▌ 套餐版本 │  （不变，   │
│           │             │     │▌ 授权    │   浮层只盖   │
│ ─────────│             │     │▌ 设置    │   住侧栏）   │
│ ▢ 用户3271│             │     │▌ 帮助与反馈│             │
│   积分1279│             │     │▌ 检查更新 │             │
└──────────┴─────────────┘     │▌ 关于    │             │
   ↑ 点这里                     │▙▁▁▁▁▁▁▁▁▟│             │
                                │ 退出登录  │             │
                                └──────────┴─────────────┘
```

**为什么这样更好**（记录理由，便于回看）：

- 需求要的右侧三分之一面板会遮住聊天内容，而这个面板的用途是「看一眼、点一下就走」，不需要那么大的画布。
- 复用 Sidebar 的宽度与视觉语言，浮层升起时用户的视线不用横跨整屏。
- 「账号信息」本来内容就少（头像 + 昵称 + 脱敏手机号），单独成一页很空，收进「设置」更实在。

**需求 §5.4.2 与 §8 已同步改写**（2026-09-07），本方案与需求正文一致，不存在「文档说 A、实现是 B」的分歧。留档见 `../开发计划.md` §4.1 第 2 项。

### 2.2 登录态

**未登录时不存在这个面板** —— 需求 §5.1.2-2「未登录只显示拦截页，不渲染会话列表、输入框、设置、个人中心」不变。侧栏本身就不渲染，浮层自然也不存在。

面板内部仍有状态分支，但都是**已登录内部的**分支：授权「已激活 / 已过期」、积分「> 0 / = 0」、套餐版本。没有「未登录态」。

## 4. 设计

### 4.1 左下角触发区

`AccountCorner.svelte` 替换 `Sidebar.svelte` 底部区块：

- 头像：昵称首字（第一个 rune，中文取汉字、英文取首字母大写），圆形色块。颜色由昵称哈希取自一组**中性色** —— 品牌主色尚未定稿（需求 §10 T2）。
- 昵称：CSS `text-overflow: ellipsis` 省略，不做字符计数截断（中英混排时按字数截断很难看）。
- 次行 `积分 {整数}`，与面板同一份 store，不各自请求。
- rail 模式只渲染头像，点击行为相同。

### 4.2 浮层

`AccountPanel.svelte`：

| 属性 | 取值 |
|---|---|
| 宽度 | 跟随 `$sidebar` 的当前宽度（`full` 时等于 `fullWidth`，`rail` 时展开到 `fullWidth` 而不是 64px —— 64px 放不下导航文字） |
| 定位 | `position: absolute`，贴左贴底，`z-index` 高于侧栏内容 |
| 动画 | 从底部升起（`transform: translateY`），200ms |
| 关闭 | 点浮层外任意处、Esc、再次点左下角 |
| 触发区 | 浮层升起时，左下角触发区**保持可见并高亮**，作为「再点一次收起」的锚点 |

Esc 要注册进上游的 `globalKeys.ts` 体系，否则会和命令面板、模态框抢按键。

### 4.3 导航结构

浮层顶部是账户摘要（不可点，只是信息），下面是导航项，底部固定「退出登录」。

| 区块 | 内容 | 点击行为 | 归属 |
|---|---|---|---|
| 摘要 | 头像、昵称、`积分 {n}` | 无 | 本 PR |
| 套餐版本 | 「体验版」+ 右侧「升级」 | 展开二级 / 打开占位页 | 本 PR |
| 积分 | 余额、本月消耗、「充值」 | 展开二级 | P6 |
| 授权 | 「已激活 · 剩余 N 天」/「已过期 · 剩余 0 天」 | 展开二级 | 本 PR |
| 设置 | — | 展开二级 | 本 PR |
| 敏感词库 | — | 打开词库管理 | P13 |
| 帮助与反馈 | — | 展开二级（占位内容） | 本 PR |
| 检查更新 | 「即将支持」 | 无 | 本 PR |
| 关于 | 版本号 | 展开二级 | 本 PR |
| **退出登录** | 固定底部，与导航项视觉分隔 | 二次确认 | 本 PR |

**二级内容在同一个浮层内切换**（一层导航 + 一层详情，像手机设置那样左右滑动切换），不再开第二个浮层。浮层窄，塞不下「左导航 + 右内容」的双栏。

> 套餐版本 `plan.name` 存的是机器码 `"trial"`（见 §5 DTO），展示名「体验版 / Trial」走 i18n 文案层映射，不直接渲染机器码。

「设置」二级页内容：

- 账号信息：头像、昵称（可改，规则同登录页含敏感词校验）、脱敏手机号 —— 这是从需求的「账号」独立页收进来的
- 语言：中 / 英，立即生效，与拦截页同一份设置
- 新会话默认模式：隐私 / 智能 / 默认，出厂为分组「默认」（P9 填）
- 「打开完整设置」按钮 → `settingsModalOpen.set(true)`，主题、字号、模型、权限、端点仍走完整设置
- 便携包不展示开机自启动（P2 的 `AutostartAvailable()` 恒 false，前端据此不渲染）

### 4.4 昵称修改

复用 P4 的 `validateNickname` + 服务端敏感词校验，走 `PUT /api/product/nickname`。保存成功后 `productState` store 更新，左下角**立即**变 —— 共享 store 天然满足，不需要额外事件。

### 4.5 授权

需求 §5.4.2 有一条容易实现错的：「能进入个人中心，说明这份数据根**已经完成过激活**……展示状态只能是『已激活』或『已过期』，**不要出现『未激活』空态**」。

状态是二元函数，没有第三态：

```ts
const status = activation.expiresAt > now ? 'active' : 'expired'
const daysLeft = Math.max(0, diffCalendarDays(activation.expiresAt, now))
```

剩余天数按**本机本地日历日**差值，不是小时差（需求明确）。算法：两个时刻各自归一到本地零点再相减，避免时区与夏令时导致差一天。

到期**不拦截**（需求 §10 T11），显示「已过期 / 剩余 0 天」，其余功能照常。

### 4.6 帮助与反馈占位内容

需求 §9.10 允许演示包写出测试凭据。固定包含：

- 测试验证码 `123456`、激活码 `BUDING-DEMO-0001`
- 「把数据根中的积分数字改为 0 后重启或刷新」（演示积分不足，需求 §5.4.4）
- 「请先退出再拔出 U 盘」（需求 §5.1.2-8）
- 「如需更换手机号，请联系客服」（需求 §5.3.3）
- 「丢失 U 盘视同账号泄露」（需求 §5.3.5）
- SmartScreen「选择仍要运行」说明（需求 §5.1.2 末段）

进 `i18n.ts`，中英各一份；凭据本身是 ASCII 标识符不翻译。

### 4.7 退出登录

需求 §5.3.5 逐字规定，照抄：标题「退出登录」、正文「退出后需重新验证手机号才能进入。会话和配置不会删除。」、按钮「取消」「退出登录」——**不能写成「退出」**，与托盘结束进程区分。

复用 `ConfirmModal.svelte`。确认后调 `POST /api/product/logout`，`productPhase` → `blocked`，进程与托盘不动。

## 5. 接口与数据结构

```
PUT  /api/product/nickname   { "nickname": "新昵称" }
     200 { "state": <ProductStateDTO> }
   | 400 { "code": "nickname_format" | "nickname_sensitive" }

PUT  /api/product/prefs      { "locale"?: "zh"|"en", "defaultChatMode"?: "privacy"|"smart"|"default" }
     200 { "state": <ProductStateDTO> }
```

```ts
interface ProductStateDTO {
  account: { nickname: string; phoneMasked: string; lastLoginAt: string } | null
  activation: { activated: boolean; activatedAt: string; expiresAt: string } | null
  credits: { balance: number; monthUsed: number }
  plan: { name: 'trial' }
  prefs: { locale: 'zh'|'en'; inputSensitiveCheck: boolean; defaultChatMode: string }
}

// web/src/lib/stores.ts
export const accountPanelOpen: Writable<boolean>
export const accountPanelPage: Writable<'root'|'plan'|'credits'|'license'|'settings'|'help'|'about'>
```

`accountPanelPage` 的 `'root'` 是导航列表本身，其余是二级页 —— 一个 store 同时表达「在哪一层」和「哪一页」。

## 7. 测试

**前端单测**

- `diffCalendarDays`：跨夏令时、跨月、同日不同时刻；到期日等于今天 → 剩余 0（不是 -0 或 1）。
- 授权只有两态；`expiresAt` 在过去 → `expired` 且 `daysLeft === 0`。
- 昵称首字提取：中文 / 英文 / emoji 开头 / 空字符串（兜底 `?`）。
- 浮层宽度：`rail` 模式下展开到 `fullWidth` 而不是 64px。
- Esc / 点外部 / 再点触发区，三种关闭方式都生效。
- 二级页返回 `'root'` 后再次打开浮层，停在 `'root'`（不记忆上次的二级页 —— 用户下次打开多半是找别的东西）。

**Go 单测**

- `PUT /api/product/nickname` 命中敏感词 → 400 且**状态文件未被修改**（不能出现「校验失败但昵称已经写进去了」）。
- 未登录调该接口 → 产品门 403。

**手工验收**：按需求 §8「个人中心」段。特别是「把系统日期调到激活 365 天之后 → 显示已过期、剩余 0，仍能对话」。

## 10. 风险与决策

| 项 | 处理 |
|---|---|
| 浮层与完整设置功能重叠 | 浮层「设置」只放账号、语言、新会话默认模式，其余一律「打开完整设置」跳转，不做第二套 |
| rail 模式下浮层比侧栏宽，视觉突兀 | 浮层展开时同时把侧栏临时撑到 `full` 宽度，关闭后收回。若实测别扭，改为浮层固定 280px |
| 二级页层级过深 | 只有两层（导航 → 详情），不允许三层。需要三层的内容说明它应该去完整设置 |
| 头像色板与未定稿主色冲突 | 本期中性色；主色定稿后（§10 T2）改一处色值映射 |
| 需求文档未同步改 §5.4.2 | 已记入 `../开发计划.md` §4.1，评审后改需求 |
