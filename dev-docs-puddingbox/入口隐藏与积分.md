# 入口隐藏与积分

写作参照：`dev-docs/desktop-update-notice.md`

> 便携产品目前隐藏三项未交付的上游入口，并让它们无法通过旧书签继续抵达；隐藏不删除实现。余额只从服务器账本刷新，充值入口只给出已实现的“暂未开放”反馈。

## 范围

本文件定义导航可见性、深链行为、输入区附近提示、余额显示和充值入口。模式、词库和账户的具体功能分别由对应主题文档及 `本地API契约.md` 定义。

## 非目标

- 不删除上游功能代码来达到隐藏效果。
- 不维护第二套能力矩阵或按页面复制产品开关。
- 不在本地预测、扣减或汇总余额。

## 当前隐藏范围与唯一判据

`web/src/lib/features.ts` 是当前可见性判定的唯一所有者，隐藏 `channels`、`mcp` 与 `lightapps` 三个视图。侧栏从同一判定过滤导航；应用启动后的 hash 路由也在同一判定命中时回到聊天页并显示“功能暂不可用”。组件不能各自维护另一份隐藏名单。

被隐藏的入口在深链或旧书签访问时回到可用页面并给出明确提示，不能加载一个残缺页面，也不能因隐藏而绕过产品门。

该判定是黑名单，而不是“已交付能力”的允许列表：未在名单中的上游新视图默认可见。这是当前实现事实，不应把它写成默认拒绝策略；是否改为允许列表需要决定产品开放与上游合并策略，见 [待决事项](待决事项.md)。

## 上游能力保留但不可达

需要关闭的上游能力优先保留实现和稳定入口，只在产品层阻止抵达。这样既避免删除与上游修改冲突，也让未来重新开放时不必重建页面结构。

若能力会发起请求、写入数据或暴露用户可见文案，隐藏判定必须覆盖所有入口，而不仅是侧栏菜单。

## 输入区提示的顺序

输入区同时存在产品门、目录可用性、敏感词提示、余额或能力限制时，展示顺序由一个消费层决定。更高优先级的阻断结果不能被较低优先级的提示覆盖；用户始终看到当前最需要处理的原因和可执行动作。

## 积分与充值

余额是服务器账本的投影。登录、回合结束或跨窗口事件只能触发 `GET /api/product/credits` 刷新；它是唯一写入本地余额状态的路径。客户端不做本地扣费、月度统计或由 WebSocket 载荷直接覆盖余额。

积分页打开时和用户手动刷新时都会请求账本；窗口重新获得焦点、登录完成与回合结束也只触发同一刷新路径。刷新失败保留上一次余额并显示失败，而不是写入猜测值。

充值和套餐升级入口可常驻，以保持布局稳定；当前没有支付 URL 或支付流程，点击只显示“暂未开放”提示，不跳转到空白页、外链或无效地址。

## 验证

- 三项当前隐藏入口不会在导航、深链或旧书签中重新出现；新增上游视图的默认可见性按待决策略复核。
- 隐藏能力不删除上游实现，也不意外发起产品外的请求。
- 输入区在多个限制同时存在时显示唯一、稳定且可执行的优先结果。
- 余额只由账本刷新写入，跨窗口事件不会携带可覆盖的余额数值；失败时保留最后可信数值。
