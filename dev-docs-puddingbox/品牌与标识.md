# 品牌与标识

写作参照：`dev-docs/desktop-update-notice.md`

> `branding/brand.json` 是文字身份、标识符与发布元数据的唯一事实源；视觉主资产另存于 `branding/source/`，由受控生成器派生产物。用户可见名称和发布配置不能在消费端复制；上游名称只在协议兼容语境中保留。

## 范围

本文件定义品牌配置、文案、标识资产、设计交付要求和平台消费点的边界。打包消费见 `便携打包.md`。

## 非目标

- 不在代码、脚本或 UI 复制品牌字面量。
- 不用产品名替换协议名称、开源归属或必须保留的兼容标识。
- 不让设计资源绕过生成和验证流程直接散落到平台目录。

## 品牌事实源

品牌配置拥有产品名、短名、域名、标识路径和相关发布取值。生成访问器、本地化资源、桌面元数据与安装/打包资源只消费该配置；修改文字身份或标识符时，先改事实源，再生成并提交派生物。

`links.external.website` 是产品官网的唯一字段，属于 C 类固定外部 URL：它必须是一个无空格的 HTTPS URL，不随语言变化，也不能由界面代码拼接或覆盖。完整帮助使用可选的 `links.external.helpCenter`；它缺失时帮助页不显示外跳，而不是回退到官网、上游或空白页。未来版本说明可使用同样边界清晰的 `links.external.releaseNotes`。这些是用户可见的公开链接，不承载 API host、更新 manifest、签名 key、token 或环境开关；后者属于 [配置治理](配置治理.md) 的 Profile/发布信任域。当前 `website` 值仍指向上游迁移占位站点，不是可对用户展示的布丁盒子官网；在真实域名、归属与上线状态确认前，产品 UI 不得启用外跳。确认后只修改 `branding/brand.json`，运行 `make brand-sync`（或相应生成入口）并提交所有派生产物；品牌校验还应拒绝非 HTTPS、`.invalid`、上游站点以及其它明确的迁移占位值，防止误发布。

`make brand-check` 校验 schema、生成的配置副本和用户可见品牌文案是否漂移。例外必须说明它为何是协议或兼容标识，不能以“上游原来如此”代替理由。

源码扫描排除派生目录 `internal/server/webdist`、`mobile/www` 以及 Capacitor 生成并被 Git 忽略的 `mobile/ios`、`mobile/android`。`mobile/scripts/bundle-web.mjs` 复制 Web 构建结果并打包手机启动层，`mobile/scripts/wire-native.mjs` 将受控原生实现和品牌资源装配到生成工程；嵌入品牌配置值是正常产物，不构成源码硬编码。输入 `web/`、`mobile/src/`、`mobile/native/` 和生成脚本继续扫描，品牌生成配置仍由同步校验负责；其他同名目录不继承此排除。

手机隧道的用户命令取 `identifiers.current.cliCommand`，当前为 `puddingbox serve --tunnel`。Windows 安装器把 `puddingbox.exe` 安装在优先加入 PATH 的 `cli/` 子目录，兼容的 `octo.exe` 留在原安装目录；两者不能同目录，因为 Windows 会把 `PuddingBox.exe` 图形程序与 `puddingbox.exe` CLI 视为同名。macOS/Linux 桌面包在首次启动并安装随包 CLI 时，为已有的 `octo` 可执行文件创建 `puddingbox` 命令入口，用户已有同名命令不会被覆盖。Windows 便携包不附带 CLI，需另行安装 CLI 才能运行该命令；这次命名不改变 `octo-pair` 配对协议、`octo-relay` 或现有配置目录。

## 标识资产

当前必需主资产是 `branding/source/logo-mark.png`：一个带透明背景的高分辨率 PNG。生成器同时接受同名 SVG；若未来交付 SVG，会校验 viewBox、禁止 live text 和嵌入位图。当前不能把 PNG 主资产误称为矢量交付。

`logo-mono` 是可选的单色托盘源；未提供时，从主标识 alpha 派生黑色剪影。`og-card` 是可选社交卡片，缺失时不自动合成。应用图标、favicon、桌面托盘、安装资源和站点资源从这些受控源资产生成；某个消费点需要单色或特定尺寸时，使用明确的派生产物，不以运行时转换或备用旧图标兜底。

Web 界面的标识仍由 `visual.logo.mark` 指向生成后的固定文件名；构建时按文件内容生成 URL 指纹，避免 Windows WebView 沿用旧包的一年期图片缓存。静态服务只对带构建指纹的资源使用长期不可变缓存，固定文件名的标识需要每次加载时重新验证。Windows 可执行文件及快捷方式的图标则由生成后的 `cmd/octo-desktop/build/windows/icon.ico` 注入，与 Web 界面标识是两条独立链路。

生成入口是 `go run ./cmd/generate-brand-assets`；检查模式重渲染后与提交产物逐字节比较。生成器也将同一主标识制成手机端的 iOS 单张 1024 图标和 Android 各密度普通、圆形及自适应前景图标，保存在 `mobile/native/launcher/`。原生工程由 Capacitor 生成且不入库；每次重新生成后由 `mobile/scripts/wire-native.mjs` 将这些受控产物复制到平台资源目录。视觉资产变更需先确认源文件与派生物一致，再提交它们；`make brand-check` 只覆盖配置与文案，不代替这项像素资产检查。

## 验证

- 改配置后，所有配置生成物与配置一致，用户可见品牌没有硬编码副本。
- 官网地址变更后，`links.external.website` 是唯一被消费的地址；生成物同步、URL 语义校验通过，帮助页不会再指向上游或占位站点。
- 改视觉源后，生成器检查通过；各平台资源使用正确的尺寸、透明背景和模板形态。
- 便携产物、Web 资源与桌面元数据不包含旧品牌资产；跨平台产物文件名按 [待决事项](待决事项.md) 中的策略复核。
