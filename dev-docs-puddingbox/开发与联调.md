# 开发与联调

写作参照：`dev-docs/relay-runbook.md`。沿用其“适用范围 → 启动前提 → 操作路径 → 观测与故障处理”的结构；具体事实以 `Makefile`、`cmd/octo-desktop`、`cmd/productstub` 和 `internal/productclient/clienttest` 为准。

> developer Profile 同时承担日常开发和本地测试/Sandbox：它要保证调试数据与主机/正式便携数据隔离，并让桌面产品确实走过本地服务和中台边界。`productstub` 是第二件事的可执行中台替身，不是前端假后端，也不是生产组件。

## 范围与非目标

本文件说明本地开发的启动方式、数据/Profile 隔离、带壳热更新、桌面联调、`productstub` 的功能与故障走查，以及验证和演进边界。产品本地接口见 [本地 API 契约](本地API契约.md)，中台接口见 [中台接口契约](中台接口契约.md)，生产打包见 [便携打包](便携打包.md)。

不做以下事情：

- 不把热重载、普通浏览器成功或替身响应当作生产桌面交付验证。
- 不复用或修改真实用户的便携数据根，也不通过手改状态文件绕过用户流程。
- 不在 Web 端拦截 `/api/*` 并伪造成功，掩盖缺失的本地路由或契约。
- 不将联调开关、请求日志、真实上游密钥或代理行为打进产品包。

## 启动前提

- Go 版本以根模块和 `cmd/octo-desktop` 嵌套模块的 `go.mod` 为准，当前均要求 Go 1.25 及以上。
- 完整运行前端构建、测试和类型检查时使用 Node 22.22.2 及以上；`.nvmrc` 锁定推荐版本，`make node-check` 会在 npm/Vite 前给出明确错误。当前锁定的 Vite 至少要求 Node 20.19，而测试依赖 jsdom 的约束更高；只满足 Vite 会造成“能启动但测试环境不受支持”的分裂状态。
- 每个新 clone 先运行 `make hooks-install`。提交触发快速格式、文档和 fork 守卫，推送触发完整 `make gate`；它们是版本化的团队约定，不依赖某个人手工记住检查列表。
- 首次运行 `make web-dev` 前先在 `web/` 执行 `npm install`；这个 Make 目标只启动 Vite，不负责安装依赖。`make dev` 和 `make web-build` 会自行执行安装。
- 桌面壳依赖当前平台的 Wails/WebView 工具链。macOS 至少需要 Xcode Command Line Tools；Linux 需要仓库打包脚本所检查的 GTK4/WebKitGTK 6.0。跨平台产物验收仍按 [便携打包](便携打包.md) 执行，不能由本机裸二进制替代。

## 运行边界与启动选择

```text
开发时的桌面 Web UI
  → 桌面进程内本地 Go 服务 (/api/*)
  → productstub 或真实 Sandbox (/v1/*)
```

三层职责不同：

| 场景 | 推荐入口 | 能验证什么 | 不能代替什么 |
| --- | --- | --- | --- |
| 浏览器快速迭代 | `make dev` | 同时启动 `octo serve` 与 Vite，验证普通 Web UI 热更新 | window token、桌面壳和产品路由组装。 |
| 本地带壳调试 | 先 `make web-dev`，再 `make desktop-dev` | 真实桌面窗口、window token、原生桥和窗口内热更新 | 生产嵌入产物。 |
| 嵌入式桌面构建 | `make desktop`，再以测试数据根运行 `./octo-desktop` | 编译进桌面壳的 Web 资源与本地运行时 | 可移动介质交付。 |
| 中台协议与失败走查 | 启动 `productstub` 后再运行桌面开发版 | 登录、初始化、目录、模型网关和故障分支 | 本地 `/api/*` 的替身。 |

`make desktop-dev` 不会自动启动 Vite；没有先运行 `make web-dev` 时，开发窗口会加载不到页面。反过来，`make dev` 启动的是 `octo serve`，它会与桌面进程内的服务争用端口，不能用来替代桌面联调。

表中所有会启动 Go 服务或桌面壳的命令都应把 `OCTO_DATA_ROOT` 传给该进程。为了复用数据而固定一个项目目录时，也只能使用专门的测试目录，不能指向真实便携盘的 `data/`。

普通浏览器没有桌面 window token；`octo serve` 也不组装产品路由。因此不能根据浏览器中某个产品门请求失败，判断桌面产品门有缺陷。窗口身份和拦截流程应在真实桌面壳中验证，详见 [登录、访问控制与拦截页](登录、访问控制与拦截页.md)。

## 数据与 Profile 隔离

开发时显式设置 `OCTO_DATA_ROOT` 为临时或项目专用位置；每次走查使用可识别、可清理的目录。该变量必须进入**桌面壳进程**，只在 Vite 或 `productstub` 的终端中设置没有作用。运行结束后检查没有向主机 home、默认数据根或其他未声明路径写入产品文件。数据根的解析、创建、冻结和恢复规则只由 `internal/datapath` 决定，见 [便携数据根](便携数据根.md)。

开发 Profile 是随构建嵌入的明确配置，不从主机遗留文件猜测。当前没有第三个本地 Sandbox Profile：`internal/productprofile/profiles/developer.json` 同时用于日常开发和本地测试，地址统一读取 `internal/productprofile/endpoints.json`，当前将控制面和网关指向本地中台 `127.0.0.1:8000`（API 前缀 `/api/v1`）；以下替身联调需在统一入口改回 `8788`（API 前缀 `/v1`），允许开发 webview 和本地模型来源，并在 schema 中声明允许数据根覆盖。`allowDataRootOverride` 目前尚未接入运行时判定，`internal/datapath` 仍直接读取 `OCTO_DATA_ROOT`；不能把 Profile 字段误写成已经生效的生产隔离。准确边界见 [运行时 Profile 配置](运行时Profile配置.md)。

开发 Profile 显示上游 endpoint 管理入口，本地模型编辑行可以标记“私密模型”；正式产品模式隐藏该入口，不请求本地 endpoint 列表、不读取本地 endpoint 作为模型来源，也不采信本地私密标记。Composer 现在把验签后的中台目录与开发 Profile 允许出现的本地 endpoint 适配成同一套“厂商 → 模型 ID”选择器，并在厂商和模型两级稳定地把私密项排在前面；`<endpoint>::<model>` 仍是本地模型的实际路由身份，不会因为统一展示而改走产品 gateway。完整语义见 [模型选择与私密会话](模型选择与私密会话.md)。

## 本地带壳调试

需要验证 window token、产品门、托盘、原生文件选择、桌面生命周期或数据根冻结时，必须使用真实桌面壳。`desktop-dev` 只把窗口页面换成 Vite，壳内 Go 服务仍监听固定的 `127.0.0.1:8088`，Vite 将 `/api` 和 `/ws` 代理回该服务；`shell=octo-desktop`、window token 和原生桥不会因此消失。

完整产品联调使用三个终端。只调壳而不走登录、目录或 gateway 时，可以省略终端 A：

```sh
# 终端 A：中台替身；必须在桌面首次请求产品接口前启动
go run ./cmd/productstub

# 终端 B：首次使用先执行 (cd web && npm install)
make web-dev

# 终端 C：隔离产品数据，并在真实窗口中加载 Vite
export OCTO_DATA_ROOT="$(mktemp -d "${TMPDIR:-/tmp}/puddingbox-dev.XXXXXX")"
OCTO_LOG_LEVEL=debug make desktop-dev
```

终端 C 必须等 Vite 报告 `http://localhost:5173` 可用后再启动，否则窗口会白屏。不要用 `make dev` 替代终端 B：它还会启动 `octo serve`，与桌面壳争用 8088。生产 Profile 忽略 `OCTO_DESKTOP_DEV_URL`，所以这条热更新路径只能验证开发 Profile；生产嵌入资源用 `make desktop && ./octo-desktop` 验证。

调试信息有三个事实源：终端 C 的桌面进程输出、测试数据根下的 `logs/serve.log`，以及终端 A 的中台请求日志。界面成功但终端 A 没有相应请求，说明没有走中台边界；界面失败且终端 A 没有请求，先检查产品门、本地路由或 8788 连通性，而不是修改替身响应。

停止后可直接移除本次新建的临时目录。需要验证重启持久化时，先记录并复用同一个 `OCTO_DATA_ROOT`；需要全新安装状态时，换一个新的空目录，不要只删除某个状态文件拼出代码从未定义的混合状态。

## 本地模型必须完成真实聊天闭环

开发环境的本地模型能力不是模型列表或私密标签的静态演示。当前可执行的本地 endpoint 闭环是：

1. 在设置中打开 endpoint 管理，新建或编辑 endpoint，填写真实可访问的 provider、base URL、protocol、API key 与 model ID。
2. 添加模型时可设置“可用于私密会话”；已有模型也能修改该标记，保存后写入测试数据根的 `config.yml`。
3. 保存后无需重启，新模型立即出现在 Composer 统一的“厂商 → 模型”选择器中；选择结果保存准确的 `<endpoint>::<model>` 复合身份。
4. 在普通会话发送文本，请求经本地 Go 服务的现有 `senderForEntry` 和 provider 适配器到达所填 endpoint，并在真实桌面中显示流式回复。
5. 给至少一个实际可用的本地模型勾选“可用于私密会话”。在尚未发送消息的新会话中开启“私密会话”：当前模型不合格时应自动切到排序最前的私密模型，并持续显示“私密会话 · 仅使用私密模型”；发送后请求仍应到达该本地 endpoint，而不是 `productstub` gateway。
6. 普通会话手动选择带“私密”标识的模型后仍是普通会话，不能替用户自动开启私密会话。私密会话首条消息后策略锁定，普通模型不可选；若撤销当前模型的私密标记，下一回合应明确拒绝且不能回退其他公共模型。
7. 重启桌面后 endpoint、模型与私密标记仍存在，再次选择后仍能聊天。

自动化测试已覆盖 endpoint CRUD、复合身份绑定、OpenAI 兼容 SSE 增量、会话落盘以及不调用产品 gateway；它使用本机 `httptest` provider，不证明某个真实第三方服务的密钥、网络或方言兼容。上面第 1–7 步仍是测试环境的桌面人工验收，其中普通会话和私密会话都必须观察真实 endpoint 的请求日志，不能只根据选择器标签判断路由正确。

本地路径与 `productstub -upstream` 不同：后者验证中台目录模型经产品 gateway 转发到真实模型；本地模型闭环验证用户配置的 endpoint 直接复用上游 provider 路由。开发桌面仍可使用 `productstub` 提供登录、目录和余额等控制面状态，但选择本地模型后，模型回合不应打到 `productstub /v1/chat/completions`。两条路径都应保留，分别证明本地模型来源和中台模型来源真实可聊。

## productstub 是什么

`productstub` 监听本机回环地址（默认 `127.0.0.1:8788`），替代**中台**而非本地服务：

```text
Web UI → 本地 Go 服务 (/api/*) → productstub (/v1/*)
                                  ├─ 固定中台契约与测试夹具
                                  ├─ 手工走查的故障注入
                                  └─ 可选：仅模型回合转发至真实兼容提供方
```

命令直接运行 `internal/productclient/clienttest.Server`，即自动化测试所用的中台契约夹具；不另写登录、令牌、目录或错误信封。其价值是让手工走查与契约测试共享协议实现，而不是另建一套“看起来可用”的模拟环境。

它不负责窗口令牌、WebSocket、本地路由缺失或桌面生命周期；这些仍由真实桌面运行时验证。它也不定义协议：协议变化先进入 `internal/productclient` 和 `clienttest` 的测试，命令只暴露已经存在且值得人工反复观察的状态。

## 启动、接入与健康走查

```sh
# 默认监听 127.0.0.1:8788；开发 Profile 已指向它
go run ./cmd/productstub

# 所有开关必须写在可选监听地址之前
go run ./cmd/productstub -tool=terminal :9123
```

换端口或环境地址时，只修改 `internal/productprofile/endpoints.json` 的两个字段，然后重新编译并重启：

```json
{
  "apiHost": "http://127.0.0.1:9123/v1",
  "gatewayHost": "http://127.0.0.1:9123"
}
```

`apiHost` 必须带 `/v1`，因为控制面客户端据此拼接路径；`gatewayHost` 带或不带 `/v1` 都可，网关会规范化。两者都不是本地 `/api` 地址。

启动横幅报告实际地址、网关模式、工具调用和所有已启用的故障注入；请求日志记录方法、路径、状态与耗时，模型回合额外标记。用它确认桌面真的跨越了中台边界，而不是仅看 UI 成功。

健康模式提供固定输入：任意以 `1` 开头的 11 位手机号、短信码 `123456`、横幅列出的激活码与盒码，以及 1–20 个字符的昵称。主要路由为：

- `POST /v1/auth/sms/send`、`/auth/login`、`/auth/refresh`；
- `GET /v1/catalog/models`（无 `knownVersion` 为首次、过期或损坏缓存的全量目录；只有未过期缓存带版本做条件刷新）；
- `GET /v1/box`：返回确定性的单盒子安全投影，用于验证“我的盒子”的状态、能力布局和失败态；不返回 activation code、地址或凭证。
- `POST /v1/feedback`：验证 bearer gate、类别、标题、详细描述、影响程度与可选用户填写字段，以及 `Idempotency-Key` 的相同回执与冲突；节流响应由同一 `clienttest` 替身的契约测试覆盖。实现前不得把缺失端点伪装为成功。
- `POST /v1/chat/completions`，需要替身签发的 Bearer access token，并以流式响应返回。

所有替身状态都在内存。重启会恢复已消费的短信码/激活码，也会重新签发固定 refresh token。客户端文件直接位于数据根：凭据是 `$OCTO_DATA_ROOT/credential.json`，不是 `$OCTO_DATA_ROOT/data/credential.json`。真正从“全新安装”重新走查时应使用新的空数据根，使 `credential.json`、`product-state.json` 和 `catalog.json` 同时回到一致初始状态；只删除凭据适用于专门验证“本地凭据丢失”，不等于全新安装。

## 工具调用与故障注入

`-tool` 只提供可重复的预设回合：

```sh
# 请求 hostname，应落入权限询问路径
go run ./cmd/productstub -tool=terminal

# 请求读取 go.mod，应走默认自动允许路径
go run ./cmd/productstub -tool=read_file
```

未设置 `-tool` 是健康基线。`-tool` 与 `-upstream` 互斥：前者强制替身构造工具回合，后者让真实模型决定回合，两种结果不能混在一次演示中。

所有故障注入在开始监听前应用，首个请求即可看到结果；默认关闭且横幅会报告已启用项。

| 验证对象 | 开关 | 目的 |
| --- | --- | --- |
| 余额 | `-balance=<balanceMicroCredits 整数>` | `-balance=0` 验证零余额，区别于字段缺失。 |
| 账本、模型回合、注销 | `-fail-ledger=<状态>[:业务码]`、`-fail-completions=<状态>[:业务码]`、`-fail-logout=<状态>[:业务码]` | 分别验证纯 HTTP 故障与带业务码的失败。 |
| 模型目录 | `-model-ineligible=<模型>`、`-catalog-version=<版本>` | 验证撤回模型与目录版本回退防护。 |
| 签名策略 | `-catalog-ttl=<秒>`、`-policy-audience=<受众>`、`-omit-policy`、`-tamper-policy` | 验证过期、受众不符、缺失和签名篡改。 |
| 会话 | `-expire-access-tokens` | access token 一律拒绝、refresh token 保持可用，验证刷新路径。 |
| 字段完整性 | `-omit-ledger-balance` | 验证“余额不存在”不被当成零。 |

典型命令：

```sh
go run ./cmd/productstub -balance=0
go run ./cmd/productstub -fail-completions=402:insufficient_credits
go run ./cmd/productstub -tamper-policy
```

没有暴露成命令参数的 `clienttest` setter，不应通过修改产品代码来临时“补开关”。只有稳定、长期且确需手工观察的场景，才可按下文演进规则增加。

## 可选的真实模型转发

未设置 `-upstream` 时，模型路由只返回确定性的替身流，不产生任何外网请求。若需要人工确认完整桌面链路可接入真实 OpenAI 兼容模型：

```sh
export OCTO_UPSTREAM_KEY='提供方密钥'
go run ./cmd/productstub \
  -upstream=https://api.deepseek.com/v1 \
  -model=deepseek-chat
```

`-key` 也可提供密钥，但环境变量不易进入 shell 历史。开启 `-upstream` 必须有密钥；上游地址带或不带 `/v1` 均可，命令会得到唯一的 `/v1/chat/completions` 地址。

转发边界是：

- 仅代理 `POST */chat/completions`；登录、初始化、目录仍由确定性替身回答。
- 先验证请求携带替身签发的 access token；未授权请求仍是替身的 `401`，不会消耗提供方额度。
- 向提供方发送 `OCTO_UPSTREAM_KEY` / `-key`，绝不转发桌面携带的中台 token。
- `-model` 将 fixture 模型 ID（如 `buding-*`）改为真实模型 ID；未指定会原样转发，通常被真实提供方拒绝。
- 保留其他请求字段和流式标记，立即 flush 上游 SSE；上游状态、内容类型和错误正文透传，连接失败才转为 `upstream_unavailable`。

这个模式只回答“中台目录模型能否经 gateway 与真实模型流式通信”。它不替代上文的本地 endpoint 真实聊天闭环，不进入自动测试，也不应成为默认联网行为。

## 常见故障按边界定位

| 现象 | 优先检查 | 结论或处置 |
| --- | --- | --- |
| `desktop-dev` 窗口白屏 | 5173 是否已监听、Vite 终端是否因 Node 版本或依赖失败 | 先恢复 `make web-dev`；不要再启动一个 `octo serve`。 |
| 桌面启动提示 8088 被占用 | 是否已有 `octo serve`、`octo-desktop` 或上次调试进程 | 关闭旧进程后重试；产品桌面端口固定，不通过改端口绕过单实例问题。 |
| 登录、初始化或目录请求失败且 `productstub` 无日志 | 8788 是否监听、开发 Profile 是否仍指向默认替身 | 失败发生在中台之前；先查本地产品门和网络连接。 |
| 普通浏览器访问产品接口得到 403 或缺路由 | 是否误用 `make dev` 验证产品门 | 普通浏览器没有桌面 window token，改用带壳调试。 |
| 本地 endpoint 在开发模式可见、产品模式不可见 | 当前 Profile 的 `allowEnvironmentModelSource` | 这是预期隔离；不能通过直接调用隐藏 API 把本地模型塞回产品选择器。 |
| 重启后状态与预期不一致 | 桌面进程是否复用了同一 `OCTO_DATA_ROOT`，替身是否被重启 | 持久化测试复用同一目录；全新安装测试改用新的空目录。 |
| 本地模型能列出但不能回复 | `<endpoint>::<model>`、protocol、base URL、密钥及终端 A 是否收到 gateway 请求 | 本地模型应直达所配 endpoint；若终端 A 收到 completions，请先查错误路由。 |

## 验证与演进规则

开发变更先运行受影响的定向测试与守卫；涉及 Web 时补充构建、前端测试和类型检查；涉及桌面、路径或资源时在对应平台验证启动和产物。`productstub` 的定向测试是 `go test ./cmd/productstub`；桌面壳是嵌套模块，应在 `cmd/octo-desktop` 内运行 `go test ./...`。生产 Profile 边界使用 `make test-production` 验证，不能只运行根模块的默认测试。

`internal/productclient/clienttest` 是契约夹具，`cmd/productstub` 是人工操作外壳。盒子与模型走查必须从新的空数据根登录，使签名目录重新写入缓存；随后模型选择器应同时列出替身目录模型与开发者本地 endpoint，且私密目录模型优先。反馈夹具需可观察收到的结构化用户字段与幂等 key，但默认不得打印正文；手工走查应确认未带聊天或诊断字段、成功获得同一幂等回执、失败不自动重发。演进必须遵循：

1. 先变更真实中台契约、客户端和 `clienttest`，用定向测试固定请求、响应与错误语义；
2. 只有该状态需要反复人工观察时，才给命令增加默认关闭、横幅可见且有命令测试的开关；
3. 同步更新本文的目的、命令、预期结果与复位方式。

当真实 Sandbox 稳定后，开发 Profile 可以直接切换到它；`productstub` 继续承担离线、可复现的基线和失败注入。它不应演进为长期第二套中台、默认联网代理、局域网公共服务，或携带持久配置/生产凭据的发布组件。

技能管理已替换原静态演示页，不将演示内容写成真实发布数据。客户端区分中台发布目录与本地自建专家；旧会话保留专家及技能版本快照，新增技能版本不会改变旧会话。技能作为提示指令使用，不下载执行脚本。钱包刷新不得重置设置分类，反馈必填字段、提交状态与可选字段折叠由组件回归覆盖。

专家不限制模型选择，不因专家切换自动更换用户所选模型。专家角色要求进入系统提示；模型支持工具且提供 `load_platform_skill` 时，关联技能先以索引提供，按需读取锁定版本正文作为真实工具结果。不能调用加载工具时提供技能正文指导并说明工具限制，不发送不支持的工具协议字段。加载失败返回工具错误；加载成功仅代表获得指令，任务完成仍以真实工具结果和文件产物为准。代表性自动测试验证执行链路，不等于每种模型对所有专家任务的效果保证。

目录先显示缓存再刷新，固定版本详情共用账号和环境隔离的有界内存缓存，同键并发请求合并；失败不缓存。点击使用专家直接创建会话，执行前仍由中台校验专家版本，不重复读取整份目录。缓存测试以接口调用次数验证优化，不将隔离环境耗时当作生产网络或模型生成耗时承诺。

模型推理选项来自签名目录 `reasoningOptions`，未知能力仅显示模型默认。网关保留 `default/off/low/high/max` 原值，最终供应商适配负责开关和档位转换；显示推理只影响界面。偏好按模型保存在产品状态中，避免全局设置污染其他模型。

钱包用量默认近30天、最大90天，使用游标分页；加载后续页传 `include_summary=false` 跳过重复全范围汇总，并保留首屏汇总。已存在按用户、时间及ID的分页索引，不重复新增。输入个人信息保护仅覆盖用户文本；私密会话要求当前签名目录明确提供可用私密模型，没有合格模型时拒绝，不能以盒子或云模型名称推断私密能力。
