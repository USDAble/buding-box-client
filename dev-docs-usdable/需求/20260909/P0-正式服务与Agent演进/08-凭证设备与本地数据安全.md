# P0-08：客户端凭证、设备会话与本地数据安全

| 项 | 内容 |
| --- | --- |
| 当前仓库主责 | 客户端安全/桌面组 |
| 外部协作 | 中台账号组提供 token 生命周期、撤销、账户删除和审计合同；本仓库不实现账号服务或密钥托管 |
| 可并行 | P0-01 的 DTO 冻结后即可与 P0-02/P0-09 并行 |
| 依赖 | P0-01；可与 P0-02 的 mock client 并行，真实登录集成时合流 |
| 需求基线 | [P0 正式上线需求基线](../P0-正式上线需求基线.md) R3、R8；便携不代表凭证可复制 |

## 目标

把当前 `data/product-state.json` 中的旧本地 token 和账号状态拆开。正式产品的“便携”仅表示会话、产物和用户词可随 `data/` 携带，**不表示登录凭证可跨 Windows 用户或机器复制后继续使用**。访问令牌与刷新令牌不得写入 `product-state.json`、会话文件、配置、日志、导出包或诊断包。

## 当前代码风险与目标边界

当前 `productstate.Account.Token` 会明文落入 `data/product-state.json`。这在固定旧本地 token 的研发验证阶段可运行，但正式 refresh token 一旦复用这个字段，复制 U 盘即等同复制账号会话。因此 P0 必须先建立如下边界：

| 数据 | 保存位置 | 复制 `data/` 后的行为 | 是否可进入导出/诊断 |
| --- | --- | --- | --- |
| access token | 内存；进程退出即失效 | 不存在 | 否 |
| refresh token | `internal/credentialstore`；Windows 正式包用当前用户保护机制封装 | 在其他 Windows 用户/机器上不可解封，要求重新登录 | 否 |
| `installId` | 本地非敏感安装标识，随机 UUID | 可复制但不作为身份凭证；服务端可据此提示/撤销会话 | 可仅显示截断值 |
| 账号摘要、套餐、余额、目录/策略缓存（`data/catalog.json` 等） | `data/` 的无凭证缓存；保存**原始签名信封**，不保存解包后的可伪造结构 | 允许复制，但必须受 TTL、签名和 token 校验约束；复制到别处不成为授权（`audience` 与签名校验仍然生效） | 可按字段白名单导出（不含原始凭证；目录信封本身不含密钥） |
| 会话原文、附件、产物、用户词 | `data/`，默认本地 | 由用户决定是否迁移/备份；不被误称为“已加密” | 默认不进入诊断包 |

Windows 用户保护机制不能天然跨机器，正好符合“复制介质不能复制登录态”的目标。若产品承诺会话原文的静态加密，必须另立明确的用户密钥/口令 vault 方案；不能把 DPAPI 包装 refresh token 误称为“整个 U 盘已加密”。未做出该产品承诺前，界面与协议应如实说明本地数据保存在用户选择的可移动介质中。

## 当前仓库开发任务

1. 新建 `internal/credentialstore` 窄端口 —— 接口已随 P0-01 B0 落地，**方法名以代码为准**（原文档写的 `Delete`/`Unavailable` 已不成立）：`Load(ctx) (Tokens, error)`、`Save(ctx, Tokens) error`（替换语义）、`Clear(ctx) error`（幂等，空 store 清除也成功）。**只持久化 refresh token**，access token 仅在内存。`Load` 无会话时返回 `ErrNotFound`，它（正常首启态，路由到登录页）与「store 读取失败」（必须报错，不得静默登出）是两个不同结果。production Windows 实现用当前 Windows 用户保护机制；developer 只提供不可随产品发布的 mock。
2. 从 `productstate.State` 删除 `Account.Token`，将账户身份摘要、偏好、缓存和凭证分文件/分职责保存。旧 `product-state.json` 的 token 字段在迁移时丢弃并触发重新登录，绝不搬运到新文件。**各文件的 schemaVersion 现状、P0 是否需要迁移器、失败行为见 [P0-09 §数据迁移矩阵](09-便携发布更新与运行诊断.md) —— 那是唯一登记表，本节不复制**（P0 是首版，不存在已发布旧 schema 的迁移）。
3. 由 `internal/productclient` 与现有产品登录 handler 的受控挂点统一处理登录、刷新、登出：refresh 单飞成功后原子轮换，401/撤销/解封失败后先清凭证和内存 session，再回登录页；页面不能直接读 token。
4. 生成并校验随机 `installId`，只作为安装关联和风控信号。不得读取 MAC、硬盘序列号或将硬件指纹当作唯一绑定依据。
5. 实现“退出登录”和“清除此设备本地产品数据”两个不同动作：前者删除凭证但按产品规则保留本地会话；后者显示影响范围、删除可删除数据并保留最小故障恢复记录。远端账户删除/匿名化必须调用外部正式接口，不用本地删文件旧装完成。
6. 导出、备份、崩溃日志和诊断包均改为字段白名单；加入 secret scanner，拦截 Bearer token、refresh token、供应商 key、自定义认证头和完整手机号。

## 发给中台的交付要求（本仓库不实现）

1. 《会话与令牌安全规范》：access/refresh 的 TTL、audience、scope、轮换、撤销、并发刷新、泄露处置、签名密钥轮换和时钟偏差规则。
2. `logout`、会话撤销、设备会话查询/撤销、账户冻结、账户删除/匿名化的 OpenAPI、错误码、保留期和审计字段。客服换号不能隐式继承旧 refresh token。
3. `installId` 的使用边界：只能用于安装关联、风控和客服定位；不得成为硬件实名标识，也不得将其作为收费或授权的唯一依据。
4. sandbox 必须可模拟 refresh token 轮换、撤销、过期、错误 audience、复制后重新登录和账户删除请求；每个状态可按 `requestId` 追溯。
5. 《数据分类与删除说明》：账号资料、会话副本、模型请求副本、账本、审核/风控记录分别由谁保存、多长时间、谁可访问、何时删除或匿名化。

## 验收

- 全仓扫描和产品数据目录检查均找不到 access/refresh token、供应商 key 或自定义认证头。
- 拷贝整个 `data/` 到另一 Windows 用户/机器后，旧会话原文可按产品规则存在，但不能调用正式服务；用户必须重新登录。
- token 撤销、DPAPI 解封失败、刷新竞争、退出登录、清本地数据、账户删除请求和拔盘失败都有明确 UI 与恢复路径。
- 所有诊断、导出和客服上传样本通过 secret/PII 审查；测试固定在 CI。

## 不做

不把硬件指纹、供应商 API key、完整会话原文或账本写入 credential store；不在当前仓库实现中台的 token 签发、审计数据库、KMS 或账户删除后台。
