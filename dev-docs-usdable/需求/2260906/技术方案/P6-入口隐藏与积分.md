# P6 入口隐藏与积分

> **状态（2026-09-12 核实）。** **前端半已落地**：隐藏判据（`web/src/lib/features.ts`）、三处导航过滤（`Sidebar.svelte`）、深链兜底（`App.svelte`）、提示条顺序（`ComposerNotices.svelte` + `Composer.svelte`）、积分显示（`AccountCorner.svelte` / `AccountPanel.svelte` + `credits_update` 事件）都在 `v1` 上。**服务端半在 [`需求基线.md`](../../20260911/需求基线.md)：`B7`（能力矩阵与入口可见性）与 `E9`/`E10`（积分与充值）。**
>

## 1 结论

1. **隐藏的是"入口"，不是"能力"。** 上游的 IM / MCP / Light Apps 代码全部保留，只把界面到达它们的路径摘掉。理由是可回退：一个布尔数组改一行就能恢复，而删掉视图会让每次上游合并都变成 delete-vs-modify 冲突 —— 那是 git 唯一无法自动解决的一类。
2. **所有隐藏判据只有一处**（`features.ts`）。三个导航数组（`topNav` / `moreCategories` / `railNav`）都走同一个 `visibleNav()`，不允许任何组件自己写 `if` 判断。
3. **积分是只读投影，不是本地账本。** 客户端的数只用于显示；权威在中台账本（`E9`）。

## 2 术语

| 术语 | 含义 |
| --- | --- |
| 隐藏 | 从导航消失，且**深链到达也不展示功能**。不是"藏起来但可绕过" |
| 入口 | 导航项 / 空状态卡片 / 设置首页分类，三者都要摘 |
| 能力 | 服务端与前端已实现的完整功能，隐藏期间**不删除** |

## 3 入口隐藏

### 3.1 隐藏清单与唯一判据

清单是**产品常量**，写在 `web/src/lib/features.ts`：

```ts
export const HIDDEN_VIEWS = ['channels', 'mcp', 'lightapps'] as const
export function viewHidden(v: string): boolean {
  return (HIDDEN_VIEWS as readonly string[]).includes(v)
}
```

**规则.**

1. 新增一个隐藏视图 = 往 `HIDDEN_VIEWS` 加一项，**不改调用点**。
2. **判据不得复制。** 组件里出现 `v === 'mcp'` 这种直接比较即违规（§3.8 单一真相来源）。
3. 隐藏清单是**编译期常量**而不是配置：它决定"这个版本有没有这个入口"，属产品形态，不属用户偏好。
4. **本期的清单是静态的。** `B7` 落地后，入口可见性改由签名策略的 `visible` 决定（见 §3.5），届时这张表降级为"策略不可用时的出厂默认"。

### 3.2 黑名单语义与过滤点

`visibleNav()` 是**黑名单**：不在清单里的条目**一律放行**。

**这是一条刻意的选择。** 上游新增一个视图时，白名单（"只显示我认识的"）会默认把它藏掉 —— 表现为"上游加了功能，我们这个版本莫名其妙看不见"，且没有任何报错；黑名单只会把显式列出的藏掉，上游新增默认可见，漏了就是漏了，可见且可报。故障方向相反，黑名单的那个方向更容易发现。

**过滤点（三处，都必须走 `visibleNav`）：**

| 位置 | 数组 | 文件 |
| --- | --- | --- |
| 侧栏顶部 | `topNav` → `visibleTopNav` | `Sidebar.svelte` |
| "更多"分类 | `moreCategories` → `visibleMoreCategories` | 同上 |
| 窄侧栏（rail） | `railNav` → `visibleRailNav` | 同上 |

`visibleNav()` 保留原顺序、不改原数组（`filter` 返回新数组），所以上游对这些数组的改动**合并没有冲突**。

### 3.3 深链与旧书签的兜底

隐藏只做一半是危险的：用户可能有旧书签 `#/mcp`，或上一次退出时正停在那个视图（`octo.lastRoute`），冷启动会把人直接送进一个"本版本不提供"的页面，而侧栏里没有对应条目 —— 用户看到的是一页能用的功能配一个消失的入口。

**规则.** 视图切换后检查 `viewHidden($view)`，命中则回主聊天并提示一次 `feature.not_available`（"本期不提供此入口"）。**不静默重置** —— 静默重置的表现是"我点了个书签，页面自己跳到别处了"，比一句提示更费解。

**为什么在 `App.svelte` 而不是各视图内部：** 兜底必须在**进入视图之前**发生。写在视图内部等于"已经渲染了再说"，会先闪现一帧功能界面。

### 3.4 上游能力保留

服务端路由、`McpServer` 注册表、IM 适配器、Light Apps 运行时**一律不动**。

**边界（`需求基线 B7` 规则 4）：** 隐藏 ≠ 授权。入口摘掉只是界面行为；**未登录或未授权时这些能力同样不得从窗口调用** —— 那是产品门（`E8`）与权限门（`C10`）的职责，不是隐藏的职责。两者不可互相替代。

### 3.5 与能力矩阵（`B7`）的关系

`B7` 把入口可见性从"静态清单"改成"签名策略里的 `visible`"：

| | 本期（静态） | `B7` 落地后 |
| --- | --- | --- |
| 判据来源 | `HIDDEN_VIEWS` 常量 | 签名策略的 `capabilities[].visible` |
| `visible=false` | 等价于"在清单里" | 从界面移除 |
| `entitled=false` | 无此态 | **展示为不可用并给出原因**（不是移除） |
| 判据不可用时 | 不适用（常量总在） | 回落到本期的出厂清单，并**知会用户**（§3.9 有界降级） |

**接缝已经留好：** 唯一判据是 `viewHidden()` 一个函数，`B7` 只需要改它的实现（常量 → 策略查询），三个过滤点与深链兜底一行不动。

### 3.6 输入框附近提示的固定顺序

三个来源的提示会同时出现，顺序**必须在视觉上稳定**，否则同一个输入框在两种状态下提示会互换位置。

**规则（从上到下，固定）：**

| 序 | 提示 | 位置 | 是否拦截发送 |
| --- | --- | --- | --- |
| ① | 隐私模式细条 | 输入框**上方** | 否（发送前处理） |
| ② | 敏感词命中 | 输入框**下方** | **是** |
| ③ | 积分不足 | ②的**再下方** | 否（仍可发送） |

**实现方式（关键）：** 顺序**不是**由三个组件各自决定，而是**一个数组的顺序**。`Composer` 维护通知数组，`ComposerNotices.svelte` 原样渲染；`slot: 'above' | 'below'` 是通知自己声明的位置，`Composer` 只按 `slot` 分组、不写逐条规则。

这样 `P8`（敏感词）与 `P10`（隐私条）**各自往里追加一条**，不需要碰对方的代码，也不可能出现"两个 PR 各画一条、顺序靠渲染时序决定"。

## 4 积分与充值入口

### 4.1 积分的显示

左下角（`AccountCorner.svelte`）与个人中心（`AccountPanel.svelte`）显示**同一份数** —— 都读 `$productState.credits`。数据来自 `GET /api/product/state`，并由 `credits_update` WS 事件增量更新（`App.svelte`），不需要轮询。

窄侧栏（rail）时只显示头像，积分不显示（位置不够，取舍对用户可见）。

### 4.2 本地扣费规则已作废（重要）

`需求20260906.md` §5.4.4 曾规定本地假数据规则：首次激活写 1280、每条成功消息 +1 消耗、余额 > 0 再扣 1。

**该规则自 `需求基线 E9` 规则 1 起作废**，只在**假后端（`devBackend.ts`）**里保留，用于本轮 UI 演示。理由：积分的权威在中台账本，客户端**不本地扣费**（`E9` 要求）—— 保留本地扣减会在真联调时与中台账本打架，而"哪个数是对的"在界面上看不出来。

**落地后果：** 正式构建不再有"每条消息 -1"的逻辑；余额呈现为 `E9` 规则 2 的两条来源之一（本轮为 `GET /v1/credits/ledger` 拉模式）。

### 4.3 充值入口常驻

**「充值」入口常驻显示**，不依赖余额是否为 0、也不依赖是否收到 402。

理由：用户想充值的那一刻，往往正是余额**还够用**的时候（提前续费）。把入口挂在"余额为 0"上，等于要求用户先把余额用完才能找到充值按钮。

"套餐版本"页与"升级"入口同理，且支付走**外链或占位**，客户端不处理支付。

## 5 验收

| # | 验收项 | 判据 |
| --- | --- | --- |
| 1 | 侧栏无隐藏入口 | IM / MCP / Light Apps 三项不出现在侧栏任意形态（含 rail 与"更多"） |
| 2 | 深链被兜底 | 手输 `#/mcp` → 回主聊天 + 提示"本期不提供此入口"，**不闪现功能页** |
| 3 | 上游能力仍在 | 服务端路由与视图文件都存在（隐藏 ≠ 删除） |
| 4 | 判据唯一 | `rg "HIDDEN_VIEWS\|viewHidden" web/src` 只有 `features.ts` 定义、其余为调用 |
| 5 | 提示顺序 | 同时造出①+②+③ → 严格按上表顺序，隐私条在上方、另两条依次在下方 |
| 6 | 积分同源 | 个人中心改余额 → 左下角立刻同值（无需刷新） |
| 7 | 充值常驻 | 余额充足时「充值」入口仍在 |
| 8 | 无本地扣费 | 正式构建发一条消息 → 余额不变（只有假后端会变） |
