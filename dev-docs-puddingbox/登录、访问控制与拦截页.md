# 登录、访问控制与拦截页

当前中台对接行为：用户协议与隐私政策仅供查看，无确认按钮，不要求打开或同意才能激活、登录。首次激活提交短信验证码与激活信息；已激活用户主动退出或登录会话到期后，仅需短信登录。会话有效期间重启客户端或同一 U 盘换电脑自动恢复；短期访问令牌由后台续期，网络故障不清除凭据。具体参数、30 天默认会话期限和便携安装身份语义见 [中台接口契约](中台接口契约.md)。

写作参照：`dev-docs/permission-remember-design.md` 与 `dev-docs/desktop-update-notice.md`。前者的“事实源、授权边界、状态转换”用于说明产品门；后者的“故障分类、用户恢复路径”用于说明拦截页。本文以 `web/src/lib/product.ts`、`web/src/views/BlockedView.svelte`、`internal/productruntime` 和桌面组装代码为事实源。

> 登录、窗口访问控制和拦截页不是三套机制：它们组成一个闭环。桌面窗口先证明自己属于当前桌面进程，再读取产品状态；未登录或无法安全进入时只显示拦截页；登录、会话恢复或主动退出再推动状态回到正确的页面。

## 范围与边界

本文说明桌面产品的窗口令牌、产品相位、登录/激活表单、构建配置拦截、平台失败和退出/会话失效。请求和响应字段见 `本地API契约.md`；中台的 token、刷新和错误语义见 `中台接口契约.md`；控制面地址及可信密钥的来源见 `运行时Profile配置.md`。

不负责以下事项：

- 不把中台 bearer token 交给 Web UI，也不以窗口令牌替代中台会话。
- 不把普通浏览器或 `octo serve` 伪装成有桌面产品门的窗口。
- 不以组件隐藏、菜单禁用或 URL 参数作为服务端安全边界。
- 不向用户展示控制面地址、密钥标识、配置文件路径等无法自行修复的细节。

## 用户协议与隐私政策

登录页的两个协议入口通过本地 `GET /api/product/agreements/{kind}` 请求中台：用户协议为 `box`，隐私政策为 `privacy`。本地窗口令牌校验保持不变，不要求用户已登录；中台请求不携带账户凭据。

每次打开及手动重试都读取最新正文，不再使用品牌配置中的占位正文。弹窗展示服务端标题与纯文本正文，保留换行；加载失败显示重试入口，不回退到旧内容，也不影响激活或登录。关闭或切换协议时取消旧请求，避免串文。此接口保留发布版本号，但不据此记录阅读或同意。

## 闭环与唯一所有者

```text
桌面壳生成本次启动 token
  → webview URL 携带 window_token
  → 前端移入 sessionStorage，后续 /api/product/* 携带请求头
  → 服务端对已挂载产品路由校验 token
  → 前端读取控制面事实与产品状态
      ├─ 构建不可用：拦截说明页
      ├─ 未登录/状态读失败：登录或激活页
      └─ 已登录：主界面
```

事实的所有者不能互相替代：

| 事实 | 唯一所有者 | 前端能做什么 |
| --- | --- | --- |
| 当前构建是否配置控制面、是否有可信密钥 | Profile，经 `/api/product/control-plane` 投影 | 选择拦截说明页，不能猜测或修改。 |
| 当前安装是否登录、是否已激活 | 持久化产品状态，经 `/api/product/state` 投影 | 选择初始表单和相位，不能自行推断授权。 |
| 当前请求是否来自桌面窗口 | 桌面进程内的 window token 与服务端产品门 | 附带 token，不能自行放行。 |
| 中台会话是否有效 | 中台及运行时的刷新结果 | 消费本地 `unauthorized`，不能把网络失败当作失效。 |
| 当前表单形态 | 拦截页组件 | 用户可在登录、激活之间切换；这只是界面选择，不是授权事实。 |

## 窗口令牌：进程身份，不是登录凭据

桌面进程在本次启动时生成一次 32 字节随机 token（十六进制），仅存在内存。它由桌面壳加到 webview URL 的 `window_token` 查询参数；前端首次加载后移入当前 tab 的 `sessionStorage`，并立刻从地址栏移除，避免留在浏览记录中。

该 token 是**每次桌面进程启动一枚**，不是每个窗口重新签发一枚；因此它证明“属于本次桌面进程”，不表达用户身份。新启动会得到新 token，token 从不写入数据根、配置、持久状态或可分享 URL。

桌面组装将 token 交给 `server.Config.WindowToken`。经 `MountAPI` 注册的 `/api/product/*` 路由同时继承既有 API 认证、`Cache-Control: no-store` 和此 token 校验；错误或缺失时返回 `403 {"error":"product_gate"}`。比较采用常量时间比较。

产品门只覆盖 fork 自己挂载的产品路由，**不覆盖全部 `/api/*`**：上游路由仍沿用上游的信任模型，裸 `<img>` / `<iframe>` 资源也无法携带该请求头。这是经过验证的范围边界，不能由前端“补一层名单”扩大或缩小。WebSocket 因浏览器无法设置请求头而通过 `window_token` 查询参数传递；它是不同传输方式，不能据此推导产品门已覆盖全部 WebSocket 或上游 API。

普通浏览器没有 token 时，前端相位直接为 `ready`；而 `octo serve` 未组装这组产品路由。这保持上游浏览器使用方式，不提供一个可绕过的桌面门。

## 相位与拦截页选择

前端只有三个相位：

- `unknown`：尚在决定状态，作为启动过渡；
- `blocked`：当前不能进入主界面；
- `ready`：可渲染主界面。

在桌面窗口中，先读取 `/api/product/control-plane`，再读取 `/api/product/state`。控制面端点不需要已登录，但仍需要有效窗口 token。其两个事实的优先级固定：

| 读取结果 | `blockedPage` | 用户看到什么 |
| --- | --- | --- |
| `configured: false` | `unconfigured` | 本包没有可用控制面配置；不显示无效登录表单。 |
| `configured: true` 且 `hasTrustedKeys: false` | `no_keys` | 地址存在但无法验证控制面响应；不显示登录表单。 |
| 两项均为真，或控制面端点不可读/非 200 | `login` | 登录/激活页。不可读不等于构建损坏，不能误报。 |

当页面为 `login` 时，状态中 `loggedIn: true` 进入 `ready`，否则进入 `blocked`。状态读取失败同样落到 `blocked`，让用户仍有可见恢复入口，而不是永久加载。配置说明页不暴露地址或文件名，也不提供用户无权完成的“修复配置”按钮。

## 登录与激活：事实由服务端决定，形态由用户决定

短信短登录只提交手机号、区号和验证码，不展示或修改昵称；首次激活额外提交昵称、`activationCode` 与 `boxCode`。登录和激活的手机号都可从常用国家或地区中选择区号；前端向本地接口分开发送 `phone` 与不带 `+` 的 `region_code`，本地服务提交给中台的号码仍为 E.164。列表外的完整国际号码保留旧版 E.164 本地请求兼容路径。两个激活凭证是可选的一对：要么同时提供，要么同时省略。前端只做格式与成对校验；“此账号/安装是否需要激活”由中台决定。

拦截页首次出现时，以状态的 `activated` 选择默认形态：未激活时优先激活表单，已激活时优先短登录表单。此后两个入口始终都可由用户切换，状态刷新不能在用户输入或阅读错误时把表单换走。这样既支持已激活用户重新激活，也支持丢失本地数据但中台已有授权的用户直接登录。

格式错误显示在对应输入框；中台业务码显示在表单反馈区；验证码发送的冷却使用独立的 `retryAfterSec`。界面只把 machine code 映射到本地化文案，绝不直接拼接中台 `message`。未知业务码会采用明确的通用提示并记录契约异常，不能渲染为空。

登录成功后，运行时保存 refresh token、更新产品状态，并尝试刷新目录、余额和服务端词库。目录、余额或词库的普通失败不阻断本次登录；但刷新 token 被明确拒绝是会话失效，走下节的统一路径。

## 平台失败与恢复语义

本地运行时统一把平台失败映射为 machine code；页面根据代码决定用户动作，不能从 HTTP status 自行猜测。重试性与是否清凭证是两条独立判断：

| 本地分类 | 用户动作 | 凭证与相位 |
| --- | --- | --- |
| `network_unavailable` | 显示网络故障，可重试刚才失败的动作。 | 保留凭证和当前表单。 |
| `upstream_unavailable` | 显示中台暂不可用，可重试刚才失败的动作。 | 保留凭证和当前表单。 |
| `account_restricted` | 显示限制说明，不提供没有意义的重试。 | 保留凭证；用户可关闭提示。 |
| `unauthorized` | 不显示“重试”提示，返回登录页。 | 运行时清除会话，前端置 `blocked`。 |

当某次中台调用及 refresh 都明确拒绝会话时，运行时先忘记本地会话，再返回 `401 {"code":"unauthorized"}`。前端只将 `loggedIn` 改为 `false`，保留激活记录与绑定账号的公开状态；因此拦截页能显示正确的二次登录形态，不会把已经消费的一次性激活码再要求用户输入。

## 主动退出与会话失效不同

主动退出尝试先通知中台撤销，再删除本地 refresh token 并将产品状态退出登录。中台撤销失败或不可达不阻止本地退出；成功响应的 `revoked` 明确说明中台是否完成撤销。激活记录、绑定手机号和昵称都保留——退出不是取消激活，下一次应允许手机号加验证码的短登录。保留的昵称只属于已绑定账号：用户从短登录切到新激活表单时，昵称默认值在本次拦截页挂载时随机生成一次，不预填旧账号昵称；反复切换表单不重新生成，也不覆盖用户手动输入。

会话失效不是用户主动请求，也不尝试把失败解释为普通网络问题。它由中台明确拒绝触发本地清理，并直接回到拦截页。二者不能共用含糊的“已退出”提示或把失败静默吞掉。

## 验证要点

- 检查新启动生成新 token；token 只在进程内和当前 tab 的 sessionStorage 存活，且首次加载后不留在 URL。
- 用缺失、错误、正确 token 分别访问已挂载产品路由，确认只有正确 token 可通过；同时确认上游 API 没被误纳入产品门。
- 覆盖 `unknown`、`blocked`、`ready`，以及未配置、无可信密钥、控制面不可读、未登录、已登录和状态读取失败。
- 覆盖登录与激活的双向切换、字段/业务/限流错误、用户输入期间的状态刷新，以及一次性激活后的二次登录。
- 覆盖网络故障、上游故障、账号受限、明确会话失效和主动退出，分别断言重试、凭证、激活状态和页面结果。
