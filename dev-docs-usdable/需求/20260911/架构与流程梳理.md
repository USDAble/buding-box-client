## 4. 发现的问题

分为四级：**A 真缺陷 / B 结构性债 / C 文档漂移 / D 已登记有归属**。每条给证据与归属。

### A1 — 硬规则 3（`OCTO-FORK` 标记）**没有守卫，且覆盖率 21%** ⚠️ 本轮最实质的发现

**规则原文**：改上游文件必须打标记 `// OCTO-FORK: <原因> — see <设计文档>`；`grep -rn "OCTO-FORK" .` 是"这个 fork 相对上游的完整差异清单"（`CLAUDE.md` 硬规则 3 / `开发规范` §3.3）。

**实测**（`git diff --diff-filter=M 6a9d040b v1` 逐个文件 grep 标记）：

| | 数值 |
|---|---|
| 被修改的上游文件 | 306 |
| **带标记** | **64**（21%） |
| **不带标记** | **238**（79%） |
| 其中 `.go` | **194** 个 / 1,484 行 |
| 其中非代码（`.md`/`.json`/`.yml`/`.plist`/`.html`） | 34 个 / 269 行 |
| 守卫 | **没有**。`scripts/` 里没有脚本断言过这件事 |

**两类原因要分开说，不能笼统说"违规 238 处"：**

1. **规则的"形式"没写作用域（§3.10 缺失）**：`// OCTO-FORK` 在 `.md`/`.json`/`.yml` 里**写不出来**。34 个非代码文件（如 `internal/skills/defaults/*/SKILL.md` 里 `~/.octo/…` → `<data root>/…` 的批量措辞更正）**按规则无法合规**。这是规则本身的缺口，不是执行者的。
2. **`.go` 那 194 个是真缺口**，但要按体量看：**107 个只改了 1–4 行**（多为测试补一行数据根，如 `cmd/octo/session_scope_test.go`、`internal/server/agent_runs_test.go`），69 个改了 5–14 行。**实质性且无标记的少数**值得点名：`cmd/octo-desktop/lang.go`(172)、`cmd/octo-desktop/build/windows/generate-syso/main.go`(99)、`cmd/octo-relay/internal/push/push.go`(50)、**`internal/app/sender.go`(29，`PR-5b1` 新增的 `ReasoningTuning`)**、`internal/server/profile_handler.go`(23，`octoDir()` → `datapath.Root()`)。

**为什么这条重要（不是形式主义）**：这笔账正是**上游合并**要用的账 —— 合并时要逐个人工看哪段是自己的、哪段可能冲突。清单不全 ⇒ 每次合并都要重新做一遍全量 diff 考古。这也解释了为什么 `server-diff-guard` 必须存在：**因为标记清单不可信，只能靠守卫单独盯住最贵的那个文件**。

**建议（两者都要）**：
- ① 加 `fork-marker-guard`：`git diff --diff-filter=M <upstream> <branch>` 的每个文件必须含标记；**并给非代码文件定形**（`<!-- OCTO-FORK: … -->` / `# OCTO-FORK: …`），把规则的作用域补全。
- ② 补齐 `.go` 的 194 处（先补实质性的 ~10 个，机械的一行改动可一次脚本批处理 —— 但**要人是看得懂的为什么**，不许写"datapath 迁移"就完事）。

## 5. 结论

**架构有没有问题？方向没有，有一处执行缺口。**

- 分层单向、缝在正确的位置、网关复用上游 provider 而不是自写第二份解析器（`C3`）、数据路径与品牌各有唯一 owner 且有守卫 —— 这些都对。
- **三条硬规则里，两条有守卫（`datapath-guard`、`brand-guard`），第三条没有。** 而实测它恰好是**唯一没做到**的那条（覆盖率 21%）。这不是巧合：**没有被机器检查的规则就会退化**，这条结论在本仓库已经被验证过三次（`V-24`、`V-46`、`V-47`，都是"没有机器能发现"）。

**流程有没有问题？主干通，断点都在未做的 PR 上。**

- 登录→激活→目录→选择器→回合→网关，今天在 CI 内可判；失败面（四档降级、拦截页、不许回落）都有实现与钉子。
- 唯一"需求明文要求但今天不成立"的是 `P3 §5.4.3` 在 `/api` 上（`D-006`）—— 已登记但**无 PR 认领**，需要显式排除或认领。

**真正的风险不是"架构错"，而是"看起来通过"。** 本轮拆掉的前端假后端是这一族里最大的一只；`V-47`（从未验证的 tree-shake 断言）和 B2（守卫理由文本）是同一族的小只。它们的共同特征是：**形状合法、界面正常、没有任何机器能发现**。
