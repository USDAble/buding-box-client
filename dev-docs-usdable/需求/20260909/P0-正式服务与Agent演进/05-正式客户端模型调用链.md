# P0-05：正式客户端模型调用链

| 项 | 内容 |
| --- | --- |
| 当前仓库主责 | 客户端 Agent/Server/UI 组 |
| 中台协作方式 | 仅使用 P0-02/03/04 对应的外部 sandbox；不在本任务实现网关、账本或控制面 |
| 可并行 | 可先按 fake client/fixture 开发；真实集成依赖 P0-02/03/04 sandbox |
| 依赖 | P0-01、P0-02、P0-03、P0-04 |
| 需求基线 | [P0 正式上线需求基线](../P0-正式上线需求基线.md) R1、R4、R5；production 不得走本地 provider，所有 profile 均无本地扣费模拟 |

## 目标

把现有 `ensureLocalEndpoint()`、`config/endpoints`、`senderForSession()` 和聊天模式链路改造成：production 会话只能绑定外部中台 catalog 中的模型，由当前仓库的 `ModelGatewaySender` 调用网关；developer/demo 行为仍可保留，避免破坏现有演示与维护能力。本任务是客户端会话、UI 与 profile 的集成，不包含任何中台服务实现。

## 实施步骤

1. 为 session 保存稳定的 `modelId`、catalog version 与 policy version，不保存 supplier endpoint/key；目录刷新后已删除模型不得用于新回合。
2. 改造 `senderForSession`：production 忽略本地 endpoint，构造 gateway sender；demo/developer 保持现有 config provider 解析。
3. 改造 chat mode handler：从 `ControlPlaneClient.Models()` 读取模式/模型，缓存失效时明确展示“目录暂不可用”，不静默回落假模型。
4. 将 endpoint 管理组件在 production 隐藏；直接调用本地 config route 也不能把外部 endpoint 绑定进 production session。
5. 将 gateway 的 `clientRequestId`、SSE usage、错误码和余额状态转成现有 session/WS/UI 事件；会话仍本地保存原文及产物。
6. 模型工具调用进入 P0-04 的 PEP，不能因来自 gateway sender 而跳过确认。
7. **删除** `internal/server` 的 `consumeCredit()`、`internal/productstate.Store.ConsumeCredit()`、`initialCredits` 与 `productstate.Credits` mock，并删除“每成功发送一条消息扣一分/0 分仍可发”的接口响应和测试。任何 profile 都不保留本地扣减模拟；余额只来自 `UsageClient` 与 gateway 的终态事件，缓存须注明来源版本和 `asOf` 时间。

## 回归和验收

- demo 测试继续使用 local provider，但不再产生本地积分扣减；production fixture 不含任何本地 provider 配置也能完成真实流式调用。
- catalog 中无资格模型、目录过期、token 失效、余额不足、SSE 中断、模型下架均有 UI/状态测试。
- 生产包配置目录出现 API key 后，静态扫描与运行时断言都证明该 key 未被读取用于模型调用。

## 合并策略

第一 PR 加 sender/目录接口与 fake；第二 PR 改 session/chat mode；第三 PR 改生产 UI/profile guard。保持每一步能跑 demo，远端联调开关不提前默认开启。
