## 0. 一句话

**交 1 张高分辨率彩色主图 PNG（`logo-mark.png`）就能用。** macOS 托盘图标与全套尺寸（`.ico`、`.icns`、PNG）由脚本自动派生。如果你愿意再花十分钟，可以另交一张"纯黑剪影"（`logo-mono.png`），让菜单栏图标更好看 —— 不交也能跑。

> 为什么收 PNG 不收 SVG：研发实际交付物全是位图，PNG 源足够。连续几次设计交付的"SVG"其实都是把 PNG 塞进 `<image>` 标签的嵌入位图的 SVG（几百字节该有的文件被撑到 440KB），说明源文件里 logo 本身就是位图。既然如此，直接以高清 PNG 为源，见文末 §9。

## 1. 交付清单（可直接转发给设计师）

放到 `branding/source/`，文件名必须一字不差：

| 文件 | 尺寸 | 内容 | 必需 |
|---|---|---|---|
| `logo-mark.png` | **正方形，2048×2048 ~ 4096×4096** | 主标识：**完整成品彩色 logo**，透明底 | ✅ **第一批，只给这张就能跑** |
| `logo-mono.png` | 正方形，≥ 512×512 | **纯黑剪影版**（见 §3），可选 | ⏳ 可选增强 |
| `og-card.png` | **1200×630**（固定比例） | 社交分享卡片 | ⏳ 可选，可后补 |

> **为什么源图不交 SVG、只交 PNG？** 见 §0。

> **"不带字标"是什么意思？** 图标最终会缩到 16×16 像素，旁边的小字（如"布丁盒子"文字）缩到那么小就是一团糊。所以图标源图只要**图形本身**，不要带文字。若设计稿里图形和文字是一体的，请把文字部分裁掉再导。

> **尺寸要不要严格 2048？** 只给一个大图即可：工具会**自动按比例缩放**。上限 4096 是因为再大（设计软件里常见导出 12000²）解码内存大、又没有任何清晰度收益 —— 超大文件研发会先压到 2048 再入库，你不必自己压。

## 2. 对源图的建议（当前工具只强校验尺寸 ≤ 4096，其余是"最好做到"）

| 项 | 要求 | 为什么 |
|---|---|---|
| 正方形 | 最好正方形（不必严格，工具会按比例缩放并居中） | 缩放逻辑按短边适配 |
| 透明底 | 底板之外**最好透明**，不要铺白色背景 | macOS 圆角遮罩、深色托盘会露出白块 |
| 图形占画布 | 内容占画面 **约 80%**，四边各留 **8–10%** 空白 | 系统会裁边，顶格会被切到 |
| 16px 可辨识 | 把图缩到 16×16 仍认得出是布丁盒子 | 图标最小就这么大 |

## 3. `logo-mono.png`：什么是"剪影"（可选交付，看懂为何可选）

### 3.1 剪影 = 把 logo 涂成纯黑实心形状

就是把 logo 做成**只有一种纯黑 `#000000`、没有颜色和花纹**的形状，像用黑纸剪出来的影子：

```text
彩色主标识                    纯黑剪影（logo-mono.png）
┌──────────┐                 ┌──────────┐
│ ██    ██ │  彩色、有渐变      │ ████████ │  只有一种纯黑
│   ████   │  有内部层次        │ ████████ │  空白=透明
│  █ ██ █  │                  │ ██    ██ │  （不是白色）
└──────────┘                  └──────────┘
```

打个比方：主标识像**彩色照片**，剪影像把照片做成**纯黑贴纸**——只剩轮廓，但还认得出是同一个东西。

### 3.2 为什么需要一个"纯黑剪影"？

macOS 电脑屏幕最顶上那排菜单栏（电池 / Wi-Fi / 时间）右侧的小图标，走系统"模板图"通道：**系统忽略颜色，只看形状（透明 / 不透明）**，再按菜单栏深浅自己染成白色或黑色。

- 放彩色图 → 颜色全被扔掉，只剩实心坨坨，认不出。
- 放纯黑剪影 → 形状完整，深色菜单栏自动变白、浅色变黑，永远清晰。

### 3.3 不交 `logo-mono.png` 会怎样？（自动派生）

不交也不阻塞：工具会**从彩色主图自动派生剪影** —— 取主图的 alpha 通道、填成纯黑。**但有个天生的局限**：如果你的 logo 内部细节（眼睛、嘴、高光）是"画在图案上的浅色"，而不是"真镂空的透明"，这些细节**不在** alpha 通道里，自动派生后会丢失，菜单栏上就是一个实心圆/块。

所以规则是：

- **先用起来**：只交主图 → 自动派生（菜单栏显示外轮廓剪影）。
- **更好看**：设计师另交 `logo-mono.png`（真镂空的减法版）→ 工具自动优先使用它。

### 3.4 怎么做（若选择手动交付 `logo-mono.png`）

拿主标识：**去掉所有颜色、渐变、底板，只留外轮廓**，用 `#000000` 填充；眼睛等"该透光"的镂空处留成**透明**（别用白色填，白色在深色菜单栏会显示成白块）。

| 项 | 要求 |
|---|---|
| 颜色 | 只用 `#000000`，其余靠透明 |
| 造型 | 主标识"减法版"：去底板、去内部层次，留外轮廓 + 关键镂空 |
| 非透明面积 | 占画布 **20%–35%** |
| 笔画 | 比主标识更粗（菜单栏实际只有 16–22px 高） |
| 镂空 | 真镂空（透明），不要用白色填充伪装 |

**自检**：把这张图反色（黑变白）放到黑底上看——还认得出就合格；变成色块就是内部层次不够。

## 4. `og-card.png`：1200×630 社交卡片（可选，可后补）

用于微信 / Twitter / Slack 分享预览。这张需要排版与文案，**工具不会替你合成**（没有字标/背景的卡片发出去很怪），所以设计稿到位前社交预览图沿用旧图，不阻塞。

| 项 | 要求 |
|---|---|
| 尺寸 | 1200×630，固定比例 |
| 内容 | 标识 + 「布丁盒子」+ 一句话介绍 |
| 安全区 | 主要内容收在中间 1100×540 内（各平台会裁边） |
| 背景 | **不透明**浅色底，不要透明 |

## 6. 历史教训（避免重复）

1. **交了位图当源**（15 张 PNG，11 张没人用）。
2. **把 PNG 包成 SVG 冒充矢量**（440KB 嵌入位图的 SVG）—— 这是本次改收 PNG 的直接原因。
3. **底部隐藏近白字标**（深色界面露出）。
4. **图形顶到画布边**（被圆角遮罩切到）。
5. **用彩色图当 macOS 菜单栏图标**（退化成实心色块）—— 自动派生的剪影同样要接受"内部细节会丢"的现实。

## 7. 交付之后研发做什么

```bash
# 1. 放入 PNG：branding/source/logo-mark.png（可选 logo-mono.png / og-card.png）
# 2. 一条命令生成并分发全部产物
make brand
# 3. 自检（CI 同款）
make brand-check
```

> 超大源图（> 4096px）研发会先用图像工具压到 2048 再入库。

---

## 8. 与 `brand.json` 的关系

图形归本文；**文字与标识符归 `branding/brand.json`**。主色 hex 两边都要（PNG 里是实际色，`brand.json` 的 `visual.colors.primary` 是界面强调色），由 CI 保证不漂移。
