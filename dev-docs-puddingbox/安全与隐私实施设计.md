# 安全与隐私实施设计

写作参照：`dev-docs/endpoint-pr5-impl.md`

> 本文把个人信息保护、私密会话、统一模型列表和旧模式退出组织成一次可验证的跨层交付。各主题文档继续拥有产品和接口事实；本文只负责实施顺序、依赖、迁移、测试与回滚，不建立第二套需求。

## 为什么需要单独的实施设计

通常，一个功能的阶段性实现直接写在对应设计文档中即可，不需要“每个功能一份计划”，更不需要长期维护计划目录。本次改造是例外，因为一次交付同时跨越：

- 会话保护策略和 JSONL 持久化；
- 输入内容安全、个人信息脱敏和 WebSocket 回合路径；
- 中台签名目录、本地模型配置与产品 Profile；
- 统一模型选择器和“安全与隐私”面板；
- 旧 `chat_mode`、三组模式、偏好和接口的破坏性退出。

这些改动有严格先后关系，并且若只完成一部分，可能出现“界面声称私密但服务端仍可回退公共模型”或“界面先渲染原文再脱敏”等不可发布状态。若把完整实施顺序复制到每份主题文档，会形成多个计划所有者并逐渐漂移。因此单独保留一份协调性实施设计，主题文档只保留各自稳定语义和局部实现约束。

这份文档不是进度台账，不记录负责人、日期、百分比或逐日状态。实施期间只有在范围、依赖、迁移或验证方法发生变化时才更新；全部落地后改写为当前实现与迁移边界，删除已经没有长期价值的临时步骤，但保留安全不变量、兼容结论、验证入口和回滚限制。

## 范围

本次交付包括：

- 用版本化 `protection_policy` 替代会话 `chat_mode`；
- 首版九类低歧义个人信息规则和不可逆脱敏；
- 手工 Web 聊天所有用户文本入口的服务端权威保护；
- 中台厂商—模型目录、本地开发模型和统一选择器；
- 开发 Profile 从界面添加本地模型、设置模型级私密标记并完成真实流式聊天；
- 私密模型排序、自动切换、资格复核和禁止公共回退；
- Composer 中统一的“安全与隐私”面板；
- 产品 Profile 隐藏本地模型管理入口，只加载中台目录并只允许中台 gateway；开发 Profile 支持本地模型真实聊天和私密模型联调；
- 删除三组模式、旧隐私/智能/普通设置及其持久化和接口。

“手工 Web 聊天”包含桌面主界面和当前 Web 移动布局中由用户主动创建、发送、排队、steer 或编辑的文本。共享服务端入口必须全部受保护；若某个布局暂时没有私密选择器，至少使用服务端的新会话默认值，并正确展示自动脱敏与资格失败，不能静默退回旧模式。

## 非目标

- 附件正文、上传文件、OCR、工具参数、工具调用 JSON、工具返回值和 thinking block 的个人信息脱敏；
- IM、定时任务、后台自动消息和系统消息的个人信息保护选择；
- 根据内容自动判断商业秘密或自动开启私密会话；
- 改变工具权限、网络访问或现有确认机制；
- 给候选规则池的五十类规则一次性全部实现；
- 为旧客户端长期保留 `modeIds` 与新目录语义的双协议；
- 建立通用“开发计划”目录或要求普通小功能也单独写计划。

## 当前实现基线

实施前的代码事实如下，改动应复用这些所有者而不是建立平行路径：

每个功能开工前都必须对比上游基线与当前 fork 实现，先评估“直接基于上游代码扩展”和“沿当前 fork 代码修改”两条路径的实现、测试、上游合并与长期维护成本，再选择综合成本更低且不制造第二套所有者的落点。

- `agent.Session.ChatMode`、`sessionRecord.ChatMode`、`SetChatMode` 和 `chat_mode` 追加记录保存旧三组模式；分支会复制该字段。
- `internal/server/chatmode_handlers.go` 暴露 `PATCH /api/sessions/{id}/chat_mode`，会话列表和 `session_update` 继续返回旧字段。
- `SensitiveInputGate` 是现有内容安全输入门；普通发送、steer、queue 和编辑最终进入的代码路径并不完全相同，不能只在某个 HTTP handler 上增加脱敏。
- `runAgentTurnLoop` 是 Web 回合和连续 queue 的共同执行环，但入队前广播、Inbox 注入、编辑截断与 `/goal <text>` 仍需逐一核对原文是否提前被消费。
- `productclient.CatalogModel.ModeIDs`、`Catalog.Modes`、`productruntime.projectCatalog`、`CatalogOffers` 和 `/api/product/chat-modes` 拥有旧目录投影。
- `config.EndpointModel` 当前只有模型 ID 与视觉能力；本地端点 CRUD 尚不读写 `confidential`。
- `allowEnvironmentModelSource` 已是编译期 Profile 事实，但本地控制面响应尚未把它完整投影给前端。
- Composer 已有模型选择、`SensitiveToggle`、`PrivacyBar` 与 `PrivacyMark` 等零散组件，个人中心仍保存 `defaultChatMode`；这些旧组件和状态不能直接改名后继续承载新语义。

## 交付期间始终成立的安全不变量

- 保护开启时，原文不能进入广播、会话 JSONL、恢复队列、provider、日志或诊断事件。
- 内容安全先决定是否拒绝；只有允许继续的文本才执行个人信息脱敏。
- 前端 transform 改善即时体验，服务端发送入口才是权威安全边界。
- 标准占位符重复处理保持不变；前端和服务端使用同一规则引擎及规则版本。
- 首个成功接受的用户回合在保存脱敏文本的同一临界区锁定保护策略；拒绝或处理失败不锁定。
- `locked` 只能从 `false` 变为 `true`；清空、回滚、压缩、重试和编辑都不能重新解锁。
- 私密会话的每个新回合都重新验证当前模型资格和目录有效期；失败即停止，不能回退公共模型。
- 产品 Profile 不读取本地 endpoint 作为模型来源，不展示、不合并也不构建其 sender，只允许当前可信中台目录中的 gateway 模型；开发 Profile 才允许本地模型和本地私密标记。
- 私密会话只承诺模型路由，不扩大为工具数据保护承诺。
- 旧 `privacy` 模式不迁移成新的个人信息保护或私密保证。

任一阶段破坏这些不变量时，该阶段只能留在开发分支，不得部署到测试环境供产品验收。

## 阶段一：建立会话和配置事实

先建立后续各层都能依赖的持久化事实，不先做可见 UI。

### 会话保护策略

- 在 `internal/agent` 定义版本化 `ProtectionPolicy`，字段与 [模型选择与私密会话](模型选择与私密会话.md) 一致。
- 用一类完整策略记录持久化 `personal_info_protection`、`confidential_session`、`version` 和单调 `locked`，不要分别追加多个可交错的布尔记录。
- 模型绑定与策略变更必须在同一会话锁内校验和保存。开启私密会话需要自动切换模型时，对外只能观察到“新策略 + 新模型”或旧状态，不能观察到一半。
- 分支复制完整保护策略和有效模型绑定；`/clear`、压缩、历史截断、重试与编辑不改变策略。
- 首回合锁定与用户消息持久化形成一个服务端事务边界。文件系统不能提供数据库事务时，写入顺序和崩溃恢复必须保证不会留下“原文已保存但策略仍未锁定”的可继续状态。

### 旧会话解析

- 含用户历史且没有 `protection_policy` 的会话解析为两项保护均关闭且已锁定。
- 没有消息但已存在 composed system、内容更新时间、context token 或其他执行痕迹的旧会话同样保守处理，不能只用 `len(Messages)==0` 判定为全新。
- 只有没有消息且没有任何执行痕迹的空会话按新会话默认值读取：个人信息保护开启、私密会话关闭、未锁定。
- 不批量重写旧 JSONL，不根据旧 `chat_mode=privacy` 提升安全等级。会话下一次发生合法新写入时才写新策略记录。

### 本地模型与 Profile

- 给 `config.EndpointModel` 增加可选 `confidential`，缺失时为 `false`；同步 Load、Save、校验、创建 endpoint 的嵌套 model、单独添加/编辑 model、所有响应 DTO 和开发设置 UI。创建和编辑都能设置该字段，保存后无需重启即可读取。
- `GET /api/product/control-plane` 从编译期 Profile 投影 `allowEnvironmentModelSource`，前端只使用这一事实决定是否合并本地模型、显示“管理模型”和显示本地私密测试标记。
- 产品 Profile 即便 `config.yml` 中预置了本地 endpoint 或 `confidential: true` 也不得把它们加载进模型投影、选择器或回合路由；旧会话若仍绑定本地模型，开始新回合前必须拒绝，不能依赖前端隐藏或回退默认 gateway 来掩盖。

### 阶段验证

- 表驱动测试覆盖新会话、三类旧会话、分支、清空、压缩、回滚、编辑和并发首回合。
- 契约测试覆盖策略原子更新、锁定冲突、模型与策略同时更新失败时无部分写入。
- 配置 round-trip 测试覆盖缺失/false/true；生产构建测试证明本地 true 不获得产品私密资格。
- endpoint CRUD 契约测试覆盖创建时附带标记、后续新增/修改标记、响应回读、立即刷新和重启后读取；不能只测试 YAML struct。

## 阶段二：接入个人信息权威处理

### 规则引擎

- 新建 `internal/pii` 作为唯一规则所有者，不把个人信息模式塞入敏感词词库。
- 实现已确认的九个稳定规则 ID、固定占位符、重叠优先级和 `builtin-1` 规则版本。
- 引擎只返回脱敏文本、类别和数量；不得返回命中原值、可恢复映射或适合被误记日志的调试对象。
- 使用标准库校验身份证校验位、Luhn、VIN 和 IP；凭据及验证码采用明确前缀或上下文，不新增第三方依赖。
- 占位符识别必须幂等，前端 transform 后的文本再次经过服务端结果不变。

### 共同预处理入口

- 在服务端建立一个用户文本预处理函数，顺序固定为 slash command 分类、内容安全拒绝、按会话策略脱敏，再交给广播、排队、持久化和模型调用。
- 普通发送、运行中 steer、独立 queue、编辑后重跑以及携带正文的 `/goal <text>` 共享该函数或同一不可绕过的底层入口。
- 纯控制命令、重试已脱敏历史和系统生成文本不重复套用个人信息处理。
- 附件块暂不扫描；保护开启且存在附件时只返回能力边界提示，不把附件状态误记为处理成功。
- 引擎缺失或失败时返回 `privacy_transform_failed`，并保证没有任何原文副作用。

### 本地 transform 与事件

- `POST /api/product/privacy/transform` 调用同一引擎，设置 `Cache-Control: no-store`，路由访问日志不记录 body。
- 发送入口发现旧客户端原文或前端遗漏命中时，以最终脱敏文本继续，并只发送不含原值的 `privacy_applied` 瞬时事件。
- 日志和指标只记录规则版本、类别、数量、结果长度及错误码。

### 阶段验证

- 每条规则覆盖正例、反例、边界、Unicode/全角、混合命中、重复命中、冲突优先级和大文本性能。
- 用同一组 sentinel 原文断言 WebSocket 事件、JSONL、queue、fake provider、日志和错误响应均不存在原值。
- 竞态测试覆盖同时修改策略与发送首条消息、运行中 steer 和 queue、编辑旧用户消息。
- 契约测试校验九个规则 ID 与文档完全一致，并校验 transform 的 no-store 与事件形状。

## 阶段三：切换模型目录和私密路由

### 中台与客户端协同切换

- `productclient` 的目标目录一次切换到 `vendors`、`vendorId`、`confidential` 和 `confidentialPriority`，删除 `modes` 与 `modeIds` 的新消费语义。
- 先同步中台实现、签名夹具和 `productstub`，再切换客户端解码与验签后的语义校验；两侧使用同一 wire 夹具做契约测试。
- vendor 引用无效、ID 重复、优先级越界或私密模型不是合格 gateway 模型时拒绝整个新目录，不做部分修复。
- 新客户端不把旧 `modeIds` 猜成私密资格；联调环境必须在同一发布窗口完成目录切换。

### 本地产品投影

- 用 `GET /api/product/models` 替代旧 `/api/product/chat-modes` 投影，保持厂商为父级、模型为子级。
- 资格解析需要返回模型是否可选、是否私密、私密优先级、目录版本和当前有效性，不能继续压缩成 `CatalogOffers(model) bool`。
- 产品 Profile 只信任当前验签成功且未过期的中台目录；`absent`、`stale`、`unverifiable` 均不能开始新的私密回合。
- 开发 Profile 可把本地 `EndpointModel.confidential` 投影为测试资格，但仍与中台模型使用同一前端模型 DTO 和排序规则。
- 本地投影必须原样保留 `<endpoint>::<model>` 路由身份。选择后继续使用现有 `SetModelConfig`、`cachedSenderForEntry` 与 `senderForEntry`，不能因为进入统一列表而改走产品 gateway。

### 回合前资格复核

- 开启私密会话时，若当前模型不合格，在同一原子更新中选择私密优先级最高且稳定排序最前的模型。
- 普通会话手动选择私密模型仍是普通会话；空会话可以提示是否同时开启私密会话，但不得替用户静默升级。
- 私密会话锁定后禁止选择普通模型。目录过期、模型撤回或凭证失效时，新回合返回明确错误，不改变会话的私密状态。
- provider sender 的最终选择必须读取已经校验的会话绑定，不能由前端模型标签或排序结果提供安全保证。

### 阶段验证

- 目录契约测试覆盖有效、过期、缺失、验签失败、未知 vendor、重复 ID、错误 transport 和无私密模型。
- 路由测试覆盖自动切换、稳定排序、普通会话选择私密模型、锁定后拒绝普通模型和逐回合撤回资格。
- fake gateway 断言私密回合只使用绑定的私密模型；任何失败路径都不产生公共 provider 请求。
- 用本地 `httptest` 兼容 provider 断言新建 endpoint 的普通回合确实请求其 base URL、保留流式内容且不请求产品 gateway；真实密钥和外部模型只用于人工验收。

## 阶段四：完成统一 Web 交互

### 统一模型选择器

- 前端先把中台目录和允许出现的本地模型适配为统一的 vendor—model 视图；不改变上游“父级厂商、子级模型”的交互结构。
- 私密模型显示明确标识并稳定排在同级前面，排序不能成为唯一资格表达。
- 产品 Profile 不请求或合并本地 endpoint 模型，不渲染本地模型、管理入口或本地私密编辑，只消费中台目录；开发 Profile 保留现有端点管理，并给模型增加私密测试标记。
- 开发 Profile 的创建 endpoint、添加模型和编辑模型界面都能设置私密标记；保存后选择器立即出现该模型，不能要求刷新应用或手改 `config.yml`。
- 目录不可用时产品 Profile 显示明确失败并禁止开始新回合，不能出现空列表后暗中使用本地默认模型。

### 安全与隐私面板

- Composer 只保留一个“安全与隐私”入口，分别展示内容安全输入偏好、个人信息保护和私密会话，不增加总开关。
- `SensitiveToggle` 的能力并入该面板；输出防护和昵称校验显示“始终开启”。
- 新会话 pending state 在真正创建会话时与模型一起原子提交；不能先创建默认会话再 PATCH，以免首回合竞态。
- 首条消息后个人信息保护和私密会话显示服务端持久化的锁定状态，不根据前端消息数组推断。
- 私密会话显示持续提示条；自动切换、无可用私密模型和目录失效均使用明确、本地化文案。

### 自动脱敏体验

- 发送前先调用本机 transform；命中后清除原始草稿，只用 `masked` 创建 optimistic bubble 和发送请求。
- 提示展示类别与数量，不展示、缓存或恢复原值，也不提供“修改原文”。
- 服务端 `privacy_applied` 只补充提示，不用事件中的信息重建文本。
- 个人信息保护开启且有附件时，发送区域直接显示“附件内容暂不自动脱敏”，但不阻断发送。
- 主界面与移动布局共享 API 状态和错误处理；任何暂未提供完整选择器的布局也不得绕过服务端保护。

### 阶段验证

- 组件测试覆盖三项独立状态、锁定显示、附件提示、模型私密标识、自动切换提示和 Profile 差异。
- 浏览器级测试确认原文不先出现在 DOM、optimistic state、IndexedDB/localStorage 或 WebSocket 帧中。
- 多窗口测试确认一个窗口发送首条消息后，另一个窗口立即刷新为锁定状态并拒绝过期修改。

## 阶段五：删除旧语义并完成测试环境交付

新旧语义不长期共存。所有新路径验证通过后，在同一交付中删除：

- `agent.Session.ChatMode`、`sessionRecord.ChatMode`、`SetChatMode` 和 `chat_mode` 记录写入；
- `/api/sessions/{id}/chat_mode`、`/api/product/chat-modes` 及对应 DTO、事件字段和测试；
- `internal/chatmode`、前端 `pendingChatMode`、chat-mode store/helper 和 `defaultChatMode` 偏好；
- 个人中心隐私/智能/普通三组设置，以及旧 `ModeMenu`、`PrivacyBar`、`PrivacyMark` 等不再有独立用途的实现；
- 中台目录的 `modes`、模型 `modeIds`、旧签名夹具和 `productstub` 响应；
- 仅用于旧模式的本地化键、CSS、守卫例外和文档描述。

删除后使用仓库搜索作为负向守卫：产品代码和测试中不得再消费 `chat_mode`、`defaultChatMode`、`ModeIDs` 或旧三组模式 ID。若上游兼容解析必须短期保留某个 wire 字段，应只存在于明确隔离的旧数据读取边界，不能进入运行时状态或 UI。

## 验证门

阶段内先运行受影响的定向测试；准备进入测试环境前运行完整门禁：

```bash
go test -race ./internal/pii/... ./internal/agent/... ./internal/server/... ./internal/config/... ./internal/productclient/... ./internal/productruntime/...
cd web && npm test
cd web && npx svelte-check --threshold error
make gate
make test-production
```

`internal/pii` 尚未创建时，第一条命令按已存在的受影响包运行；创建后必须纳入。除自动测试外，测试环境至少人工验证：

- 新会话默认开启个人信息保护，首条消息后锁定；
- 九类规则混合命中时，屏幕、磁盘和 fake provider 只有占位符；
- 普通会话选择私密模型不会自动变为私密会话；
- 开启私密会话会切到最高优先级私密模型并持续显示状态；
- 目录过期或撤回模型后，新回合被拒绝且没有公共回退；
- 产品 Profile 看不到本地模型管理，预置本地模型也不进入选择器且不能开始新回合；开发 Profile 可添加、标记并测试本地私密模型；
- 开发 Profile 从 UI 添加一个真实 OpenAI/Anthropic 兼容 endpoint 后，无需重启即可选中并取得流式聊天回复；普通会话与私密会话都验证实际请求落到所选 endpoint。
- 附件提示准确说明尚未脱敏，工具行为没有被错误改变；
- 旧历史不会显示为已保护，旧三组模式在所有 UI 中消失。

文档改动本身继续运行 `git diff --check`、`make norms-check` 和 `make agents-check`。实现触及上游文件时，每个相邻改动还必须有说明原因的 `OCTO-FORK:` 标记，并通过 `make marker-check`。

## 发布、迁移与回滚

本次五个阶段可以分提交、分评审，但不能把不满足安全不变量的中间态作为测试环境可验收版本。测试环境切换需要同时具备新目录、新会话策略、服务端权威脱敏和新 UI。

开发 Profile 与测试/产品 Profile 是长期并存的运行形态，不是实施完成后删除开发能力的过渡方案。每次目录、模型选择或私密资格变更都要同时验证两条边界：开发环境可添加并真实调用本地模型；正式产品模式隐藏管理入口、忽略预置本地模型并只允许中台 gateway。

目录协议是中台与客户端协同切换：部署前先让目标中台环境能返回并签名新 shape，再部署只消费新 shape 的客户端；旧客户端的兼容窗口由中台发布安排解决，不在新客户端内增加长期双协议。

回滚具有额外限制：旧二进制不理解 `protection_policy`，若直接读取已经创建或更新过的私密会话，可能丢失禁止公共回退的保证。因此部署前必须备份会话和产品状态；需要回滚到旧版本时，必须同时恢复部署前数据快照，或隔离所有含新策略记录的会话并禁止继续发送。不得让旧二进制直接接管新版本触碰过的会话目录。

个人信息脱敏是不可逆的，回滚不会恢复原值，也不应尝试生成映射。中台目录回滚和客户端回滚必须同时执行；只回滚一侧会得到明确的目录不可用，而不能通过猜测字段继续工作。

## 完成定义与文档生命周期

本次功能完成需要同时满足：

- 所有安全不变量有自动测试证明，完整门禁与生产构建测试通过；
- 测试环境完成上述人工路径，未发现原文泄漏或公共模型回退；
- 旧模式的运行时代码、UI、偏好和新写入已删除；
- 中台、新客户端和 `productstub` 使用同一正式目录契约；
- 六份权威主题文档按最终代码改写为当前事实，不再把已完成能力写成“目标”；
- 本文删除临时性的先后描述，保留最终架构、迁移规则、验证入口和回滚边界。

普通功能后续仍把少量实施阶段写在各自主题文档里。只有同时涉及安全或权限、数据迁移、公开契约、跨服务协同、多个独立所有者，且错误顺序会产生不可发布中间态时，才新增类似实施设计；完成后也不把它继续维护成项目管理台账。
