# P0-07：安全、契约测试与真实 E2E 验收

| 项 | 内容 |
| --- | --- |
| 当前仓库主责 | 客户端 QA/安全组 |
| 外部协作 | 中台/网关提供 OpenAPI、sandbox、测试账号和脱敏请求检索证据；当前仓库只维护客户端测试与验收记录 |
| 可并行 | 从接口 旧本地实现 阶段就启动 |
| 依赖 | P0-02 至 P0-10 的 OpenAPI、contract sample 或 sandbox |
| 需求基线 | [P0 正式上线需求基线](../P0-正式上线需求基线.md) §7；该文的发布门是验收共同来源 |

## 目标

把 P0 从“多个服务都能返回 200”变成客户端可发布闭环。当前仓库的测试必须证明生产模型不绕过网关、工具不绕过本地确认、客户端不会制造重复扣费请求、隐私副本不泄漏、便携包能从失败恢复；服务端账本正确性由中台按同一 `clientRequestId` 提供验收证据。

## 测试层次

| 层次 | 内容 | 责任 |
| --- | --- | --- |
| 单元 | profile、policy evaluator、token 刷新单飞、credential store、词库解析、客户端账本状态映射、release manifest/schema migration | 当前仓库对应开发组 |
| 契约 | OpenAPI schema、错误码、SSE 事件顺序、Idempotency-Key、签名 envelope、删除/会话/状态接口、安全/维护终态 | 当前仓库 contract suite；中台在其 CI 验证服务实现 |
| 集成 | 合同测试实现 gateway/provider 下的 session、工具确认、余额/usage UI、凭证撤销、安全终止、更新回退 | 客户端组 |
| 安全/红队 | 无效策略、提示注入、配置绕过、token 复制、诊断泄漏、版本回退攻击、流中安全阻断 | 安全组 |
| 真机 E2E | Windows 目标矩阵、真实短信、真实模型、断网/拔盘/更新/迁移 | 客户端 QA 执行；中台提供 sandbox/测试账号/可检索证据 |

## 必测用例

1. 生产 profile 有本地 API key/endpoint 时仍只能走中台网关。
2. 无效 catalog/policy 签名、过期策略、低版本策略、错误 audience token 全部拒绝。
3. 同一个 `clientRequestId` 在重试、刷新、断网和取消中不产生第二笔供应商调用或账本。
4. 余额不足在供应商调用前拒绝；免费/套餐额度模型仅按目录显式规则放行。
5. 网页/附件里的提示不能让模型获得文件写、终端、联网、安装扩展或后台任务授权。
6. 隐私模式抓包、日志、诊断包、导出包均符合 P0-06 数据流。
7. token 撤销、手机不匹配、客服换号后的旧数据目录均不能继续访问生产服务。
8. 更新清单 hash/signature 错误、下载中断、新版本启动失败都保留/回退旧包和 `data/`。
9. `data/` 被复制到另一 Windows 用户/机器时，凭证不能解封；产品要求重新登录，且导出/诊断包没有 token 或供应商 key。
10. 状态迁移中断、缓存损坏、策略验签失败和连续崩溃均进入最小安全启动，不加载远端模型或高风险工具，且可恢复/导出诊断。
11. `safety_blocked`、429、账号冻结和维护状态分别有可理解 UI；流中安全终止不执行未批准工具、不盲重试，并按中台终态显示账务。
12. 正式包不含协议/隐私未批准文案；若环境要求显式同意，文档版本、拒绝/接受状态和确认记录接口均符合合同，客户端不能通过本地缓存制造接受记录。

## 发布门与证据

- 每项 E2E 记录客户端版本、Windows/架构、策略版本、catalog 版本、网关 request ID、账本 ID、截图/脱敏日志和结果；账本终态由中台查询结果或测试报告佐证。
- P0 通过标准是所有 P0 用例完成且无 P0/P1 安全缺陷；不是“单测绿”。
- 发现 contract breaking change 时先冻结发布，更新 OpenAPI、contract sample、SDK 和文档后再继续；禁止后端仅通过改 message 文案绕开失败。
