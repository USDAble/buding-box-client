# scripts/fork-marker-allowlist.txt
#
# Modified upstream files that carry NO "OCTO-FORK:" marker, and why they
# cannot. Hard rule 3 (dev-docs-usdable/开发规范.md §3.3) requires a marker on
# every change to an upstream file, because the marker list is the inventory an
# upstream merge is done from. Two kinds of file are structurally unable to
# hold one, and this file is the complete set of them:
#
#   binary      no comment syntax exists at all
#   generated   a hand-written marker is deleted by the next regeneration
#
# scripts/fork-marker-guard.mjs reads this file. It fails if an entry is not
# currently a modified upstream file, so a path cannot be exempted *before* it
# is edited. It also caps the entry count (ALLOWLIST_CEILING), because an
# allowlist that grows quietly is a bypass. A file that could hold a marker
# must hold one — if a text file is added here, that is the thing to review.
#
# One entry per line: <path>  <reason>
# Two or more spaces before the reason. Blank lines and "#" lines are ignored.
# Each entry must carry a written reason (开发规范 §3.7: no silent exceptions).

cmd/octo-desktop/build/darwin/icon.icns  Binary. The app icon asset; replaced wholesale for branding, and it has no comment syntax to hold a marker.
cmd/octo-desktop/build/darwin/tray-icon.png  Binary. The tray icon asset; replaced wholesale for branding.
cmd/octo-desktop/build/linux/icon.png  Binary. The Linux app icon asset; replaced wholesale for branding.
cmd/octo-desktop/build/windows/icon.ico  Binary. The Windows app icon asset; replaced wholesale for branding.
go.sum  Generated by `go mod tidy` for the two SVG-rasterisation modules in go.mod; any inserted line is not a valid checksum record and the next tidy removes it.
web/package-lock.json  Generated by npm; rewritten in full on the next install, which would delete a marker.
