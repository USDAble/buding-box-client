## 1. 已确认的架构决定

1. `internal/server` 是 2026-06-01 已存在的上游通用 server；本产品工作始于 2026-09-08。P0 **不迁移、不重构、不改路由归属**，避免扩大后续上游合并冲突。
2. 不能因此把 `internal/server` 视作完全不可改：当前生产绕过入口（开发 Web URL、环境变量 provider/model、`ensureLocalEndpoint`、channels/tools 等）就在其中。P0 只允许在 P0-00 登记过的文件增加小型、带 `OCTO-FORK` 注释的产品挂点和生产拒绝逻辑。
3. 不创建 `internal/backend`：这个名称会把“当前客户端 HTTP 调用方”和“中台服务端”混为一谈。
4. 不创建 `internal/productapp`：它与现有上游 `internal/app` 语义相近，并会诱导把 server handler 整体搬到新层。
5. P0 新增包只承担明确职责：

| 包 | 责任 | 不负责 |
|---|---|---|
| `internal/productclient` | 调用认证、bootstrap、模型目录、用量、词库、协议确认等中台 API；校验 DTO、错误码、超时与签名 envelope | 不保存业务权威状态，不计算/扣减积分，不提供 local demo adapter |
| `internal/productclient/gateway` | 将已通过策略允许的模型请求发送至中台模型网关，实现流式事件、取消、幂等请求 ID 与终态查询 | 不持有供应商 endpoint/key，不做本地模型直连 |
| `internal/productpolicy` | 校验已签名的目录/策略快照，并在发起 Agent、选择模型、发送消息前执行本地 PEP | 不向用户开放策略编辑，不以本地配置替代服务端授权 |
| `internal/credentialstore` | 通过 OS Keychain/凭证库保存 refresh token，提供轮换与清除 | 不把 token 写进 `product-state.json`，不让 UI 读取 token |

依赖方向保持为：

```text
cmd/octo-desktop
  -> internal/server                 (上游保留，仅产品挂点)
      -> internal/productclient      (认证/控制面/用量)
      -> internal/productclient/gateway
      -> internal/productpolicy
      -> internal/credentialstore
```

## 2. 现状 mock 与正式替换点

下表是 P0 必须收口的真实代码证据。这里的“替换”不代表将 demo 代码抽象后长期并存；生产 Profile 必须拒绝或完全不装配这些来源。

| # | 能力域 | 当前证据 | 正式客户端做法 | 中台交付 |
|---|---|---|---|---|
| M1 | 短信验证码 | `internal/server/product_login.go` 的 `fixedCode`、`loginCodes` | `productclient` 调发送/校验接口；生产不接受固定验证码或进程内验证码 | 认证 API、频控/错误码、sandbox |
| M2 | 激活码 | `activationCode` 固定比较 | 仅首次激活时提交给认证服务；激活状态由 bootstrap 返回 | 激活校验、幂等与错误码 |
| M3 | 登录会话 | `newAccountToken()` 生成 `local-` token | 只接受中台 access/refresh 会话；刷新单飞、401/撤销即清凭证 | 登录/刷新/登出 API |
| M4 | 登录态落盘 | `internal/productstate/state.go` 明文 `Account.Token` | 迁移 refresh token 至 `credentialstore`；状态文件只留非敏感投影 | token 生命周期、吊销语义 |
| M5 | 积分假扣减 | `internal/server/handlers.go` 的 `consumeCredit()` | 删除“每条消息扣一分”及调用/测试；客户端只读用量和请求终态 | 网关预留、结算、冲正、账本 |
| M6 | 套餐 | 首次激活写死 `trial` | 只消费 bootstrap 的套餐、状态和到期时间；UI 不自行判定额度 | 套餐/权益快照 |
| M7 | 模型目录 | `chatmode.Builtin()`、`ensureLocalEndpoint` 的 `buding-*` | 生产只使用签名目录中的 `modelId`/能力/策略版本 | 模型目录、签名、版本/失效语义 |
| M8 | 模型通道 | `internal/provider/local` 的确定性回复 | 标准产品只能经 `gateway` 访问中台；local provider 仅开发/演示 Profile | 模型网关 SSE 与终态查询 |
| M9 | 通用敏感词 | 仅内置词和用户本地词 | 本地内置 + 最近有效服务器缓存 + 用户词三层并集；服务端词不可删除 | 词库增量、ETag、签名 |
| M10 | 协议/隐私 | `web/src/lib/brand.config.json` 占位文案 | 启动时拉取必需版本；未确认或版本变更不得进入主功能 | 正式文案、版本、确认记录接口 |

## 3. 客户端契约和错误边界

`productclient` 对外暴露的是按领域划分的窄 client，不暴露一个泛化的“后端接口”：

| Client | 最小方法 | 客户端责任 |
|---|---|---|
| `AuthClient` | `SendCode`、`Login`、`Refresh`、`Logout` | 手机号规范化；将中台错误稳定映射为既有 machine code；不得在日志写入验证码/token |
| `ControlPlaneClient` | `Bootstrap`、`Models`、`SensitiveDictionary`、`LegalDocuments`、`AcceptLegal` | 校验响应 schema、时钟窗口、签名与版本；原子缓存最后一份有效快照 |
| `UsageClient` | `Usage`、`RequestStatus`、`Ledger` | 只读展示和断线后对账；没有 `Consume`/`Debit`/`amount` API |
| `GatewayClient` | `ChatCompletions`、`Cancel`、`RequestStatus` | 一个用户发送动作生成一个稳定 `clientRequestId`；处理 SSE、断线、取消和终态补查 |

统一错误结构至少包含 `code`、`messageKey`、`retryAfterSec`、`traceId`。前端只依据稳定的 machine code 映射文案，不能解析服务端自然语言消息。关键语义：

- `not_activated`、`plan_expired`、`quota_exhausted`、`model_not_entitled` 是不同状态；前端对应不同阻断动作，不能统称为“授权到期”。
- `usage_pending` 表示网络中断或流被截断后尚未确定结算；客户端查询 `RequestStatus`，不能自行回补或扣减。
- `catalog_signature_invalid`、`policy_expired`、`bootstrap_stale` 必须 fail-closed：保留当前会话展示，但阻断新 Agent 和新模型请求。

完整字段、签名、幂等、SSE 事件、鉴权、数据留存要求以[中台交付包](中台交付包.md)为准；中台变更必须先更新该文档与 OpenAPI，再由客户端更新 fixture 和 contract test。

## 4. 对上游 server 的最小接入方式

P0 只在现有 server/desktop 的 composition 和已有产品 handler 中接入新包，禁止：移动 server 路由、把通用 handler 搬至新目录、改变上游公开类型签名、将中台 HTTP 细节散落到 handler。

允许的改动范围和验收：

| 场景 | 最小改动 | 验收 |
|---|---|---|
| 启动 | 在 desktop composition 显式注入 production/developer Profile 和产品依赖 | production 不能被 `OCTO_DESKTOP_DEV_URL`、provider/model 环境变量或本地 endpoint 改写 |
| 登录/账户 | 已有产品 handler 调 `AuthClient`，将响应映射为既有 machine code | 不改变前端错误语义；token 不再落盘 |
| bootstrap/目录/词库/协议 | 已有受保护入口通过 control-plane client 获取和校验快照 | 无有效签名或必需协议未确认时 fail-closed |
| 消息/Agent | 进入现有 send 路径前做 PEP，获准后由 gateway sender 发送 | 生产不直连 provider；取消、断线、重试不重复结算 |
| 用量 | 删除 `consumeCredit()` 及固定积分演示逻辑 | 不存在客户端扣费请求或本地余额权威 |

所有 server 内改动必须带 `OCTO-FORK` 注释，注明产品原因和关联 P0 文档；修改文件/代码块登记在 P0-00。若需求无法在上述范围内完成，应先在架构评审中确认，不能以“方便接入”为由扩大重构。

## 5. 开发顺序、并行和中台协作

### B0：前置闸门（必须先完成）

1. 确认 `buding` 已接收仓库负责人批准的 `main`；当前客户端开发不配置或评估上游 remote。
2. 写出 production Profile 的拒绝矩阵：开发 Web URL、环境变量 provider/model/key、`ensureLocalEndpoint`、`OCTO_DATA_ROOT`、channels/tools/MCP/task 启动面和运行时 profile 切换都逐项判定。
3. 用 black-box 测试证明 production 启动不能落入本地 provider 或假模型，也不能被环境变量/配置/缓存/WebView 输入切为 developer；developer Profile 仍可显式使用演示能力。
4. 中台提供与[中台交付包](中台交付包.md)一致的版本化 OpenAPI、签名公钥、sandbox fixture 和错误码基线。

### B1：可并行的客户端基础

| 工作包 | 所有者 | 产物 | 依赖 |
|---|---|---|---|
| 领域 DTO/错误/HTTP 基础 | 客户端 A | `productclient`，schema/contract tests | B0 的 OpenAPI fixture |
| 签名目录和 PEP | 客户端 B | `productpolicy`，过期/篡改/撤销测试 | B0 的签名规则与 policy fixture |
| 凭证迁移 | 客户端 C | `credentialstore`，旧 token 清理/轮换/撤销测试 | B0 的 refresh 语义 |
| gateway sender | 客户端 D | `productclient/gateway`，SSE/取消/重试/补查测试 | B0 的 SSE sandbox |

### B2：受控接入与验收

1. 由一名集成人员在登记的 server 挂点装配 B1 成果；业务开发人员不并行修改同一 server handler。
2. 删除 M5 固定扣分 mock 及全部调用点；把模型选择、授权、发送和终态对账串成单个 `clientRequestId` 闭环。
3. 接入登录、bootstrap、目录、词库、协议确认和更新清单；未具备真实中台 sandbox 的功能维持“不可进入生产”的发布门禁，不能以假数据放行。
4. 完成异常闭环：登录刷新失败、套餐到期、积分用尽、流中断、取消、重复请求、目录签名失败、词库拉取失败、更新校验失败、离线重启。

## 6. Definition of Done

- P0-00 的上游基线和生产拒绝矩阵均有可复现记录。
- 标准产品请求没有任何本地 provider、固定验证码、假 token、假模型、客户端扣费或供应商密钥路径。
- 中台接口通过 schema/contract test；关键错误码、SSE 终态和幂等行为通过 sandbox 验证。
- `internal/server` 的改动能逐项在挂点清单中找到，且无路由迁移或大规模重构。
- 用量、套餐/激活、模型授权、策略校验、协议确认、词库、凭证和更新都形成成功与失败的闭环。
- 文档、OpenAPI、fixture、自动化测试的版本号一致；接口破坏性变更没有静默兼容。
