### 4.2 32 位 CDP 原子对齐

已将 `internal/browser/cdp.go` 中的 `nextID int64` 放到结构体首字段，并新增：

```text
E:\zxy\work-code\buding-box-client\internal\browser\cdp_alignment_test.go
```

回归测试：

```powershell
go test ./internal/browser -run TestCDPClientNextIDIs64BitAligned -count=1
```

该修复针对 `windows/386` 的真实运行时约束；不能通过修改 GOARCH 或跳过测试替代。

### 4.3 Desktop 嵌套模块

在默认 `windows/386` 下，直接执行 Desktop 测试会运行 Wails WebView2 的 386 回调初始化，触发上游限制：

```text
panic: compileCallback: argument size is larger than uintptr
```

这是 Wails/WebView2 依赖在 32 位宿主测试进程中的架构限制，不是品牌改造代码或主模块 Go 代码错误。当前安装的 386 Go 工具链支持交叉编译 amd64，因此使用目标架构验证 Desktop：

```powershell
$env:GOARCH='amd64'; go build ./...; Remove-Item Env:GOARCH
$env:GOARCH='amd64'; go test ./... -count=1 -timeout=2m; Remove-Item Env:GOARCH
```

两条命令均返回 0。实际发布 Desktop 仍应在对应的 64 位 Windows/macOS/Linux 构建机上完成。

### 4.4 Relay 嵌套模块

在 `cmd/octo-relay` 执行以下编译验证并返回 0：

```powershell
go test ./... -run '^$' -count=1
go build ./...
```

### 4.5 Evals 模块边界

`evals` 是故意包含不完整 hidden fixture 的独立评测模块。直接执行 `go test ./...` 会因 hidden 测试缺少 fixture 实现而失败，例如 `undefined: Config`；这不是产品模块构建失败，也不应通过删除 hidden 测试来伪造通过。评测任务应由其专用评测流程复制到 scratch repo 后运行。
