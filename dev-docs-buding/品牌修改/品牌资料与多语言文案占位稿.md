> **重要说明**：本文件是为方案评审和后续开发准备的 Mock 资料，不代表真实公司、团队、域名、邮箱、仓库或法律归属。发布前必须由项目负责人逐项替换和确认。所有 `.example` 域名均为保留示例域名，不应直接用于生产。

## 1. 使用方式

后续如果只修改品牌资料、文案、链接或联系方式，优先编辑本文件；代码实施时再把本文件中的最终值同步到 Web、桌面端、移动端、CLI、官网和发布配置。

建议编辑顺序：

1. 先改第 2 节“最终品牌资料”。
2. 再改第 3 节“多语言名称和文案”。
3. 再改第 4 节“团队、链接和法律信息”。
4. 最后确认第 5 节“未来身份迁移候选值”是否采用。
5. 执行阶段按照《品牌重塑实施计划》把确认后的资料落到代码和资源中。

### 3.3 国际化规则

- 产品品牌在代码中使用 locale key，不在组件中硬编码中文或英文。
- `Pudding Box` 是英文品牌写法，单词之间保留空格；域名、包名、环境变量等机器标识使用小写 `puddingbox` 或 `pudding-box`。
- 品牌名通常不做复数变化，不翻译成 `Pudding Case`、`Pudding Container` 等其他含义。
- 中文产品名使用“布丁盒子”，不要在同一界面混用“布丁箱”“布丁盒”或“Pudding Box 中文版”。
- 英文 UI 使用 sentence case；按钮、菜单、通知和错误提示由各自语言自然表达。
- 日期、时间、数字、货币、时区和单位使用 locale 格式化，不拼接固定中文或英文格式。
- 文案长度要预留英文、德文等语言可能比中文更长的空间。
- 暂不支持的语言回退到 `en-US`，中文用户可回退到 `zh-CN`；回退策略不要依赖品牌名字符串。
- 若未来支持 RTL 语言，布局应使用逻辑方向属性，不能把左右方向写死在品牌组件中。

## 5. Mock 视觉方向

### 5.1 Logo 概念

建议方向：一个圆角盒子中包含柔和的布丁焦糖顶部形状，强调“收纳复杂工作、输出简单体验”，避免继续使用旧章鱼轮廓或近似旧 Logo 的构图。

这是设计方向，不是最终 Logo 文件；最终应由设计稿生成统一的 SVG、PNG、ICO、ICNS、Android 和 iOS 资源。
