## 1. 背景与目标

上游桌面端可以当 GUI 用，但按「本机安装的 Octo」来做：窗口、托盘、关于页都叫 Octo；配置和会话默认写在主机 `~/.octo`；官方分发是安装包。

本期要做成：**绿色便携、先登录再进系统、能看见账号、内容过敏感词、按模式选模型、对外不再是 Octo。**

### 1.1 本期目标

1. 未登录不能进入主界面。
2. 登录后左下角展示身份，可打开个人中心。
3. **模型可见输出必过合规敏感词**（用户不可关）。用户输入默认过合规敏感词，允许关闭（关前确认）；关闭后输入按原文发送，输出仍过滤。
4. 模型选择器按「隐私 / 智能 / 默认」分组。本期「智能」与「默认」的发送策略相同（都只过合规敏感词），差别在名单与对用户的含义，见 §5.6。
5. 便携形态下，产品数据写在可执行文件**同级** `data/` 目录（已定，不再讨论其它位置）。
6. 用户可见的 Octo 品牌替换为布丁盒子 / Buding Box（随界面语言切换）；其余品牌物料本期用 mock，见 §5.2。
7. 主界面默认看不到 IM / MCP / Light Apps 入口（代码保留，见 §5.4.3）。

### 1.2 两套门

| 名称 | 作用 | 本期 |
|---|---|---|
| 机器门 | 上游已有 access key，防止远程连接本机 Agent | 保留，不改、不替代 |
| 产品门 | 决定当前用户能否使用这份程序目录 | 新增，见 §5.3 |

产品门拦的是：**桌面窗口里的界面，以及该窗口发起的聊天相关请求**。不拦 CLI；本机其它进程仍可能访问 loopback API（§9）。

## 2. 已确认约束（评审时不要再翻案）

下列五项已定。英文正式拼写、正式 Logo、真实中台、到期是否拦截等见 §10，不要和本节混为一谈。

1. **便携数据根**：可执行文件同级文件夹下的 `data/`。只此一种。各模块只认「当前数据根」，禁止再把主机 `~/.octo`、桌面、文档、`AppData` 产品目录当作数据根或降级位置。PID / 崩溃日志 / 词库 / 登录态一律在数据根（§5.7）。
2. **本期做界面与交互**：短信、积分、套餐、激活码用假数据；按钮和页面要齐，不接真实中台。
3. **只拦桌面 GUI**：不拦 CLI。
4. **激活码本期只做字符串校验**，并在数据根写入「已激活 + 绑定手机号」。不读 U 盘硬件序列号。
5. **产品名已定，且必须多语言：** 界面为中文时显示「布丁盒子」，为英文时显示「Buding Box」。界面与原生窗口文案走文案表，禁止写死某一种语言。**例外：** Windows 文件属性、exe 文件名、便携文件夹名不能随 UI 热切，按 §5.2.4 固定 mock。Logo、图标、版权、协议等品牌资产本期用本文给出的 mock，正式物料到位后只换资源、不改结构。

## 3. 术语

| 术语 | 定义 |
|---|---|
| 程序目录 | 可执行文件所在的那一层文件夹（U 盘上的一份，或拷到本机的一份） |
| 进程当前目录（cwd） | 操作系统里该进程的当前目录。便携启动后必须是**程序目录**，禁止切到主机用户家目录 |
| 数据根 | 程序目录下的 `data/` |
| 会话工作区 | Agent **默认**读写文件的目录，固定为 `data/workspace/`（不存在则创建）。不得默认切到主机用户家目录。用户在对话里**自己指定**的主机路径除外（§5.7） |
| 首次激活 | 当前数据根尚未绑定账号，须填写激活码 |
| 二次登录 | 已激活后，因退出登录再次进入（本期 token 无过期，见 §5.3.5） |
| 隐私模式 | 名单以本地 / 端侧模型为主；发送前做 PII 脱敏；聊天区持续提示 |
| 智能模式 | 名单以云端 / 更高能力模型为主；发送策略与默认模式相同，只过合规敏感词 |
| 默认模式 | 完整自选名单（可含本地与云端）；只过合规敏感词。名称「默认」指这个分组，不是「系统缺省值」三个字的泛称 |
| 出厂默认模式 | 个人中心里「新会话默认模式」的出厂值，值为分组 **「默认」** |
| 合规敏感词 | §5.5，拦截或打码违禁内容 |
| PII 脱敏 | §5.6.2，仅隐私模式，发给模型前处理手机号（本期范围） |

「布丁盒子」是产品名。指用户正在使用的那份目录时，说「程序目录」或「U 盘」，不要把「盒子」当成目录的代称。不要用「工作目录」一词，以免和 cwd、会话工作区混用。

## 4. 用户与主路径

**使用者：** 持有一份便携程序目录（通常在 U 盘）的个人用户，在 Windows 电脑上双击使用。

**主路径：**

1. 插入 U 盘（或打开已拷贝的文件夹），双击 `BudingBox.exe`。
2. 无有效登录态 → **拦截页即登录表单**（首次含激活码，其后不含），无单独的空门面再点一次「登录」。
3. 进入主界面，左下角为登录态。便携包预置假模型名单（§5.6.3），**任何情况都不出现**上游「首次配 API Key」向导；名单空则提示「该模式下暂无可用模型」。
4. 按模式选择模型，对话；输入默认过敏感词、输出必过敏感词；隐私模式有持续提示。
5. 关窗口：进托盘，进程还在。托盘「退出」：落盘后结束进程。个人中心「退出登录」：回到拦截页，**进程不退出**。数据始终在 `data/`。

## 5. 功能需求

### 5.1 启动：双击打开

#### 5.1.1 产品结论

- 双击程序目录内的桌面端 exe，直接出现布丁盒子窗口（标题随语言）。不要求安装向导、管理员权限、先开命令行或浏览器。
- 主交付是**便携目录**（文件夹内含可执行文件 + 必要依赖 + `data/`），不是安装包，**不要在主机桌面或开始菜单创建快捷方式**。
- 数据只进 `data/`，见 §5.7。上游安装包 / 主机 `~/.octo` 行为见附录 A，本期必须改掉。

#### 5.1.2 双击后的启动规则

| 序号 | 规则 |
|---|---|
| 1 | 双击程序目录内的桌面端 exe，出现布丁盒子窗口（标题随语言）。不要求安装向导，不要求管理员权限。 |
| 2 | 未登录：只显示拦截页（§5.3.1），不渲染会话列表、输入框、设置、个人中心。 |
| 3 | 已有有效登录态：进入主界面，不重复登录。便携交付须**预置假模型名单**（§5.6.3）。**禁止出现**上游「首次配 API Key」配置向导（含名单被删空、开发调试）。名单空：选择器内展示「该模式下暂无可用模型」，禁止空白无说明。 |
| 4 | 数据根不可写、空间不足、路径不可用：启动即全屏/对话框提示原因，**禁止进入主界面或拦截页业务**，**禁止改写到主机目录凑合运行**。用户只能看懂原因后点「退出」**结束进程**（不是「退出登录」；无托盘凑合挂起）。 |
| 5 | **整机同一时间只跑一份布丁盒子**（端口固定 `8088`）。第二次双击同一份或另一份程序目录：激活已有窗口。若第二次点的不是正在运行的那份目录，须提示「布丁盒子已在运行，请先退出再打开另一份」，不要在无提示的情况下让用户以为打开了第二份。单实例标识用 `app.budingbox.desktop`（§5.2.4），避免第二次双击把用户带到本机已装的 **Octo** 窗口。 |
| 6 | 端口被占且当前并没有一份布丁盒子在跑（含被 Octo、`octo serve` 或其它程序占用）：明确提示「端口 8088 已被占用。若本机正在运行 Octo 或其它程序，请先退出后再打开布丁盒子。」禁止再起一份、禁止改端口、禁止改写到其它数据根。本期**不与本机 Octo 双开**（§9）。 |
| 7 | **主机未安装 WebView2：** 须给出本机可理解的错误说明（缺组件 / 打开下载页），不能只是闪退。 |
| 8 | **关窗口默认进托盘，并不退出。** 便携场景下用户容易以为已退出而拔 U 盘。必须在托盘菜单和退出确认中写清：「退出」才会结束进程；帮助中写「请先退出再拔出 U 盘」（**含未登录、拦截页在前台时**）。本期托盘文案随品牌替换。 |
| 9 | **开机自启动默认关闭，便携形态下隐藏该开关**（该项会写主机注册表，与便携原则冲突）。完整设置里若仍有该项，便携包也不渲染。 |
| 10 | 运行中程序目录消失（拔盘、删目录、盘符没了）：立即冻结界面，提示重新接入，禁止改写主机。**同一路径（含同一盘符）恢复则可继续；换了盘符或无法恢复：不能自动接着跑，只能退出后从新路径再双击**（冷启动换盘符见 §5.7）。 |
| 11 | 三种离开不要混，见下表。 |
| 12 | 拦截页时关窗口：同样进托盘；托盘「显示」仍回到拦截页。未登录时同样适用「先退出再拔盘」。 |
| 13 | **便携形态关闭自动检查更新与托盘更新入口**（避免把程序装到主机、把绿色版变成安装版）。个人中心「检查更新」为占位「即将支持」。 |

| 动作 | 进程 | 登录态 | 界面 |
|---|---|---|---|
| 点窗口关闭 | 仍在（托盘） | 不变 | 窗口隐藏 |
| 托盘「退出」 | 先落盘再结束 | 若原先已登录则保留，下次双击直达主界面 | 无 |
| 个人中心「退出登录」 | **仍在** | 清除 | 回到拦截页 |

未签名 exe 在部分 Windows 上会被 SmartScreen 拦截，属环境限制；帮助中可写一句「选择仍要运行」。本期不做代码签名。

### 5.2 品牌

产品名本期定为 **布丁盒子**。所有**可随界面语言切换**的用户可见名称必须走多语言文案，切换后立即变，禁止在界面或原生窗口里写死某一种语言。

不能随语言热切的系统字段（exe 文件名、文件夹名、文件属性）按 §5.2.4 固定 mock，视为例外，不是「写死界面语言」。

正式 Logo、图标、协议页未到之前，**按本节 mock 先做齐**，验收按 mock 过，不挡开发。正式物料到位后只替换资源文件和文案表里的值，不改布局和键名。

替换原则：用户能看见、能在任务栏认出来的 Octo / 章鱼标都要换。Go 模块路径、内部包名、CLI 命令名 `octo` 本期不改。数据根目录名用 `data/`，用户可见处不要再出现 `.octo` 当作产品目录名。

#### 5.2.1 名称（多语言，已定）

名称是文案键，不是写死的字符串。现有界面语言为中 / 英（简体中文 / English），名称至少覆盖这两种；以后加语言只加文案行。繁体中文系统本期按英文界面（§10 T10）。

| 用途 | 中文（zh） | 英文（en） | 用在 |
|---|---|---|---|
| 全称 | 布丁盒子 | Buding Box | 窗口标题、关于、拦截页主标题、欢迎页、版权行 |
| 简称 | 布丁盒子 | Buding | 任务栏过长、托盘提示、通知标题（英文用短名以免裁切） |
| 口号（mock） | 带着走的智能工作台 | A portable AI workbench | 拦截页副文案、关于页 |

切换语言后，窗口标题、托盘「显示 / 退出」、关于页、输入框占位、通知里的产品名必须一起变。原生对话框（Wails）也要跟当前语言，不能中文界面弹英文「Quit Octo」。

文案示例（键名开发自定，语义必须有）：

| 中文 | 英文 |
|---|---|
| 欢迎使用布丁盒子 | Welcome to Buding Box |
| 发给布丁盒子… | Message Buding Box… |
| 显示布丁盒子 | Show Buding Box |
| 退出布丁盒子 | Quit Buding Box |
| 布丁盒子正在等待你的输入 | Buding Box is waiting for your input |
| … - 布丁盒子导出 | … - Buding Box Export |

「登录这台电脑时自动启动…」类文案：便携形态**不展示**该开关（§5.1.2 第 9 条）。若完整设置仍保留键名，翻译要齐，但本期便携包不得画出该开关。

用户可见的 Octo / octo 一律按上表替换。不要只换 Logo 不换句子。

#### 5.2.3 应当替换

- 会话导出、关于里的宣传短句（用 mock 口号）
- 帮助与反馈、检查更新说明（检查更新为占位，文案仍用产品名）

- 系统通知应用名等仍可能显示出来的英文名（用 Buding Box）

### 5.3 登录

启动后读取数据根中的登录态。有效则进主界面；无效则全屏拦截。

未登录不得：发消息、读历史、打开个人中心、调用聊天相关接口（**界面层与该窗口发起的请求都要挡**）。

未登录**允许**：切换界面语言（写入数据根）、打开用户协议 / 隐私政策 mock 页。除此之外不得改配置。

#### 5.3.1 拦截页

拦截页就是登录 / 激活表单，不要先做一页只有「登录」按钮再跳转。

| 元素 | 说明 |
|---|---|
| Logo + 产品名 | mock 方形 Logo + 全称（中文「布丁盒子」/ 英文 Buding Box），见 §5.2.4 |
| 口号 | mock 口号，随语言 |
| 表单 | 无绑定记录 → §5.3.3；已有绑定 → §5.3.4 |
| 主按钮 | 首次「激活并登录」；二次「登录」 |
| 页脚 | 「用户协议」「隐私政策」（随语言），打开 §5.2.4 的 mock 协议页 |

无其它入口（不能「跳过」「游客」）。

**未登录时的语言：** 数据根里已有语言设置则用它；否则跟系统 UI 语言（**简体中文**系统用中文，其它用英文，含繁体中文系统）。拦截页右上角提供中 / 英切换，写入数据根，立即刷新本页文案与 Logo 字（布 / B）。不能等到登录后才能切语言。

登录页上的校验文案随当前语言（§5.3.2～§5.3.4 中的中文句；英文须有对应句，见实现时的文案表）。

#### 5.3.2 手机号规范化（首次、二次共用）

提交与「发送验证码」前先规范化，再校验：

1. 去掉空格、短横线。
2. 若去掉后以 `+86` 或 `86` 开头，且其余部分为 11 位数字，则去掉此前缀。
3. 规范化结果须为大陆手机：`1` 开头共 11 位数字。否则：「请输入正确的手机号」。

二次登录与绑定号比较时，用**规范化后**的 11 位比较。

#### 5.3.3 首次激活（数据根内无绑定记录）

四个字段均必填。点主按钮时：**格式类错误全部同时标在对应字段旁**（不因前一个失败而隐藏后面的）。格式都过之后，再按「验证码是否已发送且正确 → 激活码是否正确」检查；任一步失败停留本页，不进入主界面。

| 字段 | 规则 |
|---|---|
| 手机号 | 按 §5.3.2。失焦或提交时校验 |
| 验证码 | 6 位数字。未发送先点提交：「请先获取验证码」。错误或过期：「验证码不正确或已过期」。发送按钮：规范化后手机号合法才可点；点击后 60 秒倒计时，倒计时内不可重发。**本期假验证码固定 `123456`**（任意合法手机号，**必须先点发送**再填此码才过）。点击发送后该码 **10 分钟内**有效；再点发送则刷新这 10 分钟。界面不要把正确答案印在输入框里。本期为演示包：帮助占位页写「测试验证码 123456」（§9） |
| 昵称 | 进入页时按**当前界面语言**随机生成：中文「用户」+ 4 位数字；英文 `User` + 4 位数字。可改。长度 2–16 字；允许中文、字母、数字、下划线。非法：「昵称格式不正确」。命中合规敏感词：「昵称包含敏感内容」（不把敏感词写成昵称，也不改成 `***` 保存） |
| 激活码 | **本期假激活码固定 `BUDING-DEMO-0001`**（大小写不敏感；首尾空格忽略；中间空格不忽略）。其它任何字符串：「激活码不正确」。空提交按不正确处理。标签：「激活码」。说明：「请输入随程序目录提供的激活码」 |

成功后在数据根记录：绑定手机号（规范化后的 11 位）、激活状态、激活时间、授权到期日（激活时间 + 365 天）、昵称、登录态、积分初始值。同一份程序目录换电脑仍视为已激活。

本期不提供换绑、解除绑定。帮助页可留「如需更换手机号，请联系客服」（占位）。

#### 5.3.4 二次登录（已有绑定记录）

| 字段 | 规则 |
|---|---|
| 手机号 | 规范化后必须与绑定号一致。不一致：「此程序目录已绑定 {脱敏手机号}」 |
| 验证码 | 同首次（须先点发送，码为 `123456`） |
| 昵称 | 预填上次昵称，可改（规则同首次，含敏感词）。**不出现激活码** |

脱敏规则：`138****1234`（前 3 后 4）。

#### 5.3.5 登录态

- 写入数据根：token（假）、昵称、脱敏手机号、激活信息、最近登录时间。
- **本期 token 无过期。** 仅个人中心「退出登录」清除登录态。关窗口、托盘退出、杀进程、换电脑，只要同一份 `data/` 还在，下次双击直达主界面。
- 持有该程序目录且未退出登录，即视为已登录。丢失 U 盘视同账号泄露，帮助中写一句即可。
- 退出登录：确认框标题「退出登录」，正文「退出后需重新验证手机号才能进入。会话和配置不会删除。」按钮：「取消」「退出登录」（不要写成「退出」，以免和托盘结束进程混淆）。确认后清登录态、回拦截页，**进程保持，托盘仍在**。积分、会话、激活绑定均保留。

不做：密码、第三方登录、多账号、用产品登录替换 access key。

#### 5.4.4 积分（假数据规则）

### 5.5 敏感词

两套能力，禁止混用一份词库逻辑：

| | 用户输入（§5.5.1） | 模型输出（§5.5.2） |
|---|---|---|
| 目的 | 不把违禁原文发给模型 | 界面与历史不出现违禁原文 |
| 用户可否关闭 | 可以，关前确认 | 不可关闭 |
| 作用范围 | 输入框内用户将要发送的可见文本 | 桌面聊天里用户能看到的模型正文；若展示思考过程，则一并过滤。界面若展示工具结果文本，同样过滤；不展示的原始 JSON / 附件二进制 / 图片 OCR 本期不做 |

本期范围：

- 做：输入框文本、模型可见文本与可见思考、界面可见的工具结果文本；登录昵称 / 个人中心改昵称（命中则拒绝保存，见 §5.3.3）。昵称检测始终开启，不受聊天输入框「敏感词检测」开关影响。
- 不做：附件二进制、图片 OCR、界面不展示的工具原始 JSON。文件名若在输入框里出现，则按文本检测。
- 词库：数据根内本地 UTF-8 文本文件，一行一词，`#` 开头为注释。替换该文件后**下一次检测**生效，无需发版。文件缺失或无法读取：用内置示例词，可提示一次「词库读取失败，已用内置词」（不反复弹）。用户直接改词库文件即可更新，无单独管理界面。
- 内置 / 示例词至少包含：`赌博`、`毒品`、`发票`、`gambling`、`drugs`、`invoice`、`fapiao`（大小写不敏感）。
- 匹配（已定）：
  1. 将待检文本与词条都做规范化：Unicode 大小写折叠（英文不区分大小写）；去掉空白（含普通空格、全角空格、制表符、换行）；去掉符号。符号表：ASCII `!"#$%&'()*+,-./:;<=>?@[\]^_`{|}~` 以及对应全角符号、中文顿号/引号/书名号/破折号/省略号 `、。「」『』《》—…·`。
  2. 在规范化后的文本里做**子串**匹配（「增值税发票管理」会命中「发票」）。
  3. 命中后在**原文**对应片段替换为 `***`；连续或相邻命中合并为一段 `***`。
  4. 不把原文送第三方审核。
- 与隐私模式同时生效时的顺序：先做输入合规检测（用户可关）；通过后，若当前会话是隐私模式，再对「发给模型的副本」做 PII（用户不可关）。两套独立，关敏感词不会关掉 PII。

#### 5.5.1 用户输入

默认开启。点发送、请求未交给模型时检测。

开启且命中：

1. 本轮不发给模型。
2. 输入框内命中词替换为 `***`（连续命中合并为一段打码）。
3. 输入框下方提示：「包含敏感内容，已替换敏感词，确认后可再次发送。」
4. 再次发送：对**当前输入框文本**重新检测。仍命中则重复 1–3；未命中才发出。
5. 用户把 `***` 改回原词再发送：视为再次命中，不得发出。

误报：输入框下方「敏感词检测」开关。关闭前确认框：「关闭后，输入将按原文发送。模型回复仍会过滤。」确认后关闭。只影响输入。状态写入数据根，重启保持。重新打开无需确认。

#### 5.5.2 模型输出

- 命中片段一律打码为 `***`（连续命中合并），**不截断整段回复**。聊天区最终状态不得停留原文。
- 流式时词语可能被拆开：允许先短暂显示再打码，或缓冲后再上屏。**写入数据根的历史必须是打码后文本**，与最终界面一致。
- 用户已发出的那一条：若发送前被替换，历史存替换后文本。

### 5.6 模式与模型

选择器在主聊天区当前会话处（输入框附近 / 会话顶栏，与现有模型选择同一位置扩展）：**先模式，后该模式下的模型**。选中值仍是某一个具体模型；模式同时是分组和该会话上的属性。

| 模式 | 对用户的含义 | 发送时额外做什么 | 本期名单从哪来 |
|---|---|---|---|
| 隐私 | 更适合本地、少外传 | 合规敏感词 + PII 脱敏；§5.6.1 三处提示 | §5.6.3 隐私列；不含云端项 |
| 智能 | 更适合云端、能力更强 | 只过合规敏感词（与默认模式相同） | §5.6.3 智能列 |
| 默认 | 自选模型，不额外套用隐私策略 | 只过合规敏感词 | §5.6.3 默认列（本地 + 云端） |

规则：

1. 名单由配置提供，不写死在页面。三个名单允许重叠。本期便携包预置 §5.6.3，用户可改配置，改完按配置走。
2. 某模式下列表为空：展示「该模式下暂无可用模型」，禁止空白无说明。**不要**因此弹出配 API Key 向导。
3. 隐私模式不应出现的模型：隐藏（本期假名单里云端项不进隐私列）。
4. 每个模式可指定一个默认模型；用户仍可在该分组改选允许的模型。
5. 新会话模式 = 个人中心里的「新会话默认模式」（出厂为分组「默认」）。
6. 仅改当前会话的选择器：不影响其它会话，不改个人中心默认值。
7. 会话中途改模式：只作用于**之后**发出的消息，已有气泡不回溯。
8. 本期「智能是否允许云端」已体现在假名单里（智能列全是云端）。是否允许云端进隐私列不挡界面，按配置；出厂配置隐私列不含云端。

#### 5.6.1 隐私模式提示

必须持续可见，不得用会消失的 Toast，不得让用户永久关闭，不得用挡住输入的全屏条。

#### 5.6.2 PII 脱敏（仅隐私模式）

### 5.7 数据与便携（路径已定）

数据根 = 可执行文件同级 `data/`。下列内容均在此，不写主机用户目录：

登录 / 激活、敏感词开关与词库、模型与偏好、会话、桌面窗口与托盘设置、上传、记忆与人设、Skills / Agents / Hooks、MCP、日志 / PID / 崩溃记录（含原 `serve.pid` 这类进程协调文件）、临时文件（优先 `data/tmp`）。

默认会话工作区：`data/workspace/`。

还必须做到：

1. 双击即认 `data/`，不要求用户先配环境变量。
2. **进程当前目录（cwd）= 程序目录**。禁止切到主机用户家目录（上游从盘符根拉起时会切到 Home，必须改掉）。
3. 换盘符后**冷启动**：新路径尽量相对数据根；对不上的旧绝对路径要能对上或明确标为损坏。运行中换盘符不能自动续跑（§5.1.2 第 10 条）。
4. 激活记录跟这份 `data/` 走；拷走整个目录在本期防不住（已知限制）。
5. 正常使用不在主机 `~/.octo`、桌面、文档、开始菜单、`AppData` 产品目录写入会话或密钥。上游「首次启动把 uv 写到 `~/.octo/bin`」必须改为写数据根或程序目录。上游「用 `~/.octo/serve.pid` 和 `octo serve` 抢同一 hub」本期改为只认数据根内 PID；**不接管、不共享**主机上已有的 Octo / `octo serve` 进程。
6. 会话增量落盘，避免 U 盘上整文件反复重写。
7. 单实例、退出落盘、拔盘冻结：见 §5.1.2。
8. 不创建主机桌面快捷方式、开始菜单项；不写开机自启动；不自动检查更新、不把新版本装到主机。

**允许留在主机的（非重要）：** 系统互斥量（尽量不落文件，落了则退出删除）；操作系统无法重定向的临时文件（记路径，退出删除）；用户在对话里**自己指定**的主机路径。

禁止把 `~/.octo`、桌面、文档、下载、`AppData` 产品目录当作降级数据根。

**启动**

- 在 Windows 上双击程序目录内 exe，出现窗口，无需先开命令行或浏览器、无需安装向导。
- 无 WebView2 时有说明，不是无提示闪退。
- 数据根不可写：有原因说明，不进业务，不写主机。

**品牌**

- 无主机桌面快捷方式、无开始菜单项（便携交付本身）。

## 附录 A　上游现状核对（供实现对照，不是产品翻案点）

以下描述当前 octo-agent 桌面端行为，用来解释「为什么本期必须改」。产品规则以正文为准。

- 桌面端是独立进程 `octo-desktop`（Wails v3），设计目标即为可双击的应用，用户不必先执行 `octo serve`，也不必自己打开浏览器。
- Windows 产物是 GUI 子系统 exe（`-H windowsgui`），资源管理器双击会出窗口，不会先弹控制台。
- 进程内启动本机 HTTP 服务（固定 `127.0.0.1:8088`），再打开内嵌窗口加载界面。本期产品仍用该端口，故与已占用 8088 的 Octo / `octo serve` 冲突。
- 官方交付物是安装包（`octo-setup.exe` → 装到 `%LOCALAPPDATA%\Programs\octo`），不是绿色目录。
- 裸 exe 双击能开窗口，但第一次运行会往主机写东西，例如：崩溃日志、桌面设置、会话到 `~/.octo`；把 `uv.exe` 复制到 `~/.octo/bin`；`~/.octo/serve.pid` 与 `octo serve` 抢同一 hub；单实例 ID `dev.octo-agent.desktop`；从盘符根拉起时把 cwd 切到用户 Home。
- 关窗口默认进托盘；有开机自启动、检查更新。本期便携包均须按正文关掉或改写到数据根。

用户可见文案目前在 `web/src/lib/i18n.ts` 与桌面 `lang.go`（如 Quit Octo、Message Octo）。替换范围见 §5.2，路径仅供实现查找，不是需求本身。
