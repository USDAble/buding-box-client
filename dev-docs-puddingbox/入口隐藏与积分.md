# 入口隐藏与积分

写作参照：`dev-docs/desktop-update-notice.md`

> 便携产品只为已批准视图提供导航入口；默认不在导航中展示上游新增视图。隐藏只影响 UI，既不删除实现，也不阻断已有深链。余额从服务器账本刷新，充值入口进入后台配置驱动的钱包与订单页面。

## 范围

本文件定义导航可见性、Profile 相关设置入口、深链边界、输入区附近提示、余额显示和充值入口。模型、词库和账户的具体功能分别由对应主题文档及 `本地API契约.md` 定义。

## 非目标

- 不删除上游功能代码来达到隐藏效果。
- 不维护第二套能力矩阵或按页面复制产品开关。
- 不在本地预测、扣减或汇总余额。

## 当前隐藏范围与唯一判据

`web/src/lib/features.ts` 是当前导航可见性判定的唯一所有者。只有 `chat`、`tasks`、`agents`、`skills`、`workflows` 与 `browser` 获得侧栏入口；不在明确集合中的视图，包括 channels、MCP、Light Apps 和未来上游新增视图，默认不显示。组件不能各自维护另一份名单。

导航隐藏不是功能门：手工 hash、已有书签、桌面壳或内部流程仍可抵达这些视图，地址栏也保留原视图 hash。这样只收窄 UI 入口，不改变路由、服务端能力、数据读写或上游实现。

新增入口需要显式加入集合，届时同步检查侧栏常规/窄栏形态和用户可见文案；无需修改被隐藏视图本身。

## 本地模型管理只在开发 Profile 可见

完整设置中的 endpoint/本地模型管理分类，以及聊天模型菜单底部的“管理模型”入口，只在开发 Profile 显示。产品 Profile 不展示这两个入口，但保留上游页面、路由和本地 API 实现，避免为隐藏入口删除上游能力。

该判断不能复用侧栏 `NAVIGATION_VIEWS`，因为它不是视图导航白名单，而是由运行 Profile 决定的开发能力。前端从本地服务读取明确的 Profile 能力投影；不能根据域名、是否已有本地 endpoint 或构建环境变量自行猜测。

产品 Profile 的统一模型列表同时排除本地配置模型。只隐藏管理入口却继续展示必然被产品网关策略拒绝的模型，会制造一个可选但不可用的假入口。

## 助手默认值中的提交署名入口暂不展示

完整设置的“助手默认值”不展示“提交署名 Co-author”开关。设置项的组件、配置读取和保存接口保留；隐藏仅影响可见入口，不修改已有的 co-author 偏好，也不改变提交署名的实际行为。验证时应确认该行不可见、其他助手默认值仍可操作，且打开设置不会写入 co-author 配置。

## 关于页隐藏首次引导、移除开源许可入口

完整设置的“关于”分类保留版本信息与更新状态，不展示“首次引导”重运行入口，也不展示“开源许可”链接。首次引导组件及重运行处理代码仍在，隐藏设置入口不改变首次安装时的引导逻辑；仓库和发行物中的许可证文件不受此界面改动影响。

## 上游能力保留但不可达

需要暂不展示的上游能力保留实现和稳定路由，只在导航层不提供入口。这样既避免删除与上游修改冲突，也让未来开放时不必重建页面结构。

导航隐藏不承担权限或安全责任；任何需要鉴权、请求限制或数据保护的能力仍由原有服务端和产品门处理。

## 输入区提示的顺序

输入区同时存在产品门、目录可用性、敏感词提示、余额或能力限制时，展示顺序由一个消费层决定。更高优先级的阻断结果不能被较低优先级的提示覆盖；用户始终看到当前最需要处理的原因和可执行动作。

## 积分与充值

余额是服务器账本的投影。登录、回合结束或跨窗口事件只能触发 `GET /api/product/credits` 刷新；它是唯一写入本地余额状态的路径。客户端不做本地扣费、月度统计或由 WebSocket 载荷直接覆盖余额。

积分页打开时和用户手动刷新时都会请求账本；窗口重新获得焦点、登录完成与回合结束也只触发同一刷新路径。刷新失败保留上一次余额并显示失败，而不是写入猜测值。

充值入口打开设置中的钱包页面，展示后台档位、可用支付方式、订单、积分流水和用量。创建订单采用稳定幂等编号；微信展示订单二维码，支付宝/Stripe通过显式点击打开服务端返回的HTTPS地址。支付通道尚未配置时保留后台档位展示，明确提示通道不可用。只有查询中台确认为 paid 后才触发余额刷新，返回客户端或本地倒计时结束都不能作为支付成功依据。

套餐升级仍为明确未开放的独立入口；积分充值不会自动授予会员权益。

## 验证

- 未获批准的入口不会出现在常规或窄栏导航；新增上游视图默认不出现。
- endpoint 管理和模型菜单的管理入口仅在开发 Profile 出现；产品 Profile 不展示本地配置模型。
- 隐藏不删除或阻断上游实现，已有深链、书签和内部流程仍保持可用。
- 输入区在多个限制同时存在时显示唯一、稳定且可执行的优先结果。
- 余额只由账本刷新写入，跨窗口事件不会携带可覆盖的余额数值；失败时保留最后可信数值。
