## 0. 这份文档怎么用

### 0.1 三种"要人跑"的理由，别混着读

`开发规范` §6.4 第 5 步要求「**单元测试 + 端到端两条都过**」才允许标 ✅。按"为什么还需要人跑"，用例分三类：

| 类 | 含义 | 走这一遍买到什么 |
| --- | --- | --- |
| **A 类 · 手工就是缺的那份证据** | 判据跨进程或要真人看界面，CI 代替不了（`🟨`） | 走完才能把状态列改成 ✅ |
| **B 类 · 补真机确认** | 判定已成立（✅），但真机上是否与测试里一致没验过 | 发现"测试绿、真机不一样"这类接线缺陷 |
| **C 类 · 一台机器做不了** | 需要第二台电脑或第二块盘 | 补齐场景类判据 |

### 0.2 用例 ID 与闭环的对应

本文用例号沿用闭环号（`TC-A1a` ↔ `L-A1a`），**不做二次编号** —— 一条闭环若需要多组操作，用 `.1` / `.2` 后缀。这样任何一条用例都能一句话回答"它验的是哪条闭环"。

### 0.3 判定与登记

每条用例跑完，**只改两处**（`手工走查单.md` §2 的同一条纪律）：

1. `E2E闭环清单.md` 对应 `L-*` 行的**状态列**；
2. `开发计划.md` 对应 PR 的**落地记录**末尾「残留」那一段。

**合计行不动** —— 它由合并者按状态列机器重数后统一改。

**走查中若发现新现象，按现象改代码，不要改期望值。** 这条不是口号：本批次已有多次"文档写的是错的、代码是对的"（`V-53` 的门策略描述、`V-57` 的 json tag）与"期望值本身写错让测试空转"（`V-22` 把缺陷写成了预期）。

### 1.2 夹具值（owner = `internal/productclient/clienttest/server.go`）

| 项 | 值 |
| --- | --- |
| 手机号 | 任意 11 位 |
| 短信验证码 | `123456`（`FixtureSMSCode`） |
| U 盘激活码 | `BUDING-DEMO-0001`（`FixtureActivationCode`） |
| 盒子编号 | `BOX-DEMO-0001`（`FixtureBoxCode`） |
| 目录里的三个模型 | `buding-privacy-1` / `buding-cloud-pro` / `buding-cloud-fast`，全部 `eligible=true` |
| 初始余额 | `12500`（`fixtureBalanceMicroCredits`） |

> `BUDING-DEMO-0001` 是**固定 ASCII 数据键**，不随品牌英文名走（`brand-guard` 的豁免项之一，见 `CLAUDE.md` 硬规则 2）。

### 1.3 故障注入 flag（owner = `cmd/productstub`）

**启动时替身会把已武装的开关打进横幅** —— 先看那一行再判断屏幕，否则"注入生效"与"流程坏了"长得一模一样。

| flag | 作用 | 本文用在哪 |
| --- | --- | --- |
| `-balance=<微积分>` | 改 ledger 报的数（`-balance=0` 是零余额那档） | `TC-C4a`, `TC-C4b` |
| `-model-ineligible=<模型 id>` | 把某模型标成 `eligible=false`（**仍在目录里**，只是不可选） | `TC-C7` |
| `-fail-ledger=<status>[:<code>]` | 每次 ledger 读都失败 | `TC-C4a` |
| `-fail-bootstrap=<status>[:<code>]` | 每次 bootstrap 都失败 | `TC-B3` |
| `-fail-completions=<status>[:<code>]` | 每次网关回合都失败 | `TC-C4c` |
| `-fail-logout=<status>[:<code>]` | 每次登出都失败 | `TC-E2` |
| `-omit-ledger-balance` | ledger 里**不给** `balanceMicroCredits`（"缺字段"而非 0） | `TC-C4a` |
| `-catalog-version=` / `-catalog-ttl=` / `-policy-audience=` | 回退攻击 / 荒谬 TTL / 发给别的产品 | `TC-C1a`, `TC-C2` |
| `-expire-access-tokens` / `-omit-policy` / `-tamper-policy` | 访问令牌失效 / 信封缺失 / 载荷被改一个字节 | `TC-A6`, `TC-C1a`, `TC-C2` |
| `-tool=terminal\|read_file` | 让替身主动请求一个工具调用 | `TC-C3c` |
| `-upstream=<url>` / `-key=<key>` / `-model=<id>` | 把回合转发到**真实供应商** | `TC-C3a` |

**`-fail-*` 的两种写法是不同的场景，不是详略之分**：`502` 是"没有业务码的拒绝"（代理层），落到客户端的**传输层**文案；`402:insufficient_credits` 是带业务码的，落到**那个码专属**的文案。

```bash
# 示例：一次全武装
go run ./cmd/productstub -balance=0 -fail-ledger=502 -model-ineligible=buding-cloud-fast
```

### TC-A1a 首次激活成功 ｜ `L-A1a` ✅ · **B 类（补真机确认）**

| # | 操作 | 期望 |

### TC-A3 退出 → 再登录 ｜ `L-A3` ✅ · **B 类（补真机确认）**

**验什么**：退出清凭证与登录态、**保留激活记录** → 再次登录回到已激活态。

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | 承接 `TC-A1a` 的登录态，确认 `data/credential.json` **存在** | —— |
| 2 | 点退出登录 | 回拦截页；`credential.json` **消失**；`loggedIn=false`；`activated` **仍为真** |
| 3 | 重启进程 | 停在拦截页，**不是**五字段激活表单 |
| 4 | 只凭手机号 + 验证码 + 昵称登录 | 成功 |

> **第 1 步不能省。** 若登出前凭证本就不存在，后面的断言会**空洞成立** —— 这是写这条用例时踩过的坑。

> **本批次最严重的单点已修**（`V-22`）：此前登出会清空 `productState` ⇒ 拦截页变回五字段 ⇒ 要重输**一次性**激活码 ⇒ **点一次登出永久锁死用户**。今天这一步是在验它没有复活。

**验什么**：四个业务码 → 各自专属文案 + 客服入口 + **不写激活记录**。**本条仍为 ⚠️** —— 客服载体未定（`V-4` / `PQ26`）。

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | 用错误的激活码提交 | 专属文案「激活码不正确」 |
| 2 | 用一个**已消耗过**的激活码提交 | 专属文案（不是「激活码不正确」） |
| 3 | 用一个平台认不出的盒子编号提交 | 专属文案 |
| 4 | 用一个**已被别的盒子用过**的激活码提交 | 专属文案 |
| 5 | 每次失败后检查 `data/` | **不落盘任何激活记录** |
| 6 | 每次失败后看表单 | 消息落在**能补救它的那个表单**上，且有一个「去激活」按钮（不按错误码出现） |

| # | 操作 | 期望 |
| --- | --- | --- |
| 8 | 用同一个盒子编号 + 第二个合法激活码提交 | **两次都成功**（一对多回归） |

**本条的已知残余（走查时必须记下来，不要勾掉）**：若用户的码确实已用尽（`activation_code_used`）或平台认不出这个盒子，**出路仍只有客服**，而客服载体未定 ⇒ 本条**不能判 ✅**。

**验什么**：剩余天数 + 脱敏手机号 + **盒子编号不脱敏**，三要素同页；老数据缺 `boxCode` 显示「—」且不拦截。

### TC-A6 凭证失效 / 会话撤销 ｜ `L-A6` ✅ · **B 类（补真机确认）**

**验什么**：401/403 → 清本地凭证 → 回拦截页，**不静默继续**；刷新失败一次后**不无限重试**。

```bash

```

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | 登录成功后，让 access token 失效 | —— |
| 2 | 触发一次已授权调用（如登录 / 拉目录） | 返回 **401 `unauthorized`** |
| 3 | 检查 `data/credential.json` | **不留 refresh token**（文件消失或为空） |
| 4 | 检查界面 | 回拦截页 |
| 5 | 检查 `data/product-state.json` | `loggedIn=false`，但 `activated` 与**绑定号码保留** |
| 6 | 检查 `data/catalog.json` | **不产生** |
| 7 | 观察网络面板 | 刷新失败后**不循环重试** |

> **代价要写明**：该替身故障下**一次激活码已被中台消耗**（消费发生在拒绝之前）。这是故障本身的固有性质，不是客户端能挽回的。
