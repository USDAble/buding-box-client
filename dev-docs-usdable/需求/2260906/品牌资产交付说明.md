## 0. 一句话

**交 3 个 SVG 文件，不要交 PNG。** 所有位图（`.ico`、`.icns`、各尺寸 PNG、favicon、社交卡片）由脚本从这 3 个 SVG 一次生成。

之所以要矢量而不是位图：这个项目的标识被内联在大约 10 个地方（界面组件、落地页的导航/主视觉/页脚、共享导航脚本、文档站、博客的社交卡片），这些位置**只能吃矢量**。交位图的话，这些位置就只能把 PNG 转成 base64 塞进 `<image>` 标签 —— 上一版就是这么干的，一个 582 字节的真矢量变成了 **218,652 字节**的假矢量，还被复制了 3 份进仓库。

## 1. 交付清单

放到 `branding/source/`，文件名必须完全一致（小写、连字符）：

| 文件 | 画布 | 内容 | 必需 |
|---|---|---|---|
| `logo-mark.svg` | `viewBox="0 0 100 100"` 正方形 | 主标识。带底板的方形图标形态 | **必需** |
| `logo-mono.svg` | `viewBox="0 0 100 100"` 正方形 | 单色剪影版，纯黑。见 §3 | **必需** |
| `og-card.svg` | `viewBox="0 0 1200 630"` 横版 | 社交分享卡片：标识 + 名称 + 一句话介绍 | **必需** |

这 3 个文件会派生出下面全部产物，设计**不需要**逐个提供：

- Windows `icon.ico`（16 / 24 / 32 / 48 / 64 / 128 / 256 七帧）
- macOS `icon.icns`
- macOS 菜单栏托盘图 88×88 纯黑（来自 `logo-mono.svg`）
- Linux `icon.png` 256×256（同时用作 Windows/Linux 托盘图）
- Web / 文档站 / 博客的 favicon
- 落地页与博客的 1200×630 社交卡片位图

> 上一版交了 15 张不同尺寸的 PNG，其中 11 张在整个仓库里没有任何消费点。不需要这么做。

## 2. 硬性技术约束

这一节的每条都会被工具校验。**违反哪条，`make brand` 就报错退出并指出是哪条。**

### 2.1 所有形状必须是 `<path>`

不允许 `<rect>`、`<circle>`、`<ellipse>`、`<line>`、`<polygon>`、`<polyline>`。请在设计工具里把所有形状**转换为路径**（Figma：Flatten；Illustrator：对象 → 复合路径）。

**为什么：** 这不是洁癖。我们实测了要用的渲染器，它**静默忽略** `<rect>` 的 `rx` 圆角属性 —— 不报错，直接画成直角。同一个图形：

| 写法 | 渲染出的角点像素 | 结果 |
|---|---|---|
| `<rect width="100" height="100" rx="22">` | `rgba(47, 84, 235, 255)` 不透明 | 圆角**丢失**，变成直角方块 |
| 转成 `<path>` 用弧线画圆角 | `rgba(0, 0, 0, 0)` 全透明 | 圆角正确 |

因为它是静默失败，人眼在 512px 预览上很容易漏掉，到了 16px 图标上就是「这个图标怎么和别人不一样」。转成路径就没有这个风险。

### 2.2 不允许的 SVG 特性

| 禁止 | 原因 |
|---|---|
| `<image>`、`xlink:href` 引用位图、base64 内嵌数据 | 这就是「假矢量」，缩放会糊，体积暴涨 |
| `<text>`（活文字） | 渲染依赖字体，本机和 CI 的字体不同 → 生成结果不一致 → CI 每次都报资产漂移。**文字必须转曲** |
| 线性/径向渐变 `<linearGradient>` `<radialGradient>` | 渲染器支持不完整；且 16px 上渐变等于噪点 |
| 滤镜 `<filter>`（阴影、模糊、发光） | 同上，且托盘单色图完全无法表达 |
| `<mask>`、`<clipPath>`、`mix-blend-mode`、`opacity` 叠加取色 | 渲染差异大 |
| 描边 `stroke`（未转为填充） | 缩放时线宽行为不一致。请**描边转填充** |
| 外部字体 / CSS `@import` / `<style>` 块 | 生成环境取不到 |

**可以用的：** `<path>` + `fill`（十六进制实色）+ `fill-rule` + `<g>` 分组 + `viewBox`。就这些。

### 2.3 几何约束

| 项 | 要求 | 为什么 |
|---|---|---|
| 画布 | `logo-mark` / `logo-mono` 必须是正方形 `0 0 100 100` | 与现有 10 处内联调用点的 viewBox 一致，可直接替换 |
| 安全边距 | 图形四边各留 **8–10%** 空白（100 单位画布上即 8–10 单位） | macOS 的圆角遮罩（squircle）和 Android 自适应图标安全区会切掉边缘。上一版那张源图**上边距是 0 像素**，图形直接顶到画布顶边 |
| 居中 | 图形包围盒中心与画布中心偏差 ≤ 1% | 缩到 16px 后偏心非常明显 |
| 形状数量 | `logo-mark` 建议 ≤ 6 个 `<path>`，`logo-mono` ≤ 4 个 | `icon.ico` 含 16×16 帧。现有标识只有 4 个形状，所以缩到 16px 还认得出；形状多、细节碎的图形在 16px 就是一团糊 |
| 最细笔画 | 在 100 单位画布上不细于 **4 单位** | 4/100 缩到 16px ≈ 0.64px，已是可辨识下限 |

### 2.4 颜色约束

| 项 | 要求 |
|---|---|
| 主色 | **一个**主色，写成 6 位十六进制（如 `#3E7BB0`）。这个值要同时填进 `branding/brand.json` 的 `visual.colors.primary` |
| 近白色禁制 | 不允许出现亮度 > 0.85 的**大面积**元素（除非它位于深色底板之上） |
| 透明底 | `logo-mark` 的底板之外必须透明，不要铺白色背景矩形 |

**近白色这条的来历：** 上一版那张源图的下半部分有一整块约 **35,000 个像素、亮度超过 0.85** 的近白色字标。白色背景上完全看不见（所以评审时没人发现），但在 macOS 深色菜单栏、深色主题的浏览器标签页上，会露出一段悬空的白字。

> 现有项目里同时存在三种蓝（`#2F54EB`、`#1677FF`、`#4f46e5`），是历史遗留。这次请统一成一个值。

## 3. `logo-mono.svg`：为什么必须单独设计

这是最容易被误解的一件交付物。**它不能从主标识自动生成**，必须单独画。

macOS 菜单栏的托盘图标走的是系统的 template image 通道（代码里是 `tray.SetTemplateIcon`）。这个通道**只读取 alpha 通道，颜色全部丢弃**，然后由系统按当前菜单栏明暗自己染色。

后果：把一个彩色图标丢进去，得到的是它的**实心剪影**。实测现有资产与上一版的替换：

| 文件 | 尺寸 | 纯黑占比 | 有彩色占比 | 去重颜色数 | 非透明占画布 |
|---|---|---|---|---|---|
| 现有 `tray-icon.png` | 88×88 | **100.0%** | 0.0% | **1** | 28% |
| 上一版换成的图 | 64×64 | 9.9% | **78.3%** | **1001** | 53% |

现有那个是教科书式的 template 图：**纯黑 + 透明，只有 1 种颜色**，非透明像素只占画布 28%（就是图形的几根主要笔画）。上一版换成了彩色立方体，1001 种颜色 —— 送进 template 通道后颜色全丢，而立方体在整个六边形轮廓内都不透明，于是 B/O/X 三个面和所有明暗全部消失，菜单栏里只会剩下一个**实心六边形色块**。

### 交付要求

| 项 | 要求 |
|---|---|
| 颜色 | **只用 `#000000` 一种填充色**，其余靠透明表达 |
| 造型 | 主标识的「减法版」：去掉底板、去掉内部层次，只留最有辨识度的外轮廓与关键镂空 |
| 非透明面积 | 占画布 **20%–35%**（对齐现有的 28%） |
| 笔画 | 比主标识更粗。菜单栏实际渲染只有 16–22px 高 |
| 镂空 | 需要「透」出来的地方用 `fill-rule="evenodd"` 做真镂空，不要用白色填充假装 |

自检方法：把这个 SVG 的所有黑色临时改成白色，放到黑色背景上看 —— 如果还认得出是什么，就合格；如果变成一个色块，就是内部层次不够。

## 4. `og-card.svg`：1200×630 社交卡片

用于微信/Twitter/Slack 等分享时的预览图，会被渲染成 PNG。

| 项 | 要求 |
|---|---|
| 画布 | `viewBox="0 0 1200 630"`，固定比例，不要改 |
| 内容 | 标识 + 「布丁盒子」+ 一句话介绍 |
| 文字 | **必须转曲**（见 §2.2）。这是这个文件最容易出错的地方 |
| 安全区 | 主要内容收在中间 **1100×540** 内。各平台裁切比例不同，边缘会被切 |
| 背景 | 需要不透明背景（浅色底即可），不要透明 —— 社交平台会用自己的底色，透明会穿透 |
| 最小字号 | 介绍文字在 1200 宽画布上不小于 **28 单位**。缩略图会缩到约 1/3 |

如果中英文各要一版，请交 `og-card.svg`（中文）和 `og-card-en.svg`（英文），研发按语言分发。

## 6. 上一版的四个实际问题（避免重复）

留档，供设计参考，不是追责：

1. **交了位图当源** —— 15 张 PNG，其中 11 张无消费点；而 10 处内联 SVG 调用点无法使用位图。
2. **底部有不可见的近白字标** —— 约 35,000 个亮度 > 0.85 的像素，白底上看不见，深色界面上露出。
3. **零上边距** —— 图形顶到画布 y=0，会被 macOS 圆角遮罩和 Android 安全区切到。
4. **用彩色图替换了单色托盘图** —— 见 §3，菜单栏里会退化成实心色块。

## 7. 交付之后研发做什么

设计只需要放文件，剩下是一条命令：

```bash
# 1. 放入 3 个 SVG
#    branding/source/logo-mark.svg
#    branding/source/logo-mono.svg
#    branding/source/og-card.svg

# 2. 一条命令生成并分发全部产物
make brand

# 3. 自检（CI 也跑同一套）
make brand-check
```

`make brand-check` 会校验 §2 的每一条，并比对生成产物与源文件是否一致 —— 也就是说，如果有人绕过流程手改了某个生成出来的 PNG，提交阶段就会被拦下。

## 8. 与 `brand.json` 的关系

图形归这份说明，**文字与标识符归 `branding/brand.json`**，两者互不重叠：

| 内容 | 归属 | 说明 |
|---|---|---|
| 图形、颜色 | 本文的 3 个 SVG | 换 logo 只动这 3 个文件 |
| 产品名、口号、版权方、协议标题 | `brand.json` 的 `product` / `about` | 换名字只动这里 |
| 主色值 `#RRGGBB` | **两边都要填** | SVG 里是实际填充色，`brand.json` 的 `visual.colors.primary` 是界面强调色，两者必须一致 |
| 路径、可执行文件名、协议名、端口 | `brand.json` 的 `identifiers` | 一律英文 ASCII，永不本地化 |

主色在两处出现是唯一的重复点。定稿后请把十六进制值一并告知研发，由研发填入 `brand.json` 并由 CI 保证两边不漂移。
