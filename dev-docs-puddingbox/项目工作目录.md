# 项目工作目录

写作参照：`dev-docs/project-workspace-design.md`

准备新对话时，选中项目后仍可点击消息输入框下方的工作目录重新选择；所选项目已有历史会话不影响这个入口。重选只更新这次新对话的待用目录和项目归属，保留输入草稿，不改已有项目的目录或历史。发送消息创建会话后，输入框中的目录只读。

侧栏项目菜单的「项目设置」修改的是项目自身的绑定，直到项目中的任一会话接受第一条消息。仅新建空会话不会锁定项目目录；发送消息后，改名和源文件夹编辑仍然可用。

## 首条消息是目录修改边界

输入框入口和项目设置均复用现有原生目录选择器；浏览器使用已有的文件夹选择弹窗。输入框重新选择后，按现有目录归属规则更新 `pendingGroupId` / `pendingWorkingDir`：目录唯一属于某项目则选中该项目，多项目时让用户选择，无归属时暂存目录，首次发送时再创建项目。该入口不 PATCH 已有项目，也不受 `working_dir_locked` 限制。切换会话或待用项目后，延迟返回的选择结果丢弃。

项目设置保存通过原有 `PATCH /api/session-groups/{id}` 的 `working_dir` 字段修改项目绑定，仍受下面的项目级锁定规则约束。

服务端是编辑资格的事实源。`projectGroupResponse` 返回 `working_dir_locked`，检查项目全部成员，而非前端当前已加载的会话页。正在运行、被其它入口租用、已有消息或已锁定首次消息状态的会话，都会阻止目录修改。无法读取会话时也拒绝修改；已删除会话留下的失效成员 ID 不阻止空项目编辑。

更新期间持有项目注册表写锁和成员会话 turn 锁，避免与首次消息交错。目录已锁定时返回 HTTP 409 和 `project_directory_locked`，项目名称、目录和源文件夹均不部分保存。前端保留弹窗并显示锁定提示。

该行为是本 fork 对上游「工作目录创建后固定」规则的调整；上游设计文档保持原样，产品差异以本文件为准。

## 用户目录不作为产品自有数据清理

选择的目录必须已存在且可访问。空路径、文件、工作区根及其内部目录、其它项目已绑定的工作目录均拒绝。沿用 `validateWorkingDir` 和 `validateSourceDirs` 的校验，不新增目录解析规则。

这是用户明确指定的工作对象，符合[便携数据根](便携数据根.md)对显式工作路径的边界。产品配置、会话和凭证仍经 `internal/datapath` 管理。保存目录绑定不会移动、复制或删除任一目录中的文件；删除项目也不删除用户目录。

`sessionGroup.WorkingDir` 记录执行目录。首次修改时，`WorkspaceDir` 保留原生成工作区，供项目记忆身份解析和启动期旧数据识别使用：

- 启动时的 `migrateProjectWorkspaces` 跳过主动选择过目录的项目，重启后不会把绑定改回默认值。
- `ProjectRef.MemoryDir` 继续使用原工作区的 basename 和项目 ID，CLI、新会话和恢复会话读取同一份记忆。
- 普通项目会话继续继承项目工作目录；CLI 等入口已有的显式会话目录仍按原优先级解析。

## 验证

后端回归见 `internal/server/project_directory_edit_test.go` 和 `projects_test.go`：空项目、空会话、消息与执行状态锁定、非法目录、持久化、启动迁移、记忆身份、删除项目后保留用户文件。

前端回归见 `web/src/components/overlays/ProjectModal.test.ts`：原生和浏览器选择目录、保存新绑定、已有消息时禁用、其它窗口开始消息后的状态更新，以及创建项目请求兼容性。

输入框入口回归见 `web/src/components/chat/Composer.async.test.ts`：已有历史项目下的新对话仍可重选、缺少锁定字段时仍可选择、原生与浏览器选择器、已存在会话只读、切换项目后丢弃延迟结果、原生选择期间禁止发送，以及取消和选择失败时保留原目录。

手工验收：在已有历史的项目下点击「新建对话」，点击输入框下方的目录，重新选择后待用路径或项目立即更新，草稿保留，旧项目绑定不变；发送后该会话目录只读。项目设置单独验证空项目可修改、首条消息后锁定及重启后保留绑定。

## 非目标

- 不允许修改已经开始对话的项目目录，不迁移现有会话历史或用户文件。
- 不改变源文件夹挂载规则、默认数据根、CLI 显式工作目录或定时任务执行逻辑。
- 不自动清理之前生成的工作区或重写上游设计文档。
