## 1. 完成结果

- 登录成功后按已缓存版本条件拉取 `/v1/dictionaries/sensitive?version=<known-version>`；`304` 归一为 unchanged，不重写缓存。
- 服务器词库采用 `{dictionary, dictionarySignature}` 原始字节分离签名信封，与策略目录共用 Ed25519 验签、受众和时钟窗口检查；验签前不解析、不落盘。
- 通过校验的完整快照或合法 delta 才能写入 `data/sensitive-dict-server.json`；版本相同不重写，版本回退拒绝，写盘使用 `internal/atomicfile`。
- 有效词库立即进入现有唯一 `internal/sensitive.Engine`，有效集合为内置 ∪ 用户 ∪ 服务器；用户文件或服务器缓存任一层损坏只影响该层。
- 同步失败保留旧版；无旧版时只使用内置词与用户词，不会 fail-open 到“不检测”。登录响应返回一次 `dictionaryNotice`，包含回落版本和 `next_login` 恢复条件；同进程恢复时返回恢复版本。

## 2. 实际改动

- 主要文件：
  - `internal/productclient/dto.go`、`client.go`、`signing.go`：新增词库 DTO、条件下载、摘要计算和共享原始字节验签。
  - `internal/productclient/clienttest/server.go`、`sign.go`：新增服务器词库替身端点、签名夹具与故障开关。
  - `internal/sensitive/server_dict.go`：缓存 owner、路径、版本单调、校验和原子写入。
  - `internal/sensitive/sensitive.go`、`dict.go`：接入服务器层并保持三层独立热加载。
  - `internal/productruntime/server_dictionary.go`、`runtime.go`：登录触发同步、full/delta 应用、失败/恢复状态及登录提示。
  - `cmd/octo-desktop/product.go`、`web/src/lib/product.ts`、`web/src/views/BlockedView.svelte`、`web/src/lib/i18n.ts`：装配服务器缓存和降级/恢复提示。
- 新增测试：客户端传输、缓存 owner、delta 应用、运行时集成、无旧版/回滚/篡改/未知 key/离线/畸形/摘要错误/写盘失败/恢复。
- 落盘变化：仅在登录同步成功且验签、摘要、版本均通过后写 `data/sensitive-dict-server.json`；启动读取不创建文件。
- 偏差：按计划推荐的 PQ30 取法①落地，未引入 JCS、第三方依赖或第二套验签器；真实中台需按同一原始 JSON 字节语义签名。

- 当前同步触发点是成功登录；按 TTL 的周期刷新未纳入本阶段，后续若需要应单独设计生命周期 owner。
