# 个人信息保护与私密会话

写作参照：`dev-docs/permission-remember-design.md`

> 个人信息保护负责在落库前不可逆脱敏，私密会话负责限制模型处理边界。两者可以组合，但不是同一个等级开关；内容安全防护继续独立处理违规或不适宜内容。

## 范围

本文记录已经确认的隐私产品边界、目标数据流、私密模型要求和首批规则选择方式。它是待实现设计，不表示当前代码已经完成个人信息脱敏或私密模型自动切换；当前实现差距在文末单列。

## 非目标

第一阶段只处理用户提交的普通文本，不覆盖：

- 附件正文、上传文件和 OCR 结果；
- 工具参数、工具调用 JSON 和工具返回值的深层结构；
- thinking block 或签名推理块；
- 依靠关键词自动判断商业秘密、合同秘密或内部经营信息。

现有输出链路已经会遮盖可见的工具结果文本；这里的“不覆盖”表示个人信息保护暂不向工具协议内部扩展，不要求撤掉已有内容安全防护。

## 三项能力各自回答一个问题

| 能力 | 回答的问题 | 主要机制 |
| --- | --- | --- |
| 内容安全防护 | 内容是否允许输入、展示和持久化 | 敏感词检查、拒绝或打码 |
| 个人信息保护 | 文本里是否留有可识别个人的信息 | 落库前不可逆脱敏 |
| 私密会话 | 整段内容允许交给哪类模型处理 | 模型可信标签、路由限制和禁止公共回退 |

三者不得共用一个总开关。私密会话默认开启个人信息保护，但这只是产品预设；技术上仍是两个独立判断，便于分别测试和审计。

## 个人信息在落库前不可逆脱敏

目标路径只有一份持久化消息：

```text
用户输入 → 本地识别 → 不可逆脱敏 → 保存脱敏文本 → 发送同一份脱敏文本
```

数据库、聊天历史、重新发送、导出和模型上下文都读取脱敏后的文本，不保存原始值，也不保存可恢复映射。这样不需要维护“本地原文”和“模型副本”两套历史，也不会在后续回合重新把历史原文带给模型。

首版使用类型占位符，例如 `<姓名>`、`<手机号>`、`<邮箱>`。不使用 `138****8000` 一类半脱敏结果，也不承诺把跨消息出现的同一个人稳定编号；前者仍泄露部分真实值，后者需要保存额外映射并重新引入敏感数据管理。

发送前应展示本次处理结果，例如“已处理 3 项个人信息：姓名、手机号、邮箱”，允许用户查看脱敏后的文本并取消本次发送。取消不落库；确认后只保留脱敏文本。

## 私密会话限制模型处理边界

个人信息规则无法识别“尚未发布的价格”“收购计划”或内部源代码等机密内容。私密会话因此不依赖关键词判断，而是限制整段对话只能发送到可信的私有模型：

- 首版只接受可信目录明确声明的私密资格，不能根据名称、地址字符串或 UI 分组自行猜测；
- 私密模型不可用时停止开始新回合，不能自动回退到公共模型；
- 开启私密会话时，如果当前模型不符合要求，自动切换到目录指定的首选私密模型，并明确提示用户；
- 模型选择器和当前模型标签都要显示可辨认的“私密”标识，不能只靠排序表达安全属性；
- 本地部署模型以后也可以关联私密会话，但用户添加的本地 endpoint 首版不能自动获得私密资格。后续需要单独定义真实请求链路、代理、日志和回退的验证方式；仅把 endpoint 命名为 local 不构成可信证明。

私密模型的展示和自动切换复用统一模型列表，具体模型来源、排序和当前实现差距见 [模式与模型](模式与模型.md)。

## 失败与提示

- 脱敏处理自身失败时，不得保存原文后继续发送；本次发送失败并提示用户重试。
- 私密会话找不到合格模型时，不得退出私密状态后继续发送；提示用户当前没有可用私密模型。
- 自动切换模型时提示“已切换到私密模型：<模型名>”，同时说明不会自动改用公共模型。
- 用户主动选择非私密模型时如何处理仍需确认：候选方案是明确确认后退出私密会话，或在私密会话中直接禁止选择。未确认前不得静默降级。

## 当前实现差距

当前代码只有隐私标识、提示文案和 `chat_mode` 会话字段，没有在落库前执行上述个人信息不可逆脱敏。现有三组模式目录与上游模型选择器也并未形成一个统一、实际可用的选择路径。

实现应先补测试证明“原始个人信息不落库、不广播、不进入模型请求”，再改变界面承诺；私密会话则需要同时验证目录标签、自动选模、模型不可用和禁止公共回退四条路径。
