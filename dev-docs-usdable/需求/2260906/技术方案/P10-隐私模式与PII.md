## 1 结论

1. **隐私模式 = 一个会话属性 + 三处持续可见的提示 + 发送前对"交给模型的副本"做 PII 脱敏。** 它不改用户的界面 —— 用户在对话框里看到的仍是原文。
2. **提示必须持续可见**，不得用会消失的 Toast、不得让用户永久关闭、不得用挡住输入的全屏条。
3. **隐私模式 PII 用户不可关，且与敏感词开关无关**（`D1` 规则 2）。关掉输入敏感词检测**不会**关掉 PII。

## 2 与另外两个模式的差别

| | `privacy` | `smart` | `default` |
| --- | --- | --- | --- |
| 合规敏感词 | 过 | 过 | 过 |
| PII 脱敏 | **做** | 不做 | 不做 |
| 三处提示 | **有** | 无 | 无 |

「合规敏感词」三个模式都过，所以隐私模式**多出来的是 PII 与提示**，不是"更严格的关键词过滤"。

出厂配置下**隐私模式不含云端模型**（`需求20260906.md` §5.6 规则 8）。落地后分组来自签名目录（`P9` §4.2）。

## 3 三处提示

三处**同时存在**；切到 `smart` 或 `default` 后**全部去掉**。

### 3.1 输入框正上方固定细条（`Composer.svelte`）

发送前必经的位置。盾牌图标 + 文案：

> 隐私模式：发送前会处理手机号等个人信息。

可展开一行说明：

> 只处理随后发给模型的内容；你在对话框里看到的仍是原文。本期演示 11 位手机号。

**不可关闭**，不是 Toast（不自动消失），不遮住输入区。

**为什么放在输入框"上方"而不是下方：** 下方已经有敏感词命中（拦截）与积分不足（不拦截）两条，位置固定不挤（见 `P6` §3.6）。而且"发送前会处理"是针对**这次发送**的告知，紧贴输入框上方才是它该在的位置。

**文案边界（必须遵守）：** 只能承诺**手机号**。不得出现"身份证 / 银行卡"字样 —— 本期不处理它们，写了就是承诺了没做的事。

### 3.2 当前模型芯片上的隐私标签（`ModeMenu.svelte` / `Composer.svelte`）

当前模型的芯片上显示「隐私」标记；选择器里**当前分组**同样可见（`PrivacyMark` 只在 `mode.id === currentMode` 时渲染）。**非当前分组保持 `P9` 的原始呈现** —— 三个分组都挂盾牌会让"现在是隐私模式"这个信息消失。

### 3.3 侧栏会话标题旁的小盾牌（`Sidebar.svelte`）

用于**多会话**区分：侧栏同时列着十几个会话时，用户需要一眼看出"哪一个在隐私模式"。这是三处里唯一跨会话可见的提示。

### 3.4 唯一判据

```ts
export function isPrivacyMode(mode: string | null | undefined): boolean {
  return mode === 'privacy'
}
```

**规则.** 三处提示全部走这一个函数，组件里不得出现 `mode === 'privacy'` 的直接比较（§3.8）。

**为什么单独抽出来：** 三处分布在三个不同组件（Composer / ModeMenu / Sidebar），各自判一次就会出现"某处判了 `'privacy'`、另一处判了 `'隐私'`"这类不一致；而判据一旦不一致，用户看到的提示就自相矛盾（盾牌在、细条不在）。抽成函数后，改动只有一处。

## 4 PII 脱敏

**作用对象：即将交给模型的文本。** 不改用户气泡、不改界面显示。

**本期范围：只演示 11 位大陆手机号。**

**算法.**

1. 先按手机号规范化规则去掉**空白与短横线**（与登录页的规范化共用同一套口径）。
2. 认**以 `1` 开头的连续 11 位数字**。
3. 把**中间 4 位**改为 `****`（例：`138****1234`）。
4. 同一条文本里**多处**手机号都处理。

**本期不做：** 身份证、银行卡。细条文案也不承诺它们（§3.1）。

## 5 与敏感词的顺序

同一轮发送的固定顺序（与 `P8` §3.7 同一处规则，此处只写隐私模式这一半）：

1. **合规敏感词检测**（用户可关）→ 命中则本轮**不发**。
2. 通过后，若当前会话是隐私模式 → 对**发给模型的副本**做 **PII 脱敏**（用户不可关）。

**两套独立。** 关敏感词不会关掉 PII；PII 也不会因为敏感词命中而未执行 —— 敏感词命中时整轮不发出，PII 没有可处理的对象，这不是"PII 被跳过"。

## 6 数据边界（必须记牢的一张表）

| | 合规敏感词 | 隐私模式 PII |
| --- | --- | --- |
| **用户气泡** | 替换后的文本 | **用户原文** |
| **交给模型** | 替换后的文本 | 脱敏后的文本 |
| **本地历史** | 与界面一致（替换后） | **原文**（在用户自己的数据根） |

**读法（两个方向都要看清）：**

- **敏感词**：用户气泡、交给模型、本地历史**三者一致**（都是替换后）。用户的输入框也已经被就地替换了 —— 他看到的自己发出去的就是打码版。
- **PII**：只有**交给模型**的那一份是脱敏的。用户气泡与本地历史存**原文**。

**为什么 PII 不脱敏本地历史：** 数据根是**用户自己的机器上的文件**，不是外传面。把用户自己打的字在他自己的历史里改成 `****`，只会让他之后搜不到自己发过什么 —— 脱敏的目的是"少外传"，不是"让用户看不见自己的话"。

**由此产生的一条交互约束：** 用户在气泡里看到 `13812341234`（原文），而模型收到的是 `138****1234`。§3.1 的展开说明就是为了讲清这件事 —— 否则用户会以为"我发的原文被改掉了"。

## 7 验收

| # | 验收项 | 判据 |
| --- | --- | --- |
| 1 | 三处同时存在 | 隐私模式会话：细条 + 芯片标签 + 侧栏盾牌**同时**可见 |
| 2 | 切模式全消失 | 切到智能或默认 → 三处**全部**消失 |
| 3 | 提示不消失 | 停留 1 分钟不用鼠标 → 细条仍在（不是 Toast） |
| 4 | 细条不挡输入 | 细条不覆盖输入框，不阻断点击 |
| 5 | 判据唯一 | `rg "=== 'privacy'" web/src` 只有 `chatMode.ts` 一处 |
| 6 | 只有当前分组有盾牌 | 选择器里非当前分组**不**显示盾牌 |
| 7 | 手机号脱敏 | 发 `13812341234` → 模型收到 `138****1234` |
| 8 | 多处都处理 | 一条消息里两个手机号 → 两个都脱敏 |
| 9 | 气泡与历史是原文 | 用户气泡显示 `13812341234`；重读历史仍是原文 |
| 10 | 与敏感词独立 | 关掉输入敏感词检测 → PII 仍生效 |
| 11 | 文案不越界 | 细条文案不含"身份证""银行卡" |
| 12 | 非隐私模式不脱敏 | 智能/默认模式发手机号 → 交给模型的是原文 |
