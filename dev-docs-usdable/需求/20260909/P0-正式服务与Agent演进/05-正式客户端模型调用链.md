# P0-05：正式客户端模型调用链

| 项 | 内容 |
| --- | --- |
| 当前仓库主责 | 客户端 Agent/Server/UI 组 |
| 中台协作方式 | 仅使用 P0-02/03/04 对应的外部 sandbox；不在本任务实现网关、账本或控制面 |
| 可并行 | 可先按 mock client/contract sample 开发；真实集成依赖 P0-02/03/04 sandbox |
| 依赖 | P0-01、P0-02、P0-03、P0-04 |
| 需求基线 | [P0 正式上线需求基线](../P0-正式上线需求基线.md) R1、R4、R5；production 不得走本地 provider，所有 profile 均无本地扣费模拟 |

## 目标

把现有 `config/endpoints`、`senderForSession()` 和聊天模式链路迁出或收口到 `productruntime`：production 会话只能绑定外部中台 catalog 中的模型，由 gateway sender（`gateway.NewObserver(app.NewSender(...))`，见 P0-01/P0-03）调用网关；developer 行为仍可保留，developer 作为其本地功能集合，避免破坏现有研发验证与维护能力。`ensureLocalEndpoint()` 与假模型种入已删除（2026-09-11）。本任务是客户端会话、UI 与 Profile 的集成，不包含任何中台服务实现。

## 实施步骤

1. 为 session 保存稳定的 `modelId`、catalog version 与 policy version，不保存 supplier endpoint/key；目录刷新后已删除模型不得用于新回合。
2. 由 `productruntime` 装配 sender：production 忽略本地 endpoint，构造 gateway sender；developer 保持现有 config provider 解析。除 P0-00 单独批准的通用端口外，不向 `internal/server` 增加产品逻辑。
3. 改造 chat mode handler：从 `ControlPlaneClient.Models()` 读取模式/模型，缓存失效时明确展示“目录暂不可用”，不静默回落本地确定性模型。
4. 将 endpoint 管理组件在 production 隐藏；直接调用本地 config route 也不能把外部 endpoint 绑定进 production session。
5. 将 gateway 的 `clientRequestId`、SSE usage、错误码和余额状态转成现有 session/WS/UI 事件；会话仍本地保存原文及产物。
6. 模型工具调用进入 P0-04 的 PEP，不能因来自 gateway sender 而跳过确认。
7. **删除** `internal/server` 的 `consumeCredit()`、`internal/productstate.Store.ConsumeCredit()`、`initialCredits` 与 `productstate.Credits` mock，并删除“每成功发送一条消息扣一分/0 分仍可发”的接口响应和测试。任何 profile 都不保留本地扣减模拟；余额只来自 `UsageClient` 与 gateway 的终态事件，缓存须注明来源版本和 `asOf` 时间。

## 回归和验收

- developer 测试继续使用 local provider（**需显式配置 endpoint**，不再自动种入），且不再产生本地积分扣减；production contract sample 不含任何本地 provider 配置也能完成真实流式调用。
- **production 二进制里不存在 local provider 的回复引擎**（P11 §7.1，2026-09-11）：`product_production` 构建下 `internal/provider/local` 只剩恒失败的桩，演示文案与 `data/logs/local-provider.jsonl` 均不进入产物。`make test-production` 与 `package-portable.mjs` 的 `checkProductionBinary()` 是这条的防回潮。**这与下面第 2 条是两回事，都要满足**：本条的失效是结构化的（发不出假回复），下面的选择判断才是"不选中它"。
- catalog 中无资格模型、目录过期、token 失效、余额不足、SSE 中断、模型下架均有 UI/状态测试。`chatmode` 的模式分组来自签名目录投影；目录不可用时展示「目录暂不可用」，出厂态不再列出任何 `buding-*` 假模型。
- 生产包配置目录出现 API key 后，静态扫描与运行时断言都证明该 key 未被读取用于模型调用（developer/test 不受此约束）。

## 合并策略

第一 PR 加 sender/目录接口与 mock；第二 PR 改 session/chat mode；第三 PR 改生产 UI/profile guard。保持每一步能跑 developer，远端联调开关不提前默认开启。
