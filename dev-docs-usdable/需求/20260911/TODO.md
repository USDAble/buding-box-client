**判据（`开发规范` §3.10 写清范围）**：进本清单的项必须同时满足 ① 与任何 `L-*` 闭环的**验收无关**或 ② 是**大功能**，修它会挤掉真正卡验收的工作。**不满足者不得进本清单** —— 如果是闭环要求的，就必须在闭环期修完，缺的只是 PR 归属，那种情况记在 `开发计划.md` §1.1 或该 PR 的方案里。

## 登记约定

- 每条格式：**编号 / 关联 `V-n` / 标题 / 为什么可以等 / 现在什么样（用户可见）/ 接手点 / owner**。
- **「现在什么样」必须写实**：不写"体验欠佳"，要写清用户或开发者此刻会看到什么。含糊的登记等于没登记（沿用 [`待解决问题.md`](待解决问题.md) 的同一条约定）。
- **「接手点」不得为空**。写"以后再说"的条目不是记录，是逃避 —— 要么给 PR 号，要么给触发条件（"下次改 X 时"）。
- 做完一条**不删行**，把状态改为 ✅ 并注明落在哪个 commit/PR（保留"曾经记过"的痕迹，便于回溯为什么当时不修）。
