# 内容安全防护

写作参照：`dev-docs/permission-remember-design.md`

> 内容安全防护分为用户可选择的输入保护、不可关闭的输出打码和始终启用的昵称校验。内置、用户和已验证服务端词共同组成同一引擎的有效词库；前端检测只改善反馈，不能成为安全边界。

## 范围

本文件定义违规或不适宜内容的输入、输出和昵称防护边界。词库编辑行为由 [词库管理](词库管理.md) 定义，接口形状由 [本地 API 契约](本地API契约.md) 定义；个人信息脱敏与模型处理边界由 [个人信息保护与私密会话](个人信息保护与私密会话.md) 定义。

## 非目标

- 不把客户端即时检测当作发送链路的替代。
- 不让用户关闭输出打码或昵称校验。
- 不识别一段内容是否属于商业秘密、内部资料或其他机密信息。
- 不把个人信息保护、私密会话与内容安全词库合并成一个开关或一套规则。

## 输入保护可由用户选择

开启输入敏感词检测后，用户提交的正文在广播、落库和模型请求之前检查。命中时拒绝当前输入，向该会话发送带打码文本的 `input_sensitive` 事件；前端以此恢复可编辑内容并提示原因。被拒文本不进入会话记录，也不产生模型请求。

关闭前应给出明确确认。关闭影响后续输入，不修改既有消息，不关闭输出防护、昵称校验或个人信息保护。即时检查接口只用于输入框预览；服务端发送链路必须使用同一词库再次判定。

输入检查不再以单独一行常驻输入框底部；它进入“安全与隐私”面板的“内容安全防护”条目。条目中的开关只控制用户输入检查，并同时说明“模型输出与昵称始终防护”，避免一个总开关让用户误以为关闭了全部安全能力。词库编辑仍从个人中心进入，不塞进输入区弹层。

输入检查开关继续使用账户级偏好，对当前账号的所有会话生效，而不是当前会话字段。面板条目必须显示“对所有会话生效”，修改后通过产品状态同步到其他窗口；个人信息保护和私密会话则是当前会话级状态，三者不能因为位于同一面板就混淆作用域。

## 输出与昵称不能绕过

模型或工具输出的敏感内容由同一进程引擎包裹发送器；流式回复以一次快照跨 chunk 匹配后再显示或落盘，不以“只提示”代替处理。昵称校验始终启用，先检查格式再检查词库；命中时拒绝而非存成打码昵称，并按本地 API 契约返回正确的业务结果。

输出过滤不截断模型回复；它改变可见和持久化文本，保留消息结构与回合完成语义。

## 词库和归一化只有一个所有者

内置词、用户词文件和最后一次验证通过的服务端词共同构成词库。词库引擎按文件变化和服务端词版本热更新；服务端词缺失或不可读时只移除该层，不会抹去内置和用户层。归一化、去重、命中和打码由唯一词库引擎定义；前端可做相同方向的预检，但不自行发明另一套符号表、词形规则或持久化格式。

用户词位于数据根，内置词不可由用户删除。用户词写入为原子替换，并保留文件开头连续的注释/空行；词条之后的注释不保证保留。词库读取、整份替换和导入分别遵循 [本地 API 契约](本地API契约.md)，写入后的实际词表由服务端返回。

## 与个人信息保护和私密会话的边界

内容安全防护判断的是内容能否输入、展示和持久化；个人信息保护在消息落库前执行不可逆脱敏，保存和发送同一份脱敏文本；私密会话限制整段对话只能交给可信的私有模型处理。三项能力使用不同事实源和失败策略，不能因为其中一项开启或关闭而静默改变另外两项。

当前代码已经实现内容安全防护，但尚未实现上述个人信息不可逆脱敏。界面中“发送前处理手机号”等表述不能作为已经具备该能力的证明；实现前以 [个人信息保护与私密会话](个人信息保护与私密会话.md) 的目标边界为准。

## 验证

- 输入命中在任何发送入口都被同一规则拒绝，且不广播原文、不落盘、不调用模型；前端收到会话级打码回填。
- 输出总是跨流分片打码后再显示和持久化；昵称总是校验；用户开关只影响输入保护。
- 即时检测、词库编辑和发送链路对同一词条给出一致结论；用户词写入后无需重启即可被引擎读取。
- “安全与隐私”面板中的三个条目分别说明状态；关闭输入检查不会改变个人信息保护或私密会话。
