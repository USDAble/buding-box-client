## 2. 逐个 PR

### `PR-1` 契约层 + 中台替身 + 客户端骨架（最小范围）

**为什么三者必须同一个 PR：** 替身是客户端的**镜像**。先写替身会发明一份契约，再写客户端又发明一份，两份必然漂移 —— 正是 `§3.8` 禁止的"同一件事两处定义"。**一份 Go 类型，两个实现**，替身才具备证明力。

> **⚠️ 实施期范围修正（2026-09-11，落代码时发现，已按此实现）。** 本节原先把 JCS + ed25519 验签列在 `PR-1`。**这是错的**：`PR-1` 的四个端点（发码 / 登录 / 刷新 / bootstrap）**没有任何签名要验** —— 需要验签的是**签名目录与策略信封**。而 bootstrap 在合同里**同时返回目录**（`中台交付包` §4.1 第 5 行：账户摘要 + 权益 + 余额 + **模型目录** + 能力矩阵 + 策略版本），所以正确做法是**把 bootstrap 收敛为「账户 + 激活 + 余额」，目录与能力矩阵留到 `PR-4`**，签名代码整体下沉到 `PR-4`。理由有二：① 让 `PR-1` 不包含本题**唯一没有现成实现**的一处，符合"先走通流程、别太复杂"；② JCS 是 RFC 8785，手写一份不合规的实现比不写更危险，它应当与目录一起一次做对。**bootstrap 不带目录是合法状态，不是错误**（`B4`：目录未就绪时选择器为空 + 不可用提示）。

**做：**

1. `internal/productclient/` —— **契约层**：`dto.go`（请求/响应类型 + 错误码常量，是字段名与错误码的**唯一 owner**）+ `client.go`（4 个端点 + 内存凭证持有者 + 401 单飞刷新与一次重放，即 `PR-1` 即已落地 `L-A6`）。
2. `internal/productclient/clienttest/` —— **中台替身**：真 HTTP handler、可编排场景、含测试码重置，**与客户端共用上面那份类型**。
3. 测试：用替身驱动客户端，覆盖 `L-A1a` `L-A2`–`L-A6` 的**客户端侧**分支（`L-A1b` 有意不实现）。

**不做（留到后续 PR）：** **JCS + ed25519 签名/验签（下沉 `PR-4`）**、模型目录与能力矩阵（`PR-4`）、网关 SSE（`PR-5`）、词库（`PR-6`）、`/api/product/*` 本地服务（`PR-2`）、前端接线、`devBackend` 拆除、可执行替身文件。

**验收：**

- 用替身跑通 `L-A2`（二次登录**不需要**激活码与盒子编号）、`L-A5`（bootstrap 回填 `boxCode`；缺失时是空值而非报错）、`L-A6`（401 单飞刷新一次 + 重放一次；刷新被拒 → 清凭证 + `ErrSessionExpired`，不重试）。
- 四个激活错误码（`activation_invalid` / `activation_code_used` / `box_code_unknown` / `box_code_mismatch`）**各自**可被触发并断言（`L-A4`）；`phone_mismatch` 亦单列。
- 同一盒子编号 + 两个不同激活码 → **两次都成功**（`L-A4` 的一对多回归）。
- 平台完全不可达 → `network_unavailable`（与上游 5xx 区分，且**不**回落本地模型源）。
- `L-A1b` 的"响应已送达但响应丢失"分支 **不实现**，登记为 `PQ25` 的未决面。

**替身的形态：**

| 项 | 定 |
| --- | --- |
| 落点 | 库 `internal/productclient/clienttest`（仓库内，测试可用），暴露 `Handler()` 由调用方用 `httptest.NewServer` 包起来。**不做**独立的可执行替身文件 —— 最小范围内它只服务 Go 测试；前端 E2E 需要它时再补（那是 `PR-2` 之后的事） |
| 隔离 | 仅被 `_test.go` 引用 ⇒ 不可能进入便携包；`PR-9` 的 preflight 加一条断言兜底 |
| 契约来源 | **import `internal/productclient` 的类型**，不重写 JSON schema |
| 签名 | **`PR-1` 不需要签名**（四个端点都不验签，见上方范围修正）。测试密钥与签名能力随 `PR-4` 的目录/策略一起引入 |
| 场景编排 | 用特定手机号 / 激活码触发特定错误码，使每个分支**按需到达**（Sandbox 做不到这点）。已内置：同一盒子编号的两个激活码（一对多）、只发给特定手机的激活码（`phone_mismatch`）、未知盒子编号、真实但对不上的盒子编号、失效访问令牌、被撤销的刷新令牌、平台不可达 |
| 重置 | `New()` 每次都是干净状态，等价于重置测试激活码，对应 `S-8` 要中台提供的那一项 |

**同时定死 `V-7`（首启初始化时序）** —— 此前四处未写：责任人、时刻、初值、只读盘行为。结论落在 `需求基线` `E6.4`：

- **责任人 = Go 本地服务**。`installId` 是「这台安装」的属性，而安装边界＝数据根，数据根的唯一 owner 是 `internal/datapath`；让桌面壳生成会造出**第二个路径与生命周期的 owner**（§3.8）。壳只把**系统语言**带进来一次（`PQ18`）。
- **时刻 = 首次读取时惰性创建**，不新增任何"进程启动写文件"的路径。比 §3.9.1 允许的"启动时幂等播种"更强：**没有任何一次进程启动会写文件**。
- **只读盘 / 写失败 ⇒ 内存默认值让界面可渲染 + 错误向上返回**，不阻塞启动、**不假装已持久化**。
- **与 `E6.2` 规则 4/5 的顺序**：文件**不存在**才播种；版本**超前**与文件**损坏**都**不得**进入播种路径（否则新版本或损坏数据会被空白状态悄悄替换）。

**明确的边界（本 PR 不做）**：HTTP handler、产品门、`internal/server` 的接线、凭证与 `productclient` 的对接（令牌从内存到凭证文件的搬运）。这些是 `PR-2b1` / `PR-2b2a`。

### `PR-2b1` 本地 `/api/product/*` 端点（已完成）

**做：** `internal/productruntime` 承载 5 个端点（`GET /state`、`POST /send-code`、`POST /login`、`POST /logout`、`PUT /locale`），按 [`本地API契约.md`](本地API契约.md) 的三类信封与错误码实现。

**实施期定下三件契约上的事（都已回写文档）：**

1. **信封层级由本地契约决定，不由中台决定。** 中台会在错误体里带 `field`（它把 `activation_invalid` 标成 `activationCode` 的错），但 `本地API契约.md` §3 把这四个激活失败定为**业务级**，所以实现忽略中台的 `field`。理由：用户改不动这些值（`activation_code_used` 只能找客服），落在输入框下面会误导成"改一下就能过"。层级表只有 3 个字段级 code，落在 `envelope.go` 的 `fieldLevelCodes`。
2. **`invalid_phone` / `invalid_code` 同名两层的消解规则**：格式问题在**本地校验**阶段拦下（`validPhone` / `validCode`），所以**凡从中台回来的同码按业务级处理**。这条不写下来，实现者一定会"顺手统一"。
3. **`phoneMasked` 必须由中台给**（新增字段，`中台交付包` §3.2 已补）。触发 `phone_mismatch` 的典型场景是「全新 `data/` + 已被绑定的激活码」，本地从没见过那个号码。
4. **新增 `control_plane_unconfigured`**（已登记入 `本地API契约` §3）：本构建没配中台地址时返回它，使「未配置」与「中台挂了」可区分。S-6/S-7 的**页面口径仍未定**，本码不解决那件事。

### `PR-2b2a` 接线：把端点挂进服务（✅ **已完成 2026-09-11**，§3.3.1 顺位 3 已批准）

**为什么必须动核心文件** —— 已核实的事实（2026-09-11）：

| 事实 | 证据 |
| --- | --- |
| 便携包打的二进制是 `cmd/octo-desktop`，**该文件在上游 `main` 上** | `git cat-file -e main:cmd/octo-desktop/main.go` 命中；`scripts/package-portable.mjs` 打包该 exe |
| 该入口是**唯一**能挂产品路由的地方 | 全仓 `server.New(` 只有两处：`cmd/octo/serve.go`、`cmd/octo-desktop/main.go`（都在上游） |
| `internal/server` **没有**可用的扩展缝 | 只导出 `ListenAndServe` / `ServeOn`；`s.mux` 私有，无 `Handler()` |
| **不能直接挂在 `s.mux` 上** | 上游测试 `TestRegisterRoutes_OnlyKnownUnauthenticated`（`auth_test.go:266`）断言**直接注册只允许 4 条**（health / version / mcp oauth / `/`），新增直接注册即**测试失败**；且直挂会绕过 `requireAuth`，比其它所有路由都弱 |
| 浏览器侧够不到端点不是因为鉴权，而是**没有路由** | `requireAuth`（`auth.go:290`）对 **loopback** 请求放行，桌面 webview 走的就是这条豁免 —— 与它今天调用 `/api/sessions` 等完全相同 |

**方案（顺位 2：只加一个通用缝，改动以行计）**

1. **`internal/server/server.go`** —— 加**一个可选、无产品名词**的字段，形状**照抄既有 `s.api` 的注册器**（不是给裸 `mux`）：
   ```go
   // OCTO-FORK: 产品路由的挂载缝；只暴露既有 s.api 注册器，不带任何产品词汇 —
   // see dev-docs-usdable/需求/20260911/开发计划.md §PR-2b2a
   MountAPI func(api func(pattern string, h http.HandlerFunc))
   ```
   并在 `s.api(...)` 注册区（native 块之后）加 3 行调用它。
