## 1. WebView2 缺失检测会误判，把「装了但读不到」当成「没装」直接退出

- **状态**：未解决
- **发现时间**：2026-09-08
- **位置**：`cmd/octo-desktop/webview2_windows.go`
- **现象**：用户在干净 Windows 上装了 WebView2 Evergreen Runtime，但注册表 key 位置特殊（企业环境常见）或读取失败（权限/损坏）时，启动被误判为「未装」，弹出 FatalDialog 直接退出，无法使用。
- **根因**：
  1. 用**读注册表 key**（`SOFTWARE\Microsoft\EdgeUpdate\Clients\{F3017226-…}\pv`）作为「是否已装」的**间接代理**，而不是真实可用性信号。
  2. `webview2ClientKey` 里 `if err != nil { return false }` 把「key 不存在（`registry.ErrNotExist`）」和「读取失败（权限/损坏等其它错误）」混成一个 `false`。其实 `golang.org/x/sys/windows/registry` 能用 `ErrNotExist` 区分两者。
  3. 注释还误称「`CreateWebView2EnvironmentWithOptions` 会在缺运行时弹安装 UI」——**已核实不成立**：官方文档与 WebView2Feedback 多个 issue 确认它缺运行时只返回 `0x80070002`（`ERROR_FILE_NOT_FOUND`），不弹任何 UI。
- **为何暂缓**：
  - 这是 Windows 专属代码，macOS 开发机上无法编译/验证，必须在一台干净 Win10/Server 虚机（无 WebView2）验收，本轮排期不包含 Windows 虚机验证环境。
  - 触发概率低：标准 Evergreen 安装的 key 可正常读取，误判主要发生在企业受管 / 特殊安装环境。
  - 与 P12「便携打包」独立，不必捆绑。
- **建议方案**（推荐第 1 条）：
  1. **改用官方 `GetAvailableBrowserVersionString()`** 替代读注册表，缺运行时它抛 `WebView2RuntimeNotFoundException`——直接信号，不受 key 位置/权限影响。
  2. **检测不到时先试开窗口、起不来再弹 FatalDialog**（贴合 P2 §236「宁可多试一次」）。因为上面已核实「试窗口」最坏只返回错误、不会弹安装 UI，所以几乎零风险。
- **验收要求**：在无 WebView2 的干净 Win10 虚机上双击 → 出说明不闪退；在有 WebView2 的机器上 → 正常开窗。
