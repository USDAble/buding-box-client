## 1. 背景与目标

> **v0.2 实施前置条件**：正式中台规范已迁移至同目录 [中台交付包.md](中台交付包.md)。B0 不得定义任何客户端扣费接口。正式远程链路由模型网关在同一 `clientRequestId` 下完成 token 预留、调用、结算与账本；客户端只读用量/余额和请求终态。当前代码的 `consumeCredit` / `ConsumeCredit` 是待删除的 mock，不迁入 `backend/local`、不保留兼容路径；由 P0-05 在接入 gateway sender 时连同调用点和测试一起删除。模型目录来自中台，供应商 endpoint/key 不进入标准客户端。

### 1.1 为什么现在做

当前产品从登录到模型，整条链路是「本地假数据」，但 mock 逻辑**散落且无抽象**：

- 验证码 `fixedCode="123456"`、激活码 `activationCode="BUDING-DEMO-0001"`、假 token `newAccountToken()`、积分 `initialCredits=1280` —— 全是 `internal/server` 包的常量与函数，不是「一个可替换的后端」。
- `internal/server` 直接依赖 `internal/productstate`（状态文件）、`internal/chatmode`（模型分组）、`internal/sensitive`（词库），每一层都 `s.productState.Mutate(...)` 裸操作，**接中台时每个 handler 都要改**。
- 没有「产品服务」接口，意味着「本地假数据」和「中台」无法并存、无法切换、无法独立测试。

**目标**：建立 `internal/backend` 抽象层，定义“产品后端能力”的接口，并由很薄的 `internal/productapp` 协调用例；local/remote adapter 可以替换，UI、agent 与 transport 不感知数据来源。B0/B1 对尚存的演示行为尽量做等价迁移，但固定验证码、假 token、固定积分等不能成为 production 兼容承诺；其中本地扣费 mock 按 P0-05 删除。

### 1.2 与中台对接的关系

本计划只涉及当前仓库的客户端边界和 adapter；`backend/remote` 也是当前仓库内的 HTTP 客户端适配器。中台远程服务、模型网关、账本、数据库和部署始终不在本计划内。接中台时，客户端应新增/替换 adapter 并在 composition root 装配；handler 只进行 transport 映射，产品规则统一进入 `productapp`，不承诺“不改 handler”。

## 3. 抽象层设计

### 3.1 边界：什么抽象、什么不抽象

**抽象（会接中台的业务能力）**：

| 服务 | 职责 |
|---|---|
| `AuthPort` | 发验证码、登录（含首次激活）、刷新、登出 |
| `ControlPlanePort` | bootstrap、模型目录、能力/词库版本与服务器通用词库（第三级词源） |
| `UsageReader` | 余额/用量摘要与 `clientRequestId` 的最终状态查询；**不提供客户端扣减** |

**不抽象（本地纯机制，永不接中台，抽象只会制造噪音）**：

- 产品门 `internal/productgate`（进程内 window token，是「拦窗口」机制不是业务数据）
- 敏感词匹配引擎 `internal/sensitive`（确定性本地算法）
- PII 脱敏 `internal/pii`（本地函数）
- 昵称校验规则、手机号规范化 `internal/productstate`（本地函数）
- 会话存储、数据根 `internal/agent` / `internal/datapath`

**边界判据**：一件事「现在本地、将来远程」→ 抽象；一件事「永远本地」→ 不抽象。**别把敏感词引擎、PII、昵称校验也抽象进 backend——它们不会变远程，抽象了只会让本地调用绕一圈。**

### 3.2 依赖方向

```
internal/server ──► internal/productapp ──► internal/backend (ports)
                                                   ▲
                           ┌───────────────────────┴───────────────────────┐
                    backend/local (本地实现)                       backend/remote (中台实现)
                           │
                           └──► productstate / chatmode / sensitive / fixture
```

- `internal/server` 只负责 HTTP/WS/native transport、路由与 composition，通过 `productapp` 调用用例；不在 handler 直接调用具体 adapter、写余额或决定产品权限。
- `internal/productapp` 依赖 `backend` ports、agent/PEP/session 等用例所需的窄接口，不依赖 Web 或具体 HTTP 协议。
- `backend/local` 收口本地 projection、fixture 和仍需保留的演示行为；固定扣分不进入任何 local adapter。
- 单向依赖，符合 `.octorules` 的一方向依赖约定。

### 3.3 接口定义（Go 骨架）

```go
package backend

import (
    "context"
    "time"
)

// Backend aggregates the product services a portable client talks to. The
// server layer depends on this interface only, never on a concrete impl.
type Backend interface {
    Auth() AuthPort
    ControlPlane() ControlPlanePort
    Usage() UsageReader
}

// AuthPort is the login / activation / logout surface. First login carries
// an activation code (首次激活); subsequent logins do not.
type AuthPort interface {
    // SendCode requests an SMS code for the normalized phone, returning the
    // resend cooldown in seconds.
    SendCode(ctx context.Context, phone string) (cooldownSec int, err error)
    // Login validates the code (+ activation code on first login) and returns
    // the resulting account snapshot. Errors carry machine codes the frontend
    // maps to copy (see 3.4).
    Login(ctx context.Context, req LoginRequest) (*LoginResult, error)
    // Refresh rotates a refresh token and returns a new short-lived product
    // session. Concurrent-refresh suppression lives in the remote adapter.
    Refresh(ctx context.Context, req RefreshRequest) (*Session, error)
    // Logout clears the login token, keeping the device binding.
    Logout(ctx context.Context) error
}

type LoginRequest struct {
    Phone          string // normalized 11-digit
    Code           string // 6-digit SMS code
    Nickname       string
    ActivationCode string // required on first login, ignored after
}

type LoginResult struct {
    Account    Account
    Session    Session
    Activation *Activation // non-nil on first login
}

type RefreshRequest struct {
    RefreshToken string
    InstallID    string
}

type Session struct {
    AccessToken  string
    RefreshToken string
    ExpiresAt    time.Time
}

type Account struct {
    Phone       string
    PhoneMasked string
    Nickname    string
    LastLoginAt time.Time
}

type Activation struct {
    Activated   bool
    Code        string
    ActivatedAt time.Time
    ExpiresAt   time.Time
}

// UsageReader is a read-only view of server-authoritative usage. Production
// clients never calculate or submit a debit; ModelGatewaySender receives the
// terminal usage state from the gateway under the same clientRequestId.
type UsageReader interface {
    Usage(ctx context.Context) (Usage, error)
    RequestStatus(ctx context.Context, clientRequestID string) (RequestStatus, error)
}

type Usage struct {
    BalanceMicroCredits int64
    MonthUsed           int
    MonthKey            string
}

type RequestStatus struct {
    ClientRequestID string
    State           string // settled | reversed | reconciliation_pending
    Usage           Usage
}

// ControlPlanePort is the client view of signed product configuration. The
// remote implementation validates its envelope before exposing any value.
type ControlPlanePort interface {
    Bootstrap(ctx context.Context) (Bootstrap, error)
    Models(ctx context.Context) ([]ChatMode, error)
    SensitiveDictionary(ctx context.Context, knownVersion string) (Dictionary, error)
}

type Bootstrap struct {
    Account           Account
    Activation        Activation
    Plan              Plan
    Usage             *Usage // nil for local/developer fixtures; required in production bootstrap
    CatalogVersion    string
    PolicyVersion     string
    DictionaryVersion string
}

type Plan struct {
    Name string // machine key, e.g. "trial"; display name from the i18n layer
}

type ChatMode struct {
    ID           string
    Models       []string
    DefaultModel string
}

type Dictionary struct {
    Version string
    Words   []string
    ETag    string
}
```

### 3.4 错误语义契约

现有前端依赖 machine code（`invalid_phone` / `code_not_sent` / `code_invalid` / `activation_invalid` / `phone_mismatch` / `nickname_format` / `nickname_sensitive`）。抽象层必须**保留这套语义**，否则接中台后前端映射会漂移。

```go
// AuthError is the typed error the server maps to machine codes. The local
// and remote impls both return it, so the frontend copy never changes.
type AuthError struct {
    Code        string // invalid_phone | code_not_sent | code_invalid | activation_invalid | phone_mismatch | nickname_format | nickname_sensitive
    Field       string // optional, for round-one field errors
    PhoneMasked string // optional, echoed on phone_mismatch
    RetryAfter  int    // optional, seconds, for cooldown
}

func (e *AuthError) Error() string { return e.Code }
```

**验收约束**：现有 `product_login_test.go` / `product_account_panel_test.go` 等测试必须**不改断言地全绿**——它们锁定了 machine code 语义，是「抽象层没改行为」的证明。

### 3.5 本地实现 `backend/local`

`backend/local` 只承载本地 projection、fixture 和仍需保留的演示行为；它不承担正式业务权威，也**不迁入固定扣分 mock**：

- `AuthPort` → 迁入 `product_login.go` 的 `fixedCode` / `activationCode` / `loginCodes` map / `checkCode` / `newAccountToken` / `handleProductSendCode` / `handleProductLogin` 的业务部分；落盘仍走 `productstate.Store`。
- `UsageReader` → local 实现返回明确的 `usage_unavailable`，不伪造余额、不读取、不调用 `productstate/credits.go` 的 `ConsumeCredit`。该 mock、初始积分及其 handler 调用点由 P0-05 删除；正式用量仅从 gateway 的最终事件与请求状态查询投影而来。
- `ControlPlanePort` → local `Bootstrap` 仅组合账号/激活/套餐，`Usage=nil`；模型目录迁入 `chatmode.Load` + `Builtin`；`SensitiveDictionary` 的 local 实现返回空词表与本地版本，词库引擎仍自行合并内置词与用户词。

**`productstate` 的去向**：它暂可由 `backend/local` 读取本地投影（`product-state.json`），但 `server` 只能通过 `productapp` 调用用例，不能直接 import 并写入产品业务状态。DTO 由 adapter 内部转换；`Prefs`（locale/defaultChatMode/inputSensitiveCheck）是本地偏好，不进入中台端口，后续由 `DeviceDataUseCase` 统一协调，避免把本地偏好误抽象成产品服务。

### 3.6 装配（server 启动）

`internal/server` 在 `New(...)` 的 composition root 构造 adapter 和 use case：

```go
// 本期可用 local/fake；接中台后在此处注入 remote adapter。
b := localbackend.New(dataRoot)
app := productapp.New(productapp.Dependencies{Backend: b /* PEP, sender, session ... */})
s.productApp = app
```

Handler 改为：

```go
res, err := s.productApp.Login(r.Context(), productapp.LoginInput{...})
```

`productstate.Sensitive`（昵称敏感词 hook）的注入点**从 server 移到 local 构造**，或作为依赖注入——这同时把 C13 的「失败开」问题一并处理（见 §6 附带修复）。

## 5. 验收标准

1. **受限的行为回归**：B0/B1 对登录、账户面板、敏感词、模型选择和 local endpoint 等未改变的行为维持现有回归；`product_credits` 的固定积分断言不是长期验收项，P0-05 必须随 mock 删除或重写为 gateway usage 测试。
2. **单向依赖**：`internal/server` 经 `productapp` 调用产品用例；新迁移路径不得直接 import `productstate` / `chatmode`，用 `go list -deps` 和 use case 单测验证。
3. **machine code 契约可演进**：`AuthError` 覆盖现有机器码及中台合同的新增码；前端映射变更必须同步契约测试，不能依赖服务端文本。
4. **切换点可控**：adapter 的构造和 profile 选择只有一处 composition；业务 handler 不得自行选择 local/remote 或直连中台。
5. **不抽象不该抽象的**：`sensitive` / `pii` / `productgate` / `datapath` 仍独立，未被 backend 吞并。

## 6. 附带修复（C13 失败开）

`internal/productstate/nickname.go` 的 `var Sensitive = func(v string) bool { return false }` 是“失败开”：某个入口没注入就静默放行。B4 已把默认实现改为“失败关”（未注入时判定为敏感，宁可误拦不可放行），并有回归测试。后续词库同步接入时，由 `productapp` 的 bootstrap/词库更新路径显式提供已验证词源，而不能恢复默认放行。
