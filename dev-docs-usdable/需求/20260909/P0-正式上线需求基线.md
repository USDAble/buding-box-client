## 1. 使用规则与冲突处理

这是一份**需求基线，不是技术方案**。它定义用户可获得的能力、不可突破的边界和上线判定；代码结构、包名和具体协议实现应由对应开发方案确定。

| 优先级 | 文档 | 解决的问题 |
| --- | --- | --- |
| 1 | 本文 | 产品范围、用户行为、安全/计费底线和 P0 完成条件 |
| 2 | [中台交付包](产品客户端与中台对接/中台交付包.md) | 对外 API、签名、网关、sandbox 与服务端验收合同 |
| 3 | [P0 子需求](P0-正式服务与Agent演进/README.md) | 当前客户端的包边界、开发方案、测试和交付物 |
| 4 | [问题盘点](问题盘点.md) | 现状证据、风险来源和待解决问题的完整清单 |

- 旧 `2260906` 文档只可作为既有交互和实现的参考；其旧积分、旧本地服务或与本文冲突的规则不能继续作为 P0 需求。
- 新发现会改变用户行为、收费、安全边界或中台字段的事项，先更新本文并经产品/客户端/中台三方确认，再写代码或接口；不能由某个工作区自行“补一个合理默认值”。
- 中台接口字段以版本化 OpenAPI 为准。客户端不得从接口文档推断供应商 URL、密钥、扣费金额或未定义的降级行为。

## 2. P0 的产品目标与范围

P0 的目标是让 Windows 便携客户端从本地研发验证聊天升级为可正式交付的个人工作 Agent 基座：真实账号可登录、可获取受信模型和能力策略、可经统一网关完成一次模型请求并看到可信用量状态，本地会话/文件/工具仍处于用户可理解和可撤销的控制下。

P0 不做工作流编排、后台自动化、团队/组织、跨端同步、多 Agent 委派、技能或 MCP 市场。这些能力后续复用 P0 的账号、策略、请求关联、凭证和数据边界，不得重建另一条旁路。

## 3. 已确认的正式需求

| ID | 正式需求 | 判定规则 |
| --- | --- | --- |
| R1 | 正式包与开发能力隔离 | `production` 包保留已有配置与能力实现，但首发 UI 不展示本地添加模型和隐藏菜单；P0-05 后正式会话不能将本地配置作为模型来源，直接调用配置接口也不能绕过网关。 |
| R2 | 手机号是当前唯一需要自动识别的 PII | 不为身份证、银行卡等未采集/未产品化字段承诺自动识别。手机号不得出现在模型发送副本、普通日志和诊断包；用户自由输入的其他 PII 通过发送告知、日志白名单和隐私模式降低风险。 |
| R3 | 账号、激活、套餐和用量语义独立 | `activation`、`plan`、`usage` 是三个独立概念：激活到期当前仅展示续期/客服入口；套餐到期须由中台返回权益与降级规则；余额或配额不足由模型网关拒绝请求，不能混称“授权到期”。换绑手机号仍仅支持客服。 |
| R4 | 模型目录和能力来自受信控制面 | 正式模型列表、模型能力、可见性、账号资格、敏感词版本和策略版本由中台下发并经版本/签名校验与缓存；供应商 endpoint 和 key 永不下发到标准客户端。离线时只可使用最后一次有效缓存所允许的能力，不能静默转到本地 provider。 |
| R5 | 模型请求只经中台网关，客户端不扣费 | 客户端提交 `clientRequestId`、受信 `modelId` 和经隐私处理的消息；网关完成鉴权、预留、供应商调用、token 结算和不可变账本。P0 后不存在“每条消息扣一分”、客户端传 `amount` 或本地写余额的路径。 |
| R6 | 高风险工具由本地最终拦截 | 文件读写、终端、联网外发、后台持续执行等动作必须经过本地 PEP；隐藏菜单、模型输出、外部网页/文件内容和远端策略都不能直接授权。高风险操作说明对象、影响范围、是否记住和撤销方式。 |
| R7 | 敏感词库为三层并集 | 内置词、本地用户词和服务器通用词共同生效。服务器词只读，按版本/签名/原子缓存更新；拉取失败继续使用内置词、最近有效缓存和用户词，不能清空词库或阻塞启动。 |
| R8 | 凭证和本地数据可恢复且不可随数据根复制 | access/refresh token 不进入 `product-state.json`、导出、备份或诊断包；凭证进入平台安全存储并支持轮换、撤销和重新登录。本地偏好、账号/用量投影、目录/策略缓存、会话/产物按不同恢复价值分别版本化和迁移。 |
| R9 | 便携更新可用但由用户确认 | 更新流程为检查、展示版本/变更/包摘要、用户确认下载、校验签名和哈希、替换、重启自检；失败保留可运行旧版本并可诊断。正式包不能静默替换，也不能信任未签名更新清单。 |
| R10 | 内容安全与服务异常可解释 | 内容安全、限流、维护、鉴权、配额不足等由机器码驱动 UI；被拒绝的内容不触发工具、不展示已判定不安全的流片段，也不产生未经服务端证实的扣费。用户能带脱敏请求 ID 找到支持路径。 |
| R11 | 正式协议、隐私告知与版本同意可追溯 | 由产品/法务交付已批准的用户协议、隐私政策和适用版本；客户端不得发布未批准文本。若批准规则要求显式同意，客户端展示文档类型/版本/摘要/生效时间，且只按中台合同提交确认；服务端以账号、文档版本、时间和来源记录，本地文件不能制造同意状态。 |
| R12 | 标准包的入口可见性与 Profile 不可绕过 | `production` 对开发 WebView URL、provider/model 环境变量和数据根 override 有明确拒绝规则；`config.yml`、channel、MCP、工具与后台能力保留既有功能，首发只控制 UI 可见性并由能力矩阵和本地 PEP 约束实际执行。`config.yml` 的 endpoint/URL/key 在 developer/test **完全允许**，受限的只是 production 正式会话的模型来源。Profile 只能由嵌入二进制的全局配置和构建标签决定，任何运行时输入都不能切换为 `developer`。 |

## 4. 关键名词与端到端闭环

| 名词 | 权威来源 | 客户端职责 |
| --- | --- | --- |
| 账号与会话 | 中台身份服务 | 安全保存凭证、刷新/撤销、呈现最小账户摘要 |
| 激活授权 | 中台账户摘要 | 展示状态和续期/客服入口；当前不等同于模型配额拦截 |
| 套餐/权益 | 中台 entitlement | 决定可见模型和能力，不由前端自行推算 |
| 用量/余额/账本 | 中台模型网关 | 只读投影、按 `clientRequestId` 查询终态；不本地扣减 |
| 模型目录/策略 | 中台控制面 | 验签、缓存、将策略在本地 PEP 执行 |
| 本地会话/产物/用户词 | 客户端数据根 | 本地优先保存、按数据类型迁移/导出/清理 |

一次正式模型回合必须可闭环追踪：用户选择受信模型 → 客户端冻结 `clientRequestId`、目录/策略版本并生成发送副本 → PEP 拦截需要确认的工具动作 → 网关返回流与最终用量 → 客户端写本地会话和只读用量投影 → 用户/客服可用脱敏请求 ID 查询结果。取消、断网、重试、余额不足和策略撤销必须都有明确终态；客户端不得猜测余额或制造成功终态。

## 5. 当前仓库与中台的边界

| 名称 | 当前是否存在 | P0 后职责 | 是否在本仓库实现 |
| --- | --- | --- | --- |
| `internal/server` | **存在，且来自上游核心运行时** | 保持 HTTP/WS、agent、会话和工具；2026-09-08/09 加入的布丁产品 handler/策略按 [P0-01A](P0-正式服务与Agent演进/01A-既有产品逻辑迁出internal-server.md) 迁至 `productruntime`，P0 默认不改 server | 是，但仅保留无产品业务语义、经 P0-00 单独批准的通用扩展端口 |
| `internal/runtimeport` | **不存在；仅当 P0-01A 证明 desktop 无法装配时才创建** | `internal/server` 与 `internal/productruntime` 共同依赖的中性扩展接口（认证后路由注册器、请求过滤器、turn 上下文钩子）；不含 `product`/账号/积分/词库/供应商等业务名词 | 是；不承载产品语义，也不允许 server 反向依赖 productruntime |
| `internal/productruntime` | **不存在，P0 新建** | 产品 HTTP 映射、运行时装配、聊天前置策略及既有布丁 server 逻辑的迁移归属；协调 product client/policy/credential，不复制上游 server | 是 |
| `internal/productprofile` | **已存在（P0-00 落地）** | 解析嵌入二进制的 `production`/`developer` 全局 Profile；控制启动面和是否可读开发来源。P0-01 只消费它，不重复定义 | 是；不是用户可写的 `config.yml` |
| `internal/productclient` | **不存在，P0 新建** | 客户端对中台身份、控制面、词库和只读 usage 的 DTO、错误码、remote client/合同测试实现；`gateway` 子包适配模型流 | 是；不是中台服务，也不写客户端扣费 |
| `internal/productpolicy` | **不存在，P0 新建** | 已签名 catalog/能力矩阵缓存与本地 PEP 决策；只消费已由发布物确定的 profile | 是；不调用中台 HTTP、不决定 profile、不替代上游 permission 引擎 |
| `internal/credentialstore` | **不存在，P0 新建** | 平台安全存储可轮换的 refresh token；access token 仅驻留内存 | 是；不保存会话原文、账号投影或供应商 key |
| 中台控制面/模型网关/账本 | 不属于本仓库 | 身份、目录、策略、网关、token 结算、审计、发布合同 | 否；仅交付接口与验收材料 |

目标依赖方向是：`cmd/octo-desktop -> productprofile + productruntime -> productclient / productclient/gateway / productpolicy / credentialstore`；`internal/server` 保持上游运行时，只在无其他路径时提供一个通用窄扩展端口（`internal/runtimeport`，仅当 P0-01A 证明 desktop 无法装配时创建）。新产品包不依赖 server；模型流协议由 gateway 子包适配外部网关，本地工具仍受 PEP 约束。`internal/server` 不承载签名、重试、账本或任何新的中台业务计算。

## 6. 中台必须交付的外部合同

客户端不能用“先写一个临时接口”替代以下交付物。详细字段、签名和验收见[中台交付包](产品客户端与中台对接/中台交付包.md)。

1. 版本化 OpenAPI、错误码登记、兼容与废弃策略，以及可复现的 sandbox、contract sample 和测试账号。
2. 手机验证码、登录、刷新、登出、账号/激活/套餐/用量摘要与设备撤销的服务端语义。
3. bootstrap、模型目录、能力矩阵、服务器敏感词和发布策略的签名、版本、缓存/过期与最小客户端版本规则。
4. 唯一模型网关：短期产品令牌、SSE、取消/重试/请求状态查询、`clientRequestId` 幂等、token 预留/结算/冲正和可检索账本。
5. 内容安全、限流、维护、封禁、隐私删除/保留、支持升级和审计的机器码与运营流程。
6. 可验证的发布清单、包签名/哈希、回退规则和故障支持约定。
7. 产品/法务批准的协议、隐私告知及其版本；若产品要求显式确认，交付 bootstrap 的当前版本/确认状态和版本化确认记录接口。

## 7. P0 发布门与尚待产品确认项

P0 完成不等于“接口打通”。发布候选包至少要通过：已批准的协议/隐私告知、真实账号登录/刷新/撤销、受信目录/策略加载、网关成功与取消/断网/重复请求、余额不足、工具拒绝、PII/日志/诊断包审查、数据迁移与拔盘恢复、更新失败回退、内容安全和 Windows 真机 E2E。

以下决策必须在相应功能进入真实联调前书面确认，未确认时客户端只能展示服务端已定义的最小状态，不自行发明业务规则：

| 决策 | 负责人 | 影响 |
| --- | --- | --- |
| 便携介质上的凭证语义：复制后是重新登录、受限恢复还是允许迁移 | 产品/安全/中台 | R8、设备撤销和客服流程 |
| 隐私删除的范围、保留期限、法定例外和完成回执 | 产品/法务/中台 | 删除入口、导出和支持流程 |
| 内容安全策略的 owner、申诉、限流/封禁和账务冲正规则 | 产品/运营/中台 | R10、错误文案和 E2E |

## 8. 协作约束

- 每个 P0 PR 必须注明对应的 R 编号、P0 工作包、使用的 OpenAPI/contract sample 版本和正反向验收场景。
- 改动对外字段、错误码、策略版本、用量状态或数据保留规则时，同步更新本文与中台交付包；改动只限客户端内部实现时，更新对应 P0 开发方案即可。
- 不允许为 unblock 联调而在正式链路回退到 local provider、明文 token、固定积分或隐藏入口可绕过的权限判断。中台未交付时使用版本化 合同测试实现/contract sample，且 合同测试实现 必须显式标记为测试依赖。
