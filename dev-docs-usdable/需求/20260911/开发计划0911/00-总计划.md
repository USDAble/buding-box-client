## 4. 开发顺序与工作包

### 4.1 第一优先级：`DEV-0911-01` 服务器词库同步（`L-D5`）

**用户可见结果：** 客户端拿到更新的服务器敏感词库后安全启用；更新无效或网络失败时继续使用上一份有效词库，并明确提示失败原因和当前使用的旧版本。

**建议分支：** `feat/l-d5-sensitive-dict-sync`

**实现范围：**

- 从中台获取只读服务器词库。
- 校验 `keyId`、签名和版本。
- 缓存固定落在 `data/sensitive-dict-server.json`，路径必须由 `internal/datapath` 提供。
- 只在验签成功且版本前进时原子替换。
- 相同版本不重写；低版本拒绝并保留旧文件。
- 断网、响应异常、验签失败、写盘失败时继续使用旧版。
- 没有旧版时只使用“内置词 ∪ 用户词”，不得关闭检测。
- 用户可感知失败必须提示一次，并说明恢复条件；不得重复弹窗轰炸。
- 服务器词库只读，不能通过现有词库管理 UI 修改。

**既有能力检索与复用结论：**

| 能力 | 必须复用 | 不新建第二套的理由 |
| --- | --- | --- |
| 版本单调、缓存装载、旧版保留 | `internal/catalogstore.Store.Put` / `Load` 的实现形状 | 已有版本回滚拒绝、同版本不重写、损坏文件保留的完整先例 |
| 原子写 | `internal/atomicfile.WriteFile` | 仓库已有唯一原子写能力，禁止再写临时文件/rename 逻辑 |
| 签名与信任锚 | `internal/productclient.PolicyEnvelope.Verify` 的信任链和 `VerifyOptions` 形状 | 验签机制只能有一个 owner；`PQ30` 只决定被签字节，不允许另起第二个验签器 |
| 敏感词加载与合并 | `internal/sensitive.Engine`、`BuiltinWords`、`UserWords` | 匹配、规范化和三层合并必须继续只有一份实现 |
| 用户提示 | 复用现有产品状态/toast/i18n 通道 | 不在 Go 错误字符串和前端各自定义第二套文案 |

**TDD 顺序：**

1. 先写可编译的最小骨架，返回 `not implemented`，确保测试语义性变红。
2. 写正向测试：有效新版本验签通过、写盘、下一次检测立即包含服务器独有词。
3. 写版本测试：相同版本不重写；低版本返回回滚错误且旧文件字节不变。
4. 写签名测试：篡改 `words`、错误 key、未知 key、错误 audience/时间窗口均拒绝。
5. 写降级测试：断网、500、畸形 JSON、写盘失败时旧版仍生效。
6. 写无旧版测试：失败后内置词和用户词仍生效，不能 fail-open。
7. 写恢复测试：失败提示出现一次；下次拿到有效新版本后恢复并清除失败状态。
8. 至少做一个变异：跳过签名、允许回滚、失败时清空词库，确认对应测试会红。
9. 最后写最小实现使全部测试转绿。

**完成判据：**

- `L-D5` 的篡改签名与断网两条验收均通过。
- 缓存文件原子替换，失败时旧版文件字节不变。
- 三层词库同时生效，服务器层不能覆盖另外两层。
- 用户知道当前降级到哪一版以及何时会重试。
- `make gate` 通过；若触及桌面壳或生产装配，`make test-production` 也通过。
- 同轮更新 `E2E闭环清单.md` 对应状态、`开发计划.md` 落地记录和必要的接口 owner。

**当前阻塞边界：** `PQ30` 没确认前可以完成下载、缓存、版本和降级代码与测试，但不得自行确定最终签名字节语义，也不得把 `L-D5` 标成 ✅。为避免分支超过五个工作日，优先在开分支前拿到 `PQ30` 结论。

### 4.2 第二优先级：`DEV-0911-02` 拔盘冻结与恢复（`L-E3` / `PR-7`）

**用户可见结果：** 程序运行期间目录消失时立即冻结界面并停止所有写操作；原路径恢复后可以继续，换盘符或换路径则提示退出后重新打开。

**建议分支：** `feat/pr-7-datastore-freeze`

**实施原则：**

- 先从归档实现中按文件搬运 `cmd/octo-desktop/watchdog.go`、冻结测试和必要接缝，不整分支 cherry-pick。
- 逐项对齐当前 `datapath`、`productruntime` 和数据根规则；归档早于当前架构，不能原样相信装配点。
- 检测 owner 放在桌面壳/数据路径侧；前端继续复用已有 `FrozenOverlay` 和 `frozen` store。
- 冻结后所有落盘入口必须统一拒绝，不能只冻结 UI。
- 不得回落到主机目录继续运行。
- `datastore:lost` / `datastore:restored` 的载荷按 `G1` 决定，未拍板前只完成检测和内部状态机，不发布自造协议。

**核心测试：**

- 目录存在 → 丢失：只触发一次 lost，写入立即拒绝。
- 持续丢失：不重复广播、不反复弹提示。
- 同路径恢复：触发一次 restored，写入恢复。
- 新路径/新盘符出现：不视为恢复，要求退出。
- 启动时目录已不可用：fail-closed，不进入主界面。
- 冻结状态下会话、词库、凭证、日志均不写到主机其他位置。

## 7. 每个任务的固定开发流程

所有工作包均按以下顺序执行：

1. **粒度自检**：用一句话说明用户看到什么变化；说不清则拆分。
2. **需求分析**：写依据、正向结果、关键异常、落盘变化、阻塞、复用点和反直觉行为。
3. **人工确认四问**：做什么、什么算完成、不做什么、需要多少证据。
4. **更新 canonical 开发计划**：登记 PR、依赖、验收判据和排除项。
5. **先写测试并跑红**：必须红在缺失行为上，而不是编译错误。
6. **最小实现转绿**：不顺手扩范围，不新增无必要抽象和依赖。
7. **变异验证**：故意破坏关键规则，确认正确测试会红，再恢复。
8. **单元 + 端到端验收**：两者缺一不可。
9. **同步状态 owner**：更新闭环行、PR 落地记录和必要的 `V-n`/`PQn` 处置。
10. **本地门禁**：在提交后的树上执行 `make gate`；涉及桌面壳时另执行 `make test-production`。

## 8. 明确不做与禁止事项

- 不实现已被人工取消的 `L-C6` 能力矩阵。
- 不在正式中台信息缺失时伪造 production 地址、公钥或授权来源。
- 不为 `PQ25` 自行发明激活幂等协议。
- 不为 `PQ30` 建第二套验签器。
- 不把 `config.yml` 或本地 provider 作为 production 正式会话的降级来源。
- 不删除上游代码来关闭功能；优先通过中性门控让上游功能不可达。
- 不在启动期读改写用户可编辑文件；缓存写入也必须说明降级与恢复路径。
- 不抬高守卫 ceiling 来让失败消失；新增 allowlist 项必须单独评审。
- 不整分支合并归档实现；只能按能力取文件，并重新验证当前判据。
- 不把 `doc/` 本执行计划当作需求、接口或状态的第二个 owner。

## 9. 完成定义

一个工作包只有同时满足以下条件才算完成：

- 用户可见结果与对应 `L-*`/`V-*` 判据一致。
- 正向、关键异常和防回归测试均已先红后绿。
- 关键规则经过至少一次有效变异验证。
- 所有降级都说清回落目标、用户是否可见、恢复条件。
- 没有未经确认的认证、凭证、数据根、品牌、账务、权限、路由或上游核心改动。
- 改上游文件的每一处都有合法 `OCTO-FORK:` 标记。
- `make gate` 通过；适用时 `make test-production`、`make preflight-check` 和真实打包通过。
- 手工验收完成并更新 canonical 状态行。
- 工作区不包含其它任务的改动，一个特性对应一个独立分支和一个 squash commit。
