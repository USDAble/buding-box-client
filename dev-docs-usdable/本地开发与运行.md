## 1. 运行形态总览

仓库提供三种运行形态，端口与页面分工不同，使用前应先选定形态：

| 形态 | 命令 | 访问入口 | 用途 | 页面来源 |
|---|---|---|---|---|
| 开发态 | `make dev` | **http://localhost:5173** | 前端开发（热更新） | Vite 开发服务器；`8088` 仅提供 API |
| 交付态 | `make build` + `./octo serve` | http://127.0.0.1:8088 | 复现产品交付 UI | 嵌入二进制的前端产物 |
| 桌面态 | `make desktop` / `make desktop-app` | 应用内窗口 | 桌面产品验收 | 进程内同一 Web 服务（绑定 8088） |

### 1.1 端口与进程模型

| 端口 | 承载 | 存在的形态 | 返回页面？ |
|---|---|---|---|
| `5173` | Vite 开发服务器（前端） | 仅开发态（`make dev` / `make web-dev`） | 是——完整界面，热更新 |
| `8088` | Go 后端（API / WebSocket / 静态资源） | 交付态与桌面态；开发态中仅作 API 后端 | 视前端产物是否嵌入而定（见下） |

`8088` 是否返回完整页面，取决于前端产物是否嵌入二进制：

- 前端未构建（`internal/server/webdist/` 中仅有 `.gitkeep`）→ 返回 `indexHTMLFallback` 占位页（后端接口列表）。
- 前端已构建并嵌入（`//go:embed all:webdist`，见 `internal/server/static.go`）→ 返回完整 SPA。

**要点：`8088` 恒为后端端口，变化的只是它有无静态页面可吐。** 开发态下前端位于 `5173`，`8088` 只承担 API——这是设计行为，非缺陷（详见 §5.1）。

## 2. 环境要求

### 2.1 Go 版本

`go.mod` 声明 `go 1.25.0`，需 Go 1.25 及以上。

### 2.2 Node.js 版本（≥ 20.19，推荐 22 LTS）

**前端构建链目前要求 Node ≥ 20.19。** 版本过低时 Vite 无法启动，`5173` 打不开。

- 根因：`web/package.json` 的依赖采用 caret 区间（如 `"vite": "^8.2.2"`），`npm install` 会解析至当前最新版。现解析结果 `vite@8.2.2` 与 `rolldown@1.2.5` 在 `engines` 中声明 `"node": "^20.19.0 || >=22.12.0"`。
- 症状：Node < 20.12 时 Vite 启动即崩溃，报错 `SyntaxError: The requested module 'node:util' does not provide an export named 'styleText'`（`styleText` 自 Node 20.12.0 起才加入 `node:util`）。
- 注意：`make dev` 中的 `npm install --prefer-offline --silent`（`Makefile:78`）会吞掉 `EBADENGINE` 等版本告警，故此类失败不易从告警中察觉，应以 `node -v` 主动核对版本。

核对与切换：

```bash
node -v                 # 应 ≥ 20.19，推荐 22.x
nvm use 22              # 本机已安装 v22.x 时
nvm alias default 22    # 可选：设置默认版本，避免后续 shell 再次踩中
```

仓库根目录提供 `.nvmrc`（内容 `22`）：已配置 `nvm use` 自动钩子的 shell 会自动切换，未配置的需手动执行上述命令。

补充：`jsdom@30`（前端测试用）要求 Node ≥ 22.22.2，`undici@8` 要求 ≥ 22.19。日常 `make dev` 使用 22.x 即可；如需无告警地运行前端 `npm test`，建议使用 `lts/jod`（22.22.x）或更高。

## 3. 运行方式

### 3.1 开发态：`make dev`（前端热更新）

命令同时拉起两个进程（`Makefile:75-83`）：

```text
make dev
  ├── go run ./cmd/octo serve   → 后端，绑定 127.0.0.1:8088（仅 API）
  └── cd web && npm run dev     → 前端，Vite 开发服务器 http://localhost:5173
```

前端通过代理访问后端（`web/vite.config.ts:18-22`）：

```ts
server: {
  port: 5173,
  proxy: {
    '/api': 'http://localhost:8088',
    '/ws':  { target: 'ws://localhost:8088', ws: true },
  },
},
```

使用要点：

- 访问 `http://localhost:5173` 获得完整界面；修改 `web/` 源码即时热更新。
- 页面的 `/api`、`/ws` 请求由 Vite 转发至 `8088`，无需另行配置。
- `Ctrl-C` 一次同时退出两个进程。
- 开发态下请勿经 `8088` 访问界面（无前端产物，详见 §5.1）。
- 后端绑定地址为 `127.0.0.1:8088`（`cmd/octo/serve.go:41` 的 `-addr` 默认值）。若改动 `-addr`（如暴露到局域网 `:8088`），须同步修改 Vite 代理目标。

### 3.2 交付态：`make build` + `./octo serve`

```bash
make build      # 依次执行 web-build → rg-embed → go build，产物 ./octo
./octo serve    # 绑定 127.0.0.1:8088，直接提供完整页面
```

- `make build` 中的 `web-build`（`Makefile:71-74`）执行 `npm run build`，将前端产物写入 `internal/server/webdist/`。
- `internal/server/static.go:13-14` 以 `//go:embed all:webdist` 将产物嵌入二进制。
- 因此 `./octo serve` 在 http://127.0.0.1:8088 直接返回完整 SPA，无需另起 Vite。

交付态是需求中「产品固定 `127.0.0.1:8088`」（需求 §5.1.2）所指的形态。

### 3.3 桌面态：`make desktop` / `make desktop-app`

```bash
make desktop        # 产出 ./octo-desktop 裸二进制（需平台 WebView 工具链）
make desktop-app    # 产出 macOS .app 包（本地 ad-hoc 签名）
```

- 桌面壳 `cmd/octo-desktop/main.go:61` 以 `hubAddr = "127.0.0.1:8088"` 在进程内运行同一 Web 服务，窗口加载嵌入的前端产物。
- 与 §3.2 的差异仅在「原生窗口加载」与「浏览器访问 8088」。
- 单实例、端口占用提示等启动规则（需求 §5.1.2）属桌面壳职责，详见 `技术方案/P2-启动与生命周期.md`。

## 5. 常见问题与排查

### 5.1 现象说明：`make dev` 打开 8088 只见接口列表

属预期行为，由以下事实叠加而成：

1. `webdist/` 在开发机中为空。`.gitignore:47-49` 仅提交 `internal/server/webdist/.gitkeep`，构建产物由 `make web-build` 现场生成。`make dev` 只执行 `npm install` 与 `npm run dev`（`Makefile:78-81`），**不执行 `npm run build`**。
2. `internal/server/static.go:22-40` 检测不到 `assets/` 目录时置 `built = false`，对 `/` 返回 `indexHTMLFallback` 占位页。
3. 后端已由 `go run ./cmd/octo serve` 正常拉起，占位页所列 `/api/*` 均可调用。

**结论：8088 上的接口列表说明后端正常、前端产物未嵌入；完整界面位于 http://localhost:5173。**

### 5.2 故障排查

| 现象 | 原因 | 处置 |
|---|---|---|
| `make dev` 后 5173 打不开，终端报 `SyntaxError: ... does not provide an export named 'styleText'` | Node 版本过低（< 20.12；实际需 ≥ 20.19） | `nvm use 22` 后重跑 `make dev`（见 §2.2） |
| 5173 打不开，终端无报错或报 `EBADENGINE` | Node 版本不满足依赖要求；或端口被占；或依赖未安装完成 | `node -v` 核对 ≥ 20.19；`lsof -i :5173` 检查端口；`cd web && npm install` 单独执行以查看完整输出 |
| 5173 可访问，但 `/api` 请求失败 | 后端未启动，或 Vite 代理目标 `localhost:8088` 不可达 | 确认 `go run ./cmd/octo serve` 在运行、8088 未被占用 |
| 打开 8088 希望看到完整页面 | 前端产物未嵌入 | 使用交付态：`make build && ./octo serve`，或桌面态 |
| `make build` 失败 | `web-build`（Node 构建）或 `rg-embed`（下载 ripgrep）环节出错 | 分步执行 `make web-build`、`make rg-embed` 定位 |
| 8088 被占用 | 本机已有 `octo serve` / 桌面壳 / 其它进程 | 停用占用进程后重试；产品行为约束见需求 §5.1.2-6 |

### 5.3 首次打开要求「选语言 + 连接模型」（首次运行向导）

**现象**：`make dev` 后访问 5173，被一个全屏向导挡住，先选语言，再要求「Connect your AI model」填 provider / key。

**原因**：这是上游自带的首次运行面板 `web/src/components/overlays/FirstRunSetup.svelte`。前端启动时请求 `GET /api/onboard/status`，后端按 `internal/server/onboard_config_handlers.go` 的 `detectOnboardPhase()` 返回阶段：

| 阶段 | 判定条件 | 表现 |
|---|---|---|
| `key_setup` | 所有 endpoint 均无 API key，且对应环境变量（`DEEPSEEK_API_KEY`、`ANTHROPIC_API_KEY` 等，见 `internal/app/provider.go`）也未设置 | 全屏阻塞，必须先连接一个模型 |
| `soul_setup` | 已有 key，但尚无身份文件 `soul.md` / `user.md`，且引导未触发过 | 主界面启动后弹一次 `/onboard` 对话（软引导） |
| `''` | 已配置完成 | 直接进入主界面 |

聊天依赖真模型，后端无 key 时无法工作，因此 key 必须原生收集——这是产品设计，非缺陷。

**向导各步**：

1. 语言（zh / en）——写入后端 config，持久化，此后界面语言随配置。
2. 连接模型——选 provider 填 API key；本地 Ollama / vLLM 一类无需 key 的 Custom endpoint 也视为「已配置」。
3. 浏览器自动化——可选，可跳过，之后在设置中补配。

**处置**：

- 配置一次后写入本机 config（当前代码仍写 `~/.octo/config.yml`，fork 的 P1 数据根落地后改到产品 `data/` 根），重启不再弹。
- Settings → About →「First-run Setup」可随时重跑该向导。
- 不想走 UI：`make dev` 前先导出 key 环境变量（`DEEPSEEK_API_KEY=xxx make dev`），后端同样判定为已配置。

**与本产品规划的关系**：本 fork 的 P9（模式与模型）方案要求**交付/开发态不出现配 Key 向导**、预置模型名单，P11 提供假模型通道供演示与离线测试。当前代码尚未实现到该里程碑（P9 排期里程碑 4），故开发态看到的仍是上游原生向导。走完向导配一个真实 key 即可开始正常开发。

## 6. 与需求文档「8088」条款的关系

需求 `需求20260906.md` §5.1.2 关于固定端口 `8088` 的条款均指**交付形态**（桌面壳或嵌入前端的 `octo serve`），与开发态的 `make dev` 无关：

- 交付 / 验收形态：`8088` = 完整页面（§3.2、§3.3）。
- 本地开发形态：`8088` = 纯 API，页面位于 `5173`（§3.1）。

二者不冲突，前提是区分「开发态」与「交付态」。品牌升级方案及 P2 中所有涉及 `8088` 的约束（端口占用提示、单实例等）均属交付态范畴。
