## 1. 目标与非目标

**目标**

1. 一条命令产出可直接拷到 U 盘的 `PuddingBox/` 目录。
2. exe 文件名、文件属性、图标符合 §5.2.4。
3. 产物自检：确认目录结构完整、不含开发残留、启动后不写主机。

**非目标**

- 不做代码签名（需求 §7）。
- 不做安装器（需求 §5.2.5「安装器作为主交付」本期不改，但它不再是**主**交付）。
- 不做便携更新（需求 §10 T9）。

## 2. 现状（代码事实）

## 3. 设计

### 3.1 产物结构

```
PuddingBox/                      ← 用户拷到 U 盘的就是这一层
├── PuddingBox.exe               ← GUI 子系统，图标与文件属性来自 brand.json
├── WebView2Loader.dll           ← 若 Wails 需要随包
├── bin/
│   └── uv.exe                   ← 随包工具，首次运行复制到 data/bin（P1）
├── data/                        ← 预置的空数据根
│   ├── sensitive-words.txt      ← 预置空词库（仅头部注释块；内置词在 Go 常量里、不落文件，见 P7 §3.5 / P13 §4.1）
│   ├── config.yml               ← 预置空配置（不在 production 种入本地模型 endpoint）
│   └── workspace/               ← 空目录，包含 `.gitkeep` 标记文件
└── 使用说明.txt                  ← 中英双语，含「先退出再拔 U 盘」等
```

**预置 `data/` 而不是首次运行生成**：这样用户拿到手就能看到并编辑词库（需求 §5.5「用户直接改词库文件即可更新」）。首次运行的降级逻辑仍要保留 —— 用户删了文件也得能跑。

> **2026-09-10 修订，2026-09-11 更新**：本段的 P11 本地 endpoint 配置已被当前 P0 production 规则废止，并且 `ensureLocalEndpoint()` 及 `config.yml` 的 `buding` endpoint 种入**已从代码中删除**。标准包必须以 `product_production` 构建，且不得在 `config.yml` 种入或保留本地模型 endpoint。本地确定性通道只可存在于 developer 构建，且需**显式配置** endpoint。
>
> **`chat-modes.json` 已从预置清单删除（不是"TBD"，是定案）**：它的出厂内容原本是 4 个 `buding-*` 假模型的分组，而这些 id 依赖已删除的 `ensureLocalEndpoint()`；模型列表现在由中台签名目录下发（P0-04）。缺失该文件与出厂分组**等价** —— `chatmode.Load` 现在直接返回 `Builtin()` 且**不写盘**（该函数只含三个模式 id，不含任何模型 id），所以预置它只会把已删除的假数据重新塞回交付物。打包脚本的 `DATA_FILES` 与 `packaging/portable/data/` 已同步删除；同理，**不在启动期种出任何用户可编辑文件**（开发规范 §3.9.1）。

`使用说明.txt` 是**纯文本**不是 HTML —— 用户在没启动程序时也要能看（比如程序起不来时）。

### 3.2 make 目标

```make
# 便携目录是本产品的主交付物（需求 §5.1.1）。安装器仍可构建，但不是主交付。
desktop-portable: web-build brand-check
	@# 1. 构建 GUI 子系统 exe，注入 VERSIONINFO
	@# 2. 按 brand.json 的 identifiers.current.exeName 命名
	@# 3. 组装目录结构，复制随包工具与预置 data/
	@# 4. 跑产物自检
	node scripts/package-portable.mjs
```

用 Node 脚本而不是 shell：Windows 产物在 CI 上跑，`scripts/` 下已有 `sync-branding.mjs` 等零依赖 Node 脚本的先例（Makefile `:160` 附近注释说明这一约定），保持一致，也避免 PowerShell/bash 双份实现。

### 3.3 产物自检

打包脚本末尾跑一组断言，失败即打包失败：

| 检查 | 理由 |
|---|---|
| exe 名等于 `brand.json` 的 `identifiers.current.exeName` | 需求 §8「exe 文件名 `PuddingBox.exe`」 |
| exe 的 VERSIONINFO 产品名 / 文件说明匹配 `display.windows` | 需求 §8「文件属性产品名 Pudding Box、说明「布丁盒子」」 |
| exe 是 GUI 子系统（不弹控制台） | 需求 §5.1.2-1 |
| 目录内不含 `.map`、`.pdb`、`node_modules`、`.git` | 便携包体积与整洁 |
| `data/` 存在且含四个预置文件 | §3.1 |
| 目录内不含任何绝对路径引用构建机的字符串 | 便携性 |
| 整包体积 < 阈值（先记基线，超 20% 告警） | U 盘拷贝时间 |

VERSIONINFO 与子系统的读取用一个小的 PE 头解析（不引三方依赖 —— PE 头的这两个字段读起来只有几十行）。

### 3.4 「不创建主机痕迹」的验证

需求 §8「无主机桌面快捷方式、无开始菜单项（便携交付本身）」。这是**打包形态**的性质，不是运行期行为，所以在这里验证：

- 打包产物里不含 `.lnk`、不含任何注册表脚本。
- CI 上跑一次 P1 定义的 `portable_test.go` 集成测试（tmpdir 之外无新文件），把「运行期不写主机」也纳入打包流水线的把关。

### 3.5 CI

新增 `.github/workflows/portable.yml`（或并入既有 `desktop.yml`）：

- 触发：push 到 main / PR / tag。
- 产出：`PuddingBox-windows-amd64.zip` 作为 artifact。
- 跑自检 + `portable_test.go`。

**不做**自动发布到 release —— 本期是内部开发验证包，手工取 artifact 即可。

> **落地补充（mac + Windows 一起打包）**：需求确认「一次性打包 mac 与 Windows」。mac 的便携等价物是自包含 `.app`（`package-desktop-macos.sh`，数据根在 bundle 内，P1），故：本地加 `desktop-portable-all`（mac 主机上一次跑 `desktop-app` + `desktop-portable`）；CI 的 `portable.yml` 拆成两个 job —— `portable`（windows-latest，`PuddingBox-windows-amd64.zip`）与 `macos`（macos-latest，`Octo.app`，artifact 名 `PuddingBox-macos`）。Windows job 补了 `embed-rg-windows.ps1`（`-tags embedrg` 需要 rg 二进制，原稿漏了这一步）。`desktop-portable` 本地目标也补了 `rg-embed GOOS=windows GOARCH=amd64` 依赖。落地形态与主机要求见 §3.7。

### 3.6 图标依赖

exe 图标由品牌 PR2 的资产管线从 `branding/source/logo-mark.svg` 生成 16/24/32/48/256 的 ico（需求 §5.2.4）。PR2 未完成前，本 PR 用临时 ico 跑通链路，正式源到位后只需 `make brand` + 重新打包，**打包脚本不改**。

这与 P4 对待接入 Logo 的处理是同一原则：把依赖设计交付的部分收敛成「换一个文件 + 重跑一条命令」。

### 3.7 打包主机矩阵（2026-09-09 实测确认）

「哪个交付物必须在哪台机器上打」是验收时常被问起的问题，集中写在这里：

| 交付物 | 命令 | 主机要求 | 说明 |
|---|---|---|---|
| Windows 便携目录 `PuddingBox/` + `PuddingBox-windows-amd64.zip` | `make desktop-portable` | **任意主机**（Windows / macOS / Linux） | 纯 Go 交叉编译 + Node 组装，不依赖 Windows 机器。macOS 主机实测可产出（需 Node ≥ 20.19，见 `本地开发与运行.md` §2.2） |
| macOS 自包含 `.app`（`Octo.app`） | `make desktop-app` | **仅 macOS**（需 Xcode CLT + lipo） | CGO 链接 WKWebView，必须原生构建；CI 的 `portable.yml` macos job 在 macOS runner 上打 |
| 一次出两个 | `make desktop-portable-all` | 仅 macOS | 内部 = `desktop-app` + `desktop-portable`（`Makefile:145`） |
| CI 自动出两个 | push 到 main 触发 `portable.yml` | GitHub Actions | windows-latest 与 macos-latest 两个 job **并行**，互不等待；artifact 即产物，无需本地跑打包 |

**结论**：不需要「两台电脑各自打包」。本地打：Windows 目录不挑机器，macOS `.app` 才必须 mac，而一台 mac 可用 `desktop-portable-all` 一次出两个；平时验收取产物走 CI 即可。

## 4. 接口与数据结构

无对外接口。脚本约定：

```
scripts/package-portable.mjs
  输入：环境变量 GOOS/GOARCH（默认 windows/amd64）、VERSION
  输出：dist/PuddingBox/ 目录 + dist/PuddingBox-<os>-<arch>.zip
  退出码：0 成功；非 0 且打印失败的自检项
```

## 6. 测试

**脚本单测**（`node --test`，与既有 `sync-branding.test.mjs` 同一模式）

- 自检项各自的正例与反例（构造一个缺 `data/` 的临时目录 → 自检失败）。
- `pe-info.mjs` 对一个已知 exe 读出正确的子系统与版本字段。

**手工验收**（Windows，需求 §8「便携」段）

1. `make desktop-portable` → 拿到 `PuddingBox/`。
2. 拷到 U 盘，双击 `PuddingBox.exe`，走一遍主路径。
3. 右键 exe → 属性 → 详细信息：产品名称 `Pudding Box`，文件说明「布丁盒子」。
4. 桌面无快捷方式、开始菜单无项。
5. `%USERPROFILE%\.octo` 无新增业务数据。
6. 拷到另一台机器打开同一份目录 → 会话、配置、登录态仍在。
7. 换盘符后冷启动 → 历史可用或对失效项有说明。

## 7. 上游合并影响

**等级：中。**

- `Makefile` 加一个目标：追加，冲突概率低。
- `scripts/` 全是新文件。

## 9. 风险与决策

| 项 | 处理 |
|---|---|
| WebView2 Runtime 是否随包 | **不随包**（体积大、需安装权限，与便携原则冲突）。缺失时由 P2 给说明。写进使用说明与已知限制 |
| U 盘上首次启动慢 | 实测记录基线。若过慢，考虑把 `bin/uv.exe` 的复制改为惰性（用到再复制） |
| 未签名被 SmartScreen 拦 | 需求 §5.1.2 末段已接受。使用说明写「选择仍要运行」 |
| 预置 `data/` 与首次运行生成逻辑不一致 | 预置文件由**同一份内置默认**生成（打包时调 Go 侧的默认值导出），不手工维护两份 |
| 图标依赖品牌 PR2 | 使用已验收的临时资产跑通链路，正式源到位后不改脚本 |
