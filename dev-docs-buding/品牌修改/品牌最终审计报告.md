## 5. 有意保留且不能直接删除的标识

以下标识是兼容层，不代表新产品展示名没有修改：

```text

github.com/open-octo/octo-agent

octo-setup.pkg

```

具体保留原因：

- **CLI 命令**：已有用户脚本、CI、快捷方式和文档示例依赖 `octo`。
- **配置目录**：旧会话、技能、工作流、密钥、日志和升级状态位于 `~/.octo`。
- **环境变量**：`OCTO_*` 是现有部署配置入口，直接改名会导致服务失效。
- **协议**：`octo-ui`、`octo-pair` 和相关 URL scheme 关系到 Web、桌面和移动端配对。
- **Go module / 包路径**：`github.com/open-octo/octo-agent` 影响 import、replace、构建和第三方使用方。
- **安装包/下载名**：升级器、快捷方式、安装器和发布脚本仍按旧文件名识别。
- **服务与系统标识**：systemd、launchd、Windows AppUserModelId 和旧 Bundle/协议标识需要迁移窗口，不能在一次品牌展示修改中破坏。

### 根模块全量测试的环境阻断

根目录直接执行 `go test ./...` 在当前 Windows 主机没有全绿，但失败点不在本次品牌改造文件中：

- 默认 `go env GOARCH` 为 `386`；`internal/browser` 的 CDP 测试在 `internal/browser/cdp.go:151` 触发已有的 64 位原子操作未对齐 panic。
- 使用 `GOARCH=amd64` 后，浏览器包的定向测试可以通过；`internal/tools` 的 `TestTerminalOutputTool_LinesSnapshot` 仍因测试使用 Unix `printf`、当前 Windows PowerShell 不识别而失败。
- 在未包含品牌提交的原始 `main` 工作区执行同一条 `GOARCH=amd64` 定向测试，`TestTerminalOutputTool_LinesSnapshot` 同样失败，证明该项是基线环境问题，不是本次提交引入。
- 本次提交没有修改 `internal/browser` 或 `internal/tools`；因此没有为无关问题扩大改动范围。

上述全量测试阻断已记录为环境/既有测试问题。品牌改造本身的变更范围验证已通过；正式合并前若要求“根模块全量零失败”，应另建“Windows 测试兼容性”主题修复并单独验收。
