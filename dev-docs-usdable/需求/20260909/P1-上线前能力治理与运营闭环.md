# P1：上线前能力治理与运营闭环

| 项 | 内容 |
| --- | --- |
| 定位 | P0 正式账号、网关、凭证和能力矩阵落地后的上线前工作包 |
| 前置 | P0-02、P0-03、P0-04、P0-08、P0-09 的最小发布链路完成 |
| 原则 | 保留既有功能；以状态机、能力矩阵、PEP 和运营流程治理可见性、授权、恢复与支持，不以删除代码代替治理 |
| 来源 | [问题盘点](问题盘点.md) 的 A2/A3/A4/A9、H3/H6/H7/G6、I1/I6、K2/K6、L3/L4、N1-N6、O3/O5 |

## 1. P1 做什么，不做什么

P0 解决“能以受信身份、受信模型目录和网关完成一次可追溯请求”；P1 把这条链路变成用户遇到异常、换设备、长任务、扩展、更新或客服事件时仍可恢复、解释和运营的产品。

P1 不重写 `internal/server`，不删除 `config.yml`、MCP、channel、工具或后台任务，也不自行实现中台、账本、支付或客服系统。客户端只实现中台已定义的合同、状态投影、受控 UI 和本地 PEP。

## 2. 工作包

| ID | 工作内容 | 主要代码/文档归属 | 完成标准 |
| --- | --- | --- | --- |
| P1-01 | 账户、设备、换号与丢失介质恢复 | `productclient`、`credentialstore`、账户设置 UI、客服合同 | 定义正常/迁移/撤销/待删除状态；换号和丢失设备有可审计客服路径；复制数据根不会绕过中台设备语义。 |
| P1-02 | 数据分级、备份、导入与损坏恢复 | `datapath`、迁移器、诊断白名单 | 明确哪些数据可复制、哪些凭证不可复制；导入校验、原子备份、损坏保留和恢复提示可在 Windows 上验证。 |
| P1-03 | 后台任务与长期运行可见性 | 产品任务视图、PEP、退出/拔盘处理 | 用户能看到启动者、工作目录、网络目标、取消/强杀与结果；关闭窗口、退出登录、拔盘、撤销时有明确中止语义。 |
| P1-04 | MCP、技能与第三方扩展治理 | 能力矩阵、扩展来源记录、导入 UI、PEP | 功能实现保留；首发可 `visible=false`。真正开放时必须显示来源、权限、版本、更新/撤销与禁用入口，且导入不扩权。 |
| P1-05 | 发布支持、复现与回退演练 | 发布清单、诊断、Windows matrix、CI | 固定 Windows 支持矩阵和测试运行时；每个包可追溯 commit/依赖/SBOM/签名；升级、失败回退和诊断采集可复现。 |
| P1-06 | 法务、内容与客服运营流程 | 协议版本、反馈 UI、运营合同 | 身份核验级别、内容申诉、删除/保留、服务故障与支持分级均有 owner、状态机、用户文案和审计证据。 |

## 3. 依赖顺序

```text
P0-02/03/08 账号、网关、凭证
        + P0-04 能力矩阵与 PEP
        + P0-09 发布完整性
                    ↓
P1-01 账户与设备 ──┬── P1-02 数据恢复
P1-03 长任务治理 ──┼── P1-04 扩展治理
P1-05 发布支持 ────┴── P1-06 运营闭环
```

P1-01 至 P1-06 可按依赖并行；任何需要中台新增字段、状态或审计能力的条目，先更新[中台交付包](产品客户端与中台对接/中台交付包.md)，再写客户端代码。

## 4. 统一验收

每个 P1 工作包都要同时给出：产品规则 owner、客户端/中台合同、成功与失败路径、Windows 真机证据、用户可见文案和运营/客服取证方式。仅有页面、仅有接口或仅有本地状态都不算完成。
