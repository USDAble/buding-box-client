# 开发期假后端（临时）

| 项 | 内容 |
|---|---|
| 状态 | **临时替身 —— 真后端落地后删除** |
| 位置 | `web/src/dev/devBackend.ts` |
| 安装点 | `web/src/main.ts`（`import.meta.env.DEV` 门后，两行） |
| 作用域 | 开发 · 浏览器端 · 运行期（开发规范 §3.10） |
| 上线影响 | 无。生产构建里 `import.meta.env.DEV` 为 false，调用被消除、模块被 tree-shake（已对构建产物验证） |

## 1. 它是什么

一份**假的后端**：在浏览器里拦下 `/api/*` 就地应答，让 P1–P13 的页面能点得通、流程能走完。

**它不是什么**：不是设计、不是接口草案、不是真后端的替代品。里面的任何实现细节都不要照搬进真实现。

## 2. 为什么需要它

P1–P13 的页面调用 `/api/product/*`，真实现是 `internal/server` 里的一组 handler（见 §3）。**这些代码不在本分支上**（在 20260909 线上），于是：

- `GET /api/product/state` 404 → `refreshProductState()` 兜底把 phase 置成 `blocked`
- 发验证码 / 登录 404 → 永远停在登录页，进不了聊天页

结论：**没有应答方，流程一步都走不了**。这个文件只解决"让流程走通"这一件事。

## 3. 真后端会怎么替换它

真后端落地后，下表路由交给真实现，**本文件整体删除**（见 §4）。

| 假后端应答的路由 | 真实现位置（20260909 线） |
|---|---|
| `/api/product/state`、`/locale`、`/logout` | `internal/server/product_handlers.go`（+ `internal/productstate`） |
| `/api/product/send-code`、`/login` | `internal/server/product_login.go`（门：`internal/productgate`） |
| `/api/product/nickname` | `internal/server/product_nickname.go` |
| `/api/product/prefs` | `internal/server/product_prefs.go` |
| `/api/product/sensitive/check` | `internal/server/product_sensitive.go`（+ `internal/sensitive`） |
| `/api/product/sensitive/dict`（GET/PUT）、`/import` | `internal/server/sensitive_dict_handlers.go` |
| `/api/product/chat-modes` | `internal/server/chatmode_handlers.go`（+ `internal/chatmode`） |
| 其余（`config` / `sessions` / `endpoints` / …） | 上游既有 handler；本文件只给空壳 |
| WebSocket 事件流 | `internal/server` 的 ws handler；本文件用桩，只回 `subscribed` |

## 4. 怎么删除

1. 删掉 `web/src/dev/devBackend.ts`
2. 删掉 `web/src/main.ts` 里的两行：

   - `import { installDevBackend } from './dev/devBackend'`
   - `if (import.meta.env.DEV) installDevBackend()`

没有第三个引用点 —— `rg devBackend web/` 可自证。

## 5. 它故意不实现什么

| 不实现 | 为什么 |
|---|---|
| 字段校验、手机号绑定/遮码 | 真后端的职责。在这里重写等于给出**第二份契约定义**，必然漂移（开发规范 §3.8） |
| 词库去重 / 导入预览 | 同上；`internal/sensitive/normalize.go` 是唯一 owner |
| 真实持久化 | 只在内存里，刷新即回初始态 |
| WebSocket 事件流 | 只回 `subscribed`（新会话首条消息靠它才放行）。其余事件用 `window.__dev.push(...)` 手动注入 |

凭据只认需求 §8 钉死的那两个（见 §6），其余一律拒绝 —— 保留错误路径可走。

## 7. 为什么不用真后端跑

真后端要整套 Go 服务加桌面壳：window token 由 `cmd/octo-desktop` 铸造（没有它产品门不生效，也就看不到登录页），Vite 侧的 `/api`、`/ws` 代理已配好指向 `:8088`。本批次只要"可交互的静态页面"，所以选了成本最低的浏览器内替身。
