# 模式与模型

写作参照：`dev-docs/endpoint-pr5-impl.md`

> 模式是产品固定的数据键，选择器展示经过签名目录投影的可用模型。模式展示名是前端文案；目录不可用时停止开始新回合，不回退到本地模型名单。

## 范围

本文件定义模式选择、会话级模式、目录投影和用户可见降级。接口形状由 `本地API契约.md` 定义，签名目录与策略由 `中台接口契约.md` 定义。

## 非目标

- 不在前端维护模型 ID 到展示名的映射表。
- 不把旧 `chat-modes.json` 或本地 provider 当作目录不可用时的 fallback。
- 不让目录以未知 mode ID 扩展产品模式集合。

## 三个模式

`privacy`、`smart` 和 `default` 是稳定 ID，不本地化；`internal/chatmode` 是它们的唯一集合与展示顺序所有者。用户可见名称由前端 `mode.<id>` 文案渲染；模型展示名来自签名目录。模式归属来自模型的 `modeIds`，运行时投影为选择器需要的两级结构。

目录只能为这三组提供模型和各组默认模型：未知 mode ID 被记录并忽略，不会生成第四组。每个模式保留，即使当前没有合格模型；合格条件为 `eligible=true` 且 `transport="gateway"`。组合模型 ID 保持为 `endpoint::model`，避免同名模型在不同 endpoint 间失去身份。

## 选择器与会话

选择器在聊天输入区可达，先展示模式，再展开该组模型；当前模式初始展开。选择一个模型同时写入该会话的 `chat_mode` 与模型绑定，顺序为先写模式、后写模型；它不改变其他会话或账户默认模式。模式更新通过既有会话路由和 `session_update` 广播。

模型不由组件各自缓存为事实源。前端读取目录投影，运行时负责判断目录版本、有效期与可用性；已有会话若绑定的网关模型已不在有效目录中，不能静默换模型，而是要求用户重新选择。账户默认模式目前使用同一固定模式集合、并非目录投影，理由和演进取舍见 [待决事项](待决事项.md)。

## 目录不可用时 fail closed

目录状态分为 `ready`、`absent`、`stale` 与 `unverifiable`。前端仅把状态映射为文案和可重试动作；不重新推断状态，也不提供内置模型名单。

没有可用目录时，选择器显示明确原因，发送入口不能开始新回合。空分组与目录不可用是不同情形：前者表示目录有效但该模式没有模型，后者表示无法信任或取得目录。

## 验证

- 模式 ID 与顺序只来自 `internal/chatmode`；模型展示名、组内默认模型和组合 ID 来自有效目录投影。
- 会话切换模式后写入会话并向正确窗口广播；选模型不会影响账户默认模式或其他会话。
- 目录缺失、过期、验签失败和有效但空分组展示不同且不回退；未知目录模式不产生新分组。
- 目录不可用时，用户不能以旧缓存或本地 provider 开启新回合；已下架的会话绑定不会被静默替换。
