## 7. 这个仓库会咬人的地方（本会话逐条踩过）

1. **`make gate` 不覆盖 `cmd/octo-desktop`** —— 它是**嵌套 module**，根 `go test ./...` 会跳过它，而**出货的那个二进制正是从那里构建的**。它只由 `make test-production` 与 CI 的 `test-production` job 跑（`cd cmd/octo-desktop && go test -tags product_production ./...`）。**在那里加测试后，别只看 `make gate` 绿就以为被跑了。**

2. **注释会说谎。** 本会话抓到三处"声称有机制兜底"的假注释：`SettingsPage.svelte` 称便携不显示自启开关因为 `AutostartAvailable()` 恒 false（**该函数全仓零命中**）；`main.go` 的 `UpdateCheck` 注释称"版本徽章需要它"（**徽章根本没被挂载**）；`SettingsModal.svelte` 称 badge "always mounted"。**做法：注释里点名的符号，先 `grep` 再信。**

3. **同义的"第二个面"是主要缺陷形态。** 关掉一个功能时，**改登记到的那几处不够**：`V-86` 登记三处、实际五处（另有 `GET /api/version` 的**出站查询**与完整设置里那句没人验证过的"已是最新版本"）；`V-79` 的品牌守卫也是同一形态（还有"说了谎的 `OCTO-FORK` 标记"）。**做法：按"用户能看到什么"把所有入口搜出来，而不是按登记清单。**

4. **`✅` 曾经被读成"进度"，而它只表示"规格完整性"。** 全表曾有 **17 条**属于"函数在但无调用点 / 前端在但路由未注册 / 上游能力在但产品通道不存在"。**单元测试绿 ≠ 闭环合上**（`§6.4` 第 5 步），判据要落在**用户可见结果**上，能用**字节**判就别用"函数存在"判（`L-D2` 读会话 JSON 的字节就为此）。

5. **两个需求目录别混。** [`需求/20260911/`](.) ＝ 批次账本（闭环 / 计划 / TODO / 契约 / 走查）；[`需求/2260906/`](../2260906/) ＝ 需求原文 ＋ 技术方案 `P*.md`。**`dev-docs/` 是上游目录，禁止加下游文档。**

6. **替身的启动横幅会打出已武装的开关** —— **先看那一行再判断屏幕**，否则"注入生效"与"流程坏了"长得一样。`-fail-*` 的 `402` 与 `402:insufficient_credits` 是**两个不同场景**（前者是代理层无业务码的拒绝，落到传输层文案）。

7. **`production.json` 仍是占位**（`*.invalid` ＋ 空 `trustedKeyIDs`）⇒ 用 production Profile 出的包**默认停在"未配置"拦截页**；这也是 `L-C5` 只能等中台（`D-001`）的原因，不是代码没写。

8. **上游代码只许"到不了"，不许删。** 任何改上游文件的地方都要 `// OCTO-FORK: <原因> — see <设计文档>`；`fork-marker-guard` 是**棘轮**（`MARKER_DEBT_CEILING = 0`：每个被改的上游文件都得有标记），它**还有第二道棘轮** `ALLOWLIST_CEILING = 6` —— 往 allowlist 里加一条也是需要评审的动作。**删除会产生 delete-vs-modify 冲突，每次上游合并都要人肉解。** `V-86` 是标准形状：一个常量做唯一 owner，每处上游代码加一层门控。

9. **数据路径与品牌字面量两条守卫会直接拦你。** 数据路径一律走 `internal/datapath`（`".octo"` 字面量零例外，真需要时在文件里按行写 `octo-literal-allow:` ＋ 理由）；产品名一律插值 `{brand}`/`{brandShort}`（唯一例外：端口提示里的 "Octo" 指**上游**产品；`BUDING-DEMO-0001`/`buding-*` 是固定数据键）。

10. **`svelte-check` 必须从 `web/` 跑。** 从仓库根跑会捡不到 Svelte 源文件的 tsconfig、报一墙假错误（2026-09-15 实测 107 条），读起来像"环境坏了"然后被无视。这也是 `make web-gate` 存在的原因。

11. **死代码先确认再改。** `VersionBadge.svelte` ＋ 它的测试**已不挂载**（`AboutPage.svelte` 的版本行取代了它），全仓只有它自己的测试引用它。这类"上游还在、产品已不用"的面要改之前，先用 import 可达性确认它在不在渲染路径上。

## 8. 用 AI 编码工具接手时

这个仓库是**为 AI 工具协作而写的**（`AGENTS.md` / `.cursor/rules/` / `CLAUDE.md` / `.octorules` 都是入口文件，且由守卫断言它们**指向** `开发规范.md`）。

- **别直接编辑 `AGENTS.md`** —— 它是 `scripts/sync-agents.mjs` 从 `.octorules` 生成的内联副本；改 `.octorules` 后跑 `make agents`，用 `make agents-check` 验。
- **让工具先读 [`../../开发规范.md`](../../开发规范.md) 再动手**（`.cursor/rules/dev-norms.mdc` 已经这么要求）。三条硬规则是最容易被"顺手"违反的。
- **守卫是棘轮**：`fork-marker-guard` / `server-diff-guard` 的上限**只能降**。失败时的正确修法是改代码或加标记，**不是抬 ceiling**（抬 ceiling 是一次需要评审的动作）。
- **改完跑 `make gate`**；动了 `cmd/octo-desktop` 或打包脚本时**另跑 `make test-production`**（见陷阱 1）。
- **本仓库的既有做法是"先证钉子会红"**：写断言后**故意把实现改坏一次**，确认它红在**预计的那条**上，再恢复。`PR` 里有大量这类记录（"N 条钉子 / M 个变异全中"），照这个标准写。
