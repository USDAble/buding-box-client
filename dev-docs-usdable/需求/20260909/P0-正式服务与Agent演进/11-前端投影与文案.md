## 目标

把「模型投影、能力可见性、状态与错误码文案」收成前端一个工作包，消灭两个 owner 同时改 `web/src/lib/` 却无人裁决的冲突面。

本工作包**不产生**任何数据，也**不判断**任何授权：后端已经验签、已经决定 `visible`/`entitled`/`available`，前端只负责**渲染它、在它缺失时说清楚、并拒绝用本地猜测填补它**。

## 契约（唯一来源，不自行扩展）

前端只消费三类输入，且都来自已冻结的契约：

| 输入 | 来源 | 前端用途 |
| --- | --- | --- |
| 只读 DTO（目录/能力/套餐/余额/词库版本/legal） | [P0-01 合同骨架](01-运行时Profile与窄端口抽象.md#合同骨架) 的 `ControlPlaneClient` / `UsageClient` | 渲染选择器、账户面板、告知页 |
| session 事件与终态（`clientRequestId`、usage、终态、错误码） | P0-05 转出的会话事件；错误码以[中台交付包](../产品客户端与中台对接/中台交付包.md) §3.2 为准 | 流式状态、余额对账、断线提示 |
| 本地 PEP 决定（`allow`/`ask`/`deny` + 审计字段） | [P0-04](04-模型目录能力矩阵与策略执行.md) | 工具确认与阻断 UI |

**三条硬边界**：

1. **不解析 `message`**。错误响应的 `message` 是给人看的，不是文案来源；只按 `code` + HTTP 状态 + 结构化字段映射（中台交付包 §3.2）。前端不得对 `message` 做字符串匹配。
2. **不解析后端结构**。不读 `internal/*` 的类型、不猜 JSON 层级、不在页面层做签名/版本判断。
3. **不本地补齐**。额度、到期、资格、模型列表**一律**取投影结果；不许"取不到就按本地缓存/默认值显示可用"。

### machine code → 文案映射表（前端唯一文案真相）

单一映射表文件，是前端唯一允许出现业务码的地方：

```text
web/src/lib/copy/errorCopy.ts   (示意路径，落地时按现有 i18n 约定)
  code + 阻断级别  ->  { titleKey, bodyKey, actionKey }
```

规则：

- **每个码必须有映射**，缺映射是构建期错误而不是运行时兜底英文。
- 文案 key 走既有 i18n（`i18n.ts`），**与模式展示名同址**（`mode.privacy` / `mode.smart` / `mode.default`），不新起一套。
- 三处「到期/不可用」必须区分，不得合并为「授权到期」：`activation_required`（未激活）、`plan_expired`（套餐到期）、`insufficient_credits`（额度用尽）、`model_not_allowed`（模型无资格）。前端的阻断动作各不相同（中台交付包 §1.2）。

## 实施步骤

### F0：投影骨架（用 contract sample 假数据，不依赖后端完成）

1. 模型选择器改为渲染**目录投影**：一级是模式（固定三个 id），二级是该模式下的模型；模型成员来自 projection，**出厂态为空是正确的**，不显示任何硬编码 `buding-*`。
2. 用户 `data/chat-modes.json`（仅用户自己创建时存在）只影响**分组顺序与默认项**，且只在目录 id 范围内生效。**用户文件的空 `models` 不得清空投影** —— 后端已按此实现（[P0-04](04-模型目录能力矩阵与策略执行.md)），前端不得再叠加一次"空即清空"。
3. 状态与错误码映射表落地，含全部错误码；缺码即构建失败。

### F1：可见性与状态

4. 入口可见性由 `visible` 驱动：`visible=false` 即隐藏入口，但**不是**删除功能（[P0-00A](00A-生产入口可见性与功能保留.md)）。前端不得用编译期常量代替该字段。
5. 目录不可用时展示「目录暂不可用」，**不静默回落**到本地确定性模型或上一次缓存的模型列表（中台交付包 §3.2 的 404/`model_not_found` 与 P0-05 步骤 3）。
6. fail-closed 三态必须可见且阻断新请求：`catalog_signature_invalid`、`policy_expired`、`bootstrap_stale` —— 保留当前会话展示，但阻断新 Agent 与新模型请求（[产品客户端与中台对接/开发计划](../产品客户端与中台对接/开发计划.md) §3）。
7. 余额/用量只读展示：显示 `UsageClient` 的数值与 `asOf`/来源版本；**不存在**任何本地扣减、本地余额权威或"发一条扣一分"的 UI 反馈。

## 验收

- 出厂态（无目录、无用户文件）下选择器**不列出任何模型**，并给出「目录暂不可用」；不出现硬编码模型 id。
- 目录投影 + 用户文件覆盖的组合有用例：排序、默认项、目录外 id 被忽略并一次性提示、**空 `models` 不清空投影**。
- 每个错误码都有映射且能渲染出正确的阻断动作；`activation_required` / `plan_expired` / `insufficient_credits` / `model_not_allowed` 四种文案与动作互不相同。
- 全仓库检索证明：`web/` 内不存在对后端 `message` 字段的渲染或匹配，不存在本地额度/到期计算。
- 后端包在任何情况下不改 `web/`（由 `reuse-guard` 与 §3 所有权表共同约束）。

## 与其它工作包的分工

| 事项 | 归属 |
| --- | --- |
| 投影字段 `visible`/`entitled`/`available` 的**计算与验签** | P0-04（后端） |
| 错误码的**产生**与语义注册表 | P0-02 / P0-03 / P0-10（后端）+ 中台交付包 |
| 错误码的**展示**、入口隐藏、状态文案 | **P0-11（本文件）** |
| legal/告知的文案内容与版本号 | P0-06（后端提供版本与字段），前端只渲染 |

**前端不得反向要求后端改契约以方便渲染。** 若某个状态无法用现有 code + projection 字段表达，先按 [开发规范](../../../开发规范.md) §3.4 走「正常开发会不会这样做 / 有没有别的办法」举证，再决定是改契约还是改渲染 —— 而不是在页面层加一个本地推断。
