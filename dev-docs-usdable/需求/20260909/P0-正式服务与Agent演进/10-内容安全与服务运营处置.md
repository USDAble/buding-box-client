# P0-10：内容安全、滥用防护与服务运营处置

| 项 | 内容 |
| --- | --- |
| 当前仓库主责 | 客户端安全/产品组 |
| 外部协作 | 中台网关/风控/运营/法务确定审核策略、限流封禁、留存、申诉和账务冲正规则；本仓库不实现审核或风控服务 |
| 可并行 | P0-03/P0-04 的协议 fixture 冻结后即可开始 |
| 依赖 | P0-03、P0-04、P0-06 |

## 为什么这是 P0

P0-04 处理“本地工具是否可以执行”，P0-06 处理“向云端发送什么副本”；两者都不能替代内容安全和服务运营。真实模型上线后仍需回答：输入/输出被拒绝时如何显示、流式途中安全拦截如何收尾、是否调用过工具、是否扣费、用户如何申诉、异常高频调用由谁处置。没有这套契约，安全结果会被当成普通网络失败，最终造成越权、争议扣费或无法运营。

## 当前仓库开发任务

1. 在 gateway 错误/SSE 事件中识别 `safety_blocked`、`content_restricted`、`account_restricted`、`rate_limited`、`maintenance` 等稳定机器码；UI 使用本地文案和可恢复动作，不透传供应商原始报错或审核规则细节。
2. 定义流式安全终止规则：收到安全终态后停止渲染后续 delta、丢弃尚未批准的 tool call、禁止继续自动重试。网关若允许流中审核，必须保证未批准内容不先发送给客户端，或提供带范围的 `retract`/安全替换事件供客户端原子移除；不能只在末尾追加一句“已拦截”。已批准且已开始的高风险动作仍由 P0-04 的本地 PEP 和取消语义处理。
3. 将安全、限流、资格、余额不足和网关故障分为不同状态，分别展示等待、重试、重新登录、联系客服或申诉入口；不能全部折叠成“模型不可用”。
4. 每次正式模型调用写入最小审计关联字段：`clientRequestId`、turn/session ID、model ID、policy/catalog/safety version、终态 machine code；原始内容、token、供应商 key 不写普通日志。
5. 为“反馈/申诉/扣费争议”预留受控入口：仅提交用户确认的脱敏 request ID、版本和分类，不自动上传完整对话；远端接口未交付前显示真实客服渠道，不造本地假工单。

## 发给中台的交付要求（本仓库不实现）

1. 《内容安全与滥用策略规范》：适用地区/产品场景、策略 owner、policy version、输入与输出审核时点、模型/供应商差异、人工升级与变更公告。
2. 网关 API/SSE 机器码与终态语义：安全拦截发生在供应商调用前、流中或输出后时，是否已有 token 用量、账本该 `settled`、`reversed` 还是 `reconciliation_pending`，以及 tool call 是否允许继续，必须明确。流中审核要么只发送已批准 delta，要么定义经签名/可测试的 `retract` 或安全替换事件，禁止仅依赖客户端“收到末尾错误后别再显示”。
3. 账号/安装标识/请求级的限流、风控、冻结、解冻和维护模式接口；返回可展示的 `retryAfterSec`、`requestId`，不把供应商错误文本泄漏给客户端。
4. 《审计、留存与申诉 Runbook》：最小记录字段、访问 RBAC、保存期限、客服可见范围、用户申诉/退款/冲正时限、紧急封禁和误拦恢复 owner。
5. sandbox fixture 覆盖输入拒绝、流中拒绝、输出拒绝、429、冻结、维护和恢复；每种结果均可按 `clientRequestId` 查到审计和账本终态。

## 验收

- 安全拦截、限流、封禁、维护、余额不足和普通网络失败的 UI/重试行为彼此可区分。
- 流中安全终止不会继续触发未批准工具，也不生成第二个模型请求；账务终态严格按中台状态显示。
- 普通日志和反馈包不含原始对话、审核标签明细或供应商错误文本；客服可通过 request ID 定位。
- 每项安全/运营规则都有产品 owner、服务 owner、客户端 machine code、用户动作和 E2E 证据，缺任一项不得发布。

## 不做

不以本地敏感词替代模型内容审核；不在客户端保存或推断供应商审核规则；不让隐藏菜单、系统提示词或模型文本充当安全边界。
