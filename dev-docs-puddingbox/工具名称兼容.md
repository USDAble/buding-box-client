# 工具名称兼容

写作参照：`dev-docs/m7-skills-design.md`

模型返回的工具名称允许与当前回合已提供的工具名称仅有大小写差异。例如已提供 `skill`、`glob` 时，返回 `Skill`、`Glob` 会分别执行现有的技能加载和文件匹配工具。该规则由共享 agent 循环处理，CLI、桌面、Web 和定时任务复用同一入口。

## 在权限检查之前确定名称

`internal/agent/tool_names.go` 的 `canonicalToolName` 只查询本回合传入的 `ToolDefinition` 列表：精确匹配优先；没有精确匹配时，只有唯一的忽略大小写匹配才转换。未知名称和存在歧义的名称保留原值，不猜测工具，也不扩大工具目录。

`Agent.runLoop` 在记录工具调用、发送工具开始事件和执行权限检查之前调用 `canonicalizeToolCallNames`。因此 PreToolUse / PostToolUse hooks、权限规则、执行器、读后写检查、历史和完成事件都使用同一个标准名称。工具调用 ID、参数、参数解析错误和结果配对保持原有语义；不修改供应商返回的原始切片。

本地问题的触发记录是定时任务创建会话返回了 `Skill` 与 `Glob`，而客户端注册名称为 `skill` 与 `glob`，导致严格名称分发返回 unknown tool。技能文件已经存在，错误发生在进入技能加载前。修复不改变任务创建流程或调度规则。

## 验证

`internal/agent/tool_names_test.go` 覆盖标准名称、大小写变体、未知名称、未提供工具、名称碰撞，以及流式和非流式循环中的权限拒绝、历史、事件和调用 ID。

`internal/tools/tool_names_test.go` 以真实 agent 循环和 `DefaultRegistry` 加载隔离的 `cron-task-creator` 技能并执行 `Glob`，同时验证大小写变体不能绕过已有文件的读后写检查。测试只使用临时文件和模型回复夹具，不调用真实模型、不创建定时任务。

本地开发使用 `make desktop-dev` 时，该 Go 行为需要重新构建并重启开发桌面进程，Vite 热更新不能替换已运行的后端代码。

## 非目标

- 不支持把 `Bash` 猜测为 `terminal` 等不同名称，也不修改工具参数。
- 不增加重试、额外模型请求或备用执行器。
- 不修改权限策略、技能可用范围、MCP 配置或任务数据。
