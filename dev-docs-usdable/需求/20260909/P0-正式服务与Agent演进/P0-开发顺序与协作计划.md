## 1. 合并波次

### 文件即工作包

本目录以**一个编号 Markdown 文件 = 一位 owner 的一个开发工作包**执行。文件内部的步骤、接口和验收是该 owner 的完成定义，不再拆成多人并行的更小任务；代码可以分小 PR，但必须归属于同一编号文件。非编号的 `README.md`、本文件和`客户端架构演进评审.md`只维护共识，不承接功能实现。

| 工作包文件 | 建议 owner | 唯一主改动面 | 与他人协作的唯一接口 |
| --- | --- | --- | --- |
| `00-Fork基线与生产Profile前置.md` | 架构/发布负责人 | upstream 基线、desktop 启动面、批准的 server 挂点清单 | profile 拒绝矩阵与挂点预算 |
| `01-运行时Profile与窄端口抽象.md` | 客户端核心负责人 | 共享 DTO、error code、fake、resolver 合同 | versioned DTO/fixture |
| `02-认证与控制面Bootstrap.md` | 认证/控制面客户端负责人 | `internal/productclient` 的认证、bootstrap 与缓存 | OpenAPI/错误码/签名 fixture |
| `03-模型网关与Token账本.md` | Agent/gateway 客户端负责人 | `internal/productclient/gateway`、SSE 与请求终态 | gateway fixture、`clientRequestId` 契约 |

## 2. 文件所有权与并行边界

| 工作流 | 主改动区域 | 不得并行占用 |
| --- | --- | --- |
| Fork/profile 核心 | `P0-00` 文档、`cmd/octo-desktop/` 启动装配、登记的 `internal/server` 小挂点 | 未批准的 `internal/server` 通用 handler、路由注册和上游函数签名 |
| 产品服务 client | `internal/productclient/`、`internal/productclient/gateway/`、fake/contract | `internal/server` 的 session/WS 实现 |
| 策略与工具 | `internal/productpolicy/`、PEP adapter、模型/能力 UI projection | gateway 协议和 credential store |
| 凭证与数据 | `internal/credentialstore/`、`internal/productstate/` 迁移、`internal/datapath/`、诊断白名单 | 中台 API 实现、supplier sender |
| 隐私与运营 | sending copy、词库缓存、正式文案、安全事件映射 | 在 server handler 手写安全/词库 HTTP |
| 发布与 QA | 更新器、crashlog、SBOM/CI、contract suite、Windows 记录 | 账号/模型业务逻辑 |

对 `internal/server` 的任何修改均由 fork/profile 核心负责人串行整合；其他人提交新包、fake、fixture 和测试。跨工作流通过 DTO、fixture、error code 和 resolver interface 协作，不复制未合并的实现。

## 3. 必须通过的检查

| 关卡 | 关键验证 |
| --- | --- |
| P0-00 | `upstream` 基线已记录；标准包忽略所有开发旁路；未授权 channel/后台能力不自动启动；server 改动预算已批准 |
| B0 | package dependency、DTO/error contract、fake、无客户端扣费 API、未改变 server 行为 |
| B1 | `production` 对 dev URL、环境 provider/model、config/local endpoint、数据根 override 的黑盒拒绝；developer/demo 回归 |
| I | 签名/过期策略、401 刷新、429、余额不足、维护、断流、取消、幂等 request ID 的契约测试 |
| C | 生产模型只能经 gateway；固定积分源代码、响应和测试均删除；配置旁路无效 |
| E | Windows 真机登录、工具确认、拔盘、迁移、更新回退、token 撤销、内容安全和诊断支持全通过 |

## 4. 仍需在开发前拍板的缺口

1. 上游 remote 的真实地址和首次合并窗口。当前仓库只有 `origin`，这是 P0-00 阻塞项。
2. 标准 desktop 是否默认禁用 IM channel、后台任务和哪些工具能力；功能可保留，但启动面必须先定义。
3. 模型首发清单、免费/套餐额度规则、隐私模式是否允许任何云模型。
4. 便携凭证跨 Windows 用户/机器的恢复语义、远端删除保留期、内容安全/申诉和协议显式同意规则。
5. 中台 OpenAPI v1、sandbox、签名 key、错误码、价格/权益配置和 request ID 检索能力。
