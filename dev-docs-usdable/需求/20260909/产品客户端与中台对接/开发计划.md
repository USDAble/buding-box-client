## 1. 已确认的架构决定

1. `internal/server` 是 2026-06-01 已存在的上游通用 server；本产品工作始于 2026-09-08。P0 不迁移、不重构上游 HTTP/WS/agent/session 通用能力；但 2026-09-08/09 落入其中的布丁产品路由、状态、门、词库和发送策略必须按 [P0-01A](../P0-正式服务与Agent演进/01A-既有产品逻辑迁出internal-server.md) 迁出，避免产品改动继续扩大后续上游合并冲突。
2. 不能因此把 `internal/server` 视作完全不可改：开发 Web URL、环境模型来源和数据根 override 需要 production 护栏；但 `config.yml`、channel、MCP、工具与后台能力必须保留（`config.yml` 的 URL/key 在 developer/test 完全允许）。P0 只允许在 P0-00 登记过的文件增加小型、带 `OCTO-FORK` 注释的通用挂点；入口可见性由 P0-00A/P0-04 在产品层处理。另：`ensureLocalEndpoint()` 与假模型种入已于 2026-09-11 删除，见 P0-01A §2。
3. 不创建 `internal/backend`：这个名称会把“当前客户端 HTTP 调用方”和“中台服务端”混为一谈。
4. 不创建 `internal/productapp`：它与现有上游 `internal/app` 语义相近，并会诱导把 server handler 整体搬到新层。
5. P0 新增包只承担明确职责：

| 包 | 责任 | 不负责 |
|---|---|---|
| `internal/productclient` | 调用认证、bootstrap、模型目录、用量、词库、协议确认等中台 API；校验 DTO、错误码、超时与签名 envelope | 不保存业务权威状态，不计算/扣减积分，不提供 local developer adapter |
| `internal/productclient/gateway` | 声明网关调用的**观察/终态 contract**（`Observer.Wrap` / `CallMeta` / `TerminalSink` / `ControlClient`），把观察结果转成 `clientRequestId`、流式事件、取消与终态查询 | **装配（它不得 import `internal/app`，装配在宿主 `cmd/octo-desktop`）**、供应商 endpoint/key、本地模型直连、**SSE/HTTP/重试/token 解析（复用 `internal/provider`）** |
| `internal/productpolicy` | 校验已签名的目录/策略快照，并在发起 Agent、选择模型、发送消息前执行本地 PEP | 不向用户开放策略编辑，不以本地配置替代服务端授权 |
| `internal/credentialstore` | 通过 OS Keychain/凭证库保存 refresh token，提供轮换与清除 | 不把 token 写进 `product-state.json`，不让 UI 读取 token |

依赖方向保持为：

```text
cmd/octo-desktop
  -> internal/productprofile
  -> internal/productruntime
      -> internal/productclient       (认证/控制面/用量)
      -> internal/productclient/gateway
      -> internal/productpolicy
      -> internal/credentialstore
      -> internal/runtimeport         (仅 P0-01A 获准时使用的中性接口)
  -> internal/app                     (唯一的 provider client 构造位置；gateway sender 在此装配
                                       后再交给 productruntime.Observe —— 产品包不得 import 它)
  -> internal/server                  (上游通用运行时)
      -> internal/runtimeport         (仅 P0-01A 获准时使用的中性接口)
```

## 2. 现状 mock 与正式替换点

下表是 P0 必须收口的真实代码证据。这里的“替换”不代表将 developer 代码抽象后长期并存；生产 Profile 必须拒绝或完全不装配这些来源。

| # | 能力域 | 当前证据 | 正式客户端做法 | 中台交付 |
|---|---|---|---|---|
| M1 | 短信验证码 | `internal/server/product_login.go` 的 `fixedCode`、`loginCodes` | `productclient` 调发送/校验接口；生产不接受固定验证码或进程内验证码 | 认证 API、频控/错误码、sandbox |
| M2 | 激活码 | `activationCode` 固定比较 | 仅首次激活时提交给认证服务；激活状态由 bootstrap 返回 | 激活校验、幂等与错误码 |
| M3 | 登录会话 | `newAccountToken()` 生成 `local-` token | 只接受中台 access/refresh 会话；刷新单飞、401/撤销即清凭证 | 登录/刷新/登出 API |
| M4 | 登录态落盘 | `internal/productstate/state.go` 明文 `Account.Token` | 迁移 refresh token 至 `credentialstore`；状态文件只留非敏感投影 | token 生命周期、吊销语义 |
| M5 | 积分旧扣减 | `internal/server/handlers.go` 的 `consumeCredit()` | 删除“每条消息扣一分”及调用/测试；客户端只读用量和请求终态 | 网关预留、结算、冲正、账本 |
| M6 | 套餐 | 首次激活写死 `trial` | 只消费 bootstrap 的套餐、状态和到期时间；UI 不自行判定额度 | 套餐/权益快照 |
| M7 | 模型目录 | `chatmode.Builtin()` 的出厂 `buding-*` 名单（`ensureLocalEndpoint` 已删除） | 生产只使用签名目录中的 `id`/`displayName`/能力/策略版本（请求时该 id 作为 `modelId` 上报）；模式分组改为目录投影，**模型展示名原样渲染目录 `displayName`，前端不保留本地名称表**（debug/test 除外，见[中台交付包](中台交付包.md) §4.3） | 模型目录、签名、版本/失效语义、本地缓存与刷新 |
| M8 | 模型通道 | `internal/provider/local` 的确定性回复 | 标准产品只能经 `gateway` 访问中台；local provider 仅开发/研发验证 Profile | 模型网关 SSE 与终态查询 |
| M9 | 通用敏感词 | 仅内置词和用户本地词 | 本地内置 + 最近有效服务器缓存 + 用户词三层并集；服务端词不可删除 | 词库增量、ETag、签名 |
| M10 | 协议/隐私 | `web/src/lib/brand.config.json` 未批准文案 | 启动时拉取必需版本；未确认或版本变更不得进入主功能 | 正式文案、版本、确认记录接口 |

## 3. 客户端契约和错误边界

`productclient` 对外暴露的是按领域划分的窄 client，不暴露一个泛化的“后端接口”。**方法签名以 [P0-01 合同骨架](../P0-正式服务与Agent演进/01-运行时Profile与窄端口抽象.md#合同骨架) 为唯一来源**；本表只补充客户端责任，不重复声明签名，避免两份文档再次分叉。

| Client | 最小方法 | 客户端责任 |
|---|---|---|
| `AuthClient` | `SendCode`、`Login`、`Refresh`、`Logout` | 手机号规范化；将中台错误稳定映射为既有 machine code；不得在日志写入验证码/token |
| `ControlPlaneClient` | `Bootstrap`、`Models`、`SensitiveDictionary`、`LegalDocuments`、`AcceptLegal` | 校验响应 schema、时钟窗口、签名与版本；原子缓存最后一份有效快照 |
| `UsageClient` | `Usage`、`RequestStatus`、`Ledger` | 只读展示和断线后对账；没有 `Consume`/`Debit`/`amount` API |
| `gateway.ControlClient`（`internal/productclient/gateway`） | `Cancel`、`RequestStatus`（模型流本身复用 `internal/app` 的既有 `agent.Sender`，见 [P0-01 §合同骨架](../P0-正式服务与Agent演进/01-运行时Profile与窄端口抽象.md)） | **每次网关调用**生成一个 `clientRequestId`（一个用户回合含多轮工具调用时会有多个，各自独立预留/记账，见[中台交付包](中台交付包.md) §3.1、§5.1）；处理断线、取消和终态补查；不自行解析 SSE（复用 `internal/provider`） |

统一错误信封与错误码以[中台交付包](中台交付包.md) §3.2 为**唯一登记表**：字段固定为 `code` / `message` / `field` / `retryAfterSec` / `requestId`，`message` 仅供人读、客户端不得作为文案来源。前端只依据稳定的 machine code 映射文案。关键语义（本表不复述码值，新增码只改中台交付包 §3.2）：

- `activation_required`（未激活）、`plan_expired`（套餐到期）、`insufficient_credits`（额度不足）、`model_not_allowed`（模型无资格）是不同状态；前端对应不同阻断动作，不能统称为“授权到期”。
- `usage_pending` 表示网络中断或流被截断后尚未确定结算；客户端查询 `RequestStatus`，不能自行回补或扣减。
- `catalog_signature_invalid`、`policy_expired`、`bootstrap_stale` 必须 fail-closed：保留当前会话展示，但阻断新 Agent 和新模型请求。

完整字段、签名、幂等、SSE 事件、鉴权、数据留存要求以[中台交付包](中台交付包.md)为准；中台变更必须先更新该文档与 OpenAPI，再由客户端更新 contract sample 和 contract test。

**模型展示名与错误码同一条纪律：只有一个来源。** 用户可见的模型名取目录 `displayName` 并**原样渲染**，前端不得维护"模型 id → 名称"的本地映射（`i18n.ts` 的 `model.<id>` 一类）；中台改名后选择器应立即跟着变。debug/test 构建在无可用目录时可回退到 `id`，该回退不进 production 渲染路径。模式名不受此约束 —— 三个模式是产品固定的，仍走本地 i18n `mode.<id>`。详见[中台交付包](中台交付包.md) §4.3 与 [P0-11](../P0-正式服务与Agent演进/11-前端投影与文案.md)。

## 4. 产品运行时装配与上游 server 边界

P0 在 desktop composition 构造 `productprofile` 与 `productruntime`，由后者接入产品新包并逐步承接既有产品 handler。禁止：移动 server 通用路由、把通用 handler 搬至新目录、改变上游公开类型签名、将中台 HTTP 细节散落到 server handler。

允许的改动范围和验收：

| 场景 | 最小改动 | 验收 |
|---|---|---|
| 启动 | desktop 加载嵌入式 `production`/`developer` Profile，构造产品依赖 | production 不能被 `OCTO_DESKTOP_DEV_URL`、provider/model 环境变量或数据根 override 改写；`config.yml` 保留（developer/test 可配第三方 endpoint/URL/key），正式会话的模型来源隔离由 P0-05 验证 |
| 登录/账户 | `productruntime` 调 `AuthClient`，将响应映射为既有 machine code | 不改变前端错误语义；token 不再落盘 |
| bootstrap/目录/词库/协议 | `productruntime` 通过 control-plane client 获取和校验快照 | 无有效签名或必需协议未确认时 fail-closed |
| 消息/Agent | productruntime 在经批准的窄端口前做 PEP，获准后由 gateway sender 发送 | 生产不直连 provider；取消、断线、重试不重复结算 |
| 用量 | 删除 `consumeCredit()` 及固定积分研发验证逻辑 | 不存在客户端扣费请求或本地余额权威 |

`internal/server` 默认不改。若 desktop/productruntime 均无法完成接入，才可申请一个无产品业务名词的通用端口；该改动必须带 `OCTO-FORK` 注释，注明原因和关联 P0 文档，并登记在 P0-00。不得以“方便接入”为由扩大重构。

## 5. 开发顺序、并行和中台协作

### B0：前置闸门（必须先完成）

> **2026-09-11 进度**：合同已从文档冻结为可编译、可测试的代码 —— `productclient`（`code.go`/`envelope.go`/`dto.go`/`contract.go`）、`productclient/gateway`（`ControlClient`/`Observer`/`CallMeta`/`CapabilitiesOf`）、`productpolicy`、`credentialstore`、`productruntime`；mock（`!product_production`）覆盖成功/401/过期/取消/余额不足；依赖方向与错误码登记表各有防回潮测试。**B1 的 wire 形态已定案**：每次网关调用构造一个 sender（`clientRequestId` 随该次调用的 `Headers` 固定），不用装饰器 —— 理由与备选方案的否决过程见 [P0-01 §合同在代码中的落点](../P0-正式服务与Agent演进/01-运行时Profile与窄端口抽象.md)。

1. 确认 `buding` 已接收仓库负责人批准的 `main`；当前客户端开发不配置或评估上游 remote。
2. 落地全局嵌入式 Profile 配置，并写出 production 的拒绝矩阵：开发 Web URL、环境变量 provider/model/key、`OCTO_DATA_ROOT` 与运行时 Profile 切换必须逐项拒绝；`config.yml`、channel、MCP、工具与后台能力明确保留（`config.yml` 的 URL/key 在 developer/test 完全允许），并由 P0-00A 约束首发入口可见性。`ensureLocalEndpoint()` 已删除，不再属于本项。
3. 用黑盒测试证明 production 不能被环境变量/配置/缓存/WebView 输入切为 developer，且不加载开发 Web URL 或数据根 override；developer Profile 仍可显式使用研发验证能力。正式模型网关接入前，不把保留的本地能力误判为 P0-00 的删除对象。
4. 中台提供与[中台交付包](中台交付包.md)一致的版本化 OpenAPI、签名公钥、sandbox contract sample 和错误码基线。

### B1：可并行的客户端基础

| 工作包 | 所有者 | 产物 | 依赖 |
|---|---|---|---|
| 领域 DTO/错误/HTTP 基础 | 客户端 A | `productclient`，schema/contract tests | B0 的 OpenAPI contract sample |
| 签名目录和 PEP | 客户端 B | `productpolicy`，过期/篡改/撤销测试 | B0 的签名规则与 policy contract sample |
| 凭证迁移 | 客户端 C | `credentialstore`，旧 token 清理/轮换/撤销测试 | B0 的 refresh 语义 |
| gateway sender | 客户端 D | `cmd/octo-desktop` 装配 `app.NewSender` + `productruntime.Observe`（`productclient/gateway` 只出 contract，**不装配**）；终态/取消/补查测试；**不得新增 SSE 解析实现** | B0 的 SSE sandbox |

### B2：受控接入与验收

1. 由一名集成人员在 `productruntime` 装配 B1 成果；业务开发人员不并行修改 server。必要的 server 通用端口须先登记、单独评审。
2. 删除 M5 固定扣分 mock 及全部调用点；把模型选择、授权、发送和终态对账串成单个 `clientRequestId` 闭环。
3. 接入登录、bootstrap、目录、词库、协议确认和更新清单；未具备真实中台 sandbox 的功能维持“不可进入生产”的发布门禁，不能以旧本地数据放行。
4. 完成异常闭环：登录刷新失败、套餐到期、积分用尽、流中断、取消、重复请求、目录签名失败、词库拉取失败、更新校验失败、离线重启。

## 6. Definition of Done

- P0-00 的上游基线和生产拒绝矩阵均有可复现记录。
- 标准产品请求没有任何本地 provider、固定验证码、旧本地 token、本地确定性模型、客户端扣费或供应商密钥路径。
- 中台接口通过 schema/contract test；关键错误码、SSE 终态和幂等行为通过 sandbox 验证。
- `internal/server` 除获准的中性端口外保持零新增产品逻辑；2026-09-08/09 遗留产品路由按 P0-01A 迁出，且没有上游通用能力迁移或大规模重构。
- 用量、套餐/激活、模型授权、策略校验、协议确认、词库、凭证和更新都形成成功与失败的闭环。
- 文档、OpenAPI、contract sample、自动化测试的版本号一致；接口破坏性变更没有静默兼容。
