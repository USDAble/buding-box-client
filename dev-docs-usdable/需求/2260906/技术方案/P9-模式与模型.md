## 1 结论

1. **两级：先模式、后该模式下的模型。** 选中值仍是**某个具体模型**；模式同时是该**会话上的属性**。两者是**两个独立属性**，分别持久化（`B5` 规则 6）。
2. **模式是分组，不是过滤后的另一种模型。** 三个模式的产品常量 id 固定；**展示名是界面文案**、**分组归属来自目录** —— 两者不得互相推导（`B5` 规则 1）。
3. **换模式只影响之后的消息**，已有气泡不回溯（`B5` 规则 5）。

## 2 三个模式

| 模式 id | 对用户的含义 | 发送时额外做什么 | 名单来源（`B5` 落地后） |
| --- | --- | --- | --- |
| `privacy` | 更适合本地、少外传 | 合规敏感词 + **PII 脱敏**；`P10` 三处提示 | 目录中该模式分组的模型 |
| `smart` | 更适合云端、能力更强 | 只过合规敏感词（与默认相同） | 同上 |
| `default` | 自选模型，不额外套用隐私策略 | 只过合规敏感词 | 同上 |

三个名单**允许重叠**。出厂「新会话默认模式」＝ `default`。

## 3 选择器结构

### 3.1 挂载点与 landing 页

选择器位于**主聊天区当前会话处**（输入框附近 / 会话顶栏），与原有模型选择**同一位置扩展**。

**两种情形要分开：**

| 情形 | 模式来源 |
| --- | --- |
| 已有会话 | 该会话的 `chat_mode` 字段 |
| 空白 landing 页（会话尚未创建） | `pendingChatMode` store |

**为什么 landing 页要单独存一份：** 会话是**第一条消息到达时才创建**的（`ensureActiveSession`）。在这之前用户已经能点模式，如果直接写会话字段就会写到一个不存在的会话上。`pendingChatMode` 把选择**暂存**下来，在会话真正诞生时一次性交付 —— 与 `pendingModel` / `pendingPermissionMode` 同一个模式（它们各自对应一个"落地页选择在会话创建前是静默 no-op"的历史缺陷）。

**文案的取值链**（`Composer.svelte` 的 `currentMode`）：

```
会话自己的属性 → landing 页的待定选择 → 账号默认模式 → 'default'
```

> **引用勘误（2026-09-12）。** `web/src/App.svelte:93` 的注释把这个 §3.1 当作 `suppressOnboarding`（便携包跳过配 Key 向导）的依据，但那是 `A4`／产品门的行为，**不是**模式与模型。该处引用指向本文档的这一节属于**误引**，应改指 `需求基线` `A4`。已登记，未改代码（属注释修正，归下一次触碰该文件时一并处理）。

### 3.2 两级结构

1. 第一级：三个模式分组。
2. 第二级：该分组下的模型列表。
3. 选中某个模型 = **同时**设置该会话的模式与该模型（`setSessionMode(sid, mode, modelId)`），两个属性各自写一次。

**"点模型顺带定模式"是有意的**：两级里唯一有确定语义的落点是模型。让用户先选模式、再选模型是两步；点模型则一步到位，而模式是这个选择的**结果**（模型属于哪个分组）。用户要的是"换一个模型"，不是"先声明我在哪个模式"。

### 3.3 空名单

某模式下列表为空 → 「该模式下暂无可用模型」，**禁止空白无说明**（`B5` 规则 2、`B9`）。

**不得**因此弹出「配 API Key」向导 —— 那会把"这个分组没有模型"误解成"程序没配好"，而便携包根本没有这一步。

### 3.4 会话属性

- 改当前会话的选择器**不影响**其它会话，也**不改**个人中心的默认值（`B5` 规则 4）。
- 会话中途改模式只作用于**之后**发出的消息（`B5` 规则 5）。

## 4 数据与持久化

### 4.1 会话字段

会话上持久化两个字段：`chat_mode`（模式 id）与 `model` / `model_id`（模型）。换机器随 `data/` 走（`B8` 规则 3）。

### 4.2 分组来源（**本条的数据源已作废**）

**写作时的形态（已过时，仅供理解改动范围）：** 分组来自 `data/chat-modes.json`，经 `GET /api/product/chat-modes` 下发，形状为 `ChatModeDTO[]`；`ChatModeModel.id` 是复合 `"<endpoint>::<model>"`，模型在配置里不存在时该 id 为空（不可选）。

**`B1` 的裁定：** 目录的**唯一来源是中台签名目录**；`data/chat-modes.json` 不再落盘（`B1`）。因此：

| | 写作时 | `B1` 落地后 |
| --- | --- | --- |
| 分组来源 | 本地 `chat-modes.json` | 签名目录的 `catalog.modes` |
| 模型列表 | 本地文件 + `config.yml` 求交集 | 目录 `catalog.models`（`eligible` 且 `transport=gateway`） |
| 刷新时机 | 菜单打开时重读文件 | `B3` 定的目录刷新时机 |
| 可否离线 | 文件在就可用 | 用**验过签的缓存**（`B2`），过期按 `B4` |

**落地后果：** `loadChatModes()` 的"打开菜单时重读文件"要改成"读目录缓存"，`chatModesFallback`（"文件读不到、用了内置默认"）随之改由 `B4`/`B9` 的口径表达。

### 4.3 展示名（**硬改写**）

**写作时的实现（必须删除）：**

```ts
// modelDisplayName localises a model id. Factory models buding-* have i18n
// keys; anything else falls back to the raw id.
export function modelDisplayName(id: string): string {
  const key = `model.${id}`
  const v = tr(key)
  return v === key ? id : v
}
```

**`B6` 的裁定：原样渲染目录里的 `displayName`，前端不保留 id→名表。**

理由（这条正是 §3.8 的例子）：平台把某个模型改名后，服务端目录已经变了，而本地文案表还是旧名 —— **界面会一直显示旧名且没有任何报错**。一张本地表**遮蔽**了服务端的真值。

| 规则 | 要求 |
| --- | --- |
| 渲染 | 目录 `displayName`，形状 `{"zh": "云端旗舰", "en": "Cloud Pro"}` |
| 取法 | 按当前界面语言取；缺当前语言键 → 回落 `en`；再缺 → 回落 `id` |
| 禁止 | 客户端**不做** id→多语言的映射表 |
| 模型 `id` | 一律英文 ASCII（如 `buding-cloud-pro`），**不随语言变化、不做本地化替换** |
| 回落作用域 | 只允许出现在 **debug/test** 路径；**正式渲染路径不得回落** |

`modeDisplayName()`（模式分组名）**不是**这条的一部分：模式是**产品常量**，它的展示名是界面文案（`§5`），不从目录取。

### 4.4 store 形状（`stores.ts`）

| store | 作用 |
| --- | --- |
| `chatModes` | 已加载的分组列表 |
| `chatModesFallback` | 上次加载是否用了内置默认（`B4` 落地后含义变更，见 §4.2） |
| `chatMode` | 按会话 id 的模式，供 chip 与菜单响应式读取 |
| `pendingChatMode` | landing 页的暂存选择（§3.1） |

`chatMode` 与 `sessions` 两份都更新，是为了让**会话芯片**与**菜单高亮**都能立即响应，而不必重新拉取会话列表。

## 5 文案

**模式展示名是界面文案**（产品常量，三个模式固定）：

| key | 中文 | 英文 |
| --- | --- | --- |
| `mode.privacy` | 隐私 | Privacy |
| `mode.smart` | 智能 | Smart |
| `mode.default` | 默认 | Default |
| `mode.no_models` | 该模式下暂无可用模型 | No models available in this mode |

**与模型展示名的区别（容易混）：**

| | 来源 | 能否被平台改变 |
| --- | --- | --- |
| 模式展示名 | 本地 `i18n`（产品常量） | 否 |
| 模型展示名 | **目录 `displayName`**（服务端数据） | **是** |

`mode.*` 这四个键在 `i18n` 里**只保留一份**；**不得**为模型 id 增设 `model.<id>` 这类键（`B6` 验收：代码里搜不到该模型 id 的文案键）。

## 6 验收

| # | 验收项 | 判据 |
| --- | --- | --- |
| 1 | 两级可选 | 选模式 → 只列该分组的模型；选模型 → 模式同步变为该分组 |
| 2 | 空分组有文案 | 造一个空分组 → 「该模式下暂无可用模型」，**不弹配 Key 向导** |
| 3 | 只改本会话 | 改当前会话模式 → 其它会话与账号默认值不变 |
| 4 | 只影响之后 | 会话中途改模式 → 已有气泡不回溯 |
| 5 | landing 页选择不丢 | 空白页选模式 → 发出第一条消息 → 新会话继承该模式 |
| 6 | `displayName` 原样渲染 | 改目录里某个 `displayName.zh` → 刷新后中文界面即变（`B6`） |
| 7 | 英文界面取英文名 | 同一模型在英文界面显示 `displayName.en`（`B6`） |
| 8 | 无 id→名表 | 代码里搜不到该模型 `id` 的文案键（`B6`） |
| 9 | 下架不静默换 | 发一次消息 → 下架该模型 → 再发：提示重选，**不换模型、不报硬错**（`B8`） |
