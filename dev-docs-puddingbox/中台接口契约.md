# 中台接口契约

写作参照：`dev-docs/endpoint-custom-headers-design.md`；迁移结构补充参照 `dev-docs/endpoint-pr5-impl.md`

> 本文是当前桌面客户端实际控制面协议的服务端对照：请求路径、字段、令牌行为、已签名载荷和失败边界均以 `internal/productclient`、`internal/productruntime` 及其测试为准。Web UI 不直接调用这些接口；它只消费 [本地 API 契约](本地API契约.md)。

## 范围与运行时边界

控制面与网关是两类不同的服务：控制面处理账户、令牌、目录、词库和账本；网关承载 OpenAI 兼容的模型调用。两者的地址来自编译进二进制的 `internal/productprofile`，不能由配置文件、环境变量或 WebView 输入替换。

生产 profile 当前仍使用 `.invalid` 占位主机且没有可信签名 key，因此不是可联调的生产配置；开发 profile 使用本地控制面和一把开发公钥。部署时应替换 profile 资产并通过 profile 校验，而不是在运行时找默认 host。

本文不定义：

- Web UI 的请求、文案、窗口令牌或本地状态文件。
- 中台未被当前客户端读取的字段（例如账本 entries、能力矩阵）。服务端可以扩展成功载荷，Go JSON 解码会忽略未知字段；客户端开始消费前不得把它们写成已支持功能。
- 新的业务码。新增或改名必须同时更新 `internal/productclient`、中台 stub、测试和本文件。

## 主机与传输

| 服务 | Profile 字段 | 当前客户端怎样组路径 |
| --- | --- | --- |
| 控制面 | `apiHost` | 直接拼接以下相对路径；实际 host 必须自行带版本段，例如 `https://api.example/v1` |
| 模型网关 | `gatewayHost` | 交给既有 OpenAI provider；裸 host 或以 `/v1` 结尾均可，provider 归一化后调用 `/v1/chat/completions` |

所有控制面调用设置 `Accept: application/json`；有 JSON 请求体时设置 `Content-Type: application/json; charset=utf-8`。`X-Client-Version`、`X-Client-Platform`、`X-Client-Arch`、`X-Install-Id` 在对应元数据非空时发送。`X-Install-Id` 是一次安装生成的标识，不是硬件序列号。除产品反馈外，当前调用不会填 `Idempotency-Key`，但服务端应能忽略未知头和未来字段。

受保护调用携带 `Authorization: Bearer <access token>`。客户端响应体读取上限为 1 MiB，HTTP 客户端超时为 30 秒；连接、读 body 等未得到 HTTP 响应的失败被本地归类为 `network_unavailable`。

成功体的可互操作形状是：

```json
{"data": {"...": "..."}, "requestId": "req_...", "serverTime": "2026-09-18T00:00:00Z"}
```

当前解码器只强制需要 `data`；`requestId` 与 `serverTime` 是可用于排障的服务端字段，但客户端没有校验或消费它们。错误体不包在 `data` 下：

```json
{"code":"rate_limited","message":"diagnostic only","field":"code","retryAfterSec":60,"requestId":"req_...","phoneMasked":"138****0000"}
```

`message` 不得作为用户文案来源。没有有效 `code` 的非 2xx 响应会被客户端降级：5xx 为 `upstream_unavailable`，其余状态为 `internal_error`。`phoneMasked` 只在 `phone_mismatch` 时有业务意义，服务端必须返回真实的脱敏号码。

## 控制面端点

| 方法与路径（相对 `apiHost`） | 鉴权 | 请求 `data` | 成功 `data` | 当前运行时用途 |
| --- | --- | --- | --- | --- |
| `POST /auth/sms/send` | 否 | `{phone,purpose:"login",clientRequestId?}` | `{cooldownSec,expiresInSec}` | 发送登录验证码 |
| `POST /auth/login` | 否 | `{phone,code,nickname?,activationCode?,boxCode?,installId,clientRequestId?}` | access/refresh token、期限、account、activation | 登录并保存 refresh token |
| `POST /auth/refresh` | refresh token 在 body | `{refreshToken}` | 新 access/refresh token 与期限 | 自动续期；refresh token 必须轮换 |
| `POST /auth/logout` | Bearer | 无 body | body 可为空 | 尝试撤销平台会话 |
| `GET /client/bootstrap` | Bearer | 无 | account、activation、credits、policy envelope | 客户端已实现；当前桌面运行时没有生产调用点 |
| `GET /catalog/models?knownVersion=` | Bearer | 无 | policy envelope 或 `{unchanged:true}` | 登录后获取及按需刷新模型目录 |
| `GET /dictionaries/sensitive?version=` | Bearer | 无 | signed dictionary envelope | 仅成功登录后同步服务端词库 |
| `GET /credits/ledger` | Bearer | 无 | `{balanceMicroCredits}` | 本地余额投影的唯一写入来源 |
| `POST /feedback` | Bearer | `{category:"bug"|"suggestion"|"other",content:"..."}`；`Idempotency-Key: <UUID>` | `{feedbackId,acceptedAt}` | 接收用户主动提交的产品反馈 |

`clientRequestId` 的 struct 字段存在，但当前桌面调用未填值；服务端需接受缺失或空串。登录的 `activationCode` 与 `boxCode` 是可选的一对：两者都提供时是首次激活尝试；两者都省略时由平台判断该帐号是否已有授权；只提供一个应以 `invalid_request` 拒绝。`boxCode` 与激活码是独立校验，返回的 activation 中 `boxCode` 是展示值，不是 secret。

账本的 `balanceMicroCredits` 是指针语义：缺失与数值 `0` 不相同。客户端把缺失视作 `ErrLedgerMalformed`，保留旧余额，绝不把缺失编造成零。即使 login/bootstrap 载荷也含 credits，当前运行时也不以它们写余额；所有余额更新都必须经过 ledger 读取。

## 反馈端点只保存明确提交的反馈

`POST /feedback` 是已由桌面客户端和 `productstub` 覆盖的受保护端点。请求 body 中只允许 `category` 与 `content`；类别只能为 `bug`、`suggestion`、`other`，正文去除首尾空白后为 1–4000 个 Unicode 字符。缺失、未知字段或不合法值以 `400 invalid_request` 拒绝。中台从 bearer token 取得账户，不接受 account ID、手机号、角色或客户端自报的时间戳。

请求必须带 UUID 形式的 `Idempotency-Key`。中台以“已认证账户 + key”去重：相同 key 与相同有效载荷重复提交，返回第一次接受时的同一 `feedbackId` 和 `acceptedAt`；相同 key 但载荷不同以 `409 idempotency_conflict` 拒绝。幂等记录的保留期由中台运维策略决定，但不得短于客户端网络重试窗口。成功体仍使用共同信封：

```json
{"data":{"feedbackId":"fb_...","acceptedAt":"2026-09-19T00:00:00Z"},"requestId":"req_...","serverTime":"2026-09-19T00:00:00Z"}
```

中台可以记录认证账户、服务端接收时间、标准客户端版本/平台/架构头和安装标识以便运营与反滥用；不得期望或要求客户端上传会话、聊天、附件、OCR、工具调用、模型提示/输出、token、文件路径、电话号码、硬件标识或日志。反馈内容不可回显到其他客户端，也不可被当作模型输入。内容保留、删除请求、人工处理权限和反滥用阈值由中台数据治理落实，不由桌面客户端自行推断。

稳定失败码为：`401 unauthorized` / `token_expired`（沿用一次刷新重放）、`403 feedback_not_allowed`、`409 idempotency_conflict`、`429 feedback_rate_limited`（可带 `retryAfterSec`）及 `503 maintenance` / `upstream_unavailable`。不要用 `message` 告知用户具体审核或风控理由；桌面客户端只按稳定 code 映射可操作文案。`feedback_rate_limited` 的具体阈值是中台策略，不能硬编码到客户端或本文。

## 令牌状态机

access token 只存在内存的 `CredentialHolder`；可复制的数据根只保存 refresh token。每个受保护控制面调用走同一流程：

```text
首次请求（当前 access token）
  ├─ 非 401 ──> 原样返回
  └─ 401 / unauthorized / token_expired
       ├─ 刷新成功 ──> 用新 access token 只重放一次原请求
       ├─ 刷新被 401 拒绝 ──> 清内存凭证；运行时清本地会话
       └─ 网络或 5xx ──> 保留凭证，返回该失败
```

并发刷新由互斥锁合并；已被另一调用更新的 access token 不再次交换。refresh 成功时平台必须返回新的 refresh token，客户端把新对写入内存，运行时随后尝试持久化轮换后的 refresh token。持久化失败不会中断当前回合，但下一次启动可能要求重新登录；这是一种有日志的受限降级，不是可忽略的成功。

网关并不经控制面 HTTP 重放器。启动后的首个网关回合若内存没有 access token，会在 10 秒预算内调用同一个 `EnsureToken` 交换 refresh token；无法取得 token 时拒绝开始回合，不回退到本地模型。网关 401 也不由 OpenAI provider 自动重放。

## 已签名目录与词库

目录端点的 `data` 以如下形状携带原始 policy bytes：

```json
{"policy":{...},"policySignature":{"keyId":"kid","sig":"base64-ed25519"}}
```

词库对应为：

```json
{"dictionary":{...},"dictionarySignature":{"keyId":"kid","sig":"base64-ed25519"}}
```

签名覆盖的是嵌入 `policy` 或 `dictionary` 的**原始 JSON 字节**，而非客户端重新序列化的对象。服务端必须先序列化一次，再对完全相同的字节做 Ed25519 detached signature，并将同一字节嵌入外层信封；中间层不得重新格式化、转义或重排该值。

客户端按以下顺序 fail closed：选择 profile 中匹配 `keyId` 的 base64 公钥、验证 Ed25519 签名、解析 JSON、比较载荷内外 `keyId`、比较 audience、验证 RFC3339 的 issued/expires 窗口（允许调用方设置的时钟偏差）。任何一步失败、未知 key、无 key、不同 audience 或过期均不接受新缓存。

目录 policy 当前可消费字段为 `policyVersion`、`issuedAt`、`expiresAt`、`minClientVersion`、`audience`、`keyId` 和 `catalog`。catalog 包含 `version`、`ttlSec`、`vendors` 与 `models`；旧 `modes/modeIds` 不再解析为产品语义。当前最小形状如下：

```json
{
  "catalog": {
    "version": "2026-09-18",
    "ttlSec": 3600,
    "vendors": [
      {"id":"vendor-a","displayName":{"zh-CN":"厂商 A","en":"Vendor A"}}
    ],
    "models": [
      {
        "id":"model-a",
        "vendorId":"vendor-a",
        "displayName":{"zh-CN":"模型 A","en":"Model A"},
        "transport":"gateway",
        "eligible":true,
        "confidential":true,
        "confidentialPriority":100
      }
    ]
  }
}
```

`vendorId` 必须引用同一目录中存在的 vendor；所有模型的 `transport` 当前只接受 `gateway`；`confidential=true` 还要求 `eligible=true`。`confidentialPriority` 只允许出现在私密模型，取值为 `0..1000000`，数值越大优先级越高。未知 vendor、重复 vendor/model ID、非法 transport、矛盾资格或优先级越界时，客户端拒绝整个新目录而不是部分猜测修复。目录可包含没有私密模型的厂商，也可没有任何私密模型；后者是“当前无可用私密会话”，不是协议错误。

词库 payload 支持 `full`（完整 `words`）和 `delta`（匹配 `baseVersion` 后应用 `add`/`remove`）。`sha256` 是最终完整词表的 SHA-256：对 UTF-8 紧凑 JSON 数组字节求 hash；空列表按 `[]`。delta 的 base 不匹配、词项非法或 checksum 不匹配时客户端不写入缓存。

两个条件端点都接受已有版本：目录使用 `knownVersion`，词库使用 `version`。目录内容未变可返回 304 或 `data.unchanged:true`；词库客户端当前只把 304 转为本地 `Unchanged`，因此服务端不能用词库 body 中的 `unchanged` 字段替代 304。两种“未变”结果均不得改写缓存。目录过期时，服务端不能用“不变”掩盖需要刷新的目录。

## 错误分类与服务端约束

| 状态/码 | 客户端语义 |
| --- | --- |
| `400 invalid_phone`、`invalid_code`、`code_not_sent`、`activation_invalid`、`activation_code_used`、`box_code_unknown`、`box_code_mismatch`、`invalid_request` | 登录/激活或输入层面的业务拒绝；具体呈现由本地 API 决定 |
| `401 unauthorized`、`token_expired` | 触发一次 refresh；refresh 再拒绝才结束会话 |
| `403 activation_required`、`phone_mismatch`、`account_restricted`、`plan_expired`、`feature_not_entitled`、`model_not_allowed` | 业务或授权拒绝；不应伪装为 token 失效 |
| `402 insufficient_credits` | 网关回合的余额不足，客户端不本地推算 |
| `429 rate_limited` | 可带 `retryAfterSec`；验证码 UI 使用该值倒计时 |
| `403 feedback_not_allowed`、`409 idempotency_conflict`、`429 feedback_rate_limited` | 反馈业务拒绝、幂等冲突或节流；不结束平台会话。 |
| `503 maintenance`、5xx `upstream_unavailable`、`internal_error` | 非授权失败；不得因此清掉可重试的 refresh token |

业务码的稳定性高于 HTTP 文案。服务端可以提供诊断 `message`，但不可让客户端从 message 推断重试、注销或用户提示。没有平台明确的 401 结论时，网络失败、超时和 5xx 都必须保留本地凭证。

## 网关契约与验证

内置网关使用既有 `internal/provider/openai` 适配器，协议为 OpenAI Chat Completions；流式 SSE、tool-call 重组、请求头及 provider 错误解析不在本 fork 再实现。网关服务必须接受 Bearer access token、与目录中的稳定 model id 一致，并返回该 OpenAI 兼容协议所要求的成功或失败形状。

协议改动至少应验证：

- `internal/productclient/client_test.go`：方法、路径、headers、成功/失败信封、单次刷新与单次重放；
- `internal/productclient/signing_test.go` 与 `clienttest/wire_test.go`：原始字节签名、key/audience/有效期、签名字节不被 writer 改写；
- `internal/productruntime/session_renew_test.go`：refresh token 轮换、拒绝清会话、网络故障不清会话；
- `internal/productruntime/catalog*_test.go`、`dictionary_test.go`：条件刷新、缓存不被拒绝响应覆盖；
- `internal/productruntime/gateway*_test.go`：首回合获取 token、10 秒预算及 OpenAI 适配。
- 新增反馈时：`internal/productclient` 覆盖请求头、字段边界、一次 refresh 后重放和稳定错误码；`internal/productruntime` 覆盖本地字段校验、token 不出本地、错误映射与不持久化正文；`clienttest` 与 `productstub` 覆盖相同 key 的幂等回执、冲突和节流。

任何新增端点、字段、签名 claim 或 error code 都应先在中台与产品 stub 达成同一 wire 形状，再更新这份文档和本地 API 的受影响消费语义。不要用“本地能编译”代替跨服务契约测试。
