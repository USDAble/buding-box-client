## 1 结论

1. **权威在后端。** 前端调用只用于**即时上屏**（把输入框就地替换并给提示），它一定可以被绕过（`curl`、改前端、直接调 `/api/chat`）。所以后端在聊天路径上**必须再检一次**。
2. **两套能力不得共用一份逻辑**：输入检测（可关、拦发送）与输出检测（不可关、只打码）。混用会导致"关掉输入检测顺手把输出过滤也关了"—— 那是安全底线。
3. **匹配规则只有一处实现。** 现在有两份（前端 `normalizeWord()` 与声明中的 Go 侧），必须收敛为「Go 权威 + 前端仅预检」并加一致性断言。

## 2 职责划分

| | 用户输入（§3.1） | 模型输出（§3.2） |
| --- | --- | --- |
| 目的 | 不把违禁原文发给模型 | 界面与历史不出现违禁原文 |
| 用户可否关闭 | **可以**，关前确认 | **不可** |
| 作用范围 | 输入框内将要发送的可见文本 | 用户能看到的模型正文与可见思考；界面展示的工具结果文本 |
| 命中后果 | 本轮不发、框内打码、下方提示 | 打码 `***`，**不截断** |

**界面上不出现两套互相矛盾的提示。** 用户看到的是两者的合并结果，不是"客户端又拦了一次"。

## 3 规则

### 3.1 输入检测（可关，关前确认）

**默认开启。** 点发送、**请求未交给模型时**检测。

命中时：

1. 本轮**不发给模型**。
2. 输入框内命中词替换为 `***`（连续命中合并为一段）。
3. 输入框**下方**提示：「包含敏感内容，已替换敏感词，确认后可再次发送。」
4. 再次发送：对**当前输入框文本**重新检测 —— 未命中才发出。用户把 `***` 改回原词再发 → 视为再次命中，不得发出。

**开关.** 状态写入数据根（`prefs.inputSensitiveCheck`），重启保持；关闭前确认："关闭后，输入将按原文发送。模型回复仍会过滤。" 重新打开**无需**确认。

**作用域（必须写清）：** 关输入检测**不影响**输出过滤，也**不影响**隐私模式 PII（`D1` 规则 2 —— 三者独立）。

### 3.2 输出检测（不可关，只打码不截断）

1. 命中片段一律打码 `***`（连续命中合并），**不截断整段回复** —— 整段消失会让用户以为"模型没回"。
2. **落盘即打码**：写入 `data/` 的历史必须是打码后文本，与最终界面一致（流式可先短暂显示再打码，以落盘为准）。
3. 客户端打码与服务端 `retract`（`C6`）是**两层不同机制**，不能互相替代：前者管「本地不出现原文」，后者管「服务端已判定违禁并撤回」。
4. 不展示的工具原始 JSON、附件二进制、图片 OCR 本期**不做**。

### 3.3 昵称检测（始终开启）

昵称命中则**拒绝保存**（提示「昵称包含敏感内容」），**不写成 `***` 也不要静默替换** —— 把违禁词保存成掩码，等于替用户存了一个他不认识的昵称，而他以为保存成功了。

检测**始终开启**，不受输入框开关影响（`D3`）。格式校验在前端（`nickname.ts`），**敏感词判定归后端**。

### 3.4 三层词库与落点

有效词库 = **内置 ∪ 本地用户 ∪ 服务器下行**（并集，任一层不能覆盖另一层）。

**落点已定（`S-3`），实现不得自行发明路径：**

| 层 | 落点 | 形态 | 可写 | 缺失时 |
| --- | --- | --- | --- | --- |
| 内置 | `go:embed` 进二进制（`internal/sensitive/default-words.txt`） | 编译期嵌入 | 否 | 不存在缺失场景 |
| 用户 | `data/sensitive-words.txt`（`datapath.Join`，**扁平落在数据根下**） | UTF-8 文本，一行一词，`#` 注释 | **是**（唯一可写层） | **当作空词表，不是错误** |
| 服务器 | `data/sensitive-dict-server.json` | `{version, keyId, signature, words[], fetchedAt}` | 否（只由同步写） | 仅用内置 + 用户，可提示一次 |

**为什么内置词必须 `go:embed`：** 随包文件放在数据根里会被用户删掉或改掉，而"文件缺失 = 用默认"要求**默认值不在用户可触碰的位置**（§3.9.1）。内置词一旦成了可删文件，"删掉就没有词"就成了一个静默的 fail-open。

**量级与算法（`S-3`）：** 内置词 ≤ 2 000 条，本期用**子串匹配**。**不做** AC 自动机 / Trie —— 三层合并后总量过万再评估。

**降级（有界）：** 某层缺失/不可读 → 该层降级为"空"，其余层照常；**不整体 fail-open**。三层各自独立加载、失败互不连坐，合并后才匹配。

### 3.5 客户端调用契约与"唯一实现"

**调用（已落地）：**

```
POST /api/product/sensitive/check
Header: X-Octo-Window-Token: <window token>
Body:   { "text": "<待检文本>" }
Resp:   { "hit": bool, "masked": "<打码后文本>" }
```

`web/src/lib/sensitive.ts` 的 `checkSensitive()` 在外壳外（无窗口令牌）时直接回 `hit=false` —— 与产品门的豁免行为一致（不是绕过，是"不在这个壳里"）。

**接线点（`Composer.svelte` 的 `send()`）：**

```
if ($productState?.prefs.inputSensitiveCheck !== false) {
  const res = await checkSensitive(v)
  if (res.hit) { /* 回填输入框 + 置命中提示 + return（不发送） */ }
}
```

注释里的两条边界必须保持：

1. **这是体验层，不是权威。** 失败（网络错、500）**不阻塞发送** —— 由服务端在扣分前再查一次（`checkInputSensitive`）。若把前端失败当拦截，网络一抖用户就发不出消息，而真正该拦的那个后端判定还没跑到。
2. **命中即 `return`**，不是"发出后再提示"。

**"唯一实现"要求（`D6`，尚未满足）：**

现在有**两份**规范化实现：`web/src/lib/sensitiveDict.ts` 的 `normalizeWord()`（注释自称 "mirrors `internal/sensitive/normalize.go`"）与 Go 侧（**尚不存在**）。

| 位置 | 现状 | 目标 |
| --- | --- | --- |
| Go（`internal/sensitive`） | 不存在 | **权威判定**，规则唯一实现处 |
| 前端 `sensitiveDict.ts` | 自称镜像 Go | 降级为**仅客户端重复/空值预检**，且**必须加测试断言两者一致** |

规则本身（原文照抄，不得只写"同上游"）：Unicode 大小写折叠；去掉空白（含全角空格、制表符、换行）；去掉符号表 —— ASCII `!"#$%&'()*+,-./:;<=>?@[\]^_`{|}~` 及对应全角、中文顿号/引号/书名号/破折号/省略号 `、。「」『』《》—…·`；在**规范化文本**上做子串匹配；在**原文**上按命中片段替换为 `***`，连续命中合并为一段。

**注意最后一句的方向：** 匹配在规范化文本上做，替换在**原文**上做。对规范化文本替换会把用户没打对的空格和符号一起吞掉，输出与输入对不上。

### 3.6 与服务端内容安全的边界

1. 客户端（本节）管「本地不发送 / 不显示违禁内容」；服务端管**最终判决**，通过 `safety_blocked` + `retract`（`C6`）表达。
2. 客户端已打码的内容**不会**再被 `retract`；`retract` 撤回的内容**也不由客户端补打码**。
3. 界面不得出现两条互相矛盾的提示（"客户端拦了一次" + "服务端拦了一次"）。
4. **不得把用户原文送第三方审核**（`D8` 规则 4）。

### 3.7 与隐私模式 PII 的顺序

同一轮发送的处理顺序**固定**：

1. **输入合规检测**（用户可关）—— 命中则本轮不发。
2. 通过后，若当前会话是**隐私模式**，再对"发给模型的副本"做 **PII 脱敏**（用户不可关，`P10`）。

**两套独立**：关敏感词不会关掉 PII。用户气泡与本地历史存的是**原文**（PII 只处理发给模型的副本），而敏感词是**替换后的文本**（详见 `P10` §6 的三列表）。

## 4 验收

| # | 验收项 | 判据 |
| --- | --- | --- |
| 1 | 输入命中不发送 | 输入命中词 → 框内 `***` + 下方提示 + 本轮不发 |
| 2 | 改回原词再发仍拦 | 把 `***` 改回原词 → 仍视为命中 |
| 3 | 开关持久 | 关掉输入检测 → 重启仍是关；输出过滤仍生效 |
| 4 | 关输入不影响 PII | 关输入检测 → 隐私模式 PII 仍生效 |
| 5 | 后端可拦绕过 | `curl` 直接发命中词 → 后端仍拦 |
| 6 | 输出只在原文打码 | 命中 → 最终界面与历史都是 `***`，**不是整段消失** |
| 7 | 落盘即打码 | 重启后重读历史仍是打码后文本 |
| 8 | 昵称拒绝保存 | 用命中词改昵称 → 拒绝且提示，**不保存成 `***`** |
| 9 | 三层各自生效 | 三层各放一个独有词，三个都能拦；删掉用户文件后另两层仍生效 |
| 10 | 一份词表两种实现一致 | 含大小写、符号插入、全角的同一输入，前端预检与 Go 判定结论一致 |
| 11 | 降级不 fail-open | 服务器词库文件缺失 → 仅用内置 + 用户，**不是"不检测"** |
