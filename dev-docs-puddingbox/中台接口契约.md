# 中台接口契约

写作参照：`dev-docs/endpoint-custom-headers-design.md`；迁移结构补充参照 `dev-docs/endpoint-pr5-impl.md`

> 本文是当前桌面客户端实际控制面协议的服务端对照：请求路径、字段、令牌行为、已签名载荷和失败边界均以 `internal/productclient`、`internal/productruntime` 及其测试为准。Web UI 不直接调用这些接口；它只消费 [本地 API 契约](本地API契约.md)。

## 范围与运行时边界

控制面与网关是两类不同的服务：控制面处理账户、令牌、目录、词库和账本；网关承载 OpenAI 兼容的模型调用。两者的地址来自编译进二进制的 `internal/productprofile`，不能由配置文件、环境变量或 WebView 输入替换。

生产 profile 当前仍使用 `.invalid` 占位主机且没有可信签名 key，因此不是可联调的生产配置；开发 profile 使用本地控制面和一把开发公钥。部署时应替换 profile 资产并通过 profile 校验，而不是在运行时找默认 host。

本文不定义：

- Web UI 的请求、文案、窗口令牌或本地状态文件。
- 中台未被当前客户端读取的字段（例如账本 entries、能力矩阵）。服务端可以扩展成功载荷，Go JSON 解码会忽略未知字段；客户端开始消费前不得把它们写成已支持功能。
- 新的业务码。新增或改名必须同时更新 `internal/productclient`、中台 stub、测试和本文件。

## 主机与传输

| 服务 | Profile 字段 | 当前客户端怎样组路径 |
| --- | --- | --- |
| 控制面 | `apiHost` | 直接拼接以下相对路径；实际 host 必须自行带版本段，例如 `https://api.example/v1` |
| 模型网关 | `gatewayHost` | 交给既有 OpenAI provider；裸 host 或以 `/v1` 结尾均可，provider 归一化后调用 `/v1/chat/completions` |

所有控制面调用设置 `Accept: application/json`；有 JSON 请求体时设置 `Content-Type: application/json; charset=utf-8`。`X-Client-Version`、`X-Client-Platform`、`X-Client-Arch`、`X-Install-Id` 在对应元数据非空时发送。`X-Install-Id` 是一次安装生成的标识，不是硬件序列号。除产品反馈外，当前调用不会填 `Idempotency-Key`，但服务端应能忽略未知头和未来字段。

受保护调用携带 `Authorization: Bearer <access token>`。客户端响应体读取上限为 1 MiB，HTTP 客户端超时为 30 秒；连接、读 body 等未得到 HTTP 响应的失败被本地归类为 `network_unavailable`。

成功体的可互操作形状是：

```json
{"data": {"...": "..."}, "requestId": "req_...", "serverTime": "2026-09-18T00:00:00Z"}
```

当前解码器只强制需要 `data`；`requestId` 与 `serverTime` 是可用于排障的服务端字段，但客户端没有校验或消费它们。错误体不包在 `data` 下：

```json
{"code":"rate_limited","message":"diagnostic only","field":"code","retryAfterSec":60,"requestId":"req_...","phoneMasked":"138****0000"}
```

`message` 不得作为用户文案来源。没有有效 `code` 的非 2xx 响应会被客户端降级：5xx 为 `upstream_unavailable`，其余状态为 `internal_error`。`phoneMasked` 只在 `phone_mismatch` 时有业务意义，服务端必须返回真实的脱敏号码。

## 控制面端点

| 方法与路径（相对 `apiHost`） | 鉴权 | 请求 `data` | 成功 `data` | 当前运行时用途 |
| --- | --- | --- | --- | --- |
| `POST /auth/sms/send` | 否 | `{phone,purpose:"login",clientRequestId?}` | `{cooldownSec,expiresInSec}` | 发送登录验证码 |
| `POST /auth/login` | 否 | `{phone,code,nickname?,activationCode?,boxCode?,installId,clientRequestId?}` | access/refresh token、期限、account、activation | 登录并保存 refresh token |
| `POST /auth/refresh` | refresh token 在 body | `{refreshToken}` | 新 access/refresh token 与期限 | 自动续期；refresh token 必须轮换 |
| `POST /auth/logout` | Bearer | 无 body | body 可为空 | 尝试撤销平台会话 |
| `GET /catalog/models` | Bearer | 仅未过期缓存可带 query `knownVersion` | policy envelope 或 `{unchanged:true}` | 登录后首次全量获取；过期或损坏的本地缓存强制全量覆盖 |
| `GET /dictionaries/sensitive?version=` | Bearer | 无 | signed dictionary envelope | 仅成功登录后同步服务端词库 |
| `GET /credits/ledger` | Bearer | 无 | `{balanceMicroCredits}` | 本地余额投影的唯一写入来源 |
| `GET /box` | Bearer | 无 | 当前帐号唯一已绑定盒子的安全投影 | 读取盒子与私有能力摘要；不提供局域网管理通道 |
| `POST /feedback` | Bearer | 结构化用户反馈；`Idempotency-Key: <UUID>` | `{feedbackId,acceptedAt}` | 接收用户主动提交的产品反馈 |

`clientRequestId` 的 struct 字段存在，但当前桌面调用未填值；服务端需接受缺失或空串。登录的 `activationCode` 与 `boxCode` 是可选的一对：两者都提供时是首次激活尝试；两者都省略时由平台判断该帐号是否已有授权；只提供一个应以 `invalid_request` 拒绝。`boxCode` 与激活码是独立校验，返回的 activation 中 `boxCode` 是展示值，不是 secret。

`GET /client/bootstrap` 仍是上游客户端实现中的遗留能力，但本产品运行时不调用它，中台无需为本产品实现或维护该接口。不要把模型目录、账户、余额或激活信息重新混装进一个“bootstrap”响应：目录的唯一来源是 `/catalog/models`，余额的唯一来源是 `/credits/ledger`。账本的 `balanceMicroCredits` 是指针语义：缺失与数值 `0` 不相同。客户端把缺失视作 `ErrLedgerMalformed`，保留旧余额，绝不把缺失编造成零。

## 请求与成功载荷

除下列端点约定的 query/header 外，请求 JSON 直接作为 body，不再包一层 `data`；成功响应统一包在本文开头的 `data` 信封中。字段未标为可选即必须提供且类型正确。日期时间均为 UTC RFC3339 字符串；令牌、激活码和盒子码都是不透明字符串，客户端不解析其内部结构。

| 端点 | 请求 | `data` 成功形状 |
| --- | --- | --- |
| `POST /auth/sms/send` | `{phone,purpose:"login",clientRequestId?}` | `{cooldownSec,expiresInSec}`，均为非负整数。 |
| `POST /auth/login` | `{phone,code,nickname?,activationCode?,boxCode?,installId,clientRequestId?}` | `{accessToken,refreshToken,accessTokenExpiresInSec,account:{id,phoneMasked,nickname},activation?}`；`activation` 为 `{status,activatedAt,expiresAt,boxCode?}`。 |
| `POST /auth/refresh` | `{refreshToken}` | `{accessToken,refreshToken,accessTokenExpiresInSec}`；refresh token 每次成功必须轮换。 |
| `POST /auth/logout` | 无 body | `null`；客户端只以成功状态为准。 |
| `GET /catalog/models` | 无 query 时为全量读取；只有已验签且未过期的缓存可带 `knownVersion=<已缓存 catalog.version>` 做条件读取 | 全量：`{policy:<原始 JSON>,policySignature:{keyId,sig},unchanged:false}`；过期或损坏的本地目录必须省略 `knownVersion`，中台必须返回新的完整签名目录，不能以 304 让客户端继续持有过期资格；未变时可返回 HTTP 304 空 body，或 200 `{unchanged:true}`。 |
| `GET /dictionaries/sensitive` | 可选 `version=<已缓存版本>` | 200 `{dictionary:<原始 JSON>,dictionarySignature:{keyId,sig}}`；未变只可为 HTTP 304 空 body。 |
| `GET /credits/ledger` | 无 | `{balanceMicroCredits}`，字段必须存在，可为 `0`。 |
| `GET /box` | 无 | `id,displayName,state,boundAt,management:{canView},capabilities:{privateModels,tools,knowledge,automation}`，以及可选 `lastSeenAt,softwareVersion`；能力项为 `{state,count?}`。 |
| `POST /feedback` | 本章“反馈端点”列出的 body，且 header 有 UUID `Idempotency-Key` | `{feedbackId,acceptedAt}`。 |

登录成功后客户端立即无 query 调用一次 `/catalog/models`；这不是从 login 响应推导目录。目录过期、切换帐号、无缓存或本地损坏需要重新获取时，客户端也只调用这个端点且省略 `knownVersion`，以新的已验签全量响应覆盖本地数据；只有未过期可用缓存才携带 `knownVersion`。同一 `catalog.version` 的重新签发可延长已验签有效期，客户端仅在新有效期更晚时原子替换，不能以本地时间自行续期。中台响应验签失败不是本地缓存损坏：客户端不会自动重试同一份不可信响应，等待中台修复后才在下一次显式刷新尝试。

## 反馈端点只保存明确提交的反馈

`POST /feedback` 是已由桌面客户端和 `productstub` 覆盖的受保护端点。请求 body 只允许 `category`、`title`、`content`、可选 `reproduction`、`expected`、`contact` 和必填 `impact`。类别只能为 `bug`、`suggestion`、`other`；影响程度只能为 `low`、`normal`、`high`；标题为 1–120 个 Unicode 字符，正文为 1–4000，两个可选长文本各至多 2000，联系方式至多 200。缺失、未知字段或不合法值以 `400 invalid_request` 拒绝。中台从 bearer token 取得账户，不接受 account ID、手机号、角色或客户端自报的时间戳。

请求必须带 UUID 形式的 `Idempotency-Key`。中台以“已认证账户 + key”去重：相同 key 与相同有效载荷重复提交，返回第一次接受时的同一 `feedbackId` 和 `acceptedAt`；相同 key 但载荷不同以 `409 idempotency_conflict` 拒绝。幂等记录的保留期由中台运维策略决定，但不得短于客户端网络重试窗口。成功体仍使用共同信封：

```json
{"data":{"feedbackId":"fb_...","acceptedAt":"2026-09-19T00:00:00Z"},"requestId":"req_...","serverTime":"2026-09-19T00:00:00Z"}
```

中台可以记录认证账户、服务端接收时间、标准客户端版本/平台/架构头和安装标识以便运营与反滥用；`contact` 仅在用户主动提交时保存，不得用账户手机号替代或补充。不得期望或要求客户端上传会话、聊天、附件、OCR、工具调用、模型提示/输出、token、文件路径、电话号码、硬件标识或日志。反馈内容不可回显到其他客户端，也不可被当作模型输入。内容保留、删除请求、人工处理权限和反滥用阈值由中台数据治理落实，不由桌面客户端自行推断。

稳定失败码为：`401 unauthorized` / `token_expired`（沿用一次刷新重放）、`403 feedback_not_allowed`、`409 idempotency_conflict`、`429 rate_limited`（可带 `retryAfterSec`）及 `503 maintenance` / `upstream_unavailable`。不要用 `message` 告知用户具体审核或风控理由；桌面客户端只按稳定 code 映射可操作文案。反馈节流的具体阈值是中台策略，不能硬编码到客户端或本文。

## 盒子是中台授权的单资源

`GET /box` 只返回 bearer 所属帐号当前绑定的一个盒子。首版不支持列表、绑定、解绑、改名、远程升级、局域网发现或桌面到盒子的直接请求；盒子应主动向中台报告状态，桌面只读取中台已经做过授权和脱敏的结果。

成功 `data` 采用本地契约相同的字段：`id`、`displayName`、`state`、`boundAt`、可选 `lastSeenAt` 和 `softwareVersion`、`management.canView`，以及 `privateModels`、`tools`、`knowledge`、`automation` 四个能力的 `{state,count?}`。`state` 分别使用 `online|offline|degraded|attention|unknown` 与 `available|unavailable|coming_soon`。私有模型的具体可选列表仍属于已签名 `/catalog/models`，盒子接口只提供摘要，不能制造第二套模型目录。

成功体不得含 activation/box code、LAN/WAN 地址、端口、设备序列号、硬件指纹、日志、模型 endpoint、任何密钥或 token。帐号无权访问返回 `403 box_access_denied`，不存在或未绑定返回 `404 box_not_found`，中台无法获得状态可返回 `503 box_unavailable`；这些码进入实现前必须同时加入平台错误码注册表、客户端、替身和本地文案。当前 `productstub` 的固定盒子仅用于开发联调，绝不是生产中台允许返回的默认值。

## 令牌状态机

access token 只存在内存的 `CredentialHolder`；可复制的数据根只保存 refresh token。每个受保护控制面调用走同一流程：

```text
首次请求（当前 access token）
  ├─ 非 401 ──> 原样返回
  └─ 401 / unauthorized / token_expired
       ├─ 刷新成功 ──> 用新 access token 只重放一次原请求
       ├─ 刷新被 401 拒绝 ──> 清内存凭证；运行时清本地会话
       └─ 网络或 5xx ──> 保留凭证，返回该失败
```

并发刷新由互斥锁合并；已被另一调用更新的 access token 不再次交换。refresh 成功时平台必须返回新的 refresh token，客户端把新对写入内存，运行时随后尝试持久化轮换后的 refresh token。持久化失败不会中断当前回合，但下一次启动可能要求重新登录；这是一种有日志的受限降级，不是可忽略的成功。

网关并不经控制面 HTTP 重放器。启动后的首个网关回合若内存没有 access token，会在 10 秒预算内调用同一个 `EnsureToken` 交换 refresh token；无法取得 token 时拒绝开始回合，不回退到本地模型。网关 401 也不由 OpenAI provider 自动重放。

## 已签名目录与词库

目录端点的 `data` 以如下形状携带原始 policy bytes：

```json
{"policy":{...},"policySignature":{"keyId":"kid","sig":"base64-ed25519"}}
```

词库对应为：

```json
{"dictionary":{...},"dictionarySignature":{"keyId":"kid","sig":"base64-ed25519"}}
```

签名覆盖的是嵌入 `policy` 或 `dictionary` 的**原始 JSON 字节**，而非客户端重新序列化的对象。`sig` 使用 Go `base64.StdEncoding`（标准字母表、带 padding）编码 Ed25519 detached signature。服务端必须先序列化一次，再对完全相同的字节做签名，并将同一字节嵌入外层信封；中间层不得重新格式化、转义或重排该值。

客户端按以下顺序 fail closed：选择 profile 中匹配 `keyId` 的 base64 公钥、验证 Ed25519 签名、解析 JSON、比较载荷内外 `keyId`、比较 audience、验证 RFC3339 的 issued/expires 窗口（允许调用方设置的时钟偏差）。任何一步失败、未知 key、无 key、不同 audience 或过期均不接受新缓存。

目录 policy 当前可消费字段为 `policyVersion`、`issuedAt`、`expiresAt`、`minClientVersion`、`audience`、`keyId` 和 `catalog`。catalog 包含 `version`、`ttlSec`、`vendors` 与 `models`；旧 `modes/modeIds` 不再解析为产品语义。当前最小形状如下：

```json
{
  "catalog": {
    "version": "2026-09-18",
    "ttlSec": 3600,
    "vendors": [
      {"id":"vendor-a","displayName":{"zh-CN":"厂商 A","en":"Vendor A"}}
    ],
    "models": [
      {
        "id":"model-a",
        "vendorId":"vendor-a",
        "displayName":{"zh-CN":"模型 A","en":"Model A"},
        "transport":"gateway",
        "eligible":true,
        "confidential":true,
        "confidentialPriority":100
      }
    ]
  }
}
```

`vendorId` 必须引用同一目录中存在的 vendor；所有模型的 `transport` 当前只接受 `gateway`；`confidential=true` 还要求 `eligible=true`。`confidentialPriority` 只允许出现在私密模型，取值为 `0..1000000`，数值越大优先级越高。未知 vendor、重复 vendor/model ID、非法 transport、矛盾资格或优先级越界时，客户端拒绝整个新目录而不是部分猜测修复。目录可包含没有私密模型的厂商，也可没有任何私密模型；后者是“当前无可用私密会话”，不是协议错误。

词库 payload 支持 `full`（完整 `words`）和 `delta`（匹配 `baseVersion` 后应用 `add`/`remove`）。`sha256` 是最终完整词表的 SHA-256：对 UTF-8 紧凑 JSON 数组字节求 hash；空列表按 `[]`。delta 的 base 不匹配、词项非法或 checksum 不匹配时客户端不写入缓存。

两个条件端点都接受已有版本：目录使用 `knownVersion`，词库使用 `version`。目录的 `knownVersion` 是客户端已验签并缓存的 `catalog.version`。仅当该缓存对应的已签名 policy **此刻仍在有效窗口内**时，服务端才可返回 304 或 `data.unchanged:true`；policy 已过期时，即使模型字段未变，也必须返回一份新的、完整且仍有效的已签名 policy。目录字段、签名 key 或其他身份语义变化必须使 `catalog.version` 严格递增；只有目录语义完全不变的重新签发才可沿用同一 version，客户端也只在新签名有效期更晚时原子替换，绝不能用本地时间自行续期。两种“未变”结果均不得改写缓存。词库客户端当前只把 304 转为本地 `Unchanged`，因此服务端不能用词库 body 中的 `unchanged` 字段替代 304。

## 错误分类与服务端约束

| 状态/码 | 客户端语义 |
| --- | --- |
| `400 invalid_phone`、`invalid_code`、`code_not_sent`、`activation_invalid`、`activation_code_used`、`box_code_unknown`、`box_code_mismatch`、`invalid_request` | 登录/激活或输入层面的业务拒绝；具体呈现由本地 API 决定 |
| `401 unauthorized`、`token_expired` | 触发一次 refresh；refresh 再拒绝才结束会话 |
| `403 activation_required`、`phone_mismatch`、`account_restricted`、`plan_expired`、`feature_not_entitled`、`model_not_allowed` | 业务或授权拒绝；不应伪装为 token 失效 |
| `402 insufficient_credits` | 网关回合的余额不足，客户端不本地推算 |
| `429 rate_limited` | 可带 `retryAfterSec`；验证码和反馈 UI 使用该值倒计时。 |
| `403 feedback_not_allowed`、`409 idempotency_conflict` | 反馈业务拒绝或幂等冲突；不结束平台会话。 |
| `503 maintenance`、5xx `upstream_unavailable`、`internal_error` | 非授权失败；不得因此清掉可重试的 refresh token |

业务码的稳定性高于 HTTP 文案。服务端可以提供诊断 `message`，但不可让客户端从 message 推断重试、注销或用户提示。没有平台明确的 401 结论时，网络失败、超时和 5xx 都必须保留本地凭证。

## 网关契约与验证

内置网关使用既有 `internal/provider/openai` 适配器，协议为 OpenAI Chat Completions。服务端至少必须支持 `POST /v1/chat/completions`、`Authorization: Bearer <access token>`、JSON body、目录中稳定的 `model` id、`stream:true` 以及 `stream_options.include_usage:true`。流式成功响应为 `text/event-stream`：每个帧以 `data: ` 开头，普通 assistant delta 使用 OpenAI `chat.completion.chunk` 形状，工具调用 delta 的 `tool_calls[i].function.arguments` 可以分片，终帧携带 usage，最后以 `data: [DONE]` 结束。非流式响应和错误同样遵循 OpenAI Chat Completions 兼容形状；认证、授权、余额或上游错误不得伪装成成功 SSE。工具 JSON 的内容过滤不属于本轮产品保护范围，但网关兼容层仍必须正确承载已有工具调用协议。

协议改动至少应验证：

- `internal/productclient/client_test.go`：方法、路径、headers、成功/失败信封、单次刷新与单次重放；
- `internal/productclient/signing_test.go` 与 `clienttest/wire_test.go`：原始字节签名、key/audience/有效期、签名字节不被 writer 改写；
